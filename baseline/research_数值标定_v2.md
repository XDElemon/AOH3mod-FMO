# 数值标定 v2：现有表能不能体现「代差」？（实测，不带猜测）

> 2026-10-18 ｜ 依据：`AircraftDataManager` 字节码 + `定稿_B3_02_数值发放与生成器_v1.md` 的数值表
> 结论先说：**不能。现有表在空战结算里几乎看不出代差，甚至方向是反的。**

## 一、战力公式的实测依据

`AircraftDataManager.applyType()`（第 179-183 行）：

```smali
iget v1, v0, AircraftTypeData;->Defense:F
const/high16 v2, 0x40000000    # 2.0f
mul-float/2addr v1, v2
iput v1, p0, AirUnit;->maxHp:F
iput v1, p0, AirUnit;->hp:F
```

⇒ **血量 = 防御 × 2**（不是独立字段，`AircraftTypes.json` 里也确实没有 MaxHp 键）

空战伤害（非死代码路径，`AirForceManager` ~3246-3290）：

```
目标.hp -= 攻击方.airAttack × 0.2
存活的目标反击：攻击方.hp -= 目标.airAttack × 0.5
```

⇒ **综合战力 P = airAttack × hp = airAttack × 2 × defense**
⇒ **交换比(D损失/A损失) = 0.4 × P_A / P_D**

## 二、拿 B3-02 现有数值表套进去

| 机型 | 3 代 P | 4 代 | 5 代 | 6 代 | 3→6 代 P 比 | 3→6 代交换比 |
|---|---|---|---|---|---|---|
| 截击机 | 720 | 1140 | 1786 | 2622 | 3.64× | **1.46 : 1** |
| 战斗机 | 600 | 950 | 1426 | 2204 | 3.67× | **1.47 : 1** |
| 轰炸机 | 2640 | 4200 | 6324 | 9576 | 3.63× | **1.45 : 1** |
| 攻击机 | 1200 | 1900 | 2914 | 4332 | 3.61× | **1.44 : 1** |

**逐代看更糟**：3→4 代 P 比只有 1.58×，交换比 **0.63 : 1** —— 意思是"先进一代反而吃亏"，
因为 0.4 这个系数天然偏向防守方（反击系数 0.5 > 伤害系数 0.2）。

⇒ **用人话讲**：按现在这套表，四代机打三代机只是"稍微更能打"，六代机打三代机也就 1.46 比 1。
离你要的"三代对四代绝对打不过"差了两个数量级。

## 三、要达到你的锚点，P 需要多大

| 锚点 | 需要的 P 倍率 | 均衡拆法（atk/def 同乘） |
|---|---|---|
| −1 代 8:1（歼-8 对 F-22） | **×20** | ×4.47 |
| −2 代 18:1（歼-20 时代） | **×45** | ×6.71 |
| −3 代 45:1（外推） | **×112.5** | ×10.61 |

⚠️ 注意一个陷阱：如果**每一代**都按 8:1 复利，3→6 代就是 `20³ = 8000×`，数值会膨胀到不可用。

⇒ 所以锚点曲线必须当作**相对 3 代的绝对倍率**用：`P4=20×P3`、`P5=45×P3`、`P6=112.5×P3`，
而不是逐代连乘。

## 四、两套可选落地方案

### 方案 A：纯数值放大（符合"代差只用数值"）

以 3 代为基础，按 `[1, 20, 45, 112.5]` 缩放，均衡拆（atk、def 各乘 √）：

| 机型 | 代 | 攻 | 防 | 血(=2防) | P |
|---|---|---|---|---|---|
| 战斗机 | 3 | 20 | 15 | 30 | 600 |
| | 4 | 89 | 67 | 134 | 11,926 |
| | 5 | 134 | 100 | 200 | 26,800 |
| | 6 | 212 | 159 | 318 | 67,416 |
| 截击机 | 3/4/5/6 | 30 / 134 / 201 / 318 | 12 / 54 / 81 / 127 | 24 / 108 / 162 / 254 | 720 / 14,472 / 32,562 / 80,772 |
| 轰炸机 | 3/4/5/6 | 60 / 268 / 403 / 636 | 22 / 98 / 148 / 233 | 44 / 196 / 296 / 466 | 2640 / 52,528 / 119,288 / 296,376 |
| 攻击机 | 3/4/5/6 | 30 / 134 / 201 / 318 | 20 / 89 / 134 / 212 | 40 / 178 / 268 / 424 | 1200 / 23,852 / 53,868 / 134,832 |

- 优点：完全靠数值，不动任何公式。
- 缺点：数值跨度大（攻 20→212），UI 观感、造价平衡、AI 判断都要跟着调；且 hp 高会拉长战斗。

### 方案 B：数值 + 机动/隐身参与命中（更接近真实，但要动结算）

现在 `agility / ecm / stealth / defense` 在空战里**一次都没被读**。若引入命中率：

```
命中率 = clamp(0.5 + k1·(agility_A - agility_D) + k2·(stealth_A - ecm_D), 0.05, 0.95)
交换比 ≈ (命中率_A / 命中率_D) × (P_A / P_D) × 0.4
```

- 代差可以用"几倍命中率"表达，P 只需要小幅提升（例如 1.5~2×），数值不至于爆炸。
- 但这是**机制改动**，要动 `airCombatOne` 那段结算，风险高于填数据。

## 五、我的建议

1. **先修结算**：`airCombatOne` 目前被 `return-void` 短路，任何数值都不会生效。
2. **采用锚点绝对曲线**（P4/P3=20，P5/P3=45，P6/P3=112.5），不要逐代连乘。
3. **拆比选"偏攻"**：`atk × m^0.7`、`def × m^0.3`。
   同样 P 下，偏攻版战斗 2~3 tick 结束，偏血版要 12~14 tick；前者节奏更像空战，也不会让血条长到离谱。
4. 方案 B 留作后续（等方案 A 跑通、验收过一轮再谈）。
