# 交接 · FMO 临时更新基线工程（v1）

> 2026-10-18｜读者：接手的人或 AI｜本文件是这套工程的总入口

## 一、这套工程解决了什么

原 FMO 装机包丢失、手上只有原版壳。本工程把「**原版壳 + 仓库 smali + 占位素材**」
做成一条可复现流水线，产出可装机包，并把飞机数据层改为 JSON 真源。

## 二、三个包（在 `/sdcard/Download/fmo_baseline/`）

| 包 | 内容 | md5 | 用途 |
|---|---|---|---|
| `fmo_baseline.apk` | 纯基线（5,530 类，无改动） | `7871a9c1…` | 装机验证 PairIP 剥壳是否奏效 |
| `fmo_candidate_gen.apk` | 基线 + `unitGenOf` 取真值 | `166cae02…` | 验证 5/6 代拿到 4 发导弹 |
| `fmo_candidate_stats.apk` | 上者 + 每代数值 + 生成配置 | `c41ebfa6…` | 验证代差（4 代打 3 代 ≈ 8:1） |

三者都是 debug 签名，包名 `age.of.history3.polaris.xuanxing`，**与官方包签名不同，需先卸载**。

## 六、验收顺序（务必按这个来）

1. 装基线包 → **能否启动**（PairIP 剥壳判定）
2. 起不来的话：抓 logcat，看 `pairip` / `VerifyError` / `FATAL`
3. 能起来 → 装 `fmo_candidate_stats.apk` → 看 5/6 代是否 4 发导弹、4 代打 3 代是否约 8:1
4. 结果回填 `验收清单_真机.md` 末尾表格

## 七、关键结论（省得重走弯路）

- **`airCombatOne` 自底座起被 `return-void` 短路**（注释 `# AA disabled`）→ 空战不结算伤害
- **`unitGenOf` 原本返回常量 3** → 代际在导弹线上完全没生效
- **`hp = Defense × 2`**（实测）→ 战力 P = atk × 2 × def，交换比 = 0.4 × P_A/P_B
- **B3-02 现有数值表 3→6 代只有 1.45:1**，体现不出代差
- **`typeID`(1..4) 不等于机型表下标(0..50)**，直接用会错位且不报错
- **smali 汇编非确定** → md5 不能当判据；用「两个反汇编产物对比」（门禁 v2）
