## 三、这轮做了什么（v35 → v46）

### 3.1 空军机型与科技树
- **机型表 64 槽**：`data/aircraft_models.json`（真源），`aid = (gen-3)*16 + country*4 + axis`。
- **科技 ID 固定化**（v38）：`data/air_tech_ids.json` + `tools/air_tech_ids.py`，改名走 `aliases` 过继、删机型留占位，ID 不再漂移。
- **改名与消歧**：`MIRAGE4→MIRAGEIV`（幻影 IV，不是幻影 4000）。
- **机型审计结果落地**：图-22M ↔ 图-160 对调（三代 TU22M / 四代 TU160）、欧洲五代去 F-35（改 LAMPYRIDAE + NEURON）、J11→J16（四代攻击）、F-35 归位五代、X-32→X-47B、MIG41→S70 等。
- **编制名**：一律 `裸型号 + 中文名（仅纯字母型号）+ 种类后缀`，如 `J50攻击机`、`SU57截击机`、`TEMPEST暴风雨战斗机`。
- **国家树归属**：`AirGroupTags`（数据 `data/air_tags.json`）——中国组含巴基斯坦，美国组含台湾/日韩澳/加/以/沙特/土耳其，欧洲组 45 前缀，**其余兜底俄国组**。
- **字段**：新增 `radarDetect`（550/900/1300/1800 按代）与 `isDrone`（NEURON×2、X47B、S70）；删除 `ecm/maxFuel/fuelConsumption/currentTarget/MISSILEHOPS`；`canAttackAir` 按机型显式给；造价/工期改按机型行取（修掉"面板 1800、实扣 200"）。

### 3.2 雷达盘渲染（本项目最曲折的一块）
最终形态（v45/v46）：

```
drawAircraftRadar 开头 1 行 invoke  →  AirRadarBld.drawAll(sb)
    ├─ 遍历 AirForceManager.radarProvinces（只取本国省）
    ├─ 半径：RadarDataManager.getRange(MIDCOURSE_ABM=2400 / RADAR=600 / ABM_SITE=300) × scale（<=0 三档兜底）
    ├─ 盘心：ProvinceDrawArmy.getAirDrawPosX/Y(pid, scale)（屏幕像素）
    ├─ 压扁：ry = AirLat.r(rx, getCenterY_Real())
    └─ RadarOverlay.drawDiscAny(sb, cx, cy, rx, ry) → begin(幂等) + drawDisc
飞机盘：drawAircraftRadar 循环逐任务 drawDisc（盘心=插值坐标，跟随飞机平滑移动）
整帧：FBO 内 α=1.0 画全部盘（后画覆盖先画 ⇒ 重叠饱和）→ end() 整图合成一次
```

关键常量与做法（**照抄，别自己推**）：

| 项 | 值 |
|---|---|
| 合成 α | `0x3d9fd659`（每帧合成 2 次 ⇒ 屏上净 **0.15**）；降级路径 `RadarDisc.draw` 同值 |
| 合成矩形 | `draw(fbRegion, 0, -CFG.GAME_HEIGHT, CFG.GAME_WIDTH, CFG.GAME_HEIGHT)`，1:1 像素，**不许除 scale** |
| FBO 尺寸 | `CFG.GAME_WIDTH/HEIGHT`（`Gdx.graphics` 在 resize 后过期） |
| glViewport | `fb.end()` 后会重置 ⇒ 合成前补 `Renderer.viewport->apply()` |
| 投影 | **不要切**（当前已是屏幕像素投影，自己设会让 FBO 上下颠倒） |
| 蓝层 | `RadarBitmap` 的蓝层烘焙与绘制**已全部撤掉**，只剩 AD 红层 |

### 3.3 工作流工具（这类活的防错）
- `tools/gates/gate_java_first.py`：新逻辑必须有 `.java` 真源，否则必须在 `baseline/smali_exceptions.txt` 登记且文件里真有 libgdx 引用；原版类只许"接线级钩子"（无分支/算术、新增 ≤40 行）。
- `tools/fmo.py`：`preflight`（模板/磁盘/工具链/stage 非空）、`verify`（dex md5/aapt/apksigner/zipalign/指纹）、`build`（自动 preflight+打包+verify+批次 JSON）、`gate`（四道闸门一条命令）。
- 闸门：`gate_behavior.py` B1–B26、`lint_verifier.py`、`selftest.sh`（14 项）、`dex_fingerprint.py`、`gates/gate_change_scope.py`。

## 七、踩过的坑（省时间用）

1. **汇编非确定性**：判等价只能用结构指纹，不能比 md5。
2. **stage 目录不能空**：`build_candidate.sh` 会 `zip error: Nothing to do`；用 `--ensure-stage`。
3. **打包必须前台跑**，`nohup` 会被杀。
4. **中段插 smali 前先确认寄存器在该点已定义**（v43 把 `sput` 插到 `v15` 赋值前 → VerifyError 闪退）。
5. **`str.replace(...,1)` 在 smali 里按文本匹配会插错方法**（同一条指令多处出现）——必须先按 `.method/.end method` 切片定位。
6. **`check-cast p0` 会被 lint 判真机 VerifyError**，桥方法要用 `move-object v0, p0` 中转。
7. **先写 smali 桥再 `build_java`**：桩生成器需要被引用的 smali 类已存在。
8. **`fb.end()` 重置 glViewport**；**FBO 尺寸用 CFG**；**合成坐标不除 scale**。
9. 真机崩溃只信 `logcat -b crash`——静态闸门抓不到 ART 校验器错误的全部形态。
