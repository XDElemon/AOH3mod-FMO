## 5. 出包流水线（标准六步）

```bash
cd /tmp/fmo

# ① 改代码 → 编 Java → 生成 smali
bash tools/build_java.sh <类名...>

# ② 汇编
java -Xmx6g -cp "$(cat /tmp/smali_cp.txt)" org.jf.smali.Main assemble src/smali -o /tmp/x<NN>.dex

# ③ 四道闸门（必须 4/4）
python3 tools/fmo.py gate

# ④ 变更范围白名单（每批一个 baseline/allow_v<NN>.txt）
python3 tools/gates/gate_change_scope.py \
  --base /sdcard/Download/fmo_baseline/fmo_v<上一版>_air.apk --new /tmp/x<NN>.dex \
  --allow-file baseline/allow_v<NN>.txt

# ⑤ 出包（签名 + zipalign + verify）
python3 tools/fmo.py build \
  --template /sdcard/Download/fmo_baseline/fmo_v<上一版>_air.apk \
  --dex /tmp/x<NN>.dex --stage /tmp/stage_v47 \
  --out /sdcard/Download/fmo_baseline/fmo_v<NN>_air.apk

# ⑥ 台账 + 提交 + 推送（TLS 报错就重试，最多 3 次）
```

## 8. 导弹系统（最容易再翻车的一块）

两套时钟 + 一个状态位 `msFxInit`（0=未初始化 / 1=屏内逐帧 / 2=停用）：

```
发射（AirMission.missileTick，strikeKind=1）
  · msFlyHours = AirMissileCore.flightHours(省距, 射程, 速度)   ← 屏外小时钟用
  · seedFx()：msFxX/msFxY = 飞机贴图位置（世界坐标）
  ├─ 屏内：drawAirMissileFx → msFxStep（推进 + 接触）→ msFxContact（结算）
  └─ 屏外：missileTick 小时钟按 msFlyHours 推进 → 到达/丢失
```

**坐标契约（只许换算一次）**

| 数据 | 空间 |
|---|---|
| `msFxX/msFxY`、省中心 `getCenterX_Real` | 世界 |
| `getAirSpriteX/Y`、`getAirDrawPosX/Y` | 屏幕 = `(world + mapPos) × zoom` |
| FBO 内 | 像素 |

**已修的坑**：
1. `msFxStep` 里接触判定原本调 `contact` 但用 `if-eqz` → 未接触反而结算、`fx` 变 2、永不绘制。
   修法：换调 `notContact`（= `!contact`），分支不动。
2. `drawAirMissileFx` 里已有内联"屏幕→世界"换算，**不能再调 `sx2wx/sx2wy`**（v63 双重换算，目标点偏 5.35 万 px）。
3. smali 的 `if-nez` 是"**非零**跳转"，`if-eqz` 才是"零跳转"（v62 读反过，白加了个 `beginFx`）。
4. 速度：`HPT` 被 `if-gtz` 跳过赋值（减半）× `drawAirForce` 每帧两次（翻倍）刚好抵消 —— v66 用
   `speedDiv = playSpeed/HPT` + `gateStep`（每任务 4ms 内只进一步）正式收口，**速度观感不变**。

**离线复跑**：`tools/gate_behavior.py` 里有 smali 解释器（`Obj/STATICS/INSTANCES`），可跑
`msFxStep`/`missileTick` 的路径；审计报告 §5 有复跑脚本与建议的 B34/B35 闸门。
