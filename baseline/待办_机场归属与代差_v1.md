## 三、数值标定（已实测，用真实结算语义跑的）

真实语义：`hp<0` 才死（`hp==0` 仍活着并反击）；活着才反击；反击系数 0.5，拦截系数 0.2。

| 配置 | 实测 1 架可清几架 3 代战机(atk25/hp30) |
|---|---|
| atk 120~140, hp 100 | **8 架** ✓ 差一代目标 |
| atk 120~140, hp 250 | **20 架** ✓ 差两代目标 |
| atk 160（0.2×atk=32 > hp30） | **∞（秒杀）** ✗ 交换比无穷大 |

⇒ **「一发秒杀」和「8:1 / 20:1」互斥**。因此攻击力被"不秒杀"卡住上限
（≤ 5×目标hp ≈ 150），**代差主要靠 hp 拉开**：高代不是打得更快，而是怎么打都打不死。

## 四、机场归属 bug —— 定位结果（重要）

**全仓库写 `Airport.civID` 只有两处**：`Airport.smali:61`（构造函数）、
`SaveGameManager.smali:400`（存档序列化）。

⇒ **"省份易主时同步机场归属"这段逻辑根本不存在**，不是漏了一行。
所以和平会谈分地后，省份归你、机场还挂原主 —— 用户实测到的正是这个。

**挂钩点**：`Province.setCivID(I)`（`Province.smali:17654`，public final，所有易主都走它）。
在那里加一步：按 `provinceID` 在 `AirForceManager.allAirports` 里查该省机场 →
改 `civID` → **丙语义下同时把机场内 `airport.aircraft` 里每架飞机的 `civID` 也改成新主**（缴获）。

**待确认的第二个疑点**：`Save_Airport` 存了 `civID`，但读档里没找到写回
`Airport.civID` 的代码 —— 若成立，读档后机场归属会退回建机场时的值，需一起修。

## 九、导弹管线实测补充（v2 追加）

### 9.1 两套时钟的实际入口

| 时钟 | 入口 | 触发方式 | 现状问题 |
|---|---|---|---|
| 真实毫秒（视觉） | `ProvinceDrawArmy.msFxStep`（9885）→ `msFxContact`（5592） | 每帧由绘制路径调用，开局/菜单打开时提前 return | **没有任何雷达圈判定** |
| 游戏小时（逻辑） | `AirMission.missileTick` | 无条件推进 | **和毫秒钟同时推进 = 双重计速** |

接触判定实测：

```smali
cmpl-float v9, v7, v8      # v7=本帧步进 v8=剩余距离
if-eqz v9, :msc
:msc
    invoke-static {p0}, AirMission;->msFxContact(...)
```

⇒ 只有"本帧步进刚好吃掉剩余距离"才接触，**雷达圈完全没参与**。
后果：导弹能在雷达圈外接触结算 → 雷达范围形同虚设；且在屏幕上飞时被两套时钟同时推进。

### 9.2 速度的 TECH-HOOK 已经留好了

`AirDefense.msSpd()F`：

```smali
# r6d255 TECH-HOOK: A2A missile base speed (px per gamehour).
# The tech tree update will replace this body (single point of truth).
const v0, 0x42870000      # = 67.5f
return v0
```

⇒ 原作者明确留了这个"单一真源"点位。`MISSILESPEED` 就接这里，
但它是**无参**函数，要改成按机型取，需要：
1. 新增 `AirModelStats.missileSpeed(I)F`（已有 `MISSILESPEED:[F` 表）
2. 给 `msSpd` 加 `msSpd(I)F` 重载，或加一个"当前任务"上下文字段
3. 毫秒钟（`msFxStep` 内 `msSpd()` 调用点）与小时钟（`missileTick`）都改吃同一个值

### 9.3 目标行为（用户口径）

- 导弹在**雷达圈内 且 屏幕内** → 走毫秒钟，接触结算（`msFxContact`）
- 导弹在**雷达圈外 或 屏幕外** → 走小时钟（`missileTick`），按游戏小时推进
- 两者**互斥**，不允许同时推进

实现要点：抽一个 `msInRadarAndOnScreen(mission)Z`，两处共用，避免逻辑漂移。
