## 调研回填 1：现有防空拦截机制（2026-10-25，子代理报告）

**结论：AD 是项目自建的「按回合、按省」系统，不是原版机制；目标写死 `AirMission`，不能原样拿来拦 AGM/ALBM。**

| 关键事实 | 内容 |
|---|---|
| 触发 | `AirForceManager.updateAll()` 末尾 → `AirDefense.tickTurn()`，每回合一次（不是按帧） |
| 开火条件 | 本省有 AAA 阵地（`airDefenseAt>0`），阵地数 = 本回合发数；无弹药/无冷却 |
| 命中率 | 每发 **80%**（`adHitChance`），过 roll 后伤害**固定 50**，无末端判定 |
| 目标 | 只扫 `activeMissions` 里的 `AirMission`（敌国+交战+有活机+射程内），**不按任务类型过滤** |
| 结算 | 可见：逐帧追到才爆；不可见：`tickHits` 按 `due+12h/48h/10s` 兜底 |
| 目标绑定 | 16 个 `ad*` 字段挂在 `AirMission`；11 个方法签名全是 `AirMission` |

**对 AGM/ALBM 的结论**
- 不能复用「管线」，只能复用零件：命中率常数、固定伤害、`AirLat` 射程数学、弹迹绘制数学；
- **绝不能**把导弹伪装成 `AirMission` 塞进 `activeMissions`：`recordLoss` 会调 `sourceAirport.removeAircraft` 且无空检查（NPE），还会污染 30+ 个消费者；
- 推荐：新建 `StrikeMissile` 状态（`civID/hp/provinceID/worldX/Y/targetRef/intercepted`）+ 一份 `AdIntercept`（`due/dmg/fx*`），拦截在**发射时/终端**判定；地面伤害入口先检查 `intercepted`；
- 触发时机要选：现有 AD 只在回合末开火，同一回合内发射并命中的弹来不及拦 → 走「发射时判定」或「终端判定」，不要依赖 `tickAll`。

**附带发现（建议单独修）**：AD 射程的「雷达加成」极性疑似反了——无雷达 130、有雷达+长波反而 100；而红圈按正确的 100/130 画，会出现「圈内打不到、圈外能打到」。门禁 `check_airrange.py` / `sim_airrange.py` 的语义也反了，所以一直是绿的。

## S5/S6 拦截设计（按上述结论）

- **AGM**：低空可见 → 发射时按路径省/目标省 AAA 做 1 次拦截 roll；拦下则空中爆炸，没拦下继续飞；可见弹迹可复用 `adFxStep` 数学。

- **日志**：新增 `nADI`（拦截结算：类型/id/dmg/kill），可见路径也要写（现有 AD 可见接触完全静默）。

## 调研回填 2：ALBM 能打掉什么（2026-10-25，子代理报告）

**一句话：城市不是独立可损伤对象，打城市 = 打它所在的省；机场是"建筑+Airport 对象"两层，没有耐久，只能拆或减容量。**

| 目标 | 推荐改的值 | 说明 |
|---|---|---|
| 城市（=省） | **人口**（按族比例扣 10–30%）+ **荒废度**（+0.25~0.5，封顶 0.5）+ **经济**（-10~30%，下限 0.1） | 三个值都存盘、有慢恢复；荒废最长效（约 100 个月才退），经济立刻影响预算 |
| 机场（部分损伤） | `Airport.maxCapacity -= 10` + 按比例 `removeAircraft`（只删 `!isInFlight`） | 挡新建 + 干掉部分停放飞机；持久化到存档 |
| 机场（彻底瘫痪） | 先 `clearPatrolForAirport`，再 `destroyBuilding(空军基地)` | 建筑拆了，机场/雷达自动注销；停放飞机随对象消失 |
| 驻军（可选） | 每团 `num -= 比例`，然后 `ArmyDivision.updateArmy(true)` | 不刷会显示旧强度 |

**收尾刷新（必须做，否则面板/预算看不到）**
`updateProvinceIncome()` → `gameThread.addCivUpdateTotalIncomePerMonth(civID)` → `updateProvinceValue()` → 玩家面板 `rebuildInGame_ProvinceInfo(true)`。
经济改动用 `updateAfterEconomyChange()`。

**已知坑（实现时避开）**
1. `setDevastation` 内部的收入刷新是死代码（阈值 6.0 vs 荒废上限 0.5）——必须自己刷；
2. `setPopulationOfCivID` 正常路径恒返回 false，别拿返回值判成功；
3. `executeAttack` 改经济/人口后不刷收入——ALBM 别照抄；
4. `unregisterAirport` 的 null 判断写反（`if-nez` 应为 `if-eqz`），靠每帧 `syncAirports()` 兜底；
5. 拆机场前不 `clearPatrolForAirport` 会留孤儿任务；
6. 省份面板不自动重读，要 `rebuildInGame_ProvinceInfo(true)`。

## S0g 雷达盘裁剪（v89：根因定死 + 重写 —— **✅ 2026-10-26 真机验收通过**）

> 完整交接：`/sdcard/GLG/DSHA/FMO_雷达盘裁剪_交接_20261026.md` §11
> v89 包：`/sdcard/Download/fmo_baseline/fmo_v89_air.apk`（md5 `6def569e…`）
> 闸门：`tools/gate_air_disc_clip.py`（B41，真 Java 类 + 逐像素理想裁剪，10 场景；红样本已验证）

**v88 真机症状 → 根因（两份独立审计 + 装机 dex 核对）**：
1. **小蓝盘整块消失 / 完全不裁（随屏幕位置翻转）**：`rowInterval()` 把横区间打包成
   `(left<<16)+right`，`collectBlocked()` 解码写成 `iv-(iv>>16)`（正确 `iv&0xFFFF`）⇒
   左端≥0 时右端解成 ≈`left*65535+right`（10⁷）⇒ 遮挡段吃到行尾；左端<0 时右端巨负 ⇒ 不裁。
2. **大蓝盘在右且未包住圆心 → 右侧直边长条**：求差循环缺 `if (bs>=end) break;`。

> 教训：旧离线模拟器是**按伪代码重写**的（解码/收尾都对），所以复现不出真机 bug。
> **以后离线验证一律跑仓库里的真 Java 类。**

**v89 实现**：不再打包（`sRowL/sRowR` 双字段）；`collectBlocked(ya,blues,reds,clipL,clipR)`
排序+合并+裁到行内；`bbox(更大蓝盘 ∩ 红盘 ∩ 小盘)` 三重判交（不相交就走整盘纹理绘制）；
整盘被盖住直接跳过；行距 `≤260→1 / ≤700→2 / ≤1400→3 / else 4` 且半宽取带内最窄行（无外溢）；
单盘 try/catch 互不连坐。


**用户口径**（2026-10-26 确认）：按半径降序画；蓝盘只在"**更大的蓝盘 ∩ 红盘**"处给红让位；
其它蓝蓝重叠同色、不裁；红盘永远画满。

**实现**（纯 CPU，不依赖 GL 状态）：`AirDiscQueue.flush` 排序后，
被裁的蓝盘按 2px 扫描行求差集 `(前序蓝盘并集) ∩ (红盘并集)`，用 `AirRect` 的 1×1 白块逐行拼出可见部分。

**这一轮修掉的三个硬 bug**（都真实出过、都表现为"裁剪不对"）：
1. **无条件裁蓝**：蓝蓝重叠处没有红色可露，裁出来是洞/月牙 ⇒ 只裁与红盘相交的部分
2. **区间求差收尾**：遮挡区间伸出圆盘右端时 `break` 却没把 `start` 推到末尾，
   后面的收尾又画了回去 ⇒ "在大蓝盘里建反导阵地，裁剪不生效"
3. **底部细行**：椭圆边缘 1~2px 宽的行仍按 2px 高画 ⇒ 小蓝圈下方残留条

**已知代价**：被裁蓝盘的边缘是 2px 台阶（无抗锯齿）。

## S0f 雷达盘叠放规则（v83）

**用户口径**：不要描边环、不要半透明混色。要**小圈压在大圈上面**——大圈先画、小圈后画，
于是任何小圈都完整可见，大圈只在被小圈占住的一小块被盖，整体轮廓仍读得出来。

**实现**：新增 Java `AirDiscQueue`，四类盘每帧先入库

`RadarOverlay.drawDiscAnyColor`，然后清空。

- 同色圈重叠本来就是同一种颜色，天然融合；
- 跨颜色的谁在上，**现在完全由半径决定**（大让小）。若以后要"红永远压蓝"，
  在 `AirDiscQueue` 的排序键里加一个优先级位即可。

**改动面**：`AirDiscQueue`（新）+ `AirRadarBld/AirRadarAD/AirRadarPlane` 三处改入库
+ `ProvinceDrawArmy.drawAircraftRadar` 一处改入库、`end()` 前加 `flush`。
不改 FBO、不改合成 α、不改贴图。

### v80（同日）：修 v79 真机「绿椭圆在转 / 扫过处发红 / 露出底层蓝圈」

v79 装上后用户实测：盘变成一个**不透明绿椭圆**在转，转动处发红，还露出底下的蓝盘。两个硬错：

1. **颜色通道打包错**：`Pixmap.drawPixel` 要的是 **RGBA8888**（R 在最高字节），v79 按 ARGB 打包
   （`(a<<24)|0x00FFFFFF`）⇒ 实际写出的是 R=a、G=B=255、A=255，于是纹理全是"不透明青绿"，
   alpha 完全没生效。修：`PACK_WHITE = 0xFFFFFF00`，低字节放 alpha。
2. **椭圆不能靠旋转**：盘是纬度压扁的椭圆，把带扇面的贴图整体旋转后不再是同一个椭圆
   ⇒ 边缘会转出盘外、露出下面的盘面。修：**扇面改在纹理空间里烘**（天然就是椭圆），
   每帧按角度重烘一张 64×64 小图、`Texture.draw(Pixmap,0,0)` 上传，绘制时只拉伸、**不旋转**；
   同一帧内所有盘共用一次烘焙（`lastBaked` 角度缓存）。

### v79（同日）：蓝盘改「淡填充 + 亮描边 + 旋转扫描扇」

用户对 v78 的反馈：红圈改环只解决红盖蓝，**飞机任务盘（也是实心蓝）飞过去照样把别的圈盖掉**。
选定方案③并追加扫描动画：

- **盘面织物**：中心淡填充 α≈0.32，0.86 半径起过渡到亮描边（整圈一圈亮边）
- **扫描扇面**：105° 拖尾、**3 秒/圈**、前沿最亮向后渐隐、中心与外缘径向压低（软接缝）
- **像素由 Java 算** `AirRadarTex.fabric/sweep/rotation`（纯数学，javac 保证极性/边界）；
  smali `AirTexBake` 只做 `int[] → Pixmap → Texture → TextureRegion` 与旋转绘制
- `RadarOverlay.drawDisc`（**建筑蓝盘 + 飞机任务盘共用**）换成织物贴图，并在其后叠扫描扇
- 红圈不动：AD 仍是 v78 描边环，飞机/导弹红圈仍实心（下一批可再议）

**代价（已知）**：织物中心 α<1 ⇒ 重叠处会轻微叠亮，v45 那套"绝对不叠亮"变成"基本不叠亮"。
刻度：织物 body α 0.32、FBO 合成仍 0.15；如果实机偏亮，调 `AirRadarTex.fabric` 的 bodyA。

### v78（同日）：防空红圈改描边环，不再被蓝盘盖住

用户报：蓝盘（探测范围）与红盘（防空火力）都是实心盘，重叠区只看得到一层；
反导阵地的红盘（`100 × iMapScale = 400`）比蓝盘（`ABM_SITE = 300`）大，蓝盘整块被盖掉。

### v77（同日）：拆一栋雷达类建筑，整省蓝圈红圈全消失

用户报：一个省同时建了 雷达 + 反导阵地 + 中层反导，**随便拆一个**，雷达圈（蓝）和
火力范围圈（红）直接全消失；建回去又全出现。

### v76（同日）：v75 真机"一张都不显示"的根因修复

装上 v75 后只看到机场图标、雷达/反导/中导一个都不出来，四道闸门全绿。排查 6 个诊断包后定位，两个原因：

1. **`AirBldIcon.drawIcon` 空判极性写反**：写成 `if-nez v1, :ret`，而 `if-nez` 是**非零跳转**
   ⇒ 取到图反而直接 return，四张图一张都不画。正确为 `if-eqz v1, :ret`（等于零才 return）。
   日志 `ADI p=… n=4` 一切正常、无异常，完全静默。
2. **`drawAirForce` 里还有一段原版内联的 36×36 `airUnit → Image.draw`**（v75 只删了三个方法调用）。
   它正好盖住圆盘第一格，把"全都没画"伪装成"只画了第一张"。

修复：`if-nez → if-eqz`；删掉内联段；撤掉全部诊断代码（保留坏 id 兜底重载 + 逐张 try/catch）。
**闸门新增 B38**（桥空判必须是 `if-eqz` / 无内联 `airUnit` / 挂点存在 / 无 `ADI ` 诊断残留），
红样本已验证。技能新增 `fmo-render-invisible`，`fmo-air-rendering`/`fmo-patch-pipeline` 同步更新。

**教训**：现有四道闸门**都抓不到"极性写反"**（B31 只管 `move-object`）。手写 smali 里的任何
`if-eqz/if-nez` 要么配闸门断言，要么改成 Java 让 `javac` 决定极性。
