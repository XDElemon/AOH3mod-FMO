## 0. 结论（先行）
1. **政体字段 `REQUIRED_TECHNOLOGY` 语义已确证**：
   - `≥0`：必须"已研究该 ID 的科技"才能 切换政体 / 革命转政体 / AI 选择 / UI 可用（五处消费者同构）。

   - `≥0` 且指向被删科技：**永久不可用 + tooltip 取值悬空风险**（`lTechnology.get(req)`）→ 必须消除。
2. **B1 处置（对应新决策）**：`game/Governments.json` 的 20 处 `REQUIRED_TECHNOLOGY` **全部 → -1**。
   - 原值：`57×4、63×4、52×1、23×1`（非 -1 共 10 处），另 10 处本就是 -1。
   - 效果：科技门槛整体移除（今后由"钢丝式政体机制"批次去承载新的解锁/切换逻辑），且**无需改 smali**（B1 仍是纯资源批次）。

### 1.2 判定消费者（五处同构）
| 位置 | 用途 | 逻辑（复核后的极性） |
|---|---|---|
| `IdeologiesManager:162-254 canChangeToIdeology` | UI 可切换标记 | 当前政体→false；`req≥0 且 !researched`→false；否则进入 canBeAdded 等 |
| `IdeologiesManager:318-418 changeGovernmentType` | 实际切换 | `p3!=0` 跳过检查；否则 `req≥0 且 !researched` → 拒绝（return false） |
| `IdeologiesManager:556-626 getHoverIdeology` | 悬停提示 | `req≥0` 时显示 `RequiredTechnology: <科技名>`（`lTechnology.get(req).Name`） |
| `RevolutionManager:2895` | 革命/叛军转政体 | `req<0` 或已研究 → 允许；未研究 → 另一分支 |
| `AI_Government:312` | AI 政体选择 | 未研究 → 剔除候选 |
| `InGame_ChangeIdeology:756`（及其 `$2`、`Ideology2` 同族） | 玩家点击切换 | 未研究 → 走"不可用"分支 |
| `ButtonTechnology:2695 / 11543` | 科技按钮 tooltip | **反向**展示"此科技可解锁的政体"（`req == techID` 匹配） |
