# r6d062 · 已应用补丁清单 / 事实落盘

## 一、本批结论（一句话）
**配置解析 bug 是真的，且已定位到 5 处"方向写反"的守卫并全部修正**；用新方法 `cfgFix()` 做到
"读到什么 / 解析出什么 / 字段里是什么"三步自证，设备实测全链路一致。

## 二、根因（全部在 `AirForceManager` 内）

| # | 位置 | 错误（写反） | 正确 | 症状 |
|---|---|---|---|---|
| 1 | `cfgExtractInt` 首条守卫 | `if-nez p0, :cond_6e`（非空即跳去 return 默认） | `if-eqz p0, :cond_6e` | 文本非空 ⇒ 全部键拿默认值 |
| 2 | `cfgExtractInt` key 查找后 | `if-gez v2, :cond_6e`（找到就跳去 return 默认） | `if-ltz v2, :cond_6e` | 键存在⇒返回默认 |
| 3 | `cfgExtractInt` `:` 查找后 | `if-gez v3, :cond_6e` | `if-ltz v3, :cond_6e` | 同上 |
| 4 | `cfgExtractInt` 负号处理 | `if-nez v8, :cond_6d`（负数反而不取负） | `if-eqz v8, :cond_6d` | 解析值符号取反：`33 → -33` |
| 5 | `demoLoadCfg` prob 下限钳位 | `if-ltz v2, :cond_42`（非负反而落进清零） | `if-gez v2, :cond_42` | 叠加 #4：`prob` 必被清成 **0** |

**症状 ↔ 修复对应**：`BOOT2 prob=0 pin=-1 cap=4 build=1` = #4+#5（prob 被清 0）+ #1/#2/#3（其余键全默认）。

## 七、铁律与坑（本批新增/强化）

- **★同一类守卫可以"整组写反"**：`cfgExtractInt` 里 4 个守卫全部反向 ⇒ 只查"有没有判断"是不够的，必须**逐条给真值表**。
- **★`if-nez/if-eqz/if-ltz/if-gez` 的方向必须用"跳转目标是什么"来判读**（本例 `:cond_6e` 是 `return p2`），不能凭直觉。
- **★门禁必须解释执行真实 smali**：本批门禁先抓到"我新写的 `if-nez v2,:cf_st0` 也写反"，再抓到"符号取反"，最后**用"原始 bug 变体必须判 FAIL"** 证明门禁有效。
- **★SELinux 会挡住 `pm install /sdcard/...apk`**（system_server 读不了 fuse）⇒ 必须 `cp` 到 `/data/local/tmp` 再 `pm install`。
- **★装机后 `files/` 不会被清空**（本次实测：旧日志与配置仍在），但仍要重建/复核配置。
- 其余沿用：探针独立成方法 / 读 pkg/files 用 `java.io` / 诊断走 `dWrite` / 装机用 autotap 前台跑 / 每次交付附设计逻辑。
