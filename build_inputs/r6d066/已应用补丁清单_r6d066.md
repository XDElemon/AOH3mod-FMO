## 一、本批做了什么（一句话）
对齐《钢铁雄心4》的背景轮换设计：加载页背景**每 T 秒换一张**，T 由配置键 `load_swap_ms` 控制（默认 3000ms，0=关闭）。

## 三、判定规则（人话）
每帧加载页绘制时调用一次 `loadingRotateTick()`：
1. `dgLoadSwapMs <= 0` ⇒ 关闭；
2. `lastSwapMs == 0` ⇒ 只记录当前时刻（本次不换，保证首图展示满 T）；
3. `now - lastSwapMs < T` ⇒ 等待；
4. 否则 ⇒ `lastSwapMs = now` ⇒ `InitGame.loadBackground()`（dispose 旧纹理 → 随机取新 id（避开当前）→ 重载 → 重算 `backgroundWidth/Height`）。

挂钩点选择依据：`Renderer.drawLoading` **只被 6 个加载页调用**（`InitGame`、`Menu_LoadSavingGame`、`Menu_Load_Workshop`、`Menu_LoadSavedGame`、`Menu_LoadSaveScenario`、`Menu_LoadScenario`）⇒ 只在加载页生效。
`InitGame.loadBackground()` 同时被主菜单按钮复用 ⇒ 与钢4 的"加载页/主菜单同池"一致。

## 六、★本批血案与铁律（新增 3 条）
1. **自定义汇编器的 16 位陷阱**：值落在 `0x8000–0xFFFF` 的常量（如 `60000=0xEA60`）会被按 16 位处理并**符号扩展成负数**（实测 `fswap=-5536`）。
 ⇒ **规避：常量一律避开 0x8000–0xFFFF 区间**（本批把上限钳位从 60000 改为 30000）。
2. **产物链必须逐环核对指纹**：本批一度出现"`/tmp` 是新 dex、归档/装机是旧 dex"的错位，导致"改了却没生效"的假象。
 ⇒ **规矩：汇编后核对 dex md5 → 打包后核对 `包内 dex md5 == 期望 dex md5` → 装机后核对 `装机 base.apk 内 dex md5`**，三者一致才允许装机。
3. **`if-lt`/`if-gt`/`if-le`/`if-ge` 是两寄存器指令**：单寄存器形式只有 `if-eqz/if-nez/if-ltz/if-gez/if-gtz/if-lez`；写成 `if-lt v0, :label` 直接汇编报错。
（另沿用：文本类资源必须 `od -c` 字节对齐；极性/分支必须走真解释器门禁 + 负样本，且负样本要够深——本批"关闭失效"这条必须用**两帧序列**才能暴露。）
