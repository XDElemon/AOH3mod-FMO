## 三、本批血案与铁律（新增/强化，必读）
1. **★ 行级删除会毁树**：r6d073/r6d074 失败后，我用"按关键词删行"清理残留（`:adf1_done`/`:adf2_done`/`airFrameSkip`），删掉了引用却留下定义、并把 try 块内的指令删掉而没同步 `.catch` 标签范围 ⇒ 汇编器报
 `mismatched tree node: Lcom/.../SpriteBatch; expecting I_CATCHES` + `Cannot get the location of a label that hasn't been placed yet`（还伴随汇编器自身 NPE）。**结论：清理 == 从干净备份整份复原再重放，永不按行猜。** 复原后**一次通过**（`A=1 E=0`）。
2. **★ `getActiveDivKey()` 语义纠正**（本批最重要的认知修正）：它读的是 **`Game.activeArmy[0]`**，**选中陆军时同样非空**。因此"非空 ⇒ 空军选中"是**错的**，会连陆军框一起撤掉（r6d076 的实测症状）。正确判据 = **非空 且 以 `airhq_` 开头**。
3. **★ 真绘制者是哪一个**：`ProvinceDrawArmy` 里 `drawProvinceArmyActive` 有**两个**——
 - `public static final ... (SpriteBatch;IIF)V`（4462 行，参数含 `nProvinceID/nArmyID`，内部有 try/catch）；
 - `private static final ... (SpriteBatch;III)V`（4559 行，参数是**坐标与宽度**，方法内 **0 个 catch** ⇒ 插标签安全）。
 我把守卫放在私有那个（无 try ⇒ 结构安全），代价是**它没有部队身份**。
4. **★ 标签不得插入 try 区域**：在带 `.catch` 的方法内插标签，汇编器会报 `label hasn't been placed`。要插守卫就放到**无 catch 的方法**，或把逻辑整体挪进独立方法。
5. **★ 指令行带缩进**：smali 目录直属指令行（`.line`/`.param`）前有 4 空格，用 `startswith('.line')` 会漏判断（本批 patch 脚本第一版就栽在这）。
6. **★ 产物链每环核指纹**：汇编 dex → 包内 dex → 装机包体积，三者一致才装机（本批 `e3780cde`/`ade65f92` 均一致）。
7. **★ 装机老坑复现**：`INSTALL_FAILED_INSUFFICIENT_STORAGE` ⇒ 先清归档旧包（每版本 ~761MB，`/data` 11–12G 余量才稳）；`/sdcard/GLG/...` 属主 root、shell 读不了 ⇒ 必须先 `cp` 到 `/sdcard/Download/` 再 `cp` 到 `/data/local/tmp/` 后 `autotap_install.sh`。
