## 〇、一分钟版（TL;DR）

- **目标**：给拦截机（INTERCEPT）加"射程内（相邻省）主动发射导弹"的远程攻击能力；弹药随代际、节流按回合。
- **回合号（T0 实测修订）**：**1 回合 = 日历推进一次 = 2 游戏小时；12 回合 = 1 天**（`HOURS_PER_TURN=2`）。`TURN_ID` = **天计数器**（每 12 回合 +1）→ 战斗时标一律用**复合时标** `totalHours=TURN_ID*24+HOUR`。任务节拍（心跳）由 `throttlePass()` 门控=每 `playSpeedTIME` ms 一次（五档实测 1000/500/250/125/45ms）→ **墙钟节流会受游戏速度影响（已证）**，故本包战斗节流全部回合化。
- **弹药**：`2 颗/机×编队` 池；每轮齐射扣"当前存活机数"；打空 → `nMS dry`，之后仅机炮。
- **节流**：两次齐射间隔 ≥ **6 回合 = 12 游戏小时**（N=6，2026-09-11 用户调整；判定式见 §3.4）。
- **命中**：发射回合 T → **T+1 回合**结算伤害（K=2.0×ΣairAttack）；目标丢失 → 空爆（miss）。
- **拆包**：R6-5a（R4c99）= 机炮回合化 + 导弹逻辑 + 探针；R6-5b（R4c100）= 方块动画。
- **R6-5c（R4c103，预案）**：导弹动画锚定到飞机贴图（我方贴图中心 → 敌机贴图中心；实时追踪）；调研完成、预案就绪（详档《导弹动画贴图锚定_调研报告v2.md》+ §12）。
- **探针验收**：**9 个核心打点 + 1 个可选**（标定组 P0a/P0b 先钉死回合语义；逻辑组 6 + 绘制组 1）；数据格式/参考指令/判读手册见 §六。

## 一、术语与核心原则

| 术语 | 含义 |
|---|---|
| **回合** | 日历推进一次（`HOUR += HOURS_PER_TURN`）；**12 回合 = 1 天**（T0 实测 hpt=2） |
| **总时标** | `totalHours = TURN_ID*24 + HOUR`（单调递增；1 回合 = +2） |
| **心跳 / pass** | `AirMission.update()` 中经 `throttlePass()` 放行的"逻辑步"（≥1 次/`playSpeedTIME` ms）|
| `playSpeedTIME` | 速度档 1-5 对应的"一回合时长（ms）"（`GameThread.playSpeedTIME`），随游戏速度变化 |
| 墙钟 | `System.currentTimeMillis()`，**会受游戏速度影响，战斗节流禁用** |

**核心原则**：
1. **速度无关**：战斗节流/冷却/命中一律走回合（TURN_ID），视觉时长随回合时长自适应。
2. **不猜，打探针**：所有新逻辑挂双层探针（逻辑层 + 绘制层）对账。
3. **条件跳转三步法**（㊿102）：语义→真值表→指令；写完 `grep 'if-'` 全量复核。

## 二、深度调研结论（本轮全部实证，含行号）

### 2.1 全局回合号 = `Game_Calendar.TURN_ID`（static int）

- 字段定义：`Game_Calendar.smali:49`（`sget` 直接读，零缓存零风险）
- **递增点**：`GameThread.smali:2239-2243`
  ```
  sget v0, TURN_ID → add-int/lit8 v0, v0, 0x1 → sput v0, TURN_ID
  ```
  触发条件：`HOUR += Game.HOURS_PER_TURN`（2195-2201），`HOUR>=24` 时归零并 `TURN_ID++`（同段还做 `nextDays()` 2265-2268、`autoSave()`、`updateNewMonth/Year`）。
  **T0 实测（R4c98b）**：`HOURS_PER_TURN=2` → 每 12 回合才跨天，即 **TURN_ID = 天计数器**（nD 记录 t=2→80；nD/nT = 78/933 ≈ 1/12 实证）；**1 回合 = 2 游戏小时**。
- `Game.HOURS_PER_TURN`：`Game.smali:42`；赋值 `MapScenarios.smali:7820`（情景设定值 clamp ≤24）。**运行时实际值**：T0 实测 = **2**（`nT` 全量 933 行一致）。
- 先例：战报系统已在用（`AirMission.smali:1140` 轰炸战报；`Battle.smali:2846/2877`）。

### 2.2 任务节拍（关键修正点）

- `throttlePass()`（`AirMission.smali:1748-1791`）：**每 `playSpeedTIME` ms 恰好放行一次**（diff≥playSpeedTIME → true+重置；diff<0 异常 → true+重置）。
- `update()` 结构（2706 起）：
  1. `updateAnimClock()` → 播放门控（暂停/菜单直接 return）
  2. 进度计算 + `moveDivisionAlongFlight()`（**每帧**，平滑移动）
  3. `throttlePass()` 门控 → 未过 ⇒ return
  4. `trackTarget()`（2842）→ `airCombatTick()`（2843）→ `packed-switch v0, :pswitch_data_234`（2844，v0=state ordinal）
- **结论**：导弹/机炮的新逻辑一律放进第 4 步（与 `airCombatTick` 同拍），天然继承所有门控；`roundsInFlight` 等任务内计数也是这个节拍（随速度伸缩）。
- **补充实证（R4c99 验收期）**：`AirMission.update()` 由**渲染线程**驱动（`AA_Game.render → AirForceManager.updateMissions`）→ `missileTick` 读到的是**任意帧时刻的时钟快照**（`h=0/24` 均为合法刻度）；判读一律用 `totalHours` 差值，**不假设与回合边界对齐**。

### 2.3 机炮现状（C1 已验收逻辑，本包只改节流）

- `airCombatTick()`（3438-3600）门链：type==INTERCEPT → state∈{EN_ROUTE, EXECUTING} → `airDivisionAtProvinceID>0` → **墙钟门：`now-airCombatLastMs≥1000ms`**（3453-3459）→ 扫描。
- 扫描规则（3460-3500）：遍历 `AirForceManager.getInstance().activeMissions`；**civID 相同跳过（≠ 才视为敌）**；敌 state∈{EN_ROUTE,EXECUTING} 且 `airDivisionAtProvinceID==我的省` 选中；低 missionID 一方执行交换（3515 cmp 判定）。
- 伤害（3501-3560）：v10=Σ我方 airAttack×0.5；v11=Σ敌×0.5；`applyAirDamage(敌, v10)` + 反向；探针 `nAC hit`。
- `applyAirDamage(target, dmg)`（3602-3652）：逐机扣血（超额顺延）；hp≤0 → `recordLoss`（2593-2610：移出 alive→lost→机场移除）+ `recordKill` + `nAC kill` ；末：`recordDamage` + `target.recalcPool()`。
- **问题确认（用户判断正确）**：1000ms 墙钟在速度变化下"每回合炮击次数"漂移。
- `drawAirGunFx`（PD 8075-8136）：开火后 250ms 内显示橙色块（读 `airCombatLastMs`），`nGX shot` 用 `gunFxDbgMs` 去重。**改机炮节流后此两处继续兼容**（见 §3.8）。

### 3.3 射程与代际（2026-09-11 改定：距离制）

- **现版：距离制（雷达圈式）**——`missileIsNeighbor` 于 R4c104 改为 **Real 坐标平方距离 ≤ R²**（`d²=dx²+dy²`，与雷达探测判定同构）；不再走省邻接表。
- **R 值**：`missileRangeForGen(I)I` 占位 **全代 = 100（坐标单位，≈195km；2026-09-11 由 200 下调）**，一处可调；代际接线（M2-A）后按真代际取表。
- 旧"跳数"概念废弃：`missileHopsForGen` 占位保留不再使用（登记 §11-9）。
- 探针：`nMS fire` 追加 ` d=`（发射时双方 Real 距离）+ ` r=`（当前 R 值）→ 实测标定。

### 3.4 节流：N=2 是什么意思（用户问答 · T0 实测修订版）

> **T0 实测（R4c98b，2026-09-11）**：`HOURS_PER_TURN=2` → **1 回合 = 2 游戏小时、12 回合 = 1 天**；`Game_Calendar.TURN_ID` 实为**天计数器**（每 12 回合 +1）。⇒ 原"TURN_ID 差 ≥2"判定式作废，改用**复合时标**。

> **N=6 = "发射冷却 = 6 个回合" = 12 游戏小时**（2026-09-11 用户拍板：N 由 2 调整为 6）：
> 第 T 回合打过 → 最早 **第 T+6 回合**（+12 游戏小时 = 半天）才能再打。
> 不是墙钟、不是心跳 ⇒ **游戏加速/减速不影响**（拍板动机保持成立）。

- 复合时标：`totalHours = TURN_ID*24 + HOUR`（单调递增；1 回合 = +HPT）
- 判定式：`lastMissileHours<=0（首射） || (totalHours - lastMissileHours) >= 6*HPT`
- 常量：`MISSILE_TURN_GAP=6`（一处可调；2026-09-11 用户调整 N:2→6，登 §11）。
- 五档节拍实测（供视觉/回归参考）：1000 / 500 / 250 / 125 / 45 ms 每回合。

### 3.5 命中时序与动画

- **命中条件**：`totalHours >= fireHours + HPT`（=下一回合；在心跳检查；命中当拍结算）。
- 方块动画（5b）：`进度 = clamp((now-lastMissileMs) / playSpeedTIME, 0..1)`；`playSpeedTIME<=0` 时退化为 1200ms。
  - 快速档 → 飞行快；慢速档 → 飞行慢，与游戏节奏一致。
- **监控条款**：若出现 `nMS fire` 后超过 1 回合无 `nMS hit` → 先查 `nT/nD` 是否连续（线程/日历在推进）；确认异常再加墙钟兜底（本版保持纯粹回合制）。

### 3.6 伤害

- `dmg = K × ΣairAttack(命中时我方存活)`；`K=2.0`（≈4 秒机炮交换量，对标"导弹一轮=几次机炮"）。
- 复用 `applyAirDamage(target, dmg)`（伤害链/战损/扣池/击杀探针全复用；零新伤害代码）。
- 边界：命中时我方 Σ≤0 → 记 miss（导弹随载机战损失效）。

### 3.7 目标选择与对称性

- 与机炮扫描同规则、射程判定=**距离制**（Real 坐标 ≤ R；见 §3.3）。
- 敌我对称：敌方 INTERCEPT 任务同样发射（AI 拦截机对玩家/其他 AI）。
- 防重复：单发在空（`strikeKind==1`）期间不再发射。

### 3.8 机炮回合化（按建议执行）

- 将 1000ms 墙钟门（3453-3459）替换为**回合门（复合时标版，T0 修订）**：
  ```
  totalHours = TURN_ID*24 + HOUR
  if gunLastHours>0 且 (totalHours - gunLastHours) < HPT(=2) → :act_ret   # 本回合已打过
  ```
- 开火时（`:act_go` 3516 处）追加：`gunLastHours = totalHours` ⇒ **每回合最多 1 次炮击交换**。
- `airCombatLastMs` 写点**保留**（`drawAirGunFx` 闪光/`nGX` 去重继续用；语义变为"最近开火墙钟·仅 FX"）。
- 探针：`nAC hit` 追加 ` t=<TURN_ID> h=<HOUR>`（(t,h) 唯一标识回合，直接验收"每回合≤1次"）。
- 效果预期：慢速档每回合炮击次数下降、快速档上升 → **速度无关**（设计意图）。

**沿用（高相关）**：㊿52 探针块放标签之后｜㊿53 探针不覆盖后续寄存器｜㊿55 setColor 三态｜㊿56 坐标同源｜㊿59 内容定位｜㊿63 公式极端值手算｜㊿93 if-ltz/`if-gez` 方向（**本轮复核：airCombatTick 时间门=`if-ltz`=小于0跳=满1s才打；throttlePass 无误**）｜㊿94 wide 对｜㊿95 p0 规则｜㊿97 多调用点带源标｜㊿98 活跃区间｜㊿99 真值表回放｜㊿100 标签不落方法尾｜㊿101 热路径探针抽 helper｜㊿102 三步法。

**本包新增**：
1. `packed-switch` 前插调用**禁止 move-result**（v0 是跳转依据）。
2. 时标读取一律 `sget` 直读 `TURN_ID/HOUR` 并当拍合成 `totalHours`，**禁止跨帧缓存**（缓存会错回合/小时）。
3. `airCombatLastMs` 语义变更（仅 FX 用）——改动时同步核对 `drawAirGunFx`（250ms 窗口）与 `nGX` 去重不受影响。
4. **参考指令四步不可省**：装标签 → `append(标签)` → 装值 → `append(值)`；转录逐行核对（T0 曾漏 3 处标签 append 致输出粘连）。
5. **探查输出先自检**：新探针首出数据后先抽查 1 行格式完整性（五字段齐全），再开始依赖其判读。
6. **对象判空方向专项**：`if-eqz`=为空跳、`if-nez`=非空跳；R4c99 首版两处判空写反（无目标时误入发射段 → `NPE … missionID … missileTick` 闪退），R4c99b 修复。条件复核清单新增"对象类判空"一栏。
7. **跨线程集合迭代竞态（R4c99b 崩因 #2）**：`activeMissions` 由逻辑/AI 线程增删、渲染线程多处遍历（迷雾/RealTimeSim/导弹/机炮/绘制）→ `ConcurrentModificationException`（`PlayerFogOfWar.detectEnemyMissions`）；修复（R4c99c）：`DebugMissionList` 内核换 `CopyOnWriteArrayList`（迭代=快照、写=同步）+ `updateMissions` 唯一 `Iterator.remove` 改 `List.remove(Object)`。**待审计同类共享集合**：`radarProvinces`/`allAirports`/`RealTimeSim.entities` 等（§11）。
8. **shouldReturn 空表判空缺失（R4c99c 崩因 #3）**：`shouldReturn()` 载荷循环条件自始即为"`i>=size` 才进循环体"的历史怪态（历代备份逐一比对，非本轮引入）；大型空战里**整编被打空**的任务进入 EXECUTING 分支后 → 空表 `get(0)` → `IndexOutOfBoundsException`；修复（R4c99d）：该分支重定向至出口（空表→返回 true→走返航/ABORTED 链），非空行为保持不变。**循环本体语义修复登记为专项待办**。
9. **smali 指令操作数形态复核**：`mul/div/rem/sub/add-float` 等两操作数形式必须带 `/2addr`（如 `mul-float/2addr`）；R4c100 首编时 `mul-float vX, vY` 漏 `/2addr` 致汇编失败（错误行号还指向**下一行**）；且**汇编器出错时退出码可能仍为 0**——构建脚本必须以「产物文件存在性 + 体量」为准，不能只看 exit code。
10. **探针对账须覆盖"退化几何"**：`fire↔gx↔hit` 1:1 对账在"**源省=目标省（合拢）**"场景会被绘制条件短路（R4c100 首验 `fire×2/gx×1` 即此，非掉帧）；修复=R4c100b 放松跳绘（合拢仍绘）。后续任何"1:1 对账"设计需显式列出退化场景（合拢/瞬灭/跨天）。
11. **探针双通道复核**：`AirDbgLog.d()`=仅 logcat；`dKey()`=写文件。判读"探针为 0 条"前先确认通道——本轮 `um_p0/um_p0go` 文件里缺失实为 logcat-only，勿误读为"事件未发生"。
12. **取证命令防中断**：`grep -c` 无匹配返回 1，命令链可能被截断——收尾统一 `|| true`；输出采用"写文件+受控读取"双保险。
13. **探针节流条件的真值表复核（自我踩坑）**：R4c101 的 `nPOS` 节流写成"diff≥500 才跳过"（方向写反），实际变成逐帧记录——无功能性危害（诊断数据更全），但再次印证㊿93：任何 `if-*`（含探针代码）落笔前先过真值表。
14. **循环出口 merge 脏化寄存器被 Verifier 拉黑（R4c103→R4c104b）**：`drawAirMissileFx` 循环两出口（找到=AirMission / 耗尽=数组长度 int）在 `:mf_afterloop` 使 v7 merge=Conflict；R4c103 新代码**读取** v7 → `VerifyError[0x49]`（八检不覆盖、装机时 dex2oat 日志可见、仅真机启动暴露——㊿96 再证）。修复模式=**-init 专用持有寄存器**（`const/4 v1,0x0` + 找到路径 `move-object v1, v7`），原寄存器保持"只写不读"。
15. **集合判重条件方向核（R4c106→R4c107）**：AI 派发首版把 contains 结果写成 `if-eqz v9, :skip`——正确语义是"**未见过→去派发**"；条件写完必须按"首次/再现"两种输入各回放一遍（㊿93/㊿102）。
