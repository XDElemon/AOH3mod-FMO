## 你报的三件事，两个是同一个根因

### ① ×12 应为 ×10 + 第二个师"无飞机可用" —— 机场自动巡逻走的是**无师**路径

你在**空军司令部点的巡逻**，它设的是 `Airport.mode = PATROL`（机场级自动巡逻模式），真正派机的是每回合跑的 `tryPatrolForAirport`。而它调的是：

```smali
createPatrol(airport, 目标省, null)   ← divKey = null！
```

v81 加的"按师编制截断"(`divLimit`) **只在 divKey ≠ null 时生效**，所以机场自动巡逻完全没被管到 → `getAvailableAircraft(FIGHTER)` 把 **12 架全带走** → 贴图 ×12，第二个师 0 架可用。

**修复**：新增 `pickIdleDivKey(Airport, AirType)` —— 按 `airhqKey4(civ, prov, ord, seq)` 遍历 seq=1..10，找**存在且当前无任务**的师，拿它的 divKey 去建任务：

- 截断生效 → 大师出击显示 **×10**
- 剩下 2 架属于第二个师，**不会被吃掉** → 下回合 80% 概率轮到它自己出击
- 任务绑定了师 → Quick 面板能显示状态、能用 [巡逻] 召回
- 防重复也从机场级改成**师级**（`hasActivePatrol(airport, divKey)`）
- 探针加了 `:div=` 字段：`pt:go:tgt=<省>:div=<师key>`

### ② 空军司令部的巡逻模式关不掉 —— 找到真因了

`BtnMission.actionElement` 把"设置 mode"埋在了**逐机型可用性检查之后**：

```smali
avail = airport.getAvailableAircraft(该机型)
if (avail.isEmpty()) → 记异常日志 + skip      ← 飞机全在天上就整段跳过
if (missionType == 0) mode = PATROL
else                  mode = OFFENSIVE
```

飞机全派出去了 → 每个机型 `avail` 都是空 → **整个循环什么都没做** → 模式纹丝不动。这就是"关不掉"。

**修复**（两处）：
1. 进方法拿到机场后**立刻**按 missionType 切模式，**不再依赖有没有可用飞机**
2. missionType==1（关闭）时额外调用新增的 `stopAirportPatrols(provinceID)`：遍历 activeMissions，把该机场**在飞的 PATROL 任务**全部 `forceReturn()` 召回（探针 `pt:stop:n=<召回数>`）

> 机库三个任务键的语义（引擎原有）：**第 1 个 = 开启巡逻模式**（PATROL）· **第 2 个 = 关闭**（OFFENSIVE，现在会连带召回）· 第 3 个 = 交给 AI（mode=AI + clearPatrolForAirport）

### ③ Quick 面板 [巡逻] —— 你说没问题 ✅，本版未动

它管的是**单个师的单次任务**（点=起飞 / 再点=召回）。机库那个管的是**机场级自动模式**。两者现在分工清楚了：

| 入口 | 作用域 | 语义 |
|---|---|---|
| 空军司令部·任务键 1/2 | 机场 | 自动巡逻模式 开/关（关时召回在飞任务） |
| 师面板 [巡逻] | 单个师 | 立即起飞 / 再点召回 |
