## N1 人口伤害：以前写错了两层

原 `executeAttack` 尾部：

```smali
killed = (int)(1000 × Σ groundAttack)
provincePopulationSize  = max(0, getPopulationSize()  - killed)   ← 写缓存
provincePopulationTotal = max(0, getPopulationTotal() - killed)   ← 写缓存
```

两个问题：

1. **`getPopulationSize()` 不是人口数，是"人口条目数"（省内有几个民族/civ 的人口条）** —— 实证：`Province.atomicBombDropped` 里用它做倒序循环上界 `for(i=getPopulationSize()-1; i>=0; i--)`。所以 `条目数 - 60000` 直接被钳成 **0**，等于**把该省的人口条目计数清零**。
2. 两个字段都只是**聚合缓存**，真正的人口源是 per-civ 的 `populationOfCivID`。回合结算（`setPopulationOfCivID` / `updateIncreasePopulationOfCivID` / `updatePopulationOfProvince`）会从源重算 → **伤害被抹掉**。

**修法**（照抄引擎自己的正确写法 `atomicBombDropped`）：新增 `AirMission.applyPopDamage(Province, killed)`

```
ratio = (total - killed) / total
for (i = getPopulationSize()-1; i >= 0; i--)        ← 倒序，防 setPopulationOfCivID 删条目时错位
    civ = getPopulationCivID(i)
    amt = getPopulationID(i)
    setPopulationOfCivID(civ, (int)(amt × ratio))
```

⇒ 人口按比例逐 civ 真扣，**缓存由引擎自己维护**，回合刷新不再回弹。经济那条链（`setEconomy → ProvinceData6`）本来就是持久层，保持不动。

## N2 打击战报：复用引擎原版战报，零 UI 开发

实证发现引擎自带完整战报设施，之前**只有陆战 `Battle.updateBattle_SummaryCasualties` 在用**：

```java
BattleReport(String key, int provinceID, float warScore, boolean leftSideWon,
             boolean playerWon, int turnID, CivReport left, CivReport right)
CivReport(int civID, int soldiers, int casualties, int retreated)
Player.addBattleReport(br)
```

新增 `AirMission.emitStrikeReport(Province, killed)`，在 `executeAttack` 结算后调用：

| 字段 | 填法 |
|---|---|
| key | `CFG.extraRandomTag()`（与陆战同款随机 tag） |
| iProvinceID | 目标省 |
| iTurnID | `Game_Calendar.TURN_ID` |
| leftSideWon | true（空袭方） |
| playerWon | 我方发起 = true |
| **civReportLeft** | 我方：iCivID / **iSoldiers = 出击机数** / **iCasualties = 损失机数** |
| **civReportRight** | 目标方：iCivID / **iCasualties = 人口损失** |

**防刷屏**：只有**玩家发起**或**玩家挨打**的空袭才记录；AI 互相轰炸不进战报（也就不占你的战报列表）。

探针：`rep:prov=<省>:kill=<人口损失>`
