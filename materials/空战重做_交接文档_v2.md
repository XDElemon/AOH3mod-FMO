## 1. 三个执行面（v2 关键变化：设备面已打通）

### 1.1 Ubuntu(proot) —— 本会话的 bash
- **真实 uid = 10485**（`id` 显示的 root 是 proot `-0` 伪造；内核 `/proc/self/status` 才是真的）。
- 能做：smali 编辑、汇编、八件套、打包签名、写文档、读写 `/sdcard`。
- **不能做**：`pm`/`am`/`logcat`、读游戏私有目录、写 `/data/local/tmp`、`chroot`。
- `su` 是假的（提权后内核仍是 10485）；`sudo`/`loader` 是指向 `/data/app/...` 的**断链**。

### 1.2 Android 设备面 —— 通过「文件队列桥」（uid 2000 / Shizuku）
| 件 | 作用 |
|---|---|
| `r6s5/devbridge_poll.sh` | **常驻轮询器**（设备面启动，uid 2000）；启动自检写 `boot.txt`，每 2s 刷 `heartbeat.txt` |
| `r6s5/devbridge_send.sh '<设备命令>'` | proot 侧投递命令并取回结果（`cmd.sh` → `out.ready`） |
| `r6s5/devbridge_check.sh` | 一键验证（身份 / 心跳 / 通道） |
| `r6s5/devinstall.sh <apk>` | **三段式安装**（`install-create/write/commit`），**绕开 vivo 确认框** |
| `r6s5/devverify.sh <dex_md5> [apk_md5]` | 设备侧核验（pm path **带 20 次重试**） |

**启动（设备面执行，必须 `setsid`）**：
```sh
setsid sh /sdcard/GLG/历史23/r6s5/devbridge_poll.sh </dev/null >/dev/null 2>&1 &
```
> `nohup … &` 会被 Shizuku 会话回收；存活判据看 `heartbeat.txt` 的 mtime（别信 `ps`）。设备重启/Shizuku 重启后需重新拉起。

## 3. 铁律与坑（v2 重写；★＝本阶段新增）

### 3.1 寄存器/指令类
- `.registers ≤ v15`；**不得上调既有方法的寄存器数**（新方法可自己算足）。
- `invoke` kind 与声明一致：`static→invoke-static`、`private→invoke-direct`、实例→`invoke-virtual`。
- **invoke 与 move-result 必须紧贴**；插码插在 invoke **之前**。
- 含宽参（J/D）方法禁用 pN 别名；`const-wide` 别落进引用寄存器。
- ★**`const/4` 只能装 4 位**（-8..7）；探针码/大常数要用 `const/16`（本阶段因此汇编失败一次）。

### 3.2 ★条件跳转（本项目最大坑；本阶段我方**又犯 16 次**）
**语义表（先抄在纸上，再逐条对意图）**：

| 指令 | 含义 | 指令 | 含义 |
|---|---|---|---|
| `if-eqz` | == 0 跳 | `if-nez` | ≠ 0 跳 |
| `if-ltz` | **< 0 跳** | `if-gez` | **≥ 0 跳** |
| `if-gtz` | **> 0 跳** | `if-lez` | **≤ 0 跳** |
| `if-eq` | 相等跳 | `if-ne` | 不等跳 |

**回放三步（本阶段血的教训）**：
1. 先确定**跳转目标是什么含义**（循环头＝"跳过这个"／方法尾＝"放弃"／公共段＝"进入下一阶段"）；
2. 再判条件在该目标下是否表达了意图；
3. **布尔返回值单列**："条件成立才跳过"用 `if-nez`；"不成立才跳过"用 `if-eqz`。
   （本阶段 `pickStrikeTarget` 因 `isAtWar` 那一处 `if-eqz/if-nez` 写反，把 384 个候选全跳过 ⇒ 恒返回 -1。）

### 3.3 ★invoke arity（本地八件套抓不到的类型）
- ART 会因"寄存器数 ≠ 签名参数数"报 **VerifyError**，把**整个类**废掉（本阶段 `tryStrikeForAirport` 崩在 `AA_Game.render`）。
- **改签名必须同时改所有调用点的签名文本**（本阶段只改声明没改调用 ⇒ dex 引用不存在的方法，八件套 `MISSING` 从 15 涨到 17 才发现）。
- 三道防线：`check_arity.py`（本地，BAD 必须 0）→ 八件套 `MISSING=15` → **真机启动**。

### 3.4 跨类可见性（R4c176 血案）
- 跨类读写**私有**字段/方法 = `IllegalAccessError`（闪退）→ 一律走 public getter（如 `Province.getArmySize()`），动手前 `grep '\.field'` 看可见性。
- 提醒：`getEnemyProvincesInRange`（AFM）**名字骗人**——它实际筛的是 `civID<0` 的**无主省**；本阶段已另立 `getHostileProvincesInRange`。

### 3.5 探针类
- 一律 `AirDbgLog.dKey`（`logOnce` 有 500ms 节流会被饿死）；**标签不放方法尾部**。
- 热方法里不拼串 → 抽静态辅助（如 `dbgStrike/dbgRt/dbgHC2/dbgNV3`）。
- ★探针自己也会出错：本阶段两次栽在探针上（`if-nez` 判空写反 → `in=0` 假象；`dbgNV3` arity 不符 → 闪退）。

### 3.6 ★设备面桥类
- `setsid` 启动（`nohup &` 会被回收）；心跳判活（`cat` 偶发读空 → 重试＋回退 `stat -c %Y`）。
- **binder 调用会间歇失败**（`Failed transaction (2147483646)`）：`pm`/`am`/`cmd` **单发会抽风，必须重试**；`pm path <包> | head -1` 极易诱发，改用 `cmd package path` 或先取变量。
- 安装：`autotap_install.sh`（点框）失败时自动降级**三段式**；`install-write` 必须带 splitName（`… <sid> base.apk <path>`）。
- **不能直接从 `/sdcard` 安装**（`resolveInstallVolume` 拒绝 FUSE 卷）⇒ 738MB 推送省不掉。

### 3.7 ★打包/磁盘类
- **整包重建＋装机实测 2m03s**；`build_fast.sh`（只换 dex）**反而 289s** ⇒ **已弃用，用 `build.sh`**。
- 装机后**必 force-stop**（binder 抽风时重试；装机本身也会杀旧进程）。
- 装完清 `/data/local/tmp`；每轮产物会堆 700MB 级 apk，**定期清理**（本阶段清出 29G）。
- `unzip -t` 对签名 apk **误报 CORRUPT**，判完整性用 `unzip -Z1` 计数。
