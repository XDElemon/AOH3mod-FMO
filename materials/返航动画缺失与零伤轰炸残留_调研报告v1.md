## 一、问题一：拦截机"完成拦截后没有返航动画"

### 1.1 结论先行
拦截机击杀目标后走 **强制返航（forceReturn）** 路径；该路径有两处叠加缺陷，导致**返航视觉在战区附近滞停、随后一跳近家/归位**，观感 = "没有返航动画"：
1. `forceReturn` 用一个 `(1-fp)` 公式把返航进度**直接跳到 73%/60%**（视觉逻辑点前跳）；
2. 返航切换点**没有重置编队段动画 `airDivSegAnimMs/DurMs`**，旧追逐段的计时未走完 → `moveDivisionAlongFlight` 的步进门（`anim < dur` 即跳过）**阻塞跨省**，贴图滞留在战区附近，直到 `(dur-an)/16` 帧后才放行。

### 1.2 链路回顾（代码级）
- 状态机：`PLANNING(0)→EN_ROUTE(1)→EXECUTING(2)→RETURNING(3)→COMPLETED/ABORTED`。
- 返航有三条切换路径：① EXECUTING 油耗块（AirMission.smali:3221-3294）；② EXECUTING shouldReturn 块（3318-3409）；③ **`forceReturn()`（1967-2114）——目标丢失时由 `trackTarget` 调用（`nTRK lost/gone`），正是"完成拦截后"的路径**。
- 返航腿统一为 `setupReturnLeg()`（4177）：航段＝机场省 → 当前师省；`moveDivisionAlongFlight`（2116）内 `pct=100-fp` 反向插值实现"从当前点飞回机场"。

### 1.3 现场实证（r6s5 会话档案）
**案例 A（r4c104b，本机拦截机 id=50670374599783，击杀后强制返航）：**
```
1479875: fr_set:el=20440        ← (1-0.27)*28000：把返航进度预置到 73%
1479876: fr_enter:fp=27 st=3
1479877: forceReturn:ok
1479878: nTRK lost
1479884: nFP jump last=0.27 cur=0.73 sp=1000 el=20448   ← 进度跳变实锤
1479885: nPOS st=3 at=2336 pv=2338 pp=2343 src=2343 tgt=2336 cx=2343 fp=73 an=7808 du=11917
    ……（此后 fp 73→75 缓慢爬升，at 始终停留 2336、从未步进，直至文件尾 ~1484000 仍无步进/nRH）
```
**案例 B（r4c102，本机拦截机 id=47761356319226）：**
```
836521: fr_set:el=16800 / 836522: fr_enter:fp=40 st=3 / nTRK lost
836689+: nPOS st=3 at=2316 …… cx=2335 fp=40→60 an=5712 du=24765
    ……（at 2316 全程不动，an 涨至 16368 仍无步进，fp 76 至会话结束）
```
**对照（正常返航，同会话正常路径完全健康）：**
- r4c104b 轰炸机（id=50547106833684）：`nRT sw` 后逐省步进 `um_mvsw:to=2341→2349→…→2095`（fp 0.07→1.0）→ `nRH at=2095 fp=100` 完整归位；
- r4c106 轰炸机：`um_mvsw st=3` 步进 `2336→2316→…→2095`（fp 0.19→0.95）正常。

### 1.4 根因细节
1. **`forceReturn` 的连续性公式反噬**（1967-2114）：`el=(1-fp)*playSpeed*28`。fp 小（刚起飞/短追击）时，`(1-fp)` 很大 → 返航逻辑点直接前跳近家（实测 0.27→0.73、0.40→0.60），随后可见飞行只剩很短一截。
2. **段动画未重置**（2287-2293 步进门）：跨省步进要求 `segAnim >= segDur`；强制返航时残留追逐段的 `an=7808 < du=11917`（r4c104b）/`5712 < 24765`（r4c102）→ 步进被"按住"，贴图只能在旧段（2338→2336）内滑动 → **看上去就是"停在战区不动、没有返航飞行"**；要等 250~1200 帧才放行。
3. 次要：逻辑完成（`rounds>=distance`）时若步进落后，`nRH` 会把师直接归位（瞬移保洁，见 r4c100b fp=81/58 两例——多为清理路径，登记即可）。

### 1.5 修复建议（R4c108-A）
- **A1**：`forceReturn` 去掉 `(1-fp)` 预置，直接 `el=0`（返航从当前师省完整动画 28 单位飞回家）；
- **A2**：三处返航切换点统一重置编队段动画（`airDivSegAnimMs=0`、`airDivSegDurMs=0`；建议并入/复刻 `setupReturnLeg()` 或抽共享 helper），保证第一步跨省不被旧段计时阻塞；
- 复测观察点：`nFP jump 0.27→0.73` 消失；`nPOS st=3 fp 0→100` + `um_mvsw st=3` 逐省回家 + `nRH at==home`。

## 二、问题二：零伤"幽灵轰炸"（拦截机在击杀点放核爆+战报）

### 2.1 结论先行
**EXECUTING 处理器无条件调用 `executeAttack()`**（AirMission.smali:3185）。拦截机（无对地机型）到达目标省的同一帧：
- 求和伤害 `v4=0`，但打击管线照常执行 → `applyPopDamage(省,0)` + `emitStrikeReport(省,0)` → **`RendererGame.addNuke(省)`（核爆特效）＋ BattleReport ＋ 气泡「轰炸成功：目标省人口损失 0」**；
- 位置＝目标省＝"敌机被击落的那一省" → 用户看到"被击落地点发生了一次轰炸"。

### 2.2 现场实证（r6s5 档案）
**r4c100（airdbg_R4c100_s7.txt:651822-651829）：**
```
651823: um_enter:118668018    ← 本机拦截机（attacker）
651824: nAC kill k=1
651825: nAC hit my=15.0 e=2.0 ep=1.0 mp=2.0 t=20 h=4
651826: nAC kill k=2
651827: nMS hit t=20 h=4 dmg=60.0 ep=0.0    ← 敌池清零（击杀完成）
651828: rep:prov=2338:kill=0                 ← ★零伤"轰炸成功"（核爆+战报）
651829: nRT sw at=2338 src=2343 tgt=2338 fp=2 ap=2343   ← 同一处理器继续：切返航
```
**r4c100b（dbg_r4c100b.txt:413456-413462）：** 完全同构（`um_enter:8937927` → 击杀 `ep=0` → `rep:prov=2338:kill=0` → `nRT sw`）。
> `kill=0` 即 `damage=0` 的打击报告签名；全历史会话扫描：r4c100/ r4c100b 各 1 例，其余会话 0 例。

### 2.3 修复建议（R4c108-B）
- **B1**：`executeAttack()`（1357-1458）在求和 `v4` 后、打击块前加守卫：`v4<=0 → 直接返回`（复用现成 return 标签；插入点在 `:cond_30` 与 `getProvince` 之间，~1416）；
- **B2（双保险，可选）**：`emitStrikeReport` 内 `p2<=0 → return`；
- 影响面核对：正常轰炸（实测 `kill=60000/180000`）不受影响；拦截机不再产生核爆/战报/气泡；零闪退风险低（单文件）。
