### D7 纬度压扁（所有雷达通用要点，ICBM 同款特性）
**背景调研（2026-09-02）**：
- ICBM 特征（用户实证）：雷达圈随纬度升高变扁——越靠北/南，圈越扁（东西宽、南北窄）。数学依据：地球经线收敛（cos(lat)）——同一"地面公里"半径在高纬对应的经度跨度更大；凡以真实公里为 Range 的雷达，在（等距圆柱/等积类）地图投影上必然呈现该形状。
- AoH3 现状：官方距离链 `Game.getDistanceFromAToB_Km = getDistanceFromProvinceToProvince(平面欧氏, Game$8/$9/$10 均无三角函数) × DistanceKm(1.95)`——**官方无纬度修正**（距离=坐标平面×1.95km）。→ 纬度压扁为**新增特性**，且必须"绘制与判定同源"：画出来的是椭圆，判定就必须按椭圆算，否则"看得见的圈≠能探测的范围"。
- 坐标系（实证）：X_Real/Y_Real = 等距圆柱投影坐标（经纬度线性×系数；DistanceKm 1.95km/单位）。

**实现规范（D7 公式）**：
- 设雷达中心省纬度 lat（度→弧度，取雷达所在省中点纬度；判定时取双方平均纬度），R = 雷达 Range（单位：km）：
  - **绘制**（投影坐标系椭圆）：东西半径 `Rx = R / (1.95 × cos(lat))`，南北半径 `Ry = R / 1.95`——纬度越高 cos 越小 → Rx 越大 → **圈越扁宽**（南北相对压扁）✓
  - **判定**（与绘制同源）：目标点 (dx, dy)（相对雷达中心的投影坐标差）在圈内 ⇔ `(dx/Rx)² + (dy/Ry)² ≤ 1`；等价的公里制：`dist_km = sqrt((dx×1.95×cos(lat))² + (dy×1.95)²)  ≤ R`
- **实施范围（所有雷达统一）**：机场雷达圈（D1）、雷达/中层反导雷达/防空建筑圈（D2）、机型雷达圈（AirUnit.radarRange——R 改为 km 语义后同样适用）——**所有雷达共用同一个"雷达几何"工具方法**（新增：`radarEllipse(provinceID, rangeKm) → Rx,Ry` + `inRadar(centerProv, provID, rangeKm) → bool`），杜绝三处三套算法。
- **km 语义统一**：RadarConfig.json 的 Range 一律按 **km** 存储（ICBM 300/400 蓝本）；判定与绘制共同换算（0.75 系数修正：cos(lat) 下限 0.15，极区不外爆）。
- **验收**：莫斯科/北京（高纬）机场雷达圈明显扁宽；赤道地区近似正圆；圈内省 = 判定范围（实测抽查 3-5 个方位角一致）。

## 八、R2 实战终局复盘（R2a→R2m 全链复盘, 2026-09-03）
> ⚠️ 本节为 R2（机场雷达圈）从"看不到圈"到"修好"的完整复盘，**后人必读**：两件事——①为什么多轮探针拿不到日志；②为什么圈跟着视角变。
### 8.1 真凶链（四层叠加，逐一击破）
| 层 | 问题 | 击破手段 |
|---|---|---|
| 1 | drawAirForceRadar 挂在 drawAirForce 内，而 drawAirForce 仅在 drawArmyInProvince=true 时被调（$3.drawWithoutScale:351），用户地图模式下=false → **整链从未执行** | 雷达圈改挂 $3.drawWithoutScale_Provinces（无条件渲染层） |
| 2 | 新挂载层未验证 → 加 RDBG:radar 入口探针（文件版 dKey）证实方法执行 | 文件探针 |
| 3 | getAirportRadarPx 中机场值被机型值无条件覆盖（move v0,v3）→ 机库机型 radarRange=0 → 返回0 → 圈被 if-lez 跳过 | if-gtz v0,:cond_62 机场优先（R2l） |
| 4 | 圈半径未乘缩放 → 圈"钉不住地图"（屏上恒定、图上随缩放变化） | 绘制段 v7=v7×v3（R2m） |
### 8.2 为什么之前拿不到任何日志？（重点纠因）
**结论：不是 logcat 坏了，也不是探针没编译进去——是三层叠加导致"日志系统被冤枉"：**
1. **最根因**：A/B/C 层代码路径**根本没执行**（开关/挂载层/半径bug）——方法没跑，探针当然没日志；
2. **Log.d (logcat) 的不可靠性**：探针全用 Log.d 时，
   - logcat main buffer 滚动快，抓取时机错位（用户"好了"≠渲染帧/主地图已就绪）；
   - 游戏初始化阶段每帧抛资源异常（Roboto-Bold.ttf/invasion.png 缺失, 原版就有的引用），渲染帧数极少，探针输出稀疏；
   - 进程后台/PAUSED 时 GLThread 停 → 无任何帧日志。
   - **实证**：um_hb/hb2（每帧探针）在 logcat 全程仅 2 条（06:57 初始化期），其余时间抓不到——logcat 抓取成了"薛定谔的日志"。
3. **决定性解法**：AirDbgLog.dKey（Log.d + **写文件** /sdcard/Android/data/包/files/airdbg_key.txt）——**文件是持久证据**，装机后清空文件→用户进图→直接读文件，**不受 buffer/时机/后台影响**。拿到 45 万行后 10 秒定位。

### 8.3 为什么圈跟着视角大小变？（D7 实现缺陷）

### 12.2 smali 逆向核心方法论（实战 40+ 轮验证）
1. **寄存器类型流是 VerifyError 头号杀手**：
   - .registers N 方法：p0 物理位置 = v(N-1)（如 .registers 15 → p0=v14）；**插入代码前必先看方法头确认参数寄存器**；
   - 探针/临时变量只能选“方法体后部仍为同类型”的寄存器（ref→ref 可换、int→int 可换、**ref→int 必炸**）——实例：syncRadar 用 v5（Integer ref）OK；用 v4（Set ref 后被 const/4 变 int）→VerifyError [0x35]；syncAllFromProvinces 用 v7/v8（ref）OK；用 v1（provinceID int）→VerifyError [0xAB]；ProvinceDrawArmy 用 v12 OK；用 v14（=p0 参数）→VerifyError；
   - **每帧循环探针每帧写文件会爆量**（60MB+）——只加“事件型”探针（匹配命中时），或接受临时爆量后清理。

### 12.2 smali 逆向核心方法论（实战 40+ 轮验证）

### 11.9 R4c'（位图法/ICBM复刻）调研结论（2026-09-05）
**背景**：GPU SDF 线（R4c1-R4c34）因老版 LibGDX API 缺失（setUniform2f 等 NoSuchMethodError）+ FBO 驱动卡死 + 特殊绘制上下文污染，投入产出失衡——**暂停，改用 ICBM 位图法**（CPU 位图 OR 并集，完全避开 shader/FBO）。
**ICBM 算法确认**（exe strings 实证）：CoverageBitScale 网格 + InRangeBitscale 位图 + 位图 OR 标记（CheckCoverage）+ Coverage_XXX/Grey 纹理显示（RadarColor RGBA 着色）+ GlobalShowType 分组显隐。**核心=标记位并集**（非 alpha 累加）。
**本 APK 落地（API 已全部实证）**：
1. LibGDX 框架类齐全：Pixmap（new(II,Format)/setColor(FFFF)/fillCircle(III)/fillRectangle/setBlending）、Texture(Pixmap)、TextureRegion、SpriteBatch.draw 标准 API——**无需任何 shader/FBO**。
2. **算法**：位图 Pixmap（分辨率如 4096×2048，等距圆柱 2:1）→ 每雷达省：**不透明色填充椭圆**（fillCircle 或逐行 fillRectangle 实现椭圆：rx=R/(1.95×cos)×s、ry=R/1.95×s——D7 几何）→ **叠加处仍不透明=并集单层** → new Texture(pixmap) → 绘制时 batch.setColor(1,1,1,0.216) 整体透明 → draw(texRegion, 地图位置) → setColor(白) 恢复。
3. **更新驱动**：低频 dirty 重建（建造/拆除/回合 sync 时标记 dirty；非每帧）——重建后纹理 re-upload；绘制每帧 1 次纹理 draw。
4. **坐标映射**：省份 iCenterX_Real/Y_Real（short 真实坐标）↔ 位图像素线性映射（地图真实坐标范围聚合自省份边界）。
5. **替换点**：drawAirForceRadarIcons 圈段：逐乡圈绘制 → 纹理一次；图标段保留。
6. **优势**：零 GL 风险、零 shader 兼容问题、性能更优（1 次绘制 vs N 次圈）、ICBM 同源。
**实施点**：①新类 RadarBitmap（Pixmap/Texture/dirty/rebuild/draw）②dirty 挂钩（addNewBuilding/destroyBuilding/syncAllFromProvinces/回合）③drawAirForceRadarIcons 圈段替换 ④回路+装机验收（重叠不变亮/性能/回合稳定性）。

## 13.4 新增教训（㊿43-㊿50，12.5 表追加）
- **㊿43 dex 二进制验证陷阱**：方法引用在 dex 中非“LClass;->method”整串（method_id 分字段存储），grep “Class->method”=0 ≠ 无调用；验证调用存在性用 baksmali 反汇编（本次两次误判由此）
- **㊿44 “看似写反”的 if 语义**：if-gt v4,v6,:label + sput 在 fallthrough=“v4≤minX 才更新”为**正确取最小**（跳转目标是“跳过赋值”）；判断方向必须把**标签位置（赋值前/后）**纳入语义，不能只看指令 mnemonic（B1 误判翻车）
- **㊿45 try-catch 是抓“被吞异常”利器**：渲染链外层 catch（Renderer catch_58 exceptionStack）会静默吞异常；在被怀疑方法内加 try-catch 打印 e.toString() 一次锁定（B3 的 NPE 就是这么抓到的）
- **㊿46 AoH3 绘制契约：SpriteBatch.draw 的 y 必须取负**：Image.draw(SB,x,y,w,h) 内部=draw(tex, x, -(y+h), w, h)；所有新增裸 SpriteBatch.draw 必须对齐此契约，否则画在镜像位置（B4）
- **㊿47 大方法内插线→抽独立静态方法**：既有大方法（如 refresh）寄存器类型流复杂，内联新逻辑易撞“未定义寄存器”；抽独立 static 方法（参数 p0 起、.locals 自足）最稳（B6 后方案）
- **㊿48 补丁脚本幂等性+签名核对**：多轮脚本叠加导致“重复插入/错误签名残留”（Vector2 残影、双方法定义）；**每轮改后立即 baksmali 反汇编 grep 签名**；新方法类型路径禁止凭记忆（B7/B8）
- **㊿49 调用点必须在“定义之后”**：invoke-static{vX} 前 vX 必须已在同一路径定义（move-result-object 在前）；插入点选“move-result 之后”而非“invoke 之前”（B9）
- **㊿50 静态防线≠ART 验证**：CheckInvoke/Regs/Cast/Undef(简化版) 全 0 仍可能被 ART 拒绝（类型描述符错误、寄存器顺序）——**装机前对改动方法 baksmali 反汇编逐行核对**（R4c55-57 三连闪退均为静态线未覆盖）

## 15.7 新增教训（㊿52-㊿59，接 14.5 的 ㊿51）
- **㊿52 探针块位置=标签之后**：探针块被插在标签之前时，所有 goto/if 都跳过它 → 探针“静默失效”。出口探针必须放 `:ret` 等标签**之后**（全路径可达），入口探针放方法首个无跳转引用处。
- **㊿53 探针寄存器覆盖**：探针临时变量不得覆盖**后续仍被使用**的寄存器（rps 探针毁 v0=Set 引用 → iterator 对 String 调用 = 类型流崩溃）。用“末位死寄存器”前必须确认其后无引用；循环内探针（每省打印）默认不做，改汇总型。
- **㊿54 alpha=浓度，RGB=亮度**：用户说“调亮”只改 RGB（alpha 不动）；“加深/减淡”才碰 alpha。0.13 vs 0.20 是浓度差不是亮度差。
- **㊿55 纹理本色 vs setColor（乘色）**：SpriteBatch.draw(纹理) 时 setColor 是**乘色系数**，颜色本体=纹理像素。改色前先确认该圈是“纹理本色”还是“乘色”还是“Pixmap 填充色”——三处要同步改，只改一处=无效（机场圈就是被此坑 2 轮）。
- **㊿56 坐标体系三态**：真实坐标（centerX_Real）、屏幕坐标（x iMapScale）、绘制半径（km→坐标 ÷iMapScale）。**判定与绘制必须同一几何源**：迷雾判定漏 ÷iMapScale → 探测圈 ≈ 绘制圈 x4（本专案最大根因）。
- **㊿57 时序依赖-挂数据就绪点**：数据源（radarProvinces 注册）与消费点（fogRefresh）生命周期顺序 —— 挂点选“数据就绪点”（RadarBitmap.refresh 末尾）而非“启动点”（开局 initFogOfWar），否则 rps=0 静默漏判。
- **㊿58 setFogDrawArmy ≠ 画面刷新**：改迷雾数据后必须调 `Game.updateDrawArmy()` 触发军队绘制缓存重建，否则省可见但师不显示（R4c81 实证）。
- **㊿59 探针插入禁用硬编码行号**：多次叠加插入后行号漂移 → 探针漏插/错插。一律用**内容定位**（标签字符串/唯一指令指纹）并打印插入计数核对。

- **㊿60 新方法调用前必须参数寄存器全定义审计**：替换成新方法调用后，逐参数检查“该寄存器在本路径是否已赋值”（v12 从未赋值→[0xA7]）。dKey 防线上 CheckUndef 对多寄存器 invoke 的覆盖有限，人工清单更可靠。
