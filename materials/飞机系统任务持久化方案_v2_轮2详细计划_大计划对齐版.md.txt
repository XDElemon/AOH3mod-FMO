## 五、smali 合规守则（并入大计划第7节，本轮新增 2 条）

1~13. 沿用大计划 v2.1 第7节全部铁律（寄存器上限/私有方法 invoke-direct/const 范围/升序/类型匹配/单寄存器比较/静态方法 p0/构建≠生效/无重复 return/锚点空行精确/禁 proot find 大目录）
14. **move-result* 不得残留**：插入含分支代码时，先删除原 move-result* 再重排；装机前用脚本扫描"每个 move-result 前一条有效指令必须是 invoke"（违规=VerifyError 闪退，2026-08-27 实锤）
15. **标签命名唯一前缀**：新增标签一律带场景前缀（如 bsel_/af_preseed_），避免与现有标签冲突
16. **invoke 寄存器数量必须与签名精确匹配**（2026-08-27/28 实锤，VerifyError `[0x22D]`）：实例方法寄存器列表 = receiver + 全部参数；静态方法 = 全部参数；J/D 宽参数各占 **2 个寄存器**（如 `Long.valueOf(J)` 写 `{v0, v1}`，不能写 `{v0}`；`JsonValue.get(Ljava/lang/String;)` 写 `{v11, v12}`，不能写 `{v11}`）。症状：`Rejecting invocation, expected N argument registers, method signature has M or more`
17. **const-wide 占用寄存器对 vN:vN+1**（2026-08-27 实锤，VerifyError `[0x220]`）：`const-wide v14, 0x36ee80L` 会把 v15 污染为 long 类型；若 v15 后续用作引用类型（Map/List）→ `tried to get class from non-reference register v15`。宽值尽量放循环外并避开业务寄存器
18. **装机前必须对最终 dex 做指令级验证**（pkg_new30/31 连续两次"构建成功但 VerifyError"教训）：用 /tmp/verify_dex/CheckInvoke.java（dexlib2）扫描 classes.dex，`TOTAL BAD: 0` 才允许装机。构建成功 ≠ 验证通过
19. **Gdx Json 反序列化类型陷阱**（2026-08-27 实锤，ClassCastException）：`aliveIDs:[{value:xxx}]` 数组元素反序列化后是 **JsonValue 对象**而非 Long。读取时必须 `instance-of Long` 分支：是则直接用；否则 `check-cast JsonValue` → `get("value").asLong()` → `Long.valueOf`（注意 get 也要遵守规则16）
20. **装机前提：设备必须解锁**（vivo 锁屏时 pm install 返回 `INSTALL_FAILED_ABORTED: User rejected permissions`，确认弹窗无法显示自动拒绝）
