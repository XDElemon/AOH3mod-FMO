### 2.2 `SaveGameManager$Save_AirUnit`
unitID(long，**重连钥匙**) / type(AirType 枚举) / typeID / hp / fuel / isAlive / isShotDown / isInFlight / currentMission(AirUnit$Mission 枚举) / currentPayload / roundsInFlight / civID / airportID

### 2.4 `SaveGameManager$Save_Airforce`（顶层容器）
airports：List<Save_Airport>

## 四、加载流程（loadSave_Airforce）

1. **清任务** activeMissions.clear()（防残留）
2. **机场恢复**：确保 AirForceManager.allAirports 已由 syncAllFromProvinces 建壳 → 按 Save_Airport 覆写 total/lost/level/capacity/mode/build 进度（`new Airport(Save_Airport)` 或字段直赋，轮1定）
3. **机队重建**：Save_AirUnit → `new AirUnit(Save_AirUnit)`（静态属性 AircraftDataManager 取）→ 入 airport.aircraft[type]；维护 **unitID→AirUnit 索引池**
4. **任务重建**：Save_AirMission → `new AirMission(Save_AirMission)` → assignedAircraft/aliveAircraft/lostAircraft 经 unitID 重连（断链剔除计入 lost）→ targetAirUnitIDs 重连 → activeMissions.add；对应 AirUnit.isInFlight=true、currentMission 置枚举
5. **师绑定与位置**：airhqKey 找 airhqDivision（省军队已恢复，陆军读档在前）→ **飞行中点重放**：sourceProvinceID 沿直线 60km 步距重放至 flightProgress → 定 airDivisionAtProvinceID；prev=-1、segAnimMs=0、segDurMs=0（贴图停靠当前省，下一段恢复滑行）；无任务师回机场省
6. **EXECUTING 降级**：targetAirUnitIDs 存在但敌方对象丢失 → 任务转 RETURNING（不崩）

## 五、时钟重锚定（读档瞬间）

animStartMs/animPrevMs/lastTickMs = 当前系统时间；animElapsedMs 原样恢复；flightProgress 原样恢复。

## 六、渲染精度定义（同 v2.0，已与负责人对齐）

数据层 100% 精确；贴图读档**停靠当前省中心**（不恢复滑行中间态），下一段切换恢复逐段滑行。

## 九、风险与对策（同 v2.0 + 新增）

| 风险 | 对策 |
|---|---|
| unitID 断链 | 索引校验，断链剔除计入 lost；空机任务 RETURNING |
| 任务/飞机状态不一致 | 以 MF 为准覆写飞机状态，加载后一致性校正 |
| 时钟跳变 | 统一重锚定 |
| EXECUTING 目标丢失 | 降级 RETURNING |
| 旧档无段 | 跳过→B1 兜底 |
| **Gdx Json 枚举兼容**（枚举改名/新增） | 枚举名序列化；改枚举名时用 @Json 字段或先做版本字段（v1 阶段枚举固定，风险低） |
| **Airport 对象壳在加载时点未就绪** | 轮1 确认 AirForceManager.syncAllFromProvinces 调用顺序；若在 loadSave_Airforce 之后 → 调整挂点（在 sync 之后调） |
| 性能 | JSON 文本级读写 <2000 对象，耗时 <100ms |
