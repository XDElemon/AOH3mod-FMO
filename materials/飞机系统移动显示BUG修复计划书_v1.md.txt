## 0. 目标

让「飞机 = 师级单位」的移动表现符合预期：
1. 飞行中的编队 = 与省份图标 **同一张机型贴图**（同材质、同大小比例）
2. 飞行中「本体」随编队移动：机场不再画该机队，航线位置显示编队（HP环/朝向跟随）
3. 飞行贴图中必须包含飞机本体（不再只有光晕/圆环）
4. HP环、雷达圈、机头朝向与飞出的机型、方向一致

### 1.3 任务数据结构（AirMission.smali）
- 枚举：MissionType `PATROL=0, INTERCEPT=1, ATTACK_ARMY=2, STRATEGIC_BOMBING=3, AIR_SUPERIORITY=4`；MissionState `PLANNING=0, EN_ROUTE=1, EXECUTING=2, RETURNING=3, COMPLETED=4, ABORTED=5`；AirType `INTERCEPTOR=0, FIGHTER=1, BOMBER=2, ATTACKER=3`
- createPatrol(400-440)：只取 **FIGHTER**（机场 getAvailableAircraft(FIGHTER)）→ aliveAircraft（后续任务绘制经 aliveAircraft[0].hp 取 HP 环；**飞行贴图纹理却按 mission.type 选**）
- update()(828-1185)：PLANNING→EN_ROUTE 时 `isInFlight=true`、animStartMs=now（901/919）；EN_ROUTE 每回合 roundsInFlight++ 至 >=distanceToTarget→EXECUTING；EXECUTING linger（60 回合）/fuel<30%→RETURNING；RETURNING 回合数>=distance→COMPLETED→returnToBase（isInFlight=false、满油满血）
- 动画插值仅视觉：`v10 = clamp(animElapsedMs*100/(speed*7 或 10))`，坐标 = lerp(源,目标,v10)；**与状态机回合判据互相独立**（这是「贴图在飞、本体状态滞后」的根源之一）

## 2. 用户反馈 4 条目 → 根因映射

| 用户现象 | 根因（组合） |
|---|---|
| ① 移动动画贴图 ≠ 省份飞机贴图 | K2（纹理选择错机型）+ K3（尺寸 32 vs 40/56）+ K4（光晕遮住） |
| ② 只有贴图动、本体不动 | 省图标 isInFlight 跳过逻辑仍在（代码正确），但**任务贴图与省图标是两路绘制**；且 EXECUTING 期间编队显示在目标省（正确方向），但动画插值与状态机回合分离→视觉与数据不一致；「本体」= 省图标仅在机场→需验证 isInFlight 跳过是否真正生效（见 §4 打点） |
| ③ 飞行贴图内无飞机（J-36 图本为飞行准备） | K4 光晕覆盖 + K3 32×32 太小 + 可能 airFighter 纹理加载失败（需 um_img:t= 打点确认）；另注意**包内「飞行用图」与「省图标图」是同一张（J-36）**，若用户想区分飞行图/省图需另行准备素材 |
| ③补充 HP环/机型对不上 | K5 + 48×48 固定与省图标分级不一致；机型纹理错（K2）连带环语义错位 |

## 3. 修复方案（分阶段，每阶段可独立装机验证）

### 阶段 A：诊断基线确认（0.5 天，不改代码）
- [ ] 真机抓 logcat `--pid=<游戏>`，过滤 AIRDBG：确认 `um_dl3:id=`（飞行贴图纹理ID）、`um_img:w/h/t=`（纹理尺寸与 texture 是否 null）、`um_spr`（插值坐标）、`um_p0go/um_p2/um_p3` 时序
- [ ] 判定：airFighter 纹理 t=1（加载成功）→ K4/K3 是主因；t=0 → 需查加载（概率低，路径已对）
- [ ] 录屏一次完整「选中→行进→到目标→滞留→返航」，逐帧截图对照

### 阶段 B：统一「飞行编队」视觉（1-2 天）——解决 ①③
改动点（全部在 `drawAirForceMissions`）：
1. **纹理按机型选**：用 `aliveAircraft[0].type`（AirType）→ 映射 airInterceptor/airFighter/airBomber/airAttacker（替代现 mission.type 映射）
2. **尺寸对齐省图标**：FIGHTER/INTERCEPTOR/ATTACKER 40×40（0x28）、BOMBER 56×56（0x38）；绘制中心对齐（x-半宽，同省图标逻辑 556-566 行）
3. **降噪光晕**：radarFill 改为 40×40 半透明（或仅在「雷达接触」语义下画，见阶段 D）绘制顺序放在飞机**之后**，避免遮盖
4. **机头朝向修复（K1）**：rotation 变量改用一个新寄存器（避开 v12 被覆盖），RETURNING 时朝 180°（或按航向角 atan2(dy,dx)）
5. **金框/HP 环条件**：HP 环改为「编队有存活飞机即绘制」（不限于选中），尺寸按机型分级 22/25/33 或统一 36
- 验收：选中战斗机巡逻 → 飞行贴图=省图标同图同尺寸；机头朝目标；回程翻转；光晕不遮机

### 阶段 C：「本体随任务移动」（1-2 天）——解决 ②
1. 确认时机：PLANNING→EN_ROUTE 置 isInFlight 后，`drawAirForce` 省图标跳过该机队（代码已有，需打点 `um_skip:cnt=` 验证每帧跳过数）
2. **机场侧表现**：机队全部起飞 → 省图标不画该机型（已实现）；机队部分起飞（有多架）→ 显示剩余架数标记（v11 计数已存在，无需改）
3. **目标省表现**：EXECUTING 时任务绘制在目标省插值点=编队「到达」；达到「滞留航班驻留目标省」观感（无需新数据，动画 v10=100% 已停驻）
4. 若「本体」另指**机场 num 显示**：Airport.totalAircraft 语义确认（建议：显示总数或出动数，出任务期间 totalAircraft 不变、deployed 增加——check updateDeployedCount 651-662 行已调用）
- 验收：起飞瞬间省图标消失；航线中只有编队（含 HP 环）；到达后驻目标省该省可见；返航完成回机场恢复图标；全程无「机场仍有图标+空中另有一坨」

### 阶段 D：雷达圈/探测语义（0.5-1 天，可选）
- radarFill 在任务处的绘制改为「敌我雷达探测可视化」：圈尺寸=机型 radarRange×scale（数据已有：AirUnit.radarRange）
- 与省份雷达建筑圈（drawAirForceRadar 2044/2206）统一色/透明度
- 验收：圈半径与机型 radarRange 成比例，且不遮飞机

### 阶段 E：回归 + 装机（1 天）
- 覆盖 F1-F13 回归、S1（师模型 7 步链路）、四机型各测一次巡逻往返
- 构建/装机按 6.2 标准流程（apktool b → mkzip → 签名 → pm install -r）
