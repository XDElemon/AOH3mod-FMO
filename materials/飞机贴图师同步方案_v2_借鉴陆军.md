## 一、陆军移动渲染机制解剖（MoveUnits 系统）

### 1. 数据结构

| 字段 | 类型 | 含义 |
|---|---|---|
| `lRoute` | `List<Integer>` | 路径省 ID 链（起点→…→终点） |
| `vPoints` | `Vector2[]` | 预计算路径点数组（每省中心，地图坐标） |
| `fMovingPercentage` | `float` (0..1) | **单一进度源**：0=起点，1=终点 |
| `fCurrentMovingPercentage` | `float` | 动画实时进度（LittleAnimation 每帧推进） |
| `lMovingTime/lCurrentMovingTime` | `long` | 时间戳（进度增量计算用） |
| `fSpeed` | `float` | 移动速度（受陆军移动速度/政体加成影响） |
| `colorLine` | `Color` | 路径线颜色（随时间渐变） |

### 2. 动画推进（MoveUnits$3.update 每帧执行）

```
fCurrentMovingPercentage += (now - lCurrentMovingTime) / playSpeedTIME
```

- **与游戏速度（playSpeedTIME）挂钩**：加速/减速/暂停（GameThread.play）自然生效
- 到 1.0 后切换下一动画阶段（到达 → 军队状态转移）

### 3. 绘制（MoveUnits.draw，两层）

**第 1 层 - 路径线**：
```
shapeDrawer.setColor(colorLine)
shapeDrawer.path(vPoints, lineWidth, JoinType.SMOOTH, false)
```
线宽含移动进度（`fMovingPercentage * 3.0f + 0.4f 等`）

**第 2 层 - 移动中的军队图标**：
```
idx = (int)(fMovingPercentage * vPoints.length)
pos = vPoints[idx]  // 沿线插值取点
绘制坐标 = (pos.x + mapBG.width + mapCoords.posX) * scale   ← 与 getAirDrawPosX/Y 同系
绘制军队旗帜图标（littleAnimationMovingArmy）
```

### 4. 本体（军队）转移

- 军队本体在 `lRoute` 上"虚拟移动"，**到达终点后执行省转移**（`buildMoveUnitsLine`/到达回调）
- 移动期间省归属=沿途（移动中不显示在省上，只显示路径上的移动图标）

## 二、空军现状 vs 陆军机制对比

| 维度 | 陆军（MoveUnits） | 空军（当前实现） | 问题 |
|---|---|---|---|
| 进度源 | 单一 `fMovingPercentage` | 动画时钟 `animElapsedMs`（贴图） + 独立 `roundsInFlight`（师） | **双进度源 → 脱节** |
| 速度挂钩 | playSpeedTIME（加速/暂停生效） | 贴图用了 playSpeedTIME，师移动节流 | 师"慢半拍" |
| 位置计算 | vPoints 插值（标准坐标系） | 贴图 lerp（同系）；师=逆变换省 | 师独立计算 → 不同步 |
| 移动单位可视化 | **图标沿路径移动** | 飞机贴图（已实现沿路径） | ✅ 已有 |
| 本体（省归属） | 到达后转移 | 师逐省 setProvinceID_Point（节流） | 离散、慢半拍 |
| 暂停 | GameThread.play 冻结 | 已加 play 冻结（上一轮修复） | ✅ |

**结论**：空军缺的是"**单进度源 + 师与贴图同源计算**"。陆军模式天然解决——**固定"贴图在哪里，师就在那片"，两者用同一个 pct**。

## 三、v2 方案：单进度源（pct）驱动贴图与师

### 核心公式

```
pct = 动画进度(0..1)         （与现 animElapsedMs 同源，RETURNING 时 pct=1-pct）

贴图坐标 = lerp(源省中心, 目标省中心, pct)    （已实现，保持不变）

师归属省 = setProvinceID_Point(贴图坐标)       （每帧用贴图坐标反查省）
         → 贴图在哪个省，师就在哪个省；贴图省间过渡时师归"当前最近省"
```

**单一 pct → 贴图与师严格同步**，彻底消除"慢半拍"。

### 具体改动

**AirMission.smali（数据层 - 约 25 行）**
1. 新增缓存字段：`airDivCurProv: I`（师当前归属省）
2. `moveDivisionAlongFlight()` 重构（去掉节流/独立计算）：
   - 每帧调用（由 update() 驱动，已有 play 冻结保护）
   - 进度直接用**贴图同一 pct**（与绘制层同源，建议 pct 提升为 AirMission 字段 `fProgress`，绘制层与移动层共读）
   - `setProvinceID_Point(贴图坐标)` → 返回省 ID → 与 `airDivCurProv` 不同才执行 removeArmy/addArmy（**省切换才动手，性能安全**）
3. RETURNING：pct 反向（与贴图绘制一致）

**ProvinceDrawArmy.smali（绘制层 - 约 15 行）**
4. 贴图坐标计算**保持现状**（lerp 插值已与 pct 同源）
5. 删除移动层独立的 roundsInFlight 进度计算（统一用 fProgress）

### 同步效果验证（验收）

- 飞行中把地图放大：贴图与师完全同步（师跳省瞬间=贴图过省中心时刻）
- 军队栏：师在路径省上逐省出现，**节奏与贴图一致**
- 返航：对称同步
- 暂停：全冻结（已实现）

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| setProvinceID_Point 每帧调用性能 | 仅当反查省 ID ≠ 缓存时执行转移（省粒度操作，频率=跨省次数） |
| 反查省与贴图"空中"位置不一致 | 直线路径每帧反查，省粒度天然匹配（误差=贴图精度，视觉可接受） |
| 直线穿越非路径省（如海上） | 与 v1 相同：空军直线符合直觉；省归属取"贴图所在省"即可 |
| playSpeedTIME 加速时同步性 | 贴图/师同用 pct，天然同步 |
