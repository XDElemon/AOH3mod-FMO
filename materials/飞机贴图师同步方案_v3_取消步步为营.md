## 〇、v3 核心变更（相对 v2）

**删除/否决**：陆军移动的"步步为营"限制——**空军不接受**：
- ❌ BFS 邻接寻路（`buildPath`/`buildRoute` + `getNeighboringProvinces` 逐省扩展）
- ❌ `canBeUsedInPath` 限制（荒野不可走 / 海上移动需港口 / 敌我及战争状态判定）
- ❌ 路径省链 `lRoute` 概念（空军不逐省"走"路）

**保留**：v2 的"单一进度源 pct"核心（贴图与师同步的关键），且因此**实现更简单**：
- 空军 = **直线点对点飞行**（贴图 lerp 直线插值）
- 师归属 = **贴图坐标反查省**（每帧一次，跨省才转移），**无任何逐省/邻接/地形约束**

## 一、陆军"步步为营"限制机制（被否决项，仅作对照）

| 限制 | 实现 | 陆军表现 |
|---|---|---|
| 只能相邻省移动 | `Province.getNeighboringProvinces(I)` 遍历 + `MoveUnits.buildPath/buildRoute`（BFS） | 路径=省链，一格一格推进 |
| 荒野不可通过 | `canBeUsedInPath`：`getWasteland() >= 0` 直接禁用 | 绕路 |
| 海上移动需港口 | `canBeUsedInPath`：陆地→海上需 `getLevelOfPort() > 0` | 登船限制 |
| 敌我/战争限制 | `isFriendlyProvince_OrAtWAr` 判定 | 只能走友方/交战区 |

**对空军不适用**：飞机不受地形/邻接/港口束缚，直线飞行符合物理直觉；逐省寻路反而引入"省链""绕路""卡死"等问题。

---

## 二、v3 方案（最终）：单进度源 + 直线飞行 + 坐标反查

### 核心公式

```
pct = 动画进度(0..1)              ← 唯一进度源（贴图/师共用；RETURNING 时 pct=1-pct）

贴图坐标 = lerp(源省中心, 目标省中心, pct)      ← 直线，无省链

师归属省 = setProvinceID_Point(贴图坐标)         ← 每帧反查，跨省才转移
```

**特性**：
- ✅ 直线飞行（无邻接/地形/敌我限制）
- ✅ 单进度源 → 贴图与师严格同步（消除"慢半拍"）
- ✅ 暂停/加速与游戏速度一致（已有 play 冻结 + playSpeedTIME 挂钩）

### 具体改动（约 2 轮构建，与 v2 同量级）

**AirMission.smali（数据层 ~25 行）**
1. 新增 `fProgress: F`（进度字段，绘制层与移动层共读）与 `airDivCurProv: I`（师当前归属省缓存）
2. `moveDivisionAlongFlight()` 重构：
   - 每帧调用；进度直接读 `fProgress`（与贴图同源）
   - 贴图坐标反查省 → 与 `airDivCurProv` 不同才 `removeArmy/addArmy`
   - RETURNING：`pct` 反向处理
3. 日志 `um_mv2:pct=X:prov=Y`（验证与贴图进度一致）

**ProvinceDrawArmy.smali（绘制层 ~10 行）**
4. 贴图坐标计算保持现状（lerp 直线）
5. 删除师移动层旧的独立进度（roundsInFlight）计算

## 三、验收标准

1. 飞行中贴图与师**同节奏**（师跳省瞬间=贴图过省中心时刻）
2. 路径=**直线**（不绕路、不受荒野/海上/敌我限制）
3. 军队栏师逐省出现，节奏与贴图一致，无"慢半拍"
4. 返航对称同步；暂停全冻结
5. （后续）AI 派单/敌机任务同规则
