## 〇、v4.1 核心修正（相对 v4）

**负责人观察属实**：陆军**移动到敌方省份就即时占领，没有攻城/围城天数环节**。
- v4 中"`checkForSiege` → `addProvinceSiege` → `updateSieges` → 占领"的链路**有误**，修正为：
- ✅ **即时占领路径**（主路径）：移动到达 → `checkForSiege` → **直接 `occupyProvince()`**（无天数）
- ℹ️ 围城天数（`updateSieges`）是**另一条每日结算路径**（堡垒防守/城内战斗残局用），与"移动即占领"无关

## 一、陆军"移动即占领"真实链路（v4.1 修正版）

### 路径①：即时占领（用户观察的现象）

```
陆军 MoveUnits 移动完成（到达目标省）
→ Civilization.checkAndContinueMove(move)          [Civilization.smali:2227]
   → SiegeManager.checkForSiege(getToProvinceID())  [SiegeManager.smali:251]
   → 若省【未被占领】且省内有敌军（与省主 atWar）
       且该军 not inBattle / not inRetreat
   → Province.occupyProvince()                      [Province.smali:14594]
   → 【即时占领，无攻城天数】
```

### 路径②：即时收复（与占领独立，同属 checkForSiege 内）

```
checkForSiege 内 [SiegeManager.smali:86-96]：
   省【已被占领(isOccupied)】→ 遍历省军队：
     → 发现占领方的敌军(与 occupier atWar) → retakeOccupiedProvince()      [武力收复]
     → 发现原主军(与 owner civID 相同)     → retakeOccupiedProvince_Peace() [和平收复]
   （同样即时，无天数）
```

### 路径③：多日围城（旁路，非"移动即占领"）

```
GameThread.updateSieges()（每日调用）[GameThread.smali:5700]
→ SiegeManager.updateSieges() [SiegeManager.smali:1922]
   → 围城中：2042 retakeOccupiedProvince / 2052 occupyProvince（按围城进度结算）
→ 注：addProvinceSiege()（114行）当前【无外部调用者】→ 该路径在本版本未被主动启用
```

### 结论

| 场景 | 触发 | 有无攻城 |
|---|---|---|
| 陆军进驻无敌军敌省 | checkForSiege → occupyProvince | **无**（即时） |
| 陆军进驻有军营战/守军省 | Battle 系统（inBattle 先行） | 战斗环节 |
| 省被占后收复（武力/和平） | checkForSiege 内 retake* | 无（即时） |
| 围城天数（城池防守） | updateSieges（GameThread 每日） | 有（旁路，未主动启用） |
