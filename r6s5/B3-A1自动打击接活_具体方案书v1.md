## 2. 机制设计

### 2.1 派发层（每回合）
`AFM.update(I)`（5650）在 5708 之后新增：
```
updateOffensives(I):
    list = getAirportsForCiv(I)                 # public，AFM:4199
    rnd  = new Random(System.currentTimeMillis())   # 与 updatePatrols(6216) 同款
    for airport in list:
        if airport.mode != OFFENSIVE: continue
        tryStrikeForAirport(airport, rnd, ATTACKER)     # 攻机：对军
        tryStrikeForAirport(airport, rnd, BOMBER)       # 轰机：战略
```

### 2.2 `tryStrikeForAirport`（镜像 `tryPatrolForAirport` 七道关）
```
1. Game.player != null && Game.player.iCivID == airport.civID      # 玩家口径
2. airport.mode == OFFENSIVE
3. rnd.nextFloat() < 0.2f                                          # P6 概率门
4. divKey = pickIdleDivKey(airport, type);  null → return          # 复用 AFM:1861
5. hasActivePatrol(airport, divKey) == true → return               # 复用 AFM:1473＝"该师在飞"
6. tgt = pickStrikeTarget(airport, type);   tgt < 0 → return       # 见 §2.2
7. mission = (type==ATTACKER) ? createAttackArmy(airport, -1, tgt, divKey)
                              : createStrategicBombing(airport, tgt, divKey)
8. mission.assignedAircraft.isEmpty() → return
9. activeMissions.add(mission)
10. 探针 nAS type=… tgt=… div=…
```

### 2.3 选靶层 `pickStrikeTarget`（**public**，内部复用私有件）
```
public static int pickStrikeTarget(Airport ap, AirType type):
    cand = getEnemyProvincesInRange(ap, type)      # 私有 AFM:1345；同类内可调
                                                    # 已含：航程内 && 非本国 && civID>=0
    best = -1; bestD = Float.MAX_VALUE
    for pid in cand:
        p = Game.lProvinces.get(pid)                            # 与 AFM:1389 同款
        if !DiplomacyManager.isAtWar(ap.civID, p.getCivID()) → skip      # 战争门（正确写法）
        if type == ATTACKER && p.getArmySize() <= 0 → skip               # P1 驻军门
        if type == ATTACKER && p.getFogDrawArmy() → skip                # ★O2 视野门：仅 ARM（O4＝轰机不加）
        if hasSameTargetInFlight(pid, type) → skip                       # P3 去重
        d = provinceDistance(ap.provinceID, pid)                          # 私有 AFM:1914
        if d < bestD: bestD = d; best = pid                               # P2 最近优先
    return best
```
- `getArmySize()` 是**公开 getter**（AFM:885/1818/2019 已在用）——**不得**用私有 `iArmiesSize`（R4c176 闪退根因）。
- ⚠️**（极性订正 2026-09-22：本条结论写反了 —— 实为 `getFogDrawArmy()==true` ＝【可见】；订正依据见 附-11.1）**
- **★O2 视野门（本轮新增约束）**：判据＝`Province.getFogDrawArmy()Z`（**公开 getter**，Province.smali:11954；字段 `fogDrawArmy:Z`）。**极性已核**：`true` ＝ 该省军队**被迷雾遮住**（`ProvinceDrawArmy` 在 true 时返回空绘制体、不画军队；`Touch.smali` 1565/1691/1839/1987/2135 用它挡住「点不到看不见的部队」）→ **只有 `false`（可见）才可打**。**O4 已定：这道门仅适用于 `type == ATTACKER`（对军）；轰炸机打的是省，不加视野门。**
- `hasSameTargetInFlight` ＝ 遍历 `getInstance().activeMissions`，比 `m.targetProvinceID == pid && m.type == 同型`（字段均 public）。

### 2.4 追踪层（每帧）`AirMission.trackGroundTarget()` —— **P1 修正的落点**
自动拦截的实现（已核）：`update()`(4152) 在 **4303** 调 `trackTarget()`(4064)，而 `trackTarget` **开头就判 `type != INTERCEPT → return`**，然后按 `targetMissionID` 找到被追任务，把对方的 `airDivisionAtProvinceID`（当前所在省）刷成自己的 `targetProvinceID`。
→ 攻机照抄同构的一份：
```
private void trackGroundTarget():
    if type != ATTACK_ARMY → return
    if state in {RETURNING, PLANNING, COMPLETED, ABORTED} → return
    p = Game.getProvince(targetProvinceID);  p == null → return
    # 常见路径：目标仍合法 → 立刻返回（仅几次 getter）
    if p.getCivID() != this.civID && p.getArmySize() > 0
       && DiplomacyManager.isAtWar(this.civID, p.getCivID())
       && p.getFogDrawArmy() == false → return        # ★O2：被迷雾遮住＝目标失效
       # 注：trackGroundTarget 开头即 `type != ATTACK_ARMY → return`，故视野门天然只约束攻机（O4）
    # 目标失效（敌军撤走/被歼/停战/省被己方拿下/被迷雾重新遮住）→ 重选
    nt = AirForceManager.pickStrikeTarget(sourceAirport, ATTACKER)
    if nt >= 0: targetProvinceID = nt;  探针 nAS rt=…
    # 找不到 → **不改向、不召回**：继续朝当前目标前飞（O2 用户口径）
```
- **调用频率＝每帧**（`AA_Game.render()` 2066 → `updateMissions()` → `AirMission.update()`），所以**常见路径必须极便宜**：失效时才走重选（低频）。
- `distanceToTarget` 字段经核**只被我们自己的 dbg 探针读取**、唯一写入是构造函数的 `0` → 重瞄**不需要**重算它（探针里会一直打印 d=0，属既有现象）。
- 粒度说明：因 `targetArmyID` 恒 `-1`，重瞄是**省粒度**（跟「有驻军的敌省」），不是跟某一支部队；要跟部队需先实锤精确锁师（A4 未实锤项）→ 另立批次。
- **★O2「一直飞到雷达探测到为止」为什么成立（已核，无需新写探测）**：飞机自身雷达揭雾链 `AirMission → PlayerFogOfWar.fogPlaneCross`(27) → `planeFogClearAt`(228) → `planeFogSeen`，即 **R4c173~R4c175b 已验收的「随飞随收」**：飞行途中持续把沿途省份变可见。于是某省的 `fogDrawArmy` 一旦变 `false` 且其中有敌方驻军，**下一帧** `trackGroundTarget` 就会重瞄成功（探针 `nAS rt=`）。→ **「飞到看见为止」是复用已验收能力，不是新机制。**
- 若一路飞到燃油耗尽仍无合法目标：交由引擎既有返航逻辑处理（本批**不新增**强制召回路）。

### 2.5 去重（P3）
见 §2.3 的 `hasSameTargetInFlight`：**同型 + 同省**在飞时不再派新任务。天然替代"每省最多一个任务"的限流。

### 2.6 节拍与天然闸门（P6 ／ §六-2 依据）
- 节拍＝**每回合**（`GameThread_Turns.run()` 1335 → `updateAll()`；同回合由 `iLastUpdateTurnID` 去重），非每帧；
- 期望出击率：单机场每回合 攻 0.2 ＋ 轰 0.2 ＝ **约 0.4 次**；20 机场 ≈ 8 次/回合（上限被§下条封顶）；
- 天然四道闸门（**不再另加限流**）：①师级互斥（`pickIdleDivKey`＋`hasActivePatrol` ⇒ 每师同时 ≤1 任务）②`getAvailableAircraft` 空则不入列 ③20% 概率门 ④`canReach`/`getAircraftRange` 航程。

### 3.1 跨类可见性预检（**R4c176 血案同款，本设计第一红线**）

| `provinceDistance(II)F` (1914) | **private** | 同上，AFM 内部用 |

### 3.2 调用 kind 对照
`static → invoke-static`；`private → invoke-direct`（仅同类）；实例 public → `invoke-virtual`；`new Random(J)` → `invoke-direct {v}, Ljava/util/Random;-><init>(J)V` ＋ `move-result-object` 紧贴。

### 3.3 条件跳转真值表（新增分支逐条回放）
| 判据 | 指令 | 跳转含义 | 期望 |
|---|---|---|---|
| `nextFloat() < 0.2` | `cmpl-float`＋`if-ltz :skip` | ≥0.2 **跳走** | 与 `tryPatrolForAirport`(2530-2534) **逐字一致** |
| `mode != OFFENSIVE` | `if-ne … :skip` | 不等则跳走 | 镜像 2524 |
| `divKey == null` | `if-eqz … :skip` | 空则跳走 | 镜像 2542 |
| `hasActivePatrol == true` | `if-nez … :skip` | 非零（在飞）则跳走 | 镜像 2548 |
| `tgt < 0` | `if-ltz … :skip` | <0 跳走 | 镜像 2554 |
| `assignedAircraft.isEmpty()` | `if-nez … :skip` | 非空才继续 | 镜像 2566 |
| 目标仍合法 | `if-eqz :skip` 系列 | 合法则跳出重选 | 新增，需画全 8 条路径 |
> 每条新分支**旁边写意图注释**，并做一次全路径回放（项目历史已因方向写反犯错 5+ 次）。

### 3.4 标签唯一名（避开现有 `:cond_*`）
`:as_*`（strike 派发）｜`:os_*`（updateOffensives）｜`:gt_*`（trackGroundTarget）｜`:ps_*`（pickStrikeTarget）。**标签不得落在方法尾部**（异常处理器会流入 → Undefined → VerifyError）。

### 3.5 探针
一律 `AirDbgLog.dKey`：`nAS type=… tgt=… div=…`（派发）、`nAS rt=…`（重瞄）。热方法内不做字符串拼接（抽静态辅助）。

### 3.6 存档与字段
本设计**零新字段、零字段改型** → `Save_Airport`/`Save_AirMission` **完全不动**，读档安全。新增方法不进存档。

### 3.7 寄存器
每个新方法独立算足但 **≤ v15**；**不得上调任何既有方法的 `.registers`**；含 J/D 方法禁用 pN 别名。

### 附-2.1 迷雾系统：每个对象 × 每个观察方 一条记忆记录
存档格式串（`ICBM.exe` 内）：

实据样例（`Scenario/Main/Main-1.txt:805-822`，`unit "Submarine"` 的 `Visibility` 块，每观察方一行）：
```txt

  Owner 0
  Visibility
    visinfo vis -1 ghost true  precise true  know_exists true  pos -0.613140 0.392123 -0.685784 0.000000 head ... ftseen 0.000000
```

规模：`Main-1.txt` 3680 条、`Main-10.txt` 20100 条；全库 `visinfo` 约 **14.7 万**条。

| 字段 | 语义 | 取值 |
|---|---|---|
| `vis` | 可见状态 | `-1` / `0` |
| `ghost` | **残影**：目标已不在探测内，只剩记忆 | true/false |
| `precise` | **是否精确当前位置** | true/false |
| `know_exists` | **是否“知道它存在”**（连位置都没有） | true/false |
| `pos` / `head` | **最后已知位置 / 朝向** | 坐标 + 朝向 |
| `ftseen` | **首次看到时间戳** | `0.0`；`2147483648.0`≈“从未” |

**三态（均为实测组合）**：
1. `ghost true precise true know_exists true` → 现在看得见（精确）；
2. `ghost true precise false know_exists true` → **只记得它在那儿**（残影 + 位置）；
3. `vis 0 ghost false know_exists true` → **只知道它存在**，位置不明。

### 2. 条件跳转语义（**本项目翻车最多的一类错，写死**）

| 指令 | 真实语义 |
|---|---|
| `if-eqz v` | **v == 0（null / false / 0）才跳** |
| `if-nez v` | **v != 0（非空 / true / 非零）才跳** |
| `if-ltz v` | v < 0 才跳 ｜ `if-gez v` | v >= 0 才跳 |
| `if-lez / if-gtz` | v <= 0 / v > 0 才跳 |
| `if-eq / if-ne` | 两寄存器相等 / 不相等才跳 |
| `if-lt / if-ge / if-gt / if-le` | vA < / >= / > / <= vB 才跳 |

### 3. 根因与教训（本轮）

- **根因**：`r5b004` 的守卫把 `lArmyRegiment == null` 写成了 `if-nez`（**非空才跳**）⇒
  **清单非空的正常军队被跳过**，只能落到"扣 iArmy"兜底；而 `iArmy` 是**派生量**
  （`ArmyDivision.updateArmy()` 按团求和），很快被引擎重算覆盖 ⇒ 表现为**"炸了没反应"**。
  修正见 `r5b014`：两处判空改为 `if-eqz`（`key` 判空、清单判空）。
- **排障顺序教训**：静态分析（5 个构造器都 `new ArrayList`）早已说明"字段不可能为 null"，
  但当时继续去猜游戏 ⇒ 白跑多轮。**今后：静态判定"不可能"时，先怀疑自己的探针/断言。**
- **探针纪律**：探针**一律无分支**（`String.valueOf(obj)` 之类），否则跳转落点算错就得到自相矛盾的日志。
- **门禁盲区**：`CheckSig`/`check_calls`/`check_arity` 都抓不到"调了别的类里不存在的方法"
  （已因此崩过 3 次：原版 `removeMove`、原版 `buildAirport`、我写的 `ArmyDivision.getCivID()`）。

| 点 | 理由 |

### 附-20.2 将来必须遵守的 5 条接口约定

1. **独立计数器**：跟随若需上限，**新增字段**（如 `a1bTrackUsed`），**不要共用 `a1bHops`**（历史 `huntUsed` 被两功能共用，当时的文档就记过"建议后续独立字段"）。

3. **`targetArmyID` 已被征用**（r5b007 起为计数器）⇒ **只能"省粒度"跟随**；若要精确锁某一支部队，须**新增字段**存部队 key（独立工作量）。

5. **同帧优先级**：约定"**跟随在前、扑空重瞄在后**"——`EN_ROUTE` 期间由跟随改向；到达后发现扑空才由 `a1bReHunt` 改向（避免同一帧两处都改 `targetProvinceID` 互相覆盖）。

| 事实 | 证据 |
|---|---|
| 只有**一个**机炮特效方法 | `ProvinceDrawArmy.drawAirGunFx(oSB, mission)`（8499 行；注释 "R4c134: forward bullet stream (pulse tracer)"） |
