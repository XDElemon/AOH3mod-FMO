### 7.1 追加：为什么不直接用 Shizuku，以及替代桥（2026-09-18）

Operit 确实持有 Shizuku 权限，但**DSH 的 bash 无法直接调用**，实测证据：

- proot 的 `/proc` 里只有 **19 个进程**，全部是本会话自己的（proot/bash/node），**看不到 Operit 主进程**；
- 无 `/system`、无 `app_process`、无 `/dev/binder` → 没有 Android 运行时，也就没有 Binder 通道；
- 逐 pid 试 `\proc\<pid>\root\system\bin\sh` **无一命中** → 借道 `/proc/<pid>/root` 摸真 Android 根的路子也断了。

结论：Shizuku 的 API 只能被 **Android 应用进程 / Operit 插件**调用，proot 内的 Linux 进程够不着。
可行替代（**文件队列桥**，零安装）：

| 件 | 作用 |
|---|---|
| `r6s5/devbridge_poll.sh` | 设备面轮询器（由 Operit 的 Shizuku shell 启动，以 uid 2000 运行，`sleep 2` 轮询） |
| `r6s5/devbridge_send.sh` | proot 侧驱动：写 `cmd.sh` → 等 `out.ready` → 打印结果 |
| `r6s5/devbridge/` | 队列目录：`cmd.sh` / `cmd.run` / `out.txt` / `out.ready` / `heartbeat.txt` / `pid.txt` |

一次性引导（在 **Operit 设备面**执行）：
`nohup sh /sdcard/GLG/历史23/r6s5/devbridge_poll.sh >/dev/null 2>&1 &`

之后 proot 侧即可：`bash r6s5/devbridge_send.sh 'pm path age.of.history3.qiamxi.zhiri'`，
装机 / force-stop / logcat / 抓样 / `input tap` 全部走这条队列。风险：若 Operit 的 Shizuku shell 会回收子进程，
轮询器可能不存活 → 用 `heartbeat.txt` 判活，退路是 adb 无线调试桥。
