## 4. 构建 / 装机 / 抓样 流程

### 4.1 标准链条（每步都要看返回码）

```bash
A=/sdcard/GLG/历史23/toolchain/act
bash $A/assemble.sh <批次>                                    # 汇编 → /tmp/<批次>_classes.dex
python3 $A/check_arity.py /tmp/w3a/smali                      # ⚠ 全树扫描约 20 分钟，BAD 必须 0
python3 /sdcard/GLG/历史23/check_calls.py <改过的类>.smali      # "调用未定义"，必须 ✅
bash $A/verify.sh /tmp/<批次>_classes.dex <上一版归档apk>      # 八件套 + Sig Δ
bash $A/build.sh <批次>                                       # 打包签名归档
bash $A/install.sh <批次> --yes                               # 推送装机（需轮询器在跑）

bash $A/capture.sh <批次>                                     # 抓样
```

### 4.2 门禁判据（三条硬门）

1. `check_arity.py` → `BAD: 0`（另 3 条 WARN 是老代码自带，忽略）
2. 八件套 → `Invoke/Regs/Init/Range BAD 合计 = 0`；`MISSING` 必须等于白名单（`common.sh` 内 `NOISE_MISSING=14`）；`Sig` 增量 = **本批新增的、调往 `Laoc/...` 类**的 invoke 数（**JDK 调用不计入**！）
3. **装机后设备 dex md5 == 本地**（装机脚本自动核 `DEX_MATCH=1`）

> ⚠️ 本地八件套**抓不到 ART 级 VerifyError**（寄存器类型/参数个数）→ **真机启动自检是唯一防线**（`r5b006` 首版就是这么翻的）。

## 6. 教训清单（血泪，动手前必读）

### 6.1 条件跳转极性（本项目翻车 9+ 次！）

| 指令 | 真实语义 |
|---|---|
| `if-eqz v` | **v == 0 才跳** |
| `if-nez v` | v != 0 才跳 |
| `if-ltz v` | **v < 0 才跳**（不是"≥0 才跳"！） |
| `if-ge vA,vB` | vA ≥ vB 才跳 |

约定：**"跳过条件"一律用 `if-xxx v, :skip`，并在注释里写出真值表**（例：`if-eqz v14, :next  // 未交战(0)才跳过`）。
补丁里要写**反例断言**（出现反向写法就报错）。

### 6.2 寄存器边界（本次翻车两次）

1. **`.registers` 上限 16**：`mul-float/2addr v8, p2` 这类指令的**第二操作数只有 4 位（v0~v15）**；抬到 18 ⇒ `p2` 变 `v16` ⇒ 汇编器报 `Invalid register: v16`。
2. **参数区 = `v(registers-参数个数) .. v(registers-1)`**：4 参数方法在 `.registers16` 时 **v12~v15 就是参数**！往 `v12` 写值＝覆盖 `p0`（Province 引用）⇒ 真机 `VerifyError: tried to get class from non-reference register`。
   - 结论：**插局部变量前先算 locals 区间**；寄存器不够时优先"现取/复用"，不要把 `.registers` 抬过 16。
   - `applyArmyDamage` 实测是 **4 参数**：`(Province, int, float, int)`——第 4 个 `targetArmyID` 我们一直没用，`r5b007` 正是征用它做计数器。

### 6.3 门禁的盲区（都已补过）
