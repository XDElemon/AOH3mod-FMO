## 2. 设计（定稿）

### 2.1 数据维度
- **新增 `AirUnit.gen:I`**（缺省 **3**）——旧档/未初始化一律按 3 代处理。
- **国别组**：`0=CN, 1=EU, 2=RU, 3=US`（枚举化，便于数组/分支）。
- **机型**：沿用 `AirType` 四值（**绝不动枚举**）。

### 2.2 贴图字段（Images）
- 命名：`airG{3..6}_{CN|EU|RU|US}_{FIGHTER|INTERCEPTOR|ATTACKER|BOMBER}` ⇒ **共 64 个**（Gen4 的 16 个已存在，需补 Gen3/5/6 = **48 个**）。
- 不删除旧的 4 个全局字段（保底回退用）。

### 2.3 加载（InitGame）
- 照 A2/A3 模板**追加 48 条**（Gen3/5/6 × 4 组 × 4 型）；路径＝`game/AirUnit/AirUnitlmages/Gen{n}/{组}/{机型}.png`。

### 2.4 国别路由（新方法，独立、可测）
```
AirForceManager.artGroupOf(I civID)I   → 0/1/2/3
  ① L1 显式表（civTag/civID → 组）：中=CN、俄=RU、美=US、欧=EU、日=US、德/法/英/意=EU、印=RU(主)…
  ② L2 区域：读该国首都省 Province.iGeoRegionID / iContinentID → 区域组（东亚→RU、东南亚→混合、南亚→RU、中东→RU/US、非洲→RU(主)、拉美→US、大洋洲→US）
  ③ L3 兜底：**RU（俄系）**
```
（L1 表以"civTag 字符串表"实现最稳；L2 以 regionID→组 的整数表实现。）

### 2.5 贴图索引取值（新方法）
```
Images/或AFM: pickAirImage(III)I   → 入参 (gen, group, type) 出参 Images 静态字段的 int
  gen 夹取到 3..6；未知组合 → 回退（同组 GEN3 → 全局 airFighter 等）
```

### 2.6 绘制侧改造（最小侵入）
- `ProvinceDrawArmy` 的读取点：把 `sget Images->airFighter:I` 换成 `invoke pickAirImage(gen, group, type)`；
- `InGame_AirForceOptions:402` 同样处理；
- **每处只换取图那一两行**，不动周围寄存器用途（取图结果是同一个寄存器位）。

### 2.7 存读档
- `Save_AirUnit` 增加 `gen:I`；读取时缺省 3；写入时写出实际值（→ 属 B6，但字段一落地就要处理，避免旧档崩）。

## 4. 门禁与负样本（拟）
- 断言：① 64 个 Images 字段齐 ② InitGame 64 条加载齐 ③ `pickAirImage` 存在且四机型分支齐 ④ 绘制侧旧 `sget airFighter` 已无残留（或仅兜底）⑤ gen 夹取 3..6 ⑥ 路由 L3 返回 RU
- 负样本：把 `Gen5/CN/FIGHTER` 路径写错、把 gen 缺省改 0、把路由 L3 改成 US、删掉一个 Images 字段 ⇒ 门禁必须报错
