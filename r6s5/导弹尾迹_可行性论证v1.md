## 二、同类先例（已核）

`drawAirGunFx`（机炮曳光，R4c134 成品，PDA:8497）：
- **5 个 2×2px 方块**沿弹道链式绘制（7px 节距）；
- pulse 头点 = `(now%200)×0.42px/ms`，方块依次向内排布；
- 整串一次 `setColor`（我方黄/敌方红）、**收尾复位白色**；
- 证明："小方块串"在该渲染管线完全成熟，且**开销可忽略**。

> 尾迹与曳光的区别：曳光＝"同一时刻的直线链"（无状态、每帧重算）；
> 尾迹＝"历史位置的存留链"（需要 16 个点的小缓冲）。仅此一处差异。

**尺寸基准**（同管线已核对）：飞机贴图 60~72px ｜ 弹体 14px ｜ 曳光 2px
→ 3px 方块介于曳光与弹体之间，符合"小方块尾迹"的视觉量级；若高倍缩小下嫌细，可调 4px（留参数）。

## 三、设计方案（推荐形态）

### 1. 数据结构：环形缓冲（16 点）
- 新字段（AirMission）：`msFxTX:[F`、`msFxTY:[F`、`msFxTN:I`（计数）、`msFxTH:I`（头指针）；
- **懒分配**（首帧发射时 `new-array 16`，每任务一次，128 字节；此后每次发射复用、只重置计数）；
- 头指针掩码 `&0xF`（16=2⁴，位与即可，无取模成本）。

### 2. 推送规则（帧率无关＋"逐个删除"语义）
- 从"上一次落点"到"当前弹位"沿线段按 **4px 步进补点**（最多 8 点/帧防爆）——高速/低帧率下点距仍均匀；
- `TN<16`：累积增长；`TN=16` 后：每推 1 点自动覆盖最旧 1 点 → **尾巴长度恒定，最旧的被逐个淘汰（＝用户描述）**；
- 尾巴总长 = 节距 ×(数量−1) ≈ **4×15 = 60px**（想更长：加大节距或数量，均为常量参数）。

### 3. 绘制
- 从旧到新绘制（新点压旧点）；每点：`Images.pix->draw(batch, x-1, y-1, 3, 3)`；
- 颜色：**纯白** `setColor(1,1,1,1)`（按用户原文；可选进阶：按年龄渐隐 alpha，默认不做）；
- 顺序：**先尾迹、后弹体**；收尾复位白色（沿用曳光范式）。

### 4. 为什么不用"无状态伪尾巴"
简单方案（每帧固定画几个点）只能画出"直线光束"，与用户要的"**留在身后的点列**"语义不符；
环形缓冲成本极低（≤16 次绘制/帧），且天然支持**追击曲线下的弯尾巴**——故直接采用。

## 四、生命周期与边界（全部有对策）

| 场景 | 行为 |
|---|---|
| 每次发射 | 首帧初始化：重置 TN/TH、清阵列、弹位/速度照方案一初始化 |
| 游戏暂停 | 冻结（承接方案一的暂停门控，不推点、不移动） |
| 缩放变更 | 清尾＋重同步（点存屏幕坐标；缩放会破坏历史点） |
| 命中/到达 | 尾迹**随弹一起消失**（默认）；可选 200ms 滞留淡出（后备项） |
| 旧档/异常 | 数组懒分配，null 安全；不进存档（沿用字段白名单） |
| 多弹并发 | 每个任务独立一套数组（现状：一任务同时仅 1 发视觉） |

**性能**：每弹每帧 ≤16 次 pix 绘制＋~40 次浮点运算；按 4 发并发 ≈64 draw calls/帧——与曳光同量级，可忽略。
**内存/GC**：每任务一次性分配，无逐帧分配（避免 GC 尖峰）。

| 参数 | 初值 | 可调范围 | 备注 |
|---|---|---|---|
| 方块尺寸 | **3px** | 3~4 | 用户指定 3px |
| 点距 | **4px** | 3~6 | 4px≈点列微间隔；3px=近实线 |

| 渐隐 | 关 | 开/关 | 进阶可选项 |
| 命中后 | 立即消失 | 或 200ms 淡出 | 默认立即 |
