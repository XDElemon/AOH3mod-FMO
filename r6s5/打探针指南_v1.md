## 4. 四大陷阱（都是真实血案）

### ① 寄存器类型不一致 ⇒ ART 拒绝整个类 ⇒ **启动即崩、一条日志都没有**
- 例：把 `iget-wide v1`（long 低半）当 `String` 传给 `StringBuilder.append`。
- 报错：`VerifyError: register v1 has type Long (Low Half) but expected Precise Reference: java.lang.String`。
- 纪律：**String 恒用 v3**；long 用 v1/v2 且 `append(J)` 传 `{v0, v1, v2}`；int 单独寄存器。
- 手段：**探针必须独立成方法**（主方法只留 1 行 `invoke`），并跑 `toolchain/act/check_regtype.py`。

### ② 读 `pkg/files` 里的文件：**用 `java.io`，别用 `java.nio.file`**
- `Paths.get()+Files.readAllBytes()` 在 `/storage` 上会失败（异常被 catch 吞掉 ⇒ 返回 null ⇒ 静默用默认值）。
- 症状：`CFGRD … rd=null`、配置键全部退回默认。
- 修法：`FileInputStream` + `ByteArrayOutputStream` 循环读（见 `cfgReadText`，r6d026）。

### ③ `dKey` 有 500 ms 落盘节流 ⇒ **同刻相邻行会被吃掉**
- 症状：先写的行在，紧跟着的同刻行**没有**。
- 修法：诊断/自证类输出改用 `dWrite`（免节流）；或把两次输出错开时间。

### ④ 装机/环境类
- 装包会**清空 `files/` 并改 UID**（`u0_a663→u0_a664`）⇒ 配置与日志都没了，必须重建并 `chown`。
- `am start` 后**要验证进程在**（`ps -A | grep <pkg>`），否则你读的是"上一局的旧文件"。
- 包**非 debuggable** ⇒ `run-as` 不可用，无法以应用 UID 验证权限。

## 5. 探针怎么加（施工模板）

1. **写方法**（在 `AirDbgLog`）：`msXxx(参数)V`，内部只用 `StringBuilder` + `dKey`/`dWrite`，**严格寄存器类型纪律**，**绝不 `iput/sput` 业务字段**。
2. **写调用点**（在业务类）：主方法里**只插 1 行** `invoke-static`，需要传对象就 `move-object v9, v1` + `invoke-static {v9}`。
3. **写门禁**（新增 `r6d0NN_xxx.py` 的 `gate()`）：至少 4 条断言 + **3 个负样本**必须能"变红"。
4. **加节流**（避免日志爆炸）：帧计数 `& 0x1F`（≈1 秒）放行一次；心跳用 `& 0x1FF`。
5. **汇编 → 门禁 → 装机 → 三对齐**（apk / classes.dex / Earth3 三个 md5）。
6. **启动自证**（BOOT 行）→ 交用户实测 → 增量抓样 → 判读 → 落盘 + 推 GitHub。

## 6. 判读字典（AI 空军常用）

| 探针 | 含义 | 期望 / 判据 |
|---|---|---|
| `MT frame=` | `updateMissions` 心跳（每 ~512 帧） | 有 ⇒ 任务帧循环在跑 |
| `MS mid=.. c=.. s=.. at=.. tg=..` | 任务快照（每 ~1 秒/任务） | **同一 `mid` 连续 ≥3 次 `s/at` 不变 ⇒ STUCK（卡住）** |
| `s` | `MissionState.ordinal()` | 0 规划 / 1 在航 / 2 执行 / 3 返航 / 4 完成 / 5 中止 |
| `CFGRD e=.. r=.. len=.. rd=..` | 配置读取诊断 | `e=1 r=1 rd=ok` = 读得到；`rd=null` ⇒ 走了陷阱② |
| `BOOT2 dbg=.. prob=.. pin=..` | 配置回显 | 若与 `strike_config.json` 不符 ⇒ 解析/时序问题 |
| `nA5t civ=` | `strikeTick_A1` 入口（结算被调用） | 有 AI 文明 id ⇒ 结算入口被调到 |
| `nE5`/`upy`/`p1b*` | 既有探针 | 见 `r6s5/探针总表_可打点全清单_v1.md` |

**停滞判定（离线脚本）**：同一 `mid` 的相邻快照 `(s,at)` 连续 ≥3 次完全相同 ⇒ 判 STUCK（`r6d024_analyze.py` 已实现）。
