## 0. 先给结论：三个最可能的原因（按可能性排序）

| # | 假设 | 代码依据 | 会看到的现象 |
|---|---|---|---|
| **H1（最可能）** | **AI 的任务到目标后"没人结算"，于是永远停在目标省** | `AirForceManager.strikeTick_A1(civID)` 开头就是 `if (player==null \|\| civID != player.iCivID) return;`（**玩家门**）⇒ 只有玩家国的任务会推进/收尾。AI 造出来的任务（`executeAIAssignmentForAirport` 会造 `STRATEGIC_BOMBING`）**只被创建、不被结算** | 大规模空战时，一堆 AI 任务同时停在**同一个省**（=目标省），`state` 卡在 `EXECUTING`，永远不返航、不消失 |
| **H2** | **幽灵任务**：`aliveAircraft` 已空（全被击落）但任务没被回收 | 任务回收若挂在结算链里（同 H1 的门）⇒ 空任务滞留 | 飞机图上"停着不动"，但那其实是一条没有飞机的空任务；点它/看它都没反应 |
| **H3** | **推进依赖的"段动画时间轴"卡住**（或帧率暴跌到看不出动） | `airDivisionAtProvinceID` 的推进用 `airDivSegAnimMs / airDivSegDurMs`（帧差累加），`msFxFrameDt()` 提供 dt；大规模时帧率骤降 | 有移动但极慢 ⇒ 像"卡住"；或某一帧 dt 异常导致停住 |

> 说明：H1 与计划书里的 **G1（AI 打击结算不跑）** 是同一件事 —— 之前我们按你的要求"只让 AI 会造机，不碰作战链"，所以**这个现象在预期之内**；但需要抓样确认，而不是猜。

## 1. 探针分组设计（四组，可裁剪）

### 组1 · 任务快照（低频，一行一任务）
- **频率**：每 1000 ms 一次（或每回合一次，二者可选）
- **字段**：`mid`（任务ID）、`civ`、`mine?(是否玩家)`、`det?(是否雷达已探测)`、`type`（PATROL/STRATEGIC_BOMBING/…）、`state`、`atProv`、`prevProv`、`tgtProv`、`seg=<animMs>/<durMs>`、`ac=<alive>/<total>`、`pos=<x>,<y>`、`age=<ms>`、`sinceChange=<ms>`
- **用途**：一眼看出"停住的都是谁、什么状态、停在哪"

### 组2 · 停滞探测器（★核心：直接给结论）
- **做法**：静态 `HashMap<Long, long[]>` 记每个 missionID 的「上次 `atProv` / 上次 `segAnimMs` / 上次变化时间」；若 **连续 ≥2 秒** 两者都不变 ⇒ 打一行：
  ```
  STUCK mid=12345 civ=7 type=STRATEGIC_BOMBING state=2 at=531 tgt=531 age=83000 staticMs=4200 ac=4/4
  ```
- **优点**：只在"异常"时写日志 ⇒ 日志量小、结论直给
- **关键判据**：`state=EXECUTING 且 at==tgt` 大量出现 ⇒ **H1 成立**

### 组3 · 状态迁移埋点（事件级，只在变化时打）
| 标签 | 时机 | 字段 |
|---|---|---|
| `MK` | 任务创建 | mid / civ / type / from / to / ac |
| `SEG` | 省际段推进 | mid / from → to / anim / dur |
| `ARR` | 抵达目标（ENTER EXECUTING） | mid / prov |
| `RTB` | 开始返航 | mid / from → home |
| `DONE`/`RM` | 完成 / 移除（带原因码） | mid / reason |
| **`SETTLE`** | **每次结算 tick** | civID / 扫到任务数 / 推进数 / 完结数 ← ★最能证明 H1 |

### 组4 · 时间轴与规模基准（每 1 秒一行）
- `TICK frame=... dtMs=... missions=N divs=N aircraft=N fps≈...`
- 用途：**区分"H1/H2 逻辑卡"与"H3 帧率/时间轴卡"**，并给出"大规模"的真实数量级

## 2. 判读字典（抓到样我按这张表判）

| 读数特征 | 结论 | 对应修法（下一批） |
|---|---|---|
| `STUCK` 大量且 `state=EXECUTING`、`at==tgt`、`mine=false` | **H1**：AI 任务无结算 | 放开结算门（只对"交战中的 AI"跑），即计划书 G1/P2 |
| `STUCK` 且 `ac=0` | **H2**：幽灵任务 | 增加"空任务回收"（扫到 `aliveAircraft==0` 且超时 ⇒ 移除） |
| `STUCK` 少，但 `TICK` 显示 `dt` 极大 / 帧率极低 | **H3**：性能 | 任务更新分批（每帧只更新 N 条）、或降低视觉帧依赖 |
| `STUCK` 只在 `mine=true` | 玩家链也有问题 | 单独查玩家任务的段推进/结束条件 |
| `SETTLE` 只出现 `civ=玩家` | 直接证实 H1 | 同上 |

## 3. 成本 / 风控

- **全部走既有 `dbgOn` 总闸**：`debug:0` 时零开销、零写盘（r6d019/r6d020 已保证）。
- **日志体量**：组2 只在异常时写；组1/组4 节流 ≥1 s；预计一局 < 2 MB（对照：之前诊断版一局 8~10 MB）。
- **纯只读**：探针只读业务字段；**不得**写业务字段、不得影响任何 `if`/跳转 ⇒ 新增**门禁 82**断言（"探针块内无 `sput`→业务字段、无控制流副作用"）。
- **新增状态**：`HashMap`/计数器放在 `AirDbgLog` 里（静态字段），借空闲寄存器，不动业务方法结构。
