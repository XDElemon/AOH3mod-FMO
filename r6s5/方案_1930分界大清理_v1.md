# 1. 侦察结论（全部事实，可复查）

## 1.1 科技树：99 节点，要切在 col ≤26

- `TreeColumn 0..41` 是"年代轴"；`TreeRow 0..5` 只是编织走线（无领域语义）。
- **删除清单 = col ≤26 的全部节点 = 68 个**：
  - ID **0–66**（Library … MachineGunner）＋ ID **96**（WarTactics, col14）
- **保留清单 = col ≥27 = 31 个**：
  - `67 EarlyFighter`(6250) `68 EarlyTank`(6250) `69 WarTactics`(6350) `70 Fighter`(6500) `71 TrenchInfantry` `72 Tank` `98 Howitzer`(6500) `73 MechanizedInfantry` `74 MediumTank` `97 Bomber` `75 NuclearProgram`(8500) `76 MilitaryBase` `77 InternationalLawCompliance` `78 Infantry` `79 WarTactics` `80 SolarFarm` `81 ModernInfantry` `82 HeavyTank` `83 MLRS` `84 ModernMechanizedInfantry` `85 ModernTank` `86 DigitalCurrency` `87 MainBattleTank` `88 FutureTechnology` `89 AutomatedTaxCollection` `90 FutureFighter` `91 FutureArtillery` `92 FutureInfantry` `93 FutureMechanizedInfantry` `94 FutureTank` `95 FutureTechnology`（可重复，20000）

**边界说明**：留在保留区的第一个节点是 `67 EarlyFighter`（一战飞机）与`68 EarlyTank`（一战坦克）。如果你想更严格（1930 前一律删），`67/68/71/98`（一战档）也该删 —— 但这会把保留区推到 `69/70`，请见 §5 决策点 A。

**每条兵种线 = 一串档位，每档挂一个科技。** 被删科技的档位从此造不出来（这正是"1930 前内容消失"的直接体现）。

## 1.4 一个**必须处理**的隐藏耦合：`CivDefault_Technology` 是"下标"不是"ID"

`Civilization.buildTechTree_UnlockTechnologies(I)`：

```smali
p1 = clamp(0, TechnologyTree.iTechnologySize, iTechID)   // iTechnologySize = 科技总数
lTechResearched.set(p1, true)                            // ← 按【列表下标】置位
buildUnlockTechnologies_TechQueue1(p1) / TechQueue2(p1)   // 递归补前置
```

- ⇒ 剧本里的 `CivDefault_Technology: 81` 含义是"**解锁列表第 81 项那个科技**"（并递归补其前置）。
- ⇒ **一旦删节点，下标全体平移**，所有剧本的该数值**必须重算**，否则 2000 年开局会解锁到错误的科技。
- 同样，剧本 `Data.json` 里的每文明 `TechnologyID: N`（如 1440 剧本有 433 处）也是科技引用 —— 但那些剧本本来就要删。

## 1.5 时代定义（本方案暂不动）

`Ages.json` 12 个时代（`AgeofCivilizations` -5000 … `AgeofTomorrow` 2050+）。**我们的剧本 qianxi 用 `Age: 10`（AgeofInformation, 1991–2049）**。
- 若删掉 0–9 号时代，所有剧本的 `Age` 下标也会平移（与 §1.4 同类风险），而收益仅是"菜单里少几个时代名"。
- ⇒ **建议本轮不动**，只在将来做"年代阶梯"时一起重排（见 §4）。

# 3. 边界与不变量（必须成立）

1. **不删单位条目**：`Units.json` 用 **ID 顺序**注册兵种线（`ID 5 = Fighter`、`7..10 = 我们的四型空军`），单位在**线内的位置**就是 `armyID`。删条目会让 `armyID` 位移 ⇒ **会砸掉我们已接的 9 个取图点与 AI 逻辑**。所以被删档位**只重挂科技，不删条目**。
2. **不删 Ages**（本轮）：避免 `Age` 下标二次位移。
3. **所有引用被删科技的悬空值必须收敛**：单位 `RequiredTechID`、剧本 `CivDefault_Technology`、剧本 `Data.json` 的 `TechnologyID`（随剧本一起删）三类，逐一处理到"无悬空"。
4. **不碰**：`assets/game/AirUnit`、`unitsImages`、我们已有的 smali 改动、存档格式。
5. `CivDefault_Technology` 的**新下标**须按"目标科技在新列表中的位置"重算（不是保留原数字）。
