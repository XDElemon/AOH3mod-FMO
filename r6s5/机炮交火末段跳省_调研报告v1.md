⇒ **发射、命中、特效三个环节都在跑**。观感上"没看到导弹"的合理解释：
1. 导弹是"1 tick 结算 + 小曳光"，场面快；
2. R4c140 的 4h 冷却：每机一场最多一轮齐射（你的拍板口径）；
3. 非临省 >100 的组合被规则正确拦下（R4c142 修复后应如此）。
   若想导弹"更显眼/更常用"，备选项：加强导弹视觉（尾迹/爆点）、冷却回调、或放宽距离口径——随时可做，等你拍板。

## 二、现象②："机炮时瞬移到敌机省份" —— 已定位（真因 + 铁证）

### 真因链（代码）

1. 追敌更新：`AirMission.trackTarget()`（AM:2867 起；重算块 ~2905-2930）——敌机跨省时执行：
   ```
   sourceProvinceID   = 我方当前位置
   targetProvinceID   = 敌机新省份
   distanceToTarget   = calculateDistance()   # 按"新距离"重算
   # r4c102 注释：keep anim clocks running（不重置动画时钟）
   ```
2. 到达判定：EN_ROUTE 主分支（AM:3267-3274 `:cond_11b`）——当 `roundsInFlight >= distanceToTarget` 即视为"追上"：
   ```
   placeAirDivision(targetProvinceID)   # ← 瞬时 remove/add，末段直落（跳变点）
   state = EXECUTING                     # ← 随后进入同省机炮交火
   ```
3. `placeAirDivision`（AM:1575-1636）本身是**瞬时**的省份换位；移动系统的正常逐省步进（每跳 ~230ms）被这一步"截胡"。

### 日志铁证（inc142 两场战斗，同一模式）

       3869088 nRT sw at=5711 src=5714 tgt=5711 fp=100 ap=6355
       3869317 nGX fire        ← 机炮在"跳过去"的同省开火

       5185140 nGX fire        ← 同样的"跳过去→开火"序列

（SNAP=省位链断裂自动检测，见 `r193_chain.log`；两次跳变源省/目标省都一致，重复复现。）

## 三、修复方案（3 选 1，未实装）

### 方案 A（推荐）—— "到达闸门"
把 AM:3270 的**直落**改为条件落位：

- 仅当 `airDivisionAtProvinceID == targetProvinceID`（真的飞到了）→ `placeAirDivision` + `EXECUTING`；
- 未到 → 跳过本次判定（保持 EN_ROUTE），让移动系统把最后 1~2 跳**正常飞完**再进战斗；
- 兜底（防卡死）：① 师对象/省份异常 → 直落；② `roundsInFlight >= distanceToTarget + 8`（再等约 8 个逻辑 tick）→ 直落（保留旧行为）。

改动：单一位置 ~15-20 行，风格与 R4c142 返航闸门一致；风险低。
验证计划：一次空战后 `SNAP` 事件归零 + `nRT seg` 链中能看到 5714→5711 的正常一跳。

### 方案 B —— 视觉补间（保底）
数据层保持瞬移；绘制层对"刚落位"的师做 300~500ms 位置滑动。
优点：战斗逻辑零改动。缺点：数据跳变仍在（雷达/选中圈等次级表现仍可能瞬跳），观感一般。

### 方案 C —— 直飞末段
剩余 ≤1~2 跳时，给移动系统显式注入"直飞目标省"的最后一段（机头朝目标俯冲），到位后再 EXECUTING。
观感最佳；但需接管/扩展路径队列逻辑，改动最大、验证周期最长。

> 建议：先上 **A**（见效快、可控）；若个别追逐场景兜底频繁触发，再补 C。
