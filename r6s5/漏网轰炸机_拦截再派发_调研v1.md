# 漏网轰炸机 · "拦截不再起飞"机理调研 v1（2026-09-17）
- 现象（用户）：大型空战中两架轰炸机漏网并成功轰炸；拦截机回基地**补给完毕也无人再起飞**。
- 用户假设："拦截逻辑只扫描一次" —— **基本命中，且有第二重漏洞**。
- 结论：**两条拦截派发链各有"一次性黑名单"，且"记账发生在派发之前"** ⇒ ①派发过（哪怕后来失败/无果）→永不再派；②派发**失败**（无机可派）→同样永不再试；③没有任何"回场后复核"机制。

## 一、两条派发链（全部实锤）
- **链 A**：`PlayerFogOfWar.detectEnemyMissions()`（FM:481）——500ms 节流；由 `AA_Game.render`(:2064) 与 `RealTimeSim`(:224) 每帧驱动。
  - 条件：敌机（civ≠我 ∧ 交战 ∧ state∈{EN_ROUTE,EXECUTING}）→ 可见性判定（雷达/机场椭圆）→ `airDetSeen.contains(id)` **命中即永久跳过**；未命中 → `add` + `dispatchAutoIntercept` + 探针 `nDR_DET`（FM:824-827）。
- **链 B**：`AirForceManager.updateAIAutoIntercept()`（AFM:2868）——500ms 节流；由 `updateMissions()`(:5476) 每帧驱动。
  - 条件：敌机**目标省=我方**∧交战 → `aiRadarVision` 可见 → `aiAirDetSeen.contains(id)` **命中即永久跳过**；未命中 → `add` + `dispatchAutoIntercept`（nAVS seen / nAVS blk 探针）。
- **两个集合均无任何 clear/remove**（全树搜索）⇒ **整个游戏会话内，每个敌机任务只允许"尝试一次"**。

## 二、派发器的三个失败出口（全部"吞掉"重试机会）
`dispatchAutoIntercept`（AFM:3114）内部：
1. `no-airport`（无可用机场/航程均不覆盖 → `nDSPT3` + `nDR_DSPT no-airport`）；
2. `no-divkey`（有机但无闲置编队 → `nDSPT2` + `no-divkey`）；
3. 逐机场静默跳过（无机/航程不够）。
**关键是：链在调用派发前就已 `add` 黑名单** ⇒ 上述任何失败 = 永久放弃。

## 三、实战证据（d166_s1.txt 大空战样本）
- `nDR_DSPT ok ×5`（首波成功起飞 5 次）；
- **`nDR_DSPT no-airport ×5`**（5 次派发失败；现场 dump：6 个机场 `ik=null` 全无闲置截击编队、仅 ap6341 有一个闲置战斗机但航程不覆盖敌机省 5721）；
- `nDR_DET ×10`（= 5 成功 + 5 失败，一敌一次）；
- 失败后同一条敌机任务**再无任何重试记录**（即使后续拦截机全部回场补给）。
- `nAVS blk ×5`（链 B 侧 5 条敌机不可见被拦）；链 B 无一派发。
⇒ 用户所见"补给完也没人起飞" = **黑名单效应**实锤；漏网轰炸机极可能就在 5 条 failed 任务之中。

## 四、方案（待拍板）

### 方案①（推荐）："活猎手判定"替代一次性黑名单 + 冷却重试
- 新增 `AFM.hasActiveChaser(J enemyID, I civ)Z`：遍历 activeMissions，命中 `civ==防守方 ∧ type==INTERCEPT ∧ targetMissionID==敌ID ∧ state∈{EN_ROUTE,EXECUTING}` → true（RETURNING 不算）。
- `dispatchAutoIntercept` 入口加两道门：①已有活猎手 → 直接返回；②**每个敌机重试冷却**（新 `HashMap<Long,Long> lastTryMs`，默认 10s 墙钟 / 或 2 游戏小时，可调）→ 未到冷却直接返回（**在探针之前**，防刷屏）。
- 两条链的判定从"`contains→skip`"改为"`contains && 有活猎手 → skip`"；无猎手时照常走可见性→派发（失败会在冷却后自动重试；成功则 add 照旧）。
- 效果：①漏网→有飞机后自动重派；②无机可派→冷却后重试而非黑名单；③首波全灭/返航后自动续派第二波；④双链互查猎手，天然去重。
- 成本：AFM 新 helper + 冷却字段 + 门口（≈60-100 行）＋两条链小改（各 ~10 行）。风险低。

### 方案②（保守·局部）：失败重臂 + 终结重臂
- a) `add` 移到"派发真正成功"之后（失败不记账）；
- b) 我方拦截任务终结（COMPLETED/ABORTED/到站清理点）时，把其 `targetMissionID` 从两个集合中 remove（允许下一波）。
- 缺点：终结点分散、返航中不重派（须等彻底结束）、失败重试无冷却需另加；覆盖"无机可派"这个主漏洞不彻底（b 只覆盖成功过的）。

### 方案③（策略化·大）：每敌机状态表
- `{lastTryHours, attempts, lastChaserHours}` + 参数（最大波次 N=3 / 冷却 2h / 威胁加权：优先打"目标=本国省"的敌机）。
- 适合后续"空军 AI 策略化"批次合并，本轮不建议。

## 五、微决策（默认值）
1. 重试冷却 = **10s 墙钟**（备选：2 游戏小时）；
2. 猎手上限 = **1 个/敌机**（hasActiveChaser 天然保证；如需多波齐发可放宽）；
3. 链 A/B 都改（推荐；只改一条会留死角）；
4. 探针：新增 `nDR_RTRY k=`（重试派发命中）与 `nCT`（无猎手→可重派计数）便于验收。

## 七、实施记录（R4c166c→d，2026-09-17）

- **实现（方案①）**：AFM 新增 `hasActiveChaser(JI)Z`（activeMissions 中 civ==防守方 ∧ type==INTERCEPT ∧ targetMissionID==敌 ∧ state∈{EN_ROUTE,EXECUTING}）；新增 `dspRetryGate(J)Z`（HashMap<Long,Int> 记 lastTry 总小时＝TURN_ID*24+HOUR；≥4 游戏小时放行并刷新）；`dispatchAutoIntercept` 入口两道门（活猎手→ret；冷却→ret）＋`dspTried` 字段（0=未尝试/1=实际尝试）；
- **两链改造**：P FoW 链（FM）与 AFM 链的 "seen→skip" 均改为 "seen ∧ 有猎手→skip"，无猎手即可重扫重派；nDR_DET / nAVS seen 探针由 `dspTried` 门控（只在实际尝试时打印，防刷屏）；
- **事故与修复**：R4c166c 装机即闪退——`hasActiveChaser` 的 `if-eq v5,p1` 因 **smali 别名宽参错位** 汇编为 `v10`（long 高半字）→ ART `VerifyError`；修复（R4c166d）改显式 `v11`（同时对 `cmp-long` 改显式 v9）；
- **产物**：dex `763e2fc8…`｜apk `dea4aedb…`（738,366,573B）；装机 Success＋dex 一致＋ART verify Success＋冒烟零闪退；
- **验收关注**：①波次1结束后（或无机可派后），若敌机仍在飞且无猎手→ **4 游戏小时后自动重派**（出现新的 `nDSPT0/nDR_DSPT ok`，`nDR_DET/nAVS seen` 允许重复出现=重试痕迹）；②有猎手在追时不重派；③冷却期静默（无探针刷屏）。
