## 二、根因（拿装机 dex 反汇编逐字定位）
装机 dex 里 `pickStrikeTargetP`（已去掉注释）关键片段：
```
    const/high16 v3, 0x7f800000     # ← v3 = “+∞”，但它是 **int 常量**（Integer 类型）
    ...
:cond_19                            # ← 循环头（baksmali 标签名=代码偏移：0x19）
    invoke-interface {v6}, Iterator->hasNext()Z
    move-result v4                  # v4: int
    if-eqz v4, :cond_5e
    invoke-interface {v6}, Iterator->next()Ljava/lang/Object;
    move-result-object v4           # v4: Integer 对象
    ...
    invoke-direct {p0, v5, v8}, provinceDistance(II)F
    move-result v4                  # v4: float
    cmpg-float v4, v4, v3           # ★ 0x57：此处要求 v3 是 float ——校验失败
    if-gez v4, :cond_19
    move v3, v4                     # v3: float（回边上的另一种定义）
    move v0, v8
    goto :goto_19
```
**机制**：`const/high16` 产生的是 **int 类型常量**；该寄存器 `v3` 在**循环头**有两条汇合边——
- 进入边：`v3 = const/high16`（Integer）
- 回边：`v3 = move v3, v4`（Float）
⇒ 校验器求合并类型时得到 **Integer**，随后 `cmpg-float … , v3`（要求 Float）⇒ `[0x57] register v3 has type Integer but expected Float` ⇒ **VerifyError**。
（附带 **v4 同一类隐患**：循环头处 `v4` 在一条边是 `Integer 对象`、另一条边是 `float` ⇒ 修好 v3 后，下一次报错就是它。）

### 正确写法（二选一）
**A. 旗标法（推荐，零浮点哨兵）**
```
    const/4 v0, -0x1        # best pid
    const/4 v9, 0x0         # haveBest = 0
    ...
    invoke-direct {p0, v5, v8}, provinceDistance(II)F
    move-result v4          # v4: float（只作 float 用）
    if-eqz v9, :pst_take    # 真值表：haveBest==0 ⇒ 首个候选直接采纳
    cmpg-float v10, v4, v3  # v10 只作 int（cmp 结果），永不作 float 用
    if-gez v10, :pst_take   # v10<0 ⇔ v4<v3 ⇒ 更近 ⇒ 采纳
    goto :pst_next
:pst_take
    move v3, v4             # v3 首次定义即 float（此后永远 float）
    move v0, v8
    const/4 v9, 0x1
:pst_next
    goto :goto_19
```
**B. 保留 +∞ 哨兵，但让 v3 由 float 途径产生**
```
    sget-object v3, Ljava/lang/Float;->POSITIVE_INFINITY:Ljava/lang/Float;
    invoke-virtual {v3}, Ljava/lang/Float;->floatValue()F
    move-result v3          # v3 类型=float ✔
```
> 铁律：**同一寄存器在循环头汇合的两条边上必须是同一类型**；`const/high16` 只能当 int 用，想当 float 必须"float 渠道产生"。

## 四、★「如何正确编写」规范（交给电脑端，逐条照做）
### 4.1 寄存器纪律（本项目的头号杀手）
1. **按类型分区**（方法内自己画出表）：对象区 / int 区 / float 区 / long 区，**一个寄存器只服务一种类型**。
2. **循环携带变量专项检查**：循环头是所有回边的汇合点；把每个"循环头活跃寄存器"列出，逐条确认"每条边上的类型一致"。
3. **参数别名**：`.registers N` 时 `p0..pN` 占的就是最高的那几个 `v` 槽（例：`.registers 14` + 4 个参数 ⇒ p0=v10/p1=v11/p2=v12/p3=v13）。**绝不要 `move-result vN` 落在 p 槽上**（会把 this/参数冲掉）；`move-result` 必须紧贴 `invoke`。
4. **浮点常量陷阱**：`const`/`const/high16` 产出的常量**类型是 int**；把它与 float 定义混用同一寄存器（尤其在循环头）⇒ **必炸**。要么旗标法，要么用 `Float.xxx → floatValue()F` 得到 float。
5. **`const/4` 只覆盖 −8…7**；需要更大/float 位型用 `const`/`const/high16`（并注意第4条）。

### 4.2 控制流纪律
6. **标签自持**：新代码只用自己定义、带批次前缀的标签（`:as_*`/`:pst_*`…）；**绝不跳到猜出来的 `:cond_xx`**（baksmali 标签名＝代码偏移，装/反汇编会变 ⇒ 猜必错）。
7. **标签不得落在方法尾部**（异常处理器会流入 ⇒ Undefined ⇒ VerifyError）。
8. **真值表随身带**：每条新分支旁写"跳转含义 + 期望"，尤其：
 `if-ltz`＝<0 跳｜`if-gez`＝≥0 跳｜`if-gtz`＝>0 跳｜`if-lez`＝≤0 跳｜`if-eqz`＝=0 跳｜`if-nez`＝≠0 跳。
 本项目**已因方向写反出事 7 次**（R4c177 八处、F5/bestgate…），**关6 这次又是同一错**。
9. **项目既有语义先查权威点**：`autoStrikeOff`：**0＝开、1＝关**（老线门 AFM 8303 `if-nez ⇒ skip`）；不要凭直觉写。

### 4.3 流程纪律（缺一步都不算做完）
10. **写补丁**：锚点逐字唯一（含空行），`count==1` 否则拒写。
11. **汇编**：`java -cp "$CP" RunSmali <树> <out.dex>` ⇒ **必须看到 `result=true`**（失败也返回 0！）。
12. **跑门禁**：`toolchain/act/check_regtype.py <AirForceManager.smali>` 等（㉙–㊼）。**本项目的 ㉙ 已能抓"对象↔数值"混用**；**但当前它对"int 常量↔float"汇合是盲区**（本次就是从这个盲区溜过去的）⇒ 我会补 ㉙ 的检查项；在那之前请人工做 4.1 的第2条。
13. **反汇编自检**：用同一 dex 反汇编回来，**逐字比对新增方法**（标签会重编号，用"忽略标签名的比对"）确认没有夹带、没有猜标签。
