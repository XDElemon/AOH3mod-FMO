# 硬规则 · 交接口径 v1（任何 agent 动手前先读这一页）

> 由来：2026-09-21 发现「同一个模型、不同提示词」会导致同一个坑反复踩（如 PC 端那版出现
> **调用未定义方法 `a1LogT`**、**数组里把"长度 3"当成省号**、**对象/int 寄存器混用导致 VerifyError**）。
> 本文件把**能机器查的规则**全部写成条款；**违反即返工**，不辩论。
> 适用范围：本项目所有 smali 改动（`/tmp/w3a/smali`），无论谁来做。

## 0. 流程纪律（顺序不得颠倒）
1. **只读调研** → 出方案 → **用户拍板** → 才准动代码；
2. 改代码**只能用补丁脚本**（`/sdcard/GLG/历史23/*_patch.py`），**禁止手改 smali**；
3. 每个补丁脚本第一件事：`shutil.copy2(P, P + '.bak_<批次>')`；
4. 补丁脚本必须**幂等**（重复执行要能被 assert 拦住，不许叠加）；
5. 用户说「等一下 / 先别动」→ 立即停手，只做只读。

## 1. 寄存器与类型纪律（PC 端那版翻车的直接原因）
1. **一个寄存器只承担一种类型**：对象槽与 int 槽严格分开，禁止"这个寄存器先放 Set、再放 int"；
2. 需要"临时对象"时**多开一个专用寄存器**，别复用；
3. `.registers ≤ 16`（`p` 别名上限）；参数槽从尾部往前数：
 - 静态方法 N 个参数：`p0 = v(registers-N)`；
 - **不要**把 `p*` 当局部变量写（会踩参数槽）；
4. 段与段之间不要共享寄存器（"建立期/循环期/内层/派发期"分段分配，PC 端教训）。

## 2. 指令级硬约束
| 约束 | 说明 |
|---|---|
| **`invoke` 最多 5 个寄存器** | 超了必须 `invoke-*/range`，且 `/range` 要求寄存器**连续**。想要 6 个参数？**改方法签名**（对象参数能改 int 就改 int） |
| **数组一律 `.array-data`** | 禁止"两段 `filled-new-array` + `arraycopy`"拼接（长度常量极易被当成元素） |
| **`const/4` 只能 −8..7** | 大常量用 `const/16` / `const` |
| **private 方法必须 `invoke-direct`** | 用 `invoke-virtual` 会 VerifyError |
| **`invoke` 前先确认目标方法存在** | 见 §3 |

### 条件跳转语义表（**必须按此表核对，不许凭记忆**）
| `-z` 版（与 0 比） | 含义 | 双寄存器版 | 含义 |
|---|---|---|---|
| `if-eqz` | **==0 → 跳** | `if-eq` | == → 跳 |
| `if-nez` | **!=0 → 跳** | `if-ne` | != → 跳 |
| `if-ltz` | **<0 → 跳** | `if-lt` | < → 跳 |
| `if-gez` | **>=0 → 跳** | `if-ge` | >= → 跳 |
| `if-gtz` | **>0 → 跳** | `if-gt` | > → 跳 |
| `if-lez` | **<=0 → 跳** | `if-le` | <= → 跳 |

> 本项目已因"极性写反"翻车 **9 次**（含一次 `if-ltz` 当成 ">=0 才跳"，一次 `if-eq` 写成 `if-ne`）。
> **每个新方法的每条条件跳转，都要在补丁脚本里用真值表断言把期望的指令文本钉死。**

## 3. 方法定义纪律（PC 端那版翻车点）
1. **禁止调用"本类未定义"的方法**——`a1LogT` 就是这么炸的（调用 7 次、全类没有定义 ⇒ 运行到即 `NoSuchMethodError`）；
2. 新方法**必须与调用它的补丁同一批落地**，不许"先调用、下批再定义"；
3. 复用日志/工具方法前，**先在文件里 grep 出它的定义与签名**，再决定调用参数；
4. **每批必跑静态门禁**：`python3 /sdcard/GLG/历史23/check_calls.py <AirForceManager.smali>`
 → 必须输出 `✅ 无「调用未定义」问题`，否则**禁止打包、禁止装机**。

## 4. 每批必跑的门禁（顺序固定，全绿才准装机）
```
① 补丁脚本自检     : 真值表断言（正向 + 反向）+ §3 静态门禁
② 备份             : .bak_<批次>
③ assemble         : bash assemble.sh <批次>          → result=true
④ arity            : python3 check_arity.py <树>       → BAD=0
                      ⚠️ 全树版脚本偶发卡死；卡死则改跑目标目录版并记录
⑤ 八件套           : bash verify.sh <新dex> <对照dex>  → Invoke/Regs/Init/Range BAD 合计=0
⑥ 打包             : bash build.sh <批次>
⑦ 装机             : bash install.sh <批次> --yes      → DEX_MATCH=1 且 APK_MATCH=1
                      （装机依赖设备侧轮询器；心跳停了先拉起来：
                       nohup sh /sdcard/GLG/历史23/r6s5/devbridge_poll.sh >/dev/null 2>&1 &）
⑧ 启动自检         : 进程存活 + VerifyError 计数=0 + crash 缓冲空
⑨ 抓样             : bash capture.sh <批次> → 对账探针
⑩ 归档             : 专档登记 → 设计v2 章节 → 计划书更新 → 补丁存档 r6s5/ → 留回滚点 apk → 刷新交接文档
```
**八件套抓不到、只有真机会炸的错**（务必靠 §3 门禁 + 启动自检兜住）：
`VerifyError`、`IllegalAccessError`、`NoSuchField`、`NoSuchMethodError`。

## 5. 探针/日志纪律
1. 每步**一行日志**，失败必须一眼看出卡在哪一条；
2. 出口码统一编号并登记（例：自动打击 `k=0 ok / 1 无空闲师 / 2 航程外 / 3 无可用机 / 4 限流 / 5 目标省无效 / 6 目标是自己 / 7 异常态`）；
3. 探针**先自证**（打印已知非空/已知为真的对照项），防止"探针自身 bug 被当成数据"；
4. 日志文件会疯长（本设备曾到 **1.38 GB**）：批量验证后**及时截断**。

## 6. 数据来源纪律
1. **配置一律编译期常量**（本项目"读文件配置"路线 13 批全败：scoped storage 下 `lastModified()==0`、`internal` 抛异常、`FileManager.loadFile` 静默返回空）；
2. 需要游戏数据（邻接、建筑、机型…）时，**以 APK 自带 assets 为准**，并**双向并集**核对（例：邻省＝`ProvinceNeighboringProvinces*.json` 里 pid/wp 两向取并集）；
3. 结论**必须闭环**：dump 现场值或正反例回放，不许"看起来像"。

## 7. 交付物（缺一不可）
补丁脚本 ｜ 门禁日志 ｜ 抓样文件 ｜ 装机核验（DEX/APK MATCH）｜ 启动自检 ｜ 回滚点 apk ｜ 文档登记。

## 追加条款（r5b014 起生效）

### ① 条件跳转语义表（唯一权威，写代码时必须引用，不许凭手感）
```
if-eqz  v : v == 0（null/false/0）才跳
if-nez  v : v != 0（非空/true/非零）才跳   ← 判"为空则跳过"必须用 if-eqz
if-ltz  v : v <  0 才跳        if-gez v : v >= 0 才跳
if-lez  v : v <= 0 才跳        if-gtz v : v >  0 才跳
if-eq / if-ne      : 两寄存器相等 / 不等 才跳
if-lt / if-ge / if-gt / if-le : vA < / >= / > / <= vB 才跳
```
每处条件跳转旁边必须写明"命中才跳"的意图；补丁里必须带**反例断言**（写成反向就报错）。

### ② 探针纪律：一律无分支
探针（AIRDBG 日志）**不得包含条件跳转**。需要打印"是否为空/长度"时用
`String.valueOf(obj)`（null 会打 `null`、非 null 打对象本身）或直接打对象，
不要手写 if 分支——分支落点算错会得到自相矛盾的日志，浪费整轮排障。

### ③ 每批必跑的三条门禁 + 一条纪律
```
python3 toolchain/act/check_branch.py  <类>.smali <方法>   # 方向可疑=0 且 探针内分支=0
bash    toolchain/act/check_dangling.sh <本批 apk>          # 真悬空 = 0
python3 check_calls.py <类>.smali                           # 无「调用未定义」
```
纪律：**当静态分析给出"不可能"结论、而运行时读数与之冲突时，先怀疑探针/断言本身**
（先按 ProbeCode2 反汇编装机 dex 核对指令，再谈游戏）。

### ④ 寄存器边界（血泪）
- `.registers` **上限 16**（`mul-float/2addr` 等第二操作数只有 4 位）；抬高前先确认不越界。
- 参数占 `v(registers-参数个数) .. v(registers-1)`；**插入局部变量前先算 locals 区间**，
  否则会把 `p0` 覆盖成 int ⇒ 真机 `VerifyError`。
- 寄存器不够时优先"现取/复用"，不要盲目抬 `.registers`。
