## 一、目标与验收（一句话）
让空军从"四个机型（战斗机/截击机/攻击机/轰炸机）"扩展为 **每国 × 4 机型 × 4 代（3/4/5/6 代）** 的机队体系：
玩家能看到、能造、能区分**不同国家的不同代**战机（贴图 + 名称 + 参数 + 造价），并让 AI 也会按代际补机。

**验收（可证伪）**：
- 机场建造列表里，同一机型按**代数**分档（例：歼-7/歼-8/歼-10/歼-20 式命名，各国各自一套）；
- 选中/编队/战斗时**贴图正确**（不再黑方块、不再各国共用一张图）；
- 参数按代际递增（速度/航程/机动/载弹/雷达），且**造价与建造时间**同步；
- 旧存档可读（新字段缺省 = 3 代）；
- 门禁：≥6 断言 + ≥3 负样本（代际表读值、贴图映射、缺省回退）。

## 三、数据模型设计（草案，待第二轮钉死）
### 3.1 机型基座不变
现有：`AirUnit$AirType = {FIGHTER, INTERCEPTOR, ATTACKER, BOMBER}`（另有运输等），**保持不动**（避免动到任务/拦截/空战链）。

### 3.2 代际作为"型号变体"
参考 ICBM 的 `ImprovedBy "Generation_N_Aircraft"` 思路，但**我方不引入 ICBM 的脚本机制**，而是：
- 新增**代际维度**：`gen ∈ {3,4,5,6}`（缺省 3，保证旧档兼容）；
- 每（国家, 机型, 代）→ 一组：**贴图 + 显示名 + 参数**（速度/航程/机动/载弹/雷达/造价/建造时长）；
- **参数来源**：优先复用"我们已有的数值体系"（`Airport.p1bCost`、`p1bPickAffordable`、建造时长、`MaxPayload` 等），避免新增第二套平衡体系。

### 3.3 国家区分（核心难点）
需要第二轮调研确认**选择点**：玩家/AI 建造时如何决定"造哪国的哪一代"：
- 方案 α：**按文明 ID 查表**（每个 civID → 一份机队表；适合"历史国家"）；
- 方案 β：**按科技/年份解锁**（`RequiredTechID` + 年份门槛；与既有"档3生产门控"C1 思路一致）；
- 方案 γ：α+β 混合（国家定外型与基础参数，科技定可用代数）。
> 我倾向 **γ**：国家决定"长什么样、叫什么"，科技/年份决定"能不能造第几代"。

## 四、必须第二轮调研钉死的问题（技术前提）
1. **建造入口**：`Airport.startBuild(AirType)` / `p1bPickAffordable` / AI 的 `updateAIBuildUp` —— 现有链路只认 `AirType`（4 值），要扩成"机型+代"，需确认最小改动点（是加参数、还是加"当前代"字段）。
2. **贴图映射**：`Images`/`InitGame` 如何按（国家,机型,代）取图；现有 `AirUnitlmages` 命名规则是什么；需不需要预热加载。
3. **存读档**：机场/任务里"机型"是怎么序列化的（枚举序号？字符串？）；新增"代"字段的**缺省值**与旧档兼容路径。
4. **AI 侧**：`updateAIBuildUp` 选型时要按代际权重（同 r6d086 的 `ai_w_*` 权重一起扩展）。
5. **显示名/本地化**：名称放哪里（`Airunit` 文本表？），是否需要"国名+代数"自动拼接（例：`中国 · 第4代 战斗机`）。
6. **性能/包体**：96 张 PNG 的体积与显存（建议统一 256×256 或 128×128，PNG 压缩后 <30KB/张）。

## 六、风险与对策
| 风险 | 对策 |
|---|---|
| 扩展 `AirType` 会牵动任务/拦截/空战链（我们吃过亏） | **绝不动 `AirType`**，代际只作为"型号变体"旁挂 |
| 建造入口是热点方法 | 遵循世界书：**新增独立方法 + 顶部单行挂点**；禁止内联探针 |
| 贴图缺失 → 黑方块 | 打包铁律：素材与 dex **两步打包 + 双指纹核对**（`ringSel84`/新素材计数 ≥1） |
| 96 张图包体膨胀 | 统一规格 + 压缩；必要时按"每国主力机型"裁剪 |
| 旧档崩 | 新字段缺省 = 3 代；上线前做旧档读入回归 |
