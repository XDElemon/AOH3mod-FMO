# 一、本次新增的三条关键事实（决定方案可行性）

### 事实 1：现有 99 节点是「6 车道 × 42 列」的**编织链**，行号没有领域语义

- 结构：每一列（`TreeColumn 0..41`）放 1~3 个节点，前置指向前 1~2 列的节点；`TreeRow` 只在 0..5 之间跳动，纯粹是"编织走线"，**不代表兵种/领域**。
- 时间语义：列 = 年代（col0 = Library，col41 = FutureTechnology 可重复节点），成本从 250 平滑爬到 20000。
- 结论：**要"分带"，就是把"行"从走线改造成领域带**（这是全部方案的共同基点）。

### 事实 2：**行/列没有硬上限**，可以自由扩

- `TechnologyTree.iTechnologyWidth/Height` 取自 `techBlue` 贴图尺寸；布局 = `TreeColumn × (宽+PADDING_X=100)`、`TreeRow × (高+PADDING_Y=15)`，UI 是**可滚动的画布**。
- 结论：**8 带、更多列在技术上成立**（唯一待验证项：行 >5 时纵向滚动的可用性 —— 见 §五 待验证）。

### 事实 3：钢四的"节奏"来自 **门槛**，不是来自成本

| 钢四战斗机链 | research_cost | start_year |
|---|---|---|
| early_fighter | 2 | **1933** |
| fighter1 | 2 | **1936** |
| fighter2 | 2 | **1940** |
| fighter3 | 2 | **1944** |
| jet_fighter1 → jet_fighter2 → supersonic_fighter1 | 同上 | 喷气机还带 `allow = { is_special_project_completed = sp:sp_air_jet_engine }`（**需特殊项目**） |

- **成本几乎不变，节奏全靠年份门槛 + 前置链**；`early_fighter` 还一次分叉出 `fighter1 / CAS1 / naval_bomber1`（**主干 + 分叉**）。
- 对我们的意义：**"对齐节奏"= 对齐"门槛结构"**。游戏没有 start_year ⇒ 只能用**前置链长度 + 成本爬升**模拟（纯资源），或者改码加年份判定（不推荐，见 §四）。

# 二、三条决策轴（方案 = 在这三条轴上取值）

| 轴 | 取值 | 说明 |
|---|---|---|
| **轴 1：带粒度** | ① 6 带 ② 8 带 ③ 11~16 带 | 带＝行＝领域。带越多越像钢四的 folder 页签，但每带的横向列预算越紧 |
| **轴 2：时间轴起点** | ① 保留全史（列 0..41，古代节点仍在，靠**开局解锁**跳过） ② 压缩为 2000+（列 0 = 2000 年，删/藏古代段） | 2000 年开局 mod 的"该不该让玩家看见 Hoplites" |
| **轴 3：空军档数** | ① 4 档（三/四/五/六代，**匹配已入库的 64 张图**） ② 7 档（照抄钢四 early/1/2/3/jet1/jet2/supersonic） | 影响空军带节点数与图标量 |

**工程硬约束（所有方案都遵守）**：**只新增节点、不改动已有 99 个节点的 ID 与名称** —— 因为 `ScenarioTechnology*`（剧本开局解锁）、`SaveGameManager$Save_Civ_UnlockedTechnologies`（存档）都按 **ID** 记录，改 ID 会破坏存档与剧本。

# 三、四个可选方案（详细）

## 方案 0｜空军试点（1 批，风险最低）

**做法**：不碰任何现有节点，只在列 42~51、行 4 之后新增 **16 个空军节点**（ID 99~114），四型各 4 档；同时把四型 `AirXxx.json` 各扩成 4 档并写 `RequiredTechID`。

| 机型（4 条链） | 三代 | 四代 | 五代 | 六代 |
|---|---|---|---|---|
| 截击 Interceptor | Gen3 (col42) | Gen4 (col45) | Gen5 (col48) | Gen6 (col51) |
| 战斗 Fighter | 同上 | 同上 | 同上 | 同上 |
| 攻击 Attacker | 同上 | 同上 | 同上 | 同上 |
| 轰炸 Bomber | 同上 | 同上 | 同上 | 同上 |

- **前置**：三代的 `RequiredTech` = 现成的 ID 94（FutureTank，col40 尾段）；同型四代←三代←…… 逐档递进。
- **成本**（纯资源，对齐现有爬坡）：三代 11000 / 四代 13000 / 五代 16000 / 六代 20000。
- **AI 权重**：新节点 `AI: 8`（现全树多为 5；调高让 AI 真的会点）。
- **图标**：可先用现有 2 张（0/1 号图）→ 之后单独一批补 16 张（× 3 画质档 = 48 文件）。
- **玩家看到**：科技树最右端多出"四条并行的空军升级链"，四型飞机各自从三代爬到六代；**编制卡片图/名称随后可按档变化**。
- **验收**：①四型单位在开局只能造三代；②研究完四代节点后能造四代；③AI 国家在同一节奏下解锁。
- **回退**：删 16 个节点 + 还原 4 个 json。

## 方案 1｜6 带保留制（3 批，改动小）

**做法**：把 `TreeRow 0..5` 定义成 6 条领域带，**保留全部 99 节点的 ID / 名称 / 成本 / 前置**，只重排 `TreeColumn/TreeRow`，让每条带内的节点沿列单调推进；再在空军带补 16 个新节点。

| 行 | 领域带 | 主要承接现有节点 |
|---|---|---|
| 0 | 步兵 / 人力 | Infantry, EliteInfantry, Rifleman, LineInfantry, Musketter, FutureInfantry… |
| 1 | 装甲 / 骑兵 | Horseman, Knight, EarlyTank, Tank, MediumTank, HeavyTank, MainBattleTank, FutureTank… |
| 2 | 经济 / 社会 | Library, Temple, Bank, TaxOffice, University, SolarFarm, DigitalCurrency… |
| 3 | 火炮 / 支援 | Bowmen, MachineGunner, Howitzer, MLRS, FutureArtillery… |
| 4 | **空军** | EarlyFighter, Fighter, Bomber, FutureFighter ＋ **新增 16 节点** |
| 5 | 海军 / 工业 | Railways, Factory, Mine, MilitaryBase… |

- **代价**：纯资源；但**6 带偏粗**（步兵/支援/装甲挤在 3 带），像"钢四的简化版"。
- **风险**：重排坐标会改变"视觉走线"，前置关系不动 ⇒ 不会影响可研究性（最安全的一档）。

## 方案 2｜8 带细分制（4~5 批，**推荐**）

**做法**：把带扩到 **8 条**（`TreeRow 0..7`，需先验证纵向滚动），原 99 节点按语义搬入对应带，前置改为"**带内前一列**"，允许 `RequiredTech2` 做**跨带前置**（这正是游戏 2 前置字段的用武之地）；空军带 16 节点同方案 0。

| 行 | 领域带（≈钢四 folder） | 说明 |
|---|---|---|
| 0 | 步兵 | infantry.txt 的 60 项 ≈ 本带主干 |
| 1 | 支援 / 特种 | support.txt 的 41 项 |
| 2 | 装甲 | armor/NSB_armor |
| 3 | 火炮 | artillery |
| 4 | **空军** | air_techs + BBA |
| 5 | 海军 | naval / MTG |
| 6 | 工业 | industry |
| 7 | 电子 / 社会 | electronics ＋ 社会类 |

- **视觉**：8 条平行横向带，每条从左到右推进，**单页内呈现"钢四式分区"**（仍无页签，但分区感成立）。
- **代价/风险**：前置重排涉及"可研究性"，必须真机逐带验收；每批只搬 2~3 带。
- **收益**：**这就是"今后各方各面"的骨架** —— 以后新增任何领域内容（雷达、导弹、核、航天）都直接挂到对应带，不再破坏全局。

## 方案 3｜年代阶梯制（6+ 批，改动最大）

**做法**：在方案 2 上，把列从"0..41 的连续轴"改成**明确的年代台阶**（例：col0=2000、col3=2005、col6=2010、col9=2015、col12=2020、col15=2025、col18=2030、col21=2040、col24=2050…），带内**强制"同带上一台阶"**为前置；开局解锁截止在 2000 列；古代段（Library/Hoplites 等）**要么删、要么整体挪到"史前带"并开局解锁**。

- **玩家看到**：科技树真正变成"**年代阶梯**"——2000 年只能研究基础，2010 年后四代机才登场，2020 后五代，2030 后六代。
- **代价**：最大。需要重定整棵树的节奏、重做开局解锁清单（ScenarioTechnology）、AI 权重全线复查。
- **风险**：高（"年份门槛"仍是**软的**——因为游戏没有 start_year，只能靠前置链 + 成本；玩家若猛点前置仍可能提前拿到，故它是"节奏模拟"而非"硬门槛"）。

# 五、开工前必须验证的一件事

**行 >5 的纵向滚动可用性**：现有全树只用到 `TreeRow 0..5`。方案 2/3 要用到 `TreeRow 0..7`。
- 验证方式（1 个小批次）：把某个不痛不痒的节点临时挪到 `TreeRow 7`，装机看一眼**能不能滚到**。
- 若不能：退化到"6 带 + 每带内分两段"或在带内用"列错位"模拟。
- **建议：这个验证放进方案 0 那一批一起做**（同批不影响验收）。
