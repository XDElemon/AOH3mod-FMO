## 一、调研实证（树为真值，`/tmp/w3a/smali`）

### 1. 现在的空战伤害公式 —— **只有一行**
`.method private airCombatOne(Airport;AirUnit;I)V`（AirForceManager:3143）内：
```
v6 = 目标.hp
v9 = 攻击方.airAttack
v9 = v9 * 0.2f          ← const v5, 0x3e4ccccd (0.2f)
v6 = v6 - v9            → 目标 hp -= airAttack * 0.2
```
⇒ **无命中判定、无防御参与、无代差概念**：任何飞机打任何飞机都是"必中 + 固定比例伤害"。
⇒ 这正是"老机也能咬下先进机"的根因，也是**代差压制的唯一落点/最佳落点**。

### 2. 飞机数据表是现成的 —— `AircraftDataManager`
```
.field public static types:[Laoc/.../AircraftDataManager$AircraftTypeData;   ← 机型数据数组（按 typeID 索引）
.method public static load()V                ← 载入数据表
.method public static applyType(AirUnit;)V   ← 把表数据应用到某架飞机
```
`AirUnit` 侧对应 `.field public typeID:I`（赋值点在 `AircraftDataManager:113`）。
⇒ **C2 的"数据表"不用另造**：扩展 `AircraftTypeData` + `load()` 即可承载（国, 代, 机型）。

### 3. `AirUnit` 已有的可用参数（全部是 float/int 字段）
`hp/maxHp, airAttack, groundAttack, defense, agility, speed, combatRadius, radarRange, stealth, ecm, maxPayload, fuel/fuelConsumption, typeID, type(AirType)`
⇒ 代际差异可以**同时**体现在：airAttack / defense / agility / speed / radarRange / stealth / ecm / maxHp / maxPayload / 造价。

### 4. 游戏**本来就承认"代"** —— 只是只用在了导弹上
`AirMission.missileCountForGen(int gen)`：
```
gen <= 2  → 0 发
gen 3~4   → 2 发
gen >= 5  → 4 发
```
`missileRangeForGen(gen)` / `missileHopsForGen(gen)` 同理；调用点 4882 / 5191 / 5576 / 5626 / 6257。
⇒ 说明"gen"已经是引擎里的整数维度；**待钉**：这几个调用点传入的 `gen` 取自哪个字段（疑为 `typeID` 或 `AirUnit` 的某代数字段），确认后 C2 可直接复用它，不必新造。

## 二、设计：代差压制（方案）

### 2.1 核心公式（单点改动，风险最低）
```
掉血 = 攻击方.airAttack × 0.2 × K( 攻击方代 − 防守方代 )
```
`K` = 代差系数表（**建议初值，可调**）：

| 代差（攻−防） | K | 效果 |
|---|---|---|
| 0（同代） | 1.0 | 正常 |
| +1（先进一代） | **3** | 明显优势 |
| +2 | **10** | 碾压 |
| +3 | **30** | 屠杀（例：6 代打 3 代） |
| −1 | 1/3 ≈ 0.33 | 吃亏 |
| −2 | 0.1 | 打不动 |
| −3 | 0.03 | **"绝对打不过"** ✅ |

⇒ **"三代对四代绝对打不过"由此成立**：3 代打 4 代只能造成 1/3 伤害，而 4 代打 3 代是 3 倍伤害，交换比约 **1:9**；若再叠上 4 代更高的 airAttack/血量，实际交换比会在 1:20 以上。

### 2.2 可选增强（后续批次，不在首版）
- **A. 命中/闪避代差**：引入 `agility`/`ecm` 影响"是否命中"（现在是必中）⇒ 让"隐身/电子战"有意义；
- **B. 先敌发现**：`radarRange` 代差决定"谁先开火"（首轮额外伤害）；
- **C. 同代不同国微调**：中/美/俄/欧同代之间按型号微调（如 F-22 vs J-20），默认 1.0 不动。

### 2.3 与既有体系的兼容（不变量）
- **不动** `AirType` 四值枚举（任务/拦截/空战链都挂它）；
- **不动** 现有的 `×0.2` 基底（只乘系数）⇒ 不引入第二套平衡；
- 代差系数表**集中一处**（独立静态方法 `genFactor(II)F`），便于调参与门禁断言；
- 缺省：若某机代不明（旧档/未登记）⇒ **视为同代（K=1.0）**，保证旧档不炸。

## 三、需要你确认/讨论的点
1. **K 表数值**：3 / 10 / 30 是否合你的"绝对压制"口味？（可更狠，如 5/25/125）
2. **是否要"代差同时改数值"**：即 4 代机本身 airAttack/hp 也更高（叠乘），还是**只靠代差系数**拉开？
3. **负代差是否真的这么低**：会不会导致"3 代机完全打不动 6 代"→ 玩家觉得无意义？（可设下限，如最低 0.1）
4. **AI 是否受影响**：按你之前"AI 共享"的口径 ⇒ AI 的机也吃同一张表（默认是）。
5. **是否把"代"写进 `AircraftTypeData`**（推荐）还是新挂 `AirUnit.gen` 字段（改动更大但更直观）？

**用户锚点**：
- 歼-8（3 代）对 F-22（4 代）＝**八换一**（−1 代 ⇒ 交换比 ≈ 8:1）
- 有了歼-20 后，F-22 侧"**18 也换不了一**"（−2 代口径 ⇒ 交换比 ≈ 18:1）

**换算关系（关键）**：双方参数相同时，
```
交换比(A 打 B) = K(+n) / K(−n)
```
⇒ 要让 −1 代 = 8:1、−2 代 = 18:1，K 表须满足 `K(+1)/K(−1)=8`、`K(+2)/K(−2)=18`。

**K 表 v2（标定后，建议采用）**：

| 代差 | K（受伤侧系数）| 进攻侧 K | 交换比 | 说明 |
|---|---|---|---|---|
| −3 | 0.10 | 6 | ≈ 60:1 | 三代机撞六代机（无意义） |
| −2 | 0.222 | 4 | **18:1** ✅ | 用户锚点② |
| −1 | 0.375 | 3 | **8:1** ✅ | 用户锚点①（八换一） |
| 0 | 1.0 | 1.0 | 1:1 | 同代 |
| +1 | 3 | 0.375 | 8:1 | 先进一代 |
| +2 | 4 | 0.222 | 18:1 | 先进两代 |
| +3 | 6 | 0.10 | 60:1 | 先进三代 |

> 注：K(+n) 与 K(−n) **不互为倒数**（如 3 × 0.375 = 1.125 > 1）⇒ 代差本身略微偏向新时代机，符合直觉。
> 全部集中在一个静态方法 `genFactor(II)F` 内，调参只改这一处。
