# 设计逻辑 · B4 研究完成事件（r6d261）——11 项

> 2026-10-11｜《终序千禧》AI 空军 MOD｜类型：代码+资源批（v1）

## 1) 版本号 + 一句话定位
r6d261：给"研究完成的那一刻"装上**事件钩子**——玩家每研完一个自家空军节点，就会触发一次"航空技术突破"事件（钢四 `on_research_complete` 的近似开端）。

## 2) 设计目标
- 玩家可见的问题：研究完成是"静默"的——解锁换代，但没有"完成时刻"的反馈与可挂载点。
- 上层意图：为"完成后效果"（核/殖民/出海这类**硬开关**）铺好一条通用通路；本批先交付"通路 + 演示事件"。

## 3) 设计规则与判定顺序（人话）
研究完成瞬间（进度≥成本）依次判定：
1. **若 科技<32 或 >74** → 不触发（旧科技/其它段照旧）；
2. **若完成国 ≠ 玩家国** → 不触发（v1 玩家专属；AI 不受影响）；
3. 否则：找事件（按 id 缓存）→（首次）把标题/描述/选项从语言键**翻译成正文** → 加入"待决策事件"列表 → 调度一次**弹窗任务**；
4. 弹窗：若事件卡未在显示 → 播放提示音并弹出事件卡；玩家点选项 → 走游戏原生结算（给奖励 + 记录 + 关闭）；若一直不点，274 回合后按**选项 0**自动结算。

## 5) 状态与生命周期
- 完成 →（判定通过）→ 事件入"待决策"列表（同事件已有未决策卡时不重复入列）→ 弹窗 → 玩家决策/超时 → 结算 → 移除；再次完成 → 可再次触发。
- 全程**不改存档结构**；一切状态都在原生事件系统里。

## 6) 边界与不变量
- 对齐：复用**原生事件系统**（不修改 EventsManager / 不打补丁到事件引擎）；弹窗任务镜像原生写法；
- 明确不动：AI 文明（v1）、旧 32 科技、其它事件与列表顺序；
- 事件设 `possible_to_run=false`（+保险触发块），**不会被系统的自动扫描点燃**，只由钩子点火；
- 失败安全：钩子整体 try/catch——任何异常都不影响研究主链。

## 7) 玩家可感知的表现
- 正常：研发完成瞬间右侧弹出事件卡「航空技术突破」+ 音效；二选一结算；再研再弹。
- 异常样子：完全不弹（查"事件注册/资源缺失"）；弹了但文字是方括号键名（语言键缺失）。

## 8) 失败与回退
- 正常不触发：旧科技、他国（AI）、非 32..74。
- 回退：重装 r6d260。

## 9) 验收标准（可证伪）
- 研完任一自家节点 → 卡弹出；选项结算（研究点或月遗产其一）；再研再弹；旧科技/AI 不弹；无崩溃。
- **待用户实测**。
