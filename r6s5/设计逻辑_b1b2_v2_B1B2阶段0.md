# 设计逻辑 · b1b2_v2（阶段0 = B1+B2 联合）

> 2026-10-10 ｜ 类型：资源层批次（未动一行代码，dex md5 `02050d5b…` 不变）｜ 状态：**验收通过**

## 1) 版本号与一句话定位
**b1b2_v2**：把 AoH3 的科技树与剧本体系"裁到 2000/1936 起点"的阶段0联合批次（B1 1930 大清理 + B2 剧本与战役清理 + v3 军事基地热修）。

## 2) 设计目标
- 玩家可见的问题：原版 99 个科技节点含 68 个 1930 前节点；24 个剧本含 18 个 1930 前剧本 —— 而本 MOD 起点在 2000/1936。
- 上层意图：删古代、立公共根、全引用重挂、剧本只留现代、政体脱离科技门槛、**让每个保留科技都"有内容"**。

## 3) 设计规则与判定顺序（若…则…）
**a. 科技树**
1. 若 `TreeColumn ≤ 26` → 删除（68 个，含特例 96）；
2. 否则保留（67–95、97、98，共 31 个，保持原顺序）；
3. 新根：以旧 0 结构复制为 `ID0 = ModernTechFoundation`（col26、row2、cost250、无前置）；
4. 保留节点新 ID = MAP：67→1 … 95→29、97→30、98→31；**仅**改 ID/前置三字段，其余逐字符不动。
**b. 前置映射（每个 RequiredTech / RequiredTech2）**
① -1→-1 ｜ ② ∈保留集→MAP ｜ ③ ∈被删集（≤66、96）→0 ｜ ④ 双前置转换后相同→第二个置 -1 ｜ ⑤ 越界/非整数→整批 BLOCKED。
**c. 引用层**：仅白名单域（units / buildings / laws / advantages / resources）的"独占一行、整数或整数数组" RequiredTechID 参与改动；数组长度/格式保持；其它域（政体/空军表/剧本）只登记。
**d. 政体**：20 处 `REQUIRED_TECHNOLOGY` 全部→**-1**（=跳过科技门槛）。
**e. 剧本**：`Scenarios.txt` 只留 6 个；18 个旧剧本目录删除；6 剧本 `CivDefault_Technology` 按 MAP 重算；每文明 `TechnologyID`：≥0→MAP（缺失兜底 0）；`==-2`（DEFAULT 哨兵）保持；-1 保持。
**f. 军事基地热修**：建筑 `MilitaryBase` 门槛 `[0]→[10]`（由"军事基地"科技解锁）。
**g. 行尾保真**：按文件探测（CRLF 还原 / 纯 LF 保留 / 混合仅定点插行）。
**h. 失败即阻断**：任何锚点/唯一性/越界不满足 → 非零退出，不留"半成品可发布"。

## 5) 状态与生命周期
实体=科技节点 / 剧本 / 政体引用 / 建筑门槛。
流程：源快照冻结 → 生成候选（台账）→ 联审（v1→v2→v3）→ 打包（去签名→按前缀删除→注入→zipalign→签名）→ 装机 → 实测 → 验收。
研究态机制：`UnlockTechnologies(I)`=置 I 与其**祖先链**；建筑可建=门槛科技已研究（`lTechUnlocksBuildings` → 研究后 `addTechnology` 复制进可建列表）。

## 6) 边界与不变量
- 对齐既有机制：负值跳过门槛；下标语义（`CivDefault_Technology` / `TechnologyID`）；`Key = Value` 与 CRLF/LF 保真。
- 不修改：smali/dex、单位条目与档位、取图字段、数组长度、非白名单字段、其它语言包行。
- 必须成立：32 节点 0..31 连续；引用值域 ∈[-2..31]；剧本=6；政体 20 处 -1；无悬空引用。
