# 【设计逻辑】r5c046 —— AI 轰炸/打击"派发闸门细化 + 选靶智能化"（P2a）
版本：**v2（按代码逐条核实后修订，2026-09-25 15:24）** ｜ 基线：r5c045
产物：dex `1eaf9ccf…` / apk `2435034e…`（已装机，独立核验通过；**代码未因本次核实而改动**）

## 1) 版本号 + 一句话定位
**r5c046 = P2a**，动的是"**AI 空军的派发层**（谁去打谁、同时打几个、每回合打几次）"。
达成：把树里**已有但从未真正启用**的两条 AI 打击智能线接通，并给它们装上"军事建筑优先 + 经济人口排序 + 并发上限 + 难度频率"。

## 2) 设计目标
- 玩家可见问题：**AI 会空袭但"打得笨"**（10% 概率 + 航程内**均匀随机**挑一个省，无优先级、无上限、无难度差异）。
- 上层意图：**让 AI 真的会用自己的空军**（口径 A：引擎"机场模式驱动"派发补智能）；**难度越高，AI 空军越凶**。

## 3) 设计规则与判定顺序（已按代码逐字核对）

**A. 先决定"谁在跑"**
1. 该文明 == 玩家自己 ⇒ **智能线整体不跑**（引擎既有门 `strikeTick_A1` 跳过玩家）；
   玩家自己的机场若设为"AI 模式"，仍走**旧的 10% 随机逻辑**（本批不动）。
2. 非玩家（AI 文明；含观战/无玩家局面）⇒ 跑智能线；其中的**旧 10% 随机轰炸被关闭**
   （关闭点在**战时分支**：`isAtWar` 为真之后、选靶之前；**和平分支与概率门原样保留**）。

**B. 每个回合、每个 AI 文明，两条线各走一遍**（`update(civID)` 内：先轰炸线，再攻击机线）

**B-1 轰炸线（战略轰炸）**
3. **K 门**：该文明 `STRATEGIC_BOMBING` 在飞（未结束）**≥ 3** ⇒ 本回合不再新增（探针 `nP2cap`）。
4. **FRQ 门**：本回合该文明**已新增轰炸数 ≥ `FRQ[难度]`** ⇒ 停止（探针 `nP2frq`）。
5. **每机场**：先摇骰 `rnd < P[难度]`，不中则跳过该机场（探针不另记，靠 `nP2frq` 观察总量）。
6. **候选过滤**（该机场，逐条顺序）：`航程内省` → 省对象非空且 pid 合法 → **非本国 且 与本文明处于交战**（`DiplomacyManager.isAtWar`）
   → **必须"已记录"**（`a1Known` 记录位 0x4；**未知省跳过**）→ **该目标在飞 ≥ 2 则跳过**（历史口径）。
7. **排序（每机场每回合只派 1 次，取最优）**：
   - **档**：有军事建筑 = 档 0（置顶）；无 = 档 1；档小者必胜；
   - **同档内**：`score = (int)(经济×10) + 人口总量/100`（负值归零）高者胜；
   - **同档同分**：**蓄水池随机**（第 n 个同分候选以 1/n 概率替换）。
   - 选中后交给派发器；派发失败（无空闲机师等）不计数。

**B-2 攻击机线（对地打击）**
8. **K 门**：该文明 `ATTACK_ARMY` 在飞 ≥ 3 ⇒ 本回合不再新增（探针 `nP2cap`）。
9. **候选**：航程内省 → **确有敌军驻扎**（`isEnemyArmyInProvince`，保留硬门）→ 情报时间戳有效且新鲜（≤6 回合，旧机制）。
10. **排序**：**师的数量多者优先** → 同一师数时**在飞少者优先**（分散）→ 距离档内随机。

**B-3 视野门（本批修正方向）**
11. **看得见（fog=false）⇒ 刷新情报记录 / 盖时间戳；看不见 ⇒ 沿用旧记录**（两条线各 1 条指令）。
    旧行为相反：只有"看不见"的省才会被记录 ⇒ **看得见的军建省永远进不了候选池**。

**C. 明确不动**：结算链、自动拦截、巡逻（和平期 AI 巡逻仍在）、玩家手动出击、任务工厂本体、存档字段。

## 4) 参数与阈值表

| 名称 | 当前值 | 单位 | 含义 | 调大 / 调小 |
|---|---|---|---|---|
| `K` | **3** | 条 | 每文明 × 每任务类型**同时在飞**上限（**轰炸线与攻击机线各判一次**） | 调大＝更能齐射；调小＝更克制 |
| `每目标上限` | **2** | 条 | 同一目标省同时可承接的**轰炸**任务（攻击机线本批**不加**该上限） | 调大＝集中炸一省 |
| `FRQ[难度]` | **[1,1,1,2,2,3]** | 条/回合 | 每文明每回合**新增轰炸**上限（VeryEasy→Legendary）；**只作用于轰炸线** | 整体上调＝AI 轰炸更密 |
| `P[难度]` | `base × [0.5,0.75,1,1.25,1.5,2.0]` | 概率 | 每个机场"是否尝试"的概率；**base = `GV_Air.AIR_AI_BOMB_CHANCE_AT_WAR`（0.33）**，若载入失败（≤0）则兜底 0.33 | 上调＝更多机场会尝试 |
| `tier` | 0=有军建 / 1=无 | 档 | 军事建筑＝**置顶档**（不再是硬门） | — |
| `score` | `(int)(经济×10) + 人口总量/100` | 分 | 同档内排序（经济:人口 = 1:1）；人口用**总量**而非"条数" | 经济权重↑＝更看重富省 |
| 师数（攻击线主键） | `Province.getArmySize()` | 师 | 该省在场**师的数量**（非团数） | 仅作排序主键 |
| 记忆新鲜窗（攻击线） | 6 回合 | 回合 | 旧有 `a1Gsee` 时间戳窗口（未改） | 调大＝更依赖旧情报 |

## 5) 状态与生命周期
- **无新实体、无新存档字段**：新增状态全是**运行态静态**（`a1PkTier/a1PkScore/a1PkN/a1PkPid/a1PkP/a1FrqTurn/a1FrqN/a1bDivBest/a1bDivNew`）。
- 任务仍是既有 `AirMission`：`createStrategicBombing` / `createAttackArmy` → 入 `activeMissions` → 帧级 `updateMissions` 推进 → 结束（COMPLETED/ABORTED）被移除。
- **K 的统计**：`activeMissions` 中"同文明 + 同类型 + 状态不是 COMPLETED/ABORTED"的条数。
- **FRQ 计数**：按 `Game_Calendar.TURN_ID` 绑定，回合号一变即清零（避免首回合后永久锁死）。

## 6) 边界与不变量
- **对齐**：引擎难度系统（`Game.difficultyID` + `NORMAL_ID`）｜既有建筑判据 `a1HasMil`（`Province.buildings → getBuilding() → GroupID==1`）｜`DiplomacyManager.isAtWar`。
- **不动**：结算链、自动拦截、巡逻（`updatePatrols`/`tryPatrolForAirport`）、玩家手动出击（`createMissionForClick`）、工厂本体、存档字段（`autoStrikeOff` 的落档名 `strikePaused` 未改）。
- **不变量**：玩家自己机场的"AI 模式"旧行为、和平期 AI 巡逻、任务创建/推进/回收路径均不变。
- **顺序约束（重要）**：K/FRQ 门必须插在 `a1Scan` 的 `a1Known`/`a1Gsee` 分配块**之后**——否则早退会让 `a1bPick` 的守卫失败，攻击机线静默失效。

## 7) 玩家可感知的表现
- **正常**：AI 空袭更集中、更讲价值——优先砸有军事建筑的省，其次富庶/人多；难度高时更频繁；不会一回合在同一目标上堆一堆任务。
- **日志（AIRDBG）**：`nA2L`（线 L 战时分枝被关次数）｜`nP2dif`（难度档）｜`nP2cap`（K 拦）｜`nP2frq`（本回合新增计数）｜`nP2mil`（选中省含军建）｜`nP2s pid/tier/score`。
- **异常表现**：AI 完全不出击（`nP2frq` 恒 0）／一回合狂派（`nP2cap` 不出现）／总挑穷省（`nP2s score` 明显偏低）。

## 8) 失败与回退
- **正常节流（不是 bug）**：`nP2cap`/`nP2frq` 出现计数；某回合 AI 不派发；低难度下 AI 很安静。
- **属 bug**：闪退；`nP2mil` 恒 0 且 `nP2s` 从不出现；玩家手动出击失效；AI 和平期巡逻归零。

## 9) 验收标准（可证伪）
1. `nP2mil` **出现**（`a=1`）——历史恒 0；
2. `nP2cap` 有计数 ⇒ K 真在拦（两条线各一路径）；
3. `nP2dif` 与开局难度一致；**高难度下 `nP2frq` 峰值 > 低难度**；
4. `nP2s` 中选中省的 `tier` 多为 0（有军建）或分数线最高档；
5. 玩家手动点省出击照常（含"和平时期不能轰炸敌国"提示）；
6. AI 和平期巡逻不归零；7. 无闪退、帧率无可见下降。

## 10) 变更清单摘要
关旧随机轰炸（**仅 AI 文明的战时分支**）｜K=3（两条线，按文明×任务类型，枚举对象比较）｜
FRQ+P（难度表 + `GV_Air` 基准 + 兜底 + `TURN_ID` 绑定 + 难度 clamp）｜
轰炸线：军建**硬门 → 置顶档**、经济+人口 1:1 同档随机、每机场每回合只派 1 次、"已记录"位由 0x2 改 0x4｜
攻击线：排序主键改**师的数量**（新 helper `a1DivCount`，内部仅一处 `getArmySize()`）｜
**视野门方向修正**（可见即刷新，两条线各 1 条指令）｜新增探针 6 个。

## 11) 风险与待办
- **风险 ①（强度跃迁）**：智能线首次真正启用，AI 空袭强度会有可见跃迁（原 10%/机场 → 每回合 ≤FRQ 条）。嫌太密/太疏只需改 **FRQ 表**与 **P 的 MULT 表**。
- **风险 ②（量纲）**：`score` 的经济是浮点、人口是整数，初版常数 `×10` 与 `/100`；**抓样后我按实测回填并告知**。
- **已知遗留（本批未纳，待你定）**：
  1. 攻击机的**半程重瞄**（`a1bRetarget`，扑空后就地重瞄）仍用旧键（在飞/距离），**未纳入"师数主键"**；
  2. 轰炸线的**记忆不衰减**（`a1Known` 记录位一旦写入长期有效）→ P2b（r5c047）；
  3. 旧 `nA4v` 探针随线 L 关闭**休眠**（代码保留）；
  4. **探针语义变化**：视野门翻转后 `a1bNvis` 由"不可见计数"变为"**可见计数**"（抓样判读按新语义）。
- **待办**：P2b 记忆衰减｜P3a 拦截机型定位重排｜P3b AI"打空/情报"表现｜P4 难度表扩展｜P5 清探针。

## 附三：行为与实现口径同步（按独立审核第 2 轮，2026-09-25 17:52）
> 本节**取代** §3-B1-6、§3-B3、§4、§9、§10 中与之冲突的措辞。

### 附三-1 候选资格（轰炸线，实际生效的链）
```
航程内省 → pid 合法/未越界 → Province 非空
        → 【记忆写入：无条件写 6(有军建)/4(无军建)】
        → 【&0x4 门：因刚写入 ⇒ 恒真】          ← G1 的有意后果
        → 目标国 civID 合法、≠ 自己、且与本文明交战
        → 每目标在飞 < 2
```
**口径**：候选资格 ≈「**在航程内且交战**」；"已记录"这道门在当前实现下不构成过滤。雾标志（`getFogDrawArmy`）**不参与候选**，仅为后续"打空/情报"表现预留。

### 附三-2 排序（轰炸线）
- **档**：有军事建筑 = **0**（置顶），无 = 1；**小者胜**（dex 已核）。
- **同档**：比 `score = (int)(经济×10) + 人口总量/100`（负值归零），**大者胜**。
- **同档同分**：蓄水池随机（第 n 个同分候选以 1/n 概率替换）。
- 冒泡出的"胜利者"进入派发；派发失败不计数。

### 附三-3 派发与上限（措辞更正）
| 项 | 更正后口径 |
|---|---|
| 频率上限 | **每文明每回合 ≤ `FRQ[难度]` 条轰炸任务**（`a1FrqN` 记账；超出则打 `nP2frq` 并中止该方法本次调用） |
| "每机场每回合只派 1 次" | ❌ 不成立。选靶是每机场各一次，但**发射机场由 `a1Dispatch` 自行选择**（列表头起第一个"有空闲师且航程含目标"的机场） |
| P 骰 | 每机场一次（`rnd < P` 才尝试）；但**可被 `a1Dispatch` 的机场重选绕过**（见 P2b 待办） |
| 攻击线新鲜度 | 时间戳**无条件盖=当前小时** ⇒ "≤6 回合新鲜"门不生效；候选取决于「确有敌军驻扎」 |
| 攻击线主键 | 师数多者优先 → 在飞少者 → 距离档随机（dex 已核） |

### 附三-4 验收措辞更正（§9）
- `nP2s tier`：应为 **0 或 1**，且**多数为 0**（有军建）；若恒 1 ⇒ 候选里没有军建省（或军建判据失效），属"待观察/需查"。
- 新增观测点 **`nP2pick`**：每机场打印选中 pid（-1=该机场没选到）⇒ 分辨"无候选"与"派发失败"。
