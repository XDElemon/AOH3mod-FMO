## 1) 版本 + 一句话定位
r5c046i 修的是 **AI 空军的"选靶"环节**：让轰炸线与攻击机线**第一次真的能选出目标**，从而真正起飞。
（上一版 r5c046g 的探针显示：入口在跑、每个机场都扫了，但**一个目标都没选上**。）

## 2) 设计目标
- 玩家可见问题：**AI 的轰炸机和攻击机从不起飞**（连派发都没发生，`nA1 ap=` 恒 0）。
- 上层意图：候选池不为空的前提下，让"军事建筑优先 / 经济人口排序 / 师数主键"这套选靶规则**产生一个胜利者**；
  在此之上 K=3、FRQ、P 骰才有意义。

## 3) 设计规则与判定顺序（人话）
**轰炸线（每 AI 文明每回合，逐机场）**
1. 若该文明在飞轰炸任务 ≥ K(3) ⇒ 整条线退出（`nP2cap`）。
2. 若 `TURN_ID` 变了 ⇒ 清零本回合派发计数（FRQ 记账）。
3. 对每个机场：
   3.1 若为**玩家自己的**机场且"自动打击"关闭 ⇒ 跳过；AI 文明机场**不看**该开关。
   3.2 摇骰：`rnd ≥ P` ⇒ 跳过该机场（`P = GV_Air.AIR_AI_BOMB_CHANCE_AT_WAR(兜底0.33) × 难度系数`）。
   3.3 取"航程内省份集合"（集合大小打探针 `nP2set`）。
   3.4 逐个候选：pid 合法 → 省非空 → **登记**（写"在航程内"标记）→ 目标国 ≠ 自己且**处于交战** → 该目标在飞 < 2 → 计算档与分。
   3.5 **排序（本版修正的核心）**：**首个候选直接成为当前最优**；之后 若"新档 < 当前最优档" ⇒ 采纳；
      若"档相同" ⇒ 比 `score`：更大 ⇒ 采纳；相等 ⇒ 蓄水池随机（第 n 个同分者以 1/n 概率替换）；更小 ⇒ 丢弃。
   3.6 机场循环结束后：`a1PkPid ≥ 0` 才继续（探针 `nP2pick`）；若本回合派发数 ≥ FRQ ⇒ `nP2frq` 并退出；
      否则派发；派发成功 ⇒ 计数 +1，并打 `nP2s pid/tier/score`。

**攻击机线（每 AI 文明每回合，逐机场）**
1. 在飞攻击任务 ≥ K(3) ⇒ 退出。
2. 对每个机场：开关（同 3.1）→ `a1bPick` 选目标 → `a1bPick` 返回 `pid ≥ 0` 才派发。
3. `a1bPick` 内排序：**主键 = 该目标所在省的"师数"，多者优先**；师数相等 ⇒ 在飞更少者优先；再相等 ⇒ 距离更近者优先（同档带内随机）。

## 4) 参数与阈值表
| 名称 | 当前值 | 单位 | 含义 | 调大/调小 |
|---|---|---|---|---|
| K | 3 | 条 | 每文明同时在飞的轰炸/攻击任务上限（两条线各自计数） | 大 ⇒ 同时打击面更广、更凶；小 ⇒ 更克制 |
| 每目标在飞上限 | 2 | 条 | 同一目标省的在飞任务上限 | 大 ⇒ 可叠打同省 |
| FRQ[difficulty] | [1,1,1,2,2,3] | 条/回合 | 该文明每回合新增轰炸上限 | 与难度挂钩 |
| MULT[difficulty] | [0.5,0.75,1,1.25,1.5,2.0] | × | 概率系数 | 同上 |
| P | base×MULT | 概率 | 每机场"是否尝试"的骰子（base 取 `GV_Air` 0.33，≤0 兜底） | — |
| score | `(int)(经济×10) + 人口总量/100` | 无量纲 | 同档内比大小 | 权重由这两个常量控制 |

## 5) 状态与生命周期
- 候选暂存（`a1PkTier/a1PkScore/a1PkPid/a1PkN`）**每个机场开头重置**，机场结束即被使用（无跨机场泄漏）。
- 记忆（`a1Known`）＝"该省在航程内被登记过"；竞态/时间戳（`a1Gsee`）在攻击线用于"情报新鲜度"，
  本版两条线均**无条件登记**（见 §6 边界）。
- 派发计数 `a1FrqN` 按 `TURN_ID` 重置；任务实体由既有 `createStrategicBombing/createAttackArmy` 负责，本版不改。

## 6) 边界与不变量
- **不修改**：任务创建器、结算、拦截、UI；玩家手动出击链；线 L 的和平分支与概率门。
- 线 L（老随机线）**只对 AI 文明**关掉战时轰炸分支，玩家本国行为不变。
- `a1Known/a1Gsee` 仅 `AirForceManager` 自用（全树 8/6 处）⇒ 语义变更封闭。
- 探针只增不改行为；`nP2set` 插入点不使用"对象/int 混用"的寄存器（v5 全程引用型、v14 全程 int）。

## 7) 玩家可感知的表现
- 正常：AI 领空出现轰炸机/攻击机编队飞向**有军事建筑或高经济人口**的敌省；难度越高出动越频繁。
- 异常（上一版即如此）：AI 机场永远安静 —— 探针里 `nP2pick a=-1`、`nP2s` 全 0。

## 8) 失败与回退
- **正常节流**：K 满（`nP2cap`）、FRQ 满（`nP2frq`）、P 骰未中、该机场航程内无可打目标（`nP2pick a=-1` 且 `nP2set=0`）。
- **不正常**：入口在跑但**每个机场都 -1 且 nP2set>0** ⇒ 说明过滤/排序又写坏了（本版即此症状）。

## 11) 修 bug 三问（规范强制）
- **错误的规则**：把"当前最优值尚未设置（-1）"的判据写成了"最优值 ≥ 0 才跳进采纳块"，
  等价于"**只有已经有最优时才采纳新候选**、第一个候选永远被丢弃"；攻击线同族错误写成"师数更少者才继续"。
- **正确的规则**：`best < 0`（未设）⇒ 直接采纳首个候选；`best ≥ 0` ⇒ 按"档更小 / 分更大 / 同分随机"比较。
  攻击线：`师数差 ≥ 0`（不少于当前最优）才继续评估。
- **为什么之前会错**：Dalvik 的条件跳转助记被记反了 —— `if-ltz` 是"**小于 0** 跳"，`if-gez` 是"**大于等于 0** 跳"。
  上一轮（r5c046f）我甚至按错误记忆做过 3 处"归零钳位"修正（结果虽然正确，但依据是错的），
  这一轮的 `best` 门需要的是"**小于 0 才跳**"，于是照错记忆写成了 `if-gez`，直接导致两条线全线哑火。
- **症状 ↔ 修复对应**：`nP2pick a=-1`×245（每个机场都选不到）↔ i1；`nA1b ap=` 有几千次但任务恒 0 ↔ i3；
  `nP2s/nP2frq/nP2mil` 全 0 ↔ 二者共同后果（未派发即无后续探针）。

## 附：Dalvik 极性词典（**本版已校正**，取代 §58 旧表）
| 助记 | 语义 | 助记 | 语义 |
|---|---|---|---|
| `if-eqz` | `== 0` 跳 | `if-nez` | `!= 0` 跳 |
| `if-ltz` | `< 0` 跳 | `if-gez` | `>= 0` 跳 |
| `if-gtz` | `> 0` 跳 | `if-lez` | `<= 0` 跳 |
| `if-eq a,b` | `a == b` | `if-ne a,b` | `a != b` |
| `if-lt a,b` | `a < b` | `if-ge a,b` | `a >= b` |
| `if-gt a,b` | `a > b` | `if-le a,b` | `a <= b` |

**经验法则**：写"未设(-1)才做某事" ⇒ 必须 `if-ltz`；写"负值归零/钳位" ⇒ 必须 `if-gez`。两者极易互换。
