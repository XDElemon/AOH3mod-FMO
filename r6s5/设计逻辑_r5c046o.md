## 1) 版本 + 定位
只做两件事：**A**＝把 `Airport.autoStrikeOff` 打进机场 dump（`nA2m`/`nA3b` 新增 ` strike=`）；**B**＝`BtnMission` 在 `iActiveID` 无效时**不再静默作用到列表第 0 个机场**（改为提示+不动作），显示端也不再冒充第 0 个机场的状态，并补一条"按键落在哪个机场"的诊断探针。**不改任何派发/开关逻辑**。

## 2) 设计目标
- 玩家可见问题：①"看不出每个机场的自动打击到底是开还是关"；②"我明明把它关了，它还在出动"（实测＝按钮/文本在未选中机场时都指向列表第 0 个机场，用户误判对象）。
- 上层意图：让**状态**与**对象**都可观测、可证伪；把"静默退化"改成"明确提示"。
- 非目标：C（全局全开/全关按钮，之后做）、D（攻击机纳入自动派发，下批做）、其它按钮类的同款钳位。

## 3) 设计规则与判定顺序（人话）
1. **A**：每次机场 dump 时，追加一行 ` strike=<autoStrikeOff>`（读数语义：**1=关、0=开**，与按钮文本「自动打击：开/关」一一对应）。
2. **B（按下任务按钮）**：读 `InGame_AirForceOptions.iActiveID` →
 - 若 `<0`（初值即 -1）或 `≥` 机场数 ⇒ **不动作**：弹 Toast「请先选择机场」＋写探针 `afp:noSel`＋返回；
 - 否则 ⇒ 取列表第 `iActiveID` 个机场 → 写探针 `afp:press ap=<该机场省号>` → 执行原有逻辑（本批不动原逻辑）。
3. **B（按钮文字）**：同一判据；未选中 ⇒ 返回「**未选中机场**」，不再显示第 0 个机场的「自动打击：开/关」。

## 4) 参数与阈值表
| 名称 | 值 | 含义 | 变更影响 |
|---|---|---|---|
| ` strike=`（新键） | `0/1` | 该机场自动打击开关（与 `autoStrikeOff` 同源） | 仅日志，无行为 |
| `afp:noSel`（新键） | 恒 `1` | "未选中机场时按了按钮"的计数 | 仅日志 |
| `afp:press ap=`（新键） | 省号 | 每次按键实际作用的机场 | 仅日志 |
| Toast 文本 | 「请先选择机场」 | 提示 | 面板未初始化时由 `if-eqz menuManager` 守卫跳过 |

## 5) 状态与生命周期
不新增任何游戏状态；三个新键都是"事件/快照"型日志，随按键与机场 dump 产生。`autoStrikeOff` 的既有生命周期（默认 1／UI 翻转／存读档）**完全不变**。

## 6) 边界与不变量
- `iActiveID` **合法**时，按钮行为与 r5c046n **逐字相同**（只多一条日志）。
- `AirForceManager`／`AirMission`／`Airport` 一字未动（已用 `cmp` 验证 AFM 逐字未变）。
- 不提高任何方法的 `.registers`（`p0Air` 10／`actionElement` 11／`getTextToDraw` 8 均不变）。
- 不动派发门、10% 骰、选靶、巡逻链、存档、其它按钮类。

## 7) 玩家可感知的表现
- 机场日志里每个机场都能读到 ` strike=`（关＝1／开＝0）⇒ "谁开着"一目了然。
- 面板未点选机场时按任何任务按钮 ⇒ **弹「请先选择机场」**（此前是静默作用到第 0 个机场）；按钮文本显示「未选中机场」（此前显示第 0 个机场的开/关）。
- 点选机场后按键 ⇒ 日志出现 `afp:press ap=<你点的那个省>`（可核对）。

## 8) 失败与回退
- 正常"按了没反应"＝未选中机场（现在有 Toast 与 `afp:noSel` 可判）。
- 异常＝`afp:press ap=` 与所点机场不符 / 合法选中时也被拦 ⇒ 立即回滚：重装 r5c046n（`build_apk/dbg_signed77_v119_r5c046n.apk`）。
- 旧档/新档行为一致（本批不涉及存档字段）。
