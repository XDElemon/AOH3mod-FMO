## 0. 一句话
**这是我自己在 r6d001 写接线时打坏的两处 smali**：删/挪指令时破坏了 `move-result` 与 `invoke` 的紧邻关系，导致 ART 校验拒绝整个 `AirForceManager` 类 ⇒ 一进游戏必闪退。

## 1. 症状 → 原因 → 修复（三件事写清楚）
| 症状 | 原因（错误规则） | 正确规则 | 修复 |
|---|---|---|---|
| 一进游戏闪退（`GLThread`） | `tryStrikeForAirportP`：**我把 `invoke-virtual {p2}, Random->nextFloat()F` 连同它的 `move-result v4` 一起删掉了**（替换"概率门"整段时连调用一起吃掉了）⇒ 后面 `cmpg-float v4, ...` 用了**未定义**的 v4 ⇒ `VerifyError: register v4 has type Undefined but expected Float` | 取值必须先 `invoke` 再 `move-result`，且**不能删掉调用本身** | 补回 `nextFloat()` + `move-result v4` |
| 同上 | `pickStrikeTargetP`：dgPin 块被插在 `move-result v9` **之前**（我用 `group(1)` 的结束位置做插入点，实际落在 `move-result v9` 行首） ⇒ 产生"两个 move-result 相邻"、第一个不再是 invoke 的直接结果 ⇒ `VerifyError: invalid use of move-result*` | 插桩必须落在**整条 `move-result` 语句之后** | 把 pin 块移到 `move-result v9` 整行之后、`cmpg-float v8, v9, v3` 之前 |
| 为什么之前没发现 | **汇编器不做类型/结构校验**（`result=true` 也照样通过），而我的门禁 59 只查"接线在不在"，**不查 move-result 与 invoke 的紧邻** | 门禁必须覆盖"结构合法性"，不只"存在性" | 新增门禁 **61**：全量扫"每条 `move-result` 的前一条真指令必须是 `invoke*`" |

> **根的教训**：与之前"方向写反"同类 —— **工具链（汇编器）说 OK ≠ ART 说 OK**。能从 dex 层拦住的只有门禁，因此这次把"指令级结构"做成通用扫描，永久生效。

## 2. 版本定位
修 bug 版：让 demo（配置驱动 + 静默探针）真的能跑起来；不新增功能。

## 3. 判定顺序（受影响的两处）
- **概率门**：`invoke nextFloat()` → `move-result v4` → `v5 = dgProb/100.0f` → `cmpg v4, v4, v5` → `if v4 >= 0 则放弃` ⇒ `prob=80` 即 80% 出击。
- **钉住省**：`strikeScore → move-result v9` →（若 `pid == dgPin`）`v9 = intBitsToFloat(0xbf800000) = -1.0f` → `cmpg v8, v9, v3` → 取最小。

## 4. 参数与阈值
无变化：`prob`80 / `intel`1 / `pin`-1 / `debug`0。

## 5. 状态与生命周期
无变化（`dgInit/dgProb/dgIntel/dgPin/dgDebug` 与 `AirDbgLog.dbgOn`）。

## 6. 边界与不变量
- 本次**只补/挪指令**，不改变任何判定语义。
- 新增不变量：**每条 `move-result*` 的前一条真指令必须是 `invoke*`**（对 `AirForceManager` 与 `BtnMission` 全文成立，其余类按需扩展）。

## 11. 风险与待办
- **待办（重要）**：把"指令级结构校验"扩成通用工具（除 move-result 外，还应查：寄存器先定义后使用、`invoke` 后必有匹配的 `move-result*` 或显式忽略、标签可达性）。当前只做了 move-result 这一条。
- **我自己的流程改进**：以后凡是用"整段替换"改指令块，**必须在替换文本里显式保留被匹配到的 `invoke` 行**，并在替换后用门禁扫一遍 —— 本次血案就是"整段替换吃掉了一条指令"。
- 沿用待办：M7 全局随机流（P2）、B2 巡炸、`pin` 多目标。
