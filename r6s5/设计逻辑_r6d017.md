## 0. 一句话定位
修复"AI 只会造战斗机"——把混编轮转的**取样源**从"机场已有飞机数"换成**全局轮转计数**，让四种机型真正轮得起来。

## 1. 设计目标（玩家可见的问题 + 上层意图）
- 玩家可见问题：`ai_type=0`（混编）下，AI 机场**永远只出战斗机**，截击/攻击/轰炸一架不出。
- 上层意图：AI 的空军应当**四种机型都有**（混编），而且这个"混编"要能在**小容量机场**（`ai_cap=4`）下照样成立。

## 2. 设计规则与判定顺序（人话 + 优先级）
```
每次 AI 尝试排产（updateAIBuildUp 内、过了三闸与引擎门之后）：
  若 ai_type == 0（混编）:
      取 r = (全局轮转计数 dgRot) % 总权重          ← 本版改动点
      dgRot += 1                                     ← 每次排产推进一步
      若 r <  W_FIGHTER                      → 战斗机
      否则若 r <  W_FIGHTER+W_INTERCEPTOR    → 截击机
      否则若 r <  ...+W_ATTACKER             → 攻击机
      否则                                   → 轰炸机
  否则（1/2/3）: 走原有"单一机型优先 / 固定比例"分支（不变）
```
- 判定链先后：**先判 ai_type → 再算 r → 再按阈值落档**；阈值判定是**"从下往上落穿"**式（`if-ge` 继续往下判，落穿即命中）。
- 优先级：本版**没有**改三闸（`ai_build` / `ai_wartime` / `ai_cap`）与引擎门，它们仍在最前面，先于选型。

## 3. 参数与阈值表
| 名称 | 当前值 | 单位 | 含义 | 调大/调小会怎样 |
|---|---|---|---|---|
| `ai_type` | 0 | 枚举 | 0=混编 1=战斗机优先 2=轰炸机优先 3=固定比例 | 切成1/2/3 会退回单一/固定比例 |
| `ai_w_fighter` (dgWF) | 5 | 份数 | 战斗机权重 | 调大 ⇒ 战斗机更多 |
| `ai_w_inter` (dgWI) | 1 | 份数 | 截击机权重 | 调大 ⇒ 截击机更多 |
| `ai_w_attacker` (dgWA) | 2 | 份数 | 攻击机权重 | 调大 ⇒ 攻击机更多 |
| `ai_w_bomber` (dgWB) | 2 | 份数 | 轰炸机权重 | 设 0 ⇒ 永不造轰炸机（省钱） |
| **`dgRot`** | 运行时自增 | 计数 | **全局轮转计数（本版新增，不可配）** | 与容量无关的"第几次排产" |
| `ai_cap` | 4 | 架 | 每机场机队上限 | 与轮转已解耦（见下） |

## 4. 状态与生命周期
- `dgRot` 生命周期：**进程内静态字段**，从 0 开始，每成功进入混编选型 +1（不存盘、不随机场/文明区分）⇒ 每次重开游戏从 0 起。
- 单架飞机生命周期不变：选型 → `startBuild(type)` 入队（真实扣钱 `p1bChargeForBuild`）→ 每回合 `updateBuild()` 减 1 → 归零 ⇒ `new AirUnit` 入 `aircraft` 列表。
- **本版不涉及**：飞机退役/损失、机场回收、存档字段（`dgRot` 不在存档里，属于纯运行时）。

## 5. 边界与不变量
- **不变量**：混编块**不得**再读 `totalAircraft`（这是本版的核心约束，已写成门禁 75-3）。
- 对齐既有机制：三闸、引擎门（非玩家/空闲/队列空）、可负担筛选、`maxCapacity` 全部不动。
- 明确不修改：AI 的自动拦截/派发链（`strikeTick_A1`/`a1*`）、玩家侧派发链、探针体系。
- 工具链硬约束：AFM 那个方法 `.registers` 未上调（沿用借用的 v5/v6）。

## 6. 玩家可感知的表现
- 正常：AI 机场陆续出现**四种机型**，截击最少（权重1）、轰炸机较贵（500金/6回合）出现较慢。
- 异常：仍只有一种机型 ⇒ 看 `p1bZ` 是否只有一个值（若只有一个值且是轰炸机，说明还在旧路径/旧包；若四值都有但机场只出一种，说明该机场容量太小 + 轮转被打回）。

## 7. 失败与回退
- **正常节流（不出兵/不造）**：和平期（`ai_wartime` 门）、`ai_build=0`、该 AI 无机场建筑、**钱不够**（截击200 / 战斗260 / 攻击320 / 轰炸500 金）、机场已满（`ai_cap` / `maxCapacity`）。
- **bug 特征**：`p1bZ` 长期只有一个机型值；或 `p1bW` 全 0 且金币充足；或日志完全无 `p1b*`（说明配置/闸读取异常）。
- 回退：`cp AirForceManager.smali.pre_r6d017 → AirForceManager.smali` 重汇编重建即可回到 r6d016。

## 9. 变更清单摘要（只列规则/参数/判定）
1. 新增静态字段 `dgRot:I`（全局轮转计数）。
2. 混编选型取样源：`Airport.totalAircraft` → `AFM.dgRot`。
3. 混编块内新增 `dgRot += 1`（每次排产推进一步）。
4. 新增门禁 **75**：①字段存在 ②混编块用 dgRot ③**混编块不得读 totalAircraft** ④自增存在 ⑤模拟器序列断言 ⑥cap=4 下不得单调 + 3 负样本。

## 10. 症状 → 原因 → 修复（对照表）
| 症状 | 错误规则 | 正确规则 | 为什么之前会错 |
|---|---|---|---|
| AI 只会造战斗机 | `r = 机场已有飞机数 % 10` | `r = 全局轮转计数 % 10` | 该量被 `ai_cap=4` 夹在 0~4 ⇒ 永远落进"战斗机"档；**计数器绝不能挂在有上限的量上** |

## 11. 风险与待办
- **风险**：`dgRot` 是进程级全局 ⇒ 同一局里"哪个机场造什么"是全局轮流，而不是每机场独立轮转（体感无碍；若要每机场独立，需要给 `Airport` 新增字段，改动更大）。
- 权重为 0 的档位将永不出现（这是特性，不是 bug）。
- 沿用待办：M7（评分抖动走全局随机流，P2）、E6（按 mtime 缓存配置，P3）、E7（`pin` 多省，P3）、B2 巡炸 / B3 cfg 正式版。
- 对外发布前：`debug` 改回 `0`，恢复探针总闸。
