## 1. 一句话定位
新增**任务快照探针**：每约 1 秒把**所有在飞任务**的 `mid / civ / state / 所在省 / 目标省` 打一行，用来判定"飞机停省不动"到底是**逻辑不推进**还是**性能/时间轴**问题。

## 2. 设计目标
- 玩家可见问题：大规模空战时，飞机会**停在一个省不动**（怀疑：AI 任务到目标后无人结算 / 幽灵任务 / 帧率暴跌）。
- 上层意图：**用最少日志给出可证伪的判据**，而不是靠猜。旧探针里没有"任务级"快照，只有派发/建造类事件。

## 3. 设计规则与判定顺序（人话）
```
每帧（AFM.updateMissions() 开头）：
    msTick()：帧计数 +1；若 (计数 & 0x1F) == 0 ⇒ 置 msOn = true（≈每 32 帧 = 约 1 秒放行一次）
             否则 msOn = false
每帧遍历每条任务（原逻辑调用 mission.update() 之后）：
    调 msSnap(mid, civ, state, at, tg)
        └ 先看 msOn：false ⇒ 立即返回（不拼串、不写盘）
        └ true ⇒ 拼一行 "MS mid=.. c=.. s=.. at=.. tg=.." ⇒ 交 dKey（dKey 内还有 dbgOn 总闸 + 500ms 落盘节流）
```
- 判定先后：**msOn（节流）→ dbgOn（总闸，在 dKey 内）→ 写盘**。
- 优先级：节流在前 ⇒ 关掉时零成本；开着时每秒每任务一行。

## 4. 参数与阈值表
| 名称 | 当前值 | 含义 | 改动影响 |
|---|---|---|---|
| `msSeq` | 运行时自增 | 帧计数 | — |
| `msOn` | 布尔 | "本帧是否记录" | 决定日志量 |
| 节流掩码 | `0x1F`（32 帧） | 约 1 秒一次 | 调小 ⇒ 更密（日志更大）；调大 ⇒ 更疏 |
| 落盘节流 | `dKey` 内的 500 ms | 写文件频率 | 不变 |
| `debug`（配置） | **1** | 探针总开关 | 改 0 ⇒ 全静默 |

## 5. 状态与生命周期
- `msSeq`/`msOn`：静态字段，进程内有效，不进存档。
- 每条 `MS` 行 = 该任务"当前快照"；同一 `mid` 的**相邻行对比**即可看出它是否在推进。
- **本版不涉及**：任何业务逻辑/字段（探针**只读**）。

## 6. 边界与不变量
- **不变量（门禁 82）**：① `msSnap` 必须带 `msOn` 节流（`if-eqz` ⇒ 跳过）且必须过 `dKey` 总闸 ② `msSnap` 必须**紧随** `mission.update()` 之后 ③ `updateMissions` 的 `.registers` 提到 16 后**无寄存器越界** ④ 探针块内**不得**出现 `iput/sput`（纯只读）。
- 明确不改：任务状态机、结算链、AI 决策、可见性、雷达圈、探针旧标签。
- 寄存器：`updateMissions` `.registers 9 → 16`（locals 8 → 15），借用 v9..v14（6 个字：long mid + civ/state/at/tg）。

## 7. 玩家可感知的表现
- 正常：**玩家侧无任何变化**（探针不进入渲染路径，只写日志文件）。
- 日志：
  ```
  AIRDBG: MS mid=10231 c=7 s=1 at=531 tg=531
  ```
  `s` 是 `MissionState.ordinal()`（0=PLANNING 1=EN_ROUTE 2=EXECUTING 3=RETURNING 4=COMPLETED 5=ABORTED，具体以 `<clinit>` 顺序为准，抓样后我会核对）。
- 异常：若日志**没有** `MS` 行 ⇒ 说明该局没有任务在飞、或 `debug` 没生效。

## 11. 风险与待办
- 风险（低）：每约 1 秒 × 任务数 行日志（例：200 条任务 ⇒ ≈200 行/秒 ≈ 8 KB/s ⇒ 一局 2 分钟 ≈ 1 MB）。
