## 3) 设计规则与判定顺序（人话）
面板生成每一行前会取"该行的行段号"（`Line`）判断这一行属不属于本段。本版把"取 `Line`"换成一次查询：

```
panelRowLine(兵种对象 obj):
   obj == null            → 返回 -1（不显示；也不会崩）
   obj.File == null       → 返回 obj.Line（按原样显示）
   obj.File 以 "Air" 开头  → 记录一行证据 → 返回 -1（航空：不匹配任何行段 ⇒ 该行不创建）
   其它                    → 返回 obj.Line（与原来逐比特一致）
```
- 因为 −1 不匹配任何行段，航空行走**原有的"跳过"分支** ⇒ 行对象不创建 ⇒ **无空档、无按钮、点不到**；
- **谁压谁**：显示层只决定"生不生成这一行"，**不参与**任何招募逻辑；能否招募仍由 r6d045 的中心闸决定（两层互为兜底）。

## 5) 状态与生命周期
行对象：`InGame_RecruitArmy` 建面板时 → 逐行取兵种对象（`lUnitsTypes.get(i)` + `check-cast`）→ 把**该对象**交给 `panelRowLine` → 得到"行段号" → 若 −1 则该行**不创建**；否则按原流程创建按钮与造价文本。**不新增字段、不缓存、不改任何计数器**（`v14++`/`j++` 在守卫之后 ⇒ 跳过的行不占位）。

## 6) 边界与不变量
- **不改**：`Units.json`／兵种索引（`lUnitsTypes`118 处引用、`lArmy`301、`lArmySize`21）／存档（按 `unitID` 记）／AI 编制／空军出击链；
- **等价性**：非航空返回值 = 原 `iget Line` ⇒ 面板其余部分逐比特等价（用户实测"全回来了"）；
- **不变量**：`invoke` 与 `move-result` 紧邻；寄存器类型前后一致（`引用 → int`，与原来的 `iget` 相同）⇒ 零 `VerifyError`（已由启动自证：进程存活、`VerifyError=0`）。
