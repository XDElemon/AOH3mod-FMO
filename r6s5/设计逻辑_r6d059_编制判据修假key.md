## 1) 版本号 + 定位
**r6d059**：把"是否画成飞机"的判据从**key 前缀**改为**编制判据**，并**反向修复**被上一批误摘 key 的真空军师。

## 2) 设计目标
玩家可见问题：地图上"停在省份的飞机图标，点开是正常陆军师、编制里没有飞机"（且真空军师的贴图在上批被我误删）。
上层意图：**图标必须与实体的真实身份一致**；空军师＝"编制里含航空兵种的 airhq_ 师"。

## 3) 规则与判定顺序（人话）
绘制每一行图标前调用 `airDrawAsPlane(key, division)`，判定自上而下、先判先出：
1. `key == null` ⇒ 否（不画飞机）
2. `key` 不以 `airhq_` 开头 ⇒ 否
3. 该师编制列表为空/为 null ⇒ **摘 key（视为假身份）** ⇒ 否
4. 编制里**存在任一** `uID ∈ {7,8,9,10}`（航空兵种） ⇒ **是（真飞机）**
5. 编制里全是陆军 ⇒ **摘 key** ⇒ 否
另外（数据修复，与绘制无关）：`tickInvars` 入口若发现 `airhqDivision.key` 为空或**不是** `airhq_` 开头（=被 r6d058 误摘）⇒ 用任务的 `airhqKey` **写回**。

## 4) 参数与阈值表
| 名称 | 值 | 含义 | 改动后果 |
|---|---|---|---|
| 前缀 | `"airhq_"` | airhq 身份标记 | 改它 ⇒ 全线失配 |
| 航空兵种集合 | `uID ∈ 7..10`（由 `isAirUnitID` 的前缀规则判定） | "编制里真有飞机"的判据 | 未来新增 `Air*` 机型**自动覆盖** |
| 摘 key 行为 | `key ← CFG.extraRandomTag()` | 把假身份清成随机 tag | 不清 ⇒ 图标长期错误 |
| 摘除日志上限 | 前 **40** 次（`fkN<40`） | 证据行 `FK strip=N` | 上限满后静默（不影响功能） |

## 5) 状态与生命周期
师：创建（`ArmyDivision`）→ 若属空军（`key=airhqKey4(...)` 且编制为航空团）→ 被任务认领（`mission.airhqDivision`）→ 逐帧绘制时按上表判定 → 若判定为"假身份"则**当场摘 key**（一次性修复，之后它永远是陆军图标）→ 若为"被误摘的真师"则 `tickInvars` **写回 key**（一次性修复）。

## 6) 边界与不变量
- **不改**：招募/武器/存档格式/AI 派发/任务状态机（本批只改绘制判据 + 一处 key 修复）；
- **对齐**：复用既有 `isAirUnitID(I)Z`（r6d045，前缀规则，未来机型自动生效）；
- **不变量**：判定只读 `key` 与编制；摘/写 key 仅影响该师的 `key` 字符串；`invoke`+`move-result` 紧邻；`tickInvars` 新增块只用 `v0..v2` 且入口即用。

## 7) 玩家可感知的表现
- 正常：**真空军师照旧画飞机**（含起飞/返航/混编），**普通陆军师恒为陆军图标**；
- 异常（=不通过）：飞机贴图整体消失（上批症状）／假身份仍画飞机。

## 8) 失败与回退
- 判定异常（key 为 null、编制为 null）⇒ 返回"不画飞机"并可能摘 key ⇒ **最坏也只是图标变陆军**，不会崩（无解引用空指针路径）；
- 若整体不对 ⇒ `.pre_r6d059` 覆回两文件 → 汇编 → 构建 → 前台装机（≈4 分钟）。

## 9) 验收标准（可证伪）
① 真空军师贴图恢复；② 假身份变回陆军图标；③ 空军出击/拦截/返航照常；④ `VerifyError=0`；⑤ `FK strip=` 有值（说明确有假身份被清理）。
**实测结果**：用户确认**验收成功** ✅（①②③）｜④自证通过 ✅ ｜⑤待抓样补记。
