# 设计逻辑 · r6d161「陆军一列 / 飞机一列」

> 目标读者：不看代码也能理解"系统现在怎么运行"的人（含玩家视角）。
> 本文件是世界书规定的**设计逻辑 11 项**，必须齐全。

---

## 1) 版本号 + 一句话定位

**r6d161**（v119 / 1.035-DEMO.1）。本版只动**一个系统**：**地图上"部队图标怎么排队"的排版系统**——
让**空军师不再与陆军师挤同一条纵队**，改为"陆军保持原纵队，空军独立成列（右侧 +56px，纵向自己计数）"。

---

## 2) 设计目标

- **玩家可见的问题**：战争省份里陆军师很多时，飞机贴图被排到图标列很深处（实测第 12 个槽位 ⇒ 向下 392 像素），
  看起来像"飞机跑到别的省份去了"（此前被误描述为"Y 轴拉伸"）。
- **上层意图**：**玩家要在战争省里一眼看清"这里有一支空军"**。既然陆军堆叠是既有规则、且不该为了空军去改，
  那就让空军**换一列站着**——陆军一列、飞机一列，互不遮挡、互不挤位。

---

## 3) 设计规则与判定顺序（人话版）

排版时对省内的部队**逐个**处理，判定顺序固定为：

1. **若** 这支部队**正在移动** ⇒ 交给移动专用排版（`upySk`），**不占任何槽位**（既有规则，未改）。
2. **若** 这支部队**不移动**，则看它的身份：
   - **若** 它的 key 以 `airhq_` 开头（**空军师**）⇒
     - 用**空军自己的计数器**（`jAir`，从 0 开始）算纵向位置：`y = 高度×jAir + 2×jAir − 高度/2`；
     - 写进该部队的纵向偏移；
     - 横向偏移 = 居中量 **+ 56 像素**（右移，形成独立一列）；
     - 空军计数器 **+1**。
   - **若** 不是空军师（陆军/其他）⇒ **完全沿用旧规则**：
     - 纵向位置用**陆军计数器**（`j`，从 0 开始）：`y = 高度×j + 2×j − 高度/2`；
     - 横向偏移 = 居中量（不变）；
     - 陆军计数器 **+1**。

**优先级/先后**：移动判定最优先（第 1 条）。之后"是不是空军"只决定**用哪个计数器、加不加横向偏移**，
**不改动任何陆军师的数值**。两个计数器各走各的，互不影响。

**横向偏移写在哪里的讲究**（决定"会不会被覆盖"）：
把 +56 写进部队的**默认横向偏移函数**（`defaultShiftX`），而不是只写一次字段。
原因是：游戏里有多个地方会把"默认横向偏移"重新写进部队（部队宽度刷新、移动初始化等）——
写在函数里 ⇒ **所有写入者都会自动带上这 56px**，本版新增的列不会被任何一处刷新抹掉。

## 4) 参数与阈值表

| 名称 | 当前值 | 单位 | 含义 | 调大 / 调小会怎样 |
|---|---|---|---|---|
| 空军横向列偏移 | **+56**（`0x38`） | 屏幕像素（**不随地图缩放**） | 空军相对省份中心的横向右移量 | 调大：更靠右，极端缩小地图时可能压到邻省图形；调小：可能压住陆军方框 |
| 空军纵向槽距 | `高度×1 + 2 = 34`（高度=32） | 屏幕像素 | 同省多支空军之间的纵向间距 | 由图标高度决定，本版未改（与陆军同一公式） |
| 判定关键字 | `airhq_` | 字符串前缀 | 识别"这支部队是空军师"的唯一口径 | 改错 ⇒ 空军/陆军判反（本版最大风险点） |
| 陆军计数器 | 从 0 起 | 计数 | 陆军第几个槽位 | 未改（既有规则） |

## 5) 状态与生命周期

- **实体**：`ArmyDivision`（陆军师或空军师，同一类型，用 key 区分）。
- **产生**：部队被创建时，纵向/横向偏移取"默认值"（纵向 = 负半高 = 居中）。
- **推进（排版）**：只要省内编制变化（增删部队、移动、战斗结算、AI 重组等 20 余处触发），
  游戏就会对整个省份重跑一次排版：本版在这里按第 3 节的顺序重算**每个不移动部队的纵向偏移**，
  并（对空军）保证横向偏移为"居中量 + 56"。
- **结算/回收**：部队离开省份或移动时，改由"移动专用排版"接管位置；横向偏移通过"默认横向偏移函数"保持空军身份一致，
  从而降落/起飞都不出现位置跳变。
- **谁负责什么**：只有"省份排版"负责纵向槽位；横向"默认偏移函数"负责身份列。

---

## 6) 边界与不变量

**明确对齐的既有机制**
- 沿用旧公式 `高位×索引 + 2×索引 − 半高`（本版只换计数器，不换公式）；
- 沿用"不移动才占槽位"的规则；
- 沿用"偏移是屏幕像素、不随缩放"的既有语义。

**明确不修改的东西**
- 陆军师的槽位计数与数值：**一个字节都没改**（否则步兵堆叠、点击判定全变）；
- 移动中的部队排版（`upySk`）与"缩放偏移"字段语义；
- 其他消费"省份主人美术组"的绘制路径（机场图标、空军总部等）；
- 探针类（只读，本版新增的 `ax=` 只读一个字段）。

**必须成立的约束**
- 空军师与陆军师**各有一个独立计数器**，任何一方都不消耗另一方的槽位；
- 横向偏移必须写在"默认值函数"里，保证任何刷新路径都不会抹掉它；
- 空军 key 为空时按陆军处理（永远退化为旧行为，不会崩）。

## 7) 玩家可感知的表现

| 情况 | 表现 |
|---|---|
| **正常**（战争省里陆军 12 个师 + 1 支空军） | 陆军仍从省份中心往下排成一列；**飞机贴图贴在陆军列的右侧、位于省份中心线上**，不再被挤到省外 |
| **正常**（和平省只有 1 支空军） | 飞机贴图在省份中心偏右 56px 处（与以前"居中"略有差别，但仍在省内） |
| **正常**（同省多支空军） | 飞机在右侧一列里按 34px 纵向排开，互不重叠 |
| **异常**（判反了空军/陆军） | 陆军被右移/堆叠错乱，一眼可见 ⇒ 立刻回退 |
| **异常**（本版边缘） | 地图缩到极小时，56px 常量偏移相对省份显得偏大，飞机可能压到邻省图形（与陆军堆叠同性质，可调参数） |

**日志侧**（诊断通道 `aircfg_diag.txt`）：
- `nUPY ... air=<空军纵向偏移> ax=<空军横向偏移> mx=<省内最大|偏移|>`：
  修好后**战争省里 `air=` 不再随陆军数量增长**（应为 0 / 34 / 68…），且 `ax≈12~44`（=居中量+56）。

## 8) 失败与回退

- **空军 key 为 null** ⇒ 走陆军路径（=旧行为），安全。
- **判反**（把 `airhq_` 判据写反）⇒ 陆军被当空军/空军被当陆军 ⇒ 立刻往回退包。
- **不做节流**：本版没有"节流不出兵"概念（不涉及军事逻辑）。
- **回退**：装回 `dbg_signed77_v119_r6d160.apk`（上一版）；源码树回退见"已应用补丁清单"第二节。

---

## 9) 验收标准（可证伪）

**通过 =**
1. 战争省份里（有 5 个以上陆军师的省，最好复现过"飞机跑偏"的那个省），**飞机贴图贴在陆军列的右侧、仍在省内**；
2. 日志 `nUPY` 里，同一省的 `air=` **不再等于深槽位值**（如 392），而是 0/34/68 一类小值；
3. 同一省的 `ax=` 比陆军大 56（例如陆军 12、空军 68；或陆军 -12、空军 44）；
4. 陆军堆叠观感与 r6d160 一致（没有变乱）。

**不通过 =**
- 飞机仍在省外/被挤到远处 ⇒ 补丁未生效（`updateArmyPosY` 走了陆军分支）；
- 陆军被右移或堆叠错乱 ⇒ 判据写反；
- 装机后开局即闪退 ⇒ 寄存器/字节码问题（回退）。

## 10) 变更清单摘要

- **规则**：新增"空军师用独立纵向计数器"；新增"空军师横向 +56px 独立列"。
- **参数**：新增 1 个（横向列偏移 56px）。
- **判定**：新增 1 个身份判定（key 前缀 `airhq_`），放在"非移动"分支之后；移动分支不变。
- **代码面**：3 个文件、3 个方法（`Province.updateArmyPosY`、`ArmyDivision.defaultShiftX`、探针 `AirPosProbe.up`）。

## 11) 风险与待办

**已知副作用**
- 横向列偏移是**固定屏幕像素**：地图缩到极小时可能压到邻省图形（与陆军堆叠同样的性质，可调 56 这个值）；
- 空军"起飞后"由移动排版接管，落点仍在列上，但如果目的地省份的陆军很多，飞行中的位置与落地位置会在横向保持一致（设计如此）。

**故意不改的项**
- 不改陆军堆叠公式与计数；
- 不做"空军每省只保留一架贴图"的合并（那属于"重合/叠两层"课题，另案）。

**下一批要接的东西**
1. **复现校验**：用户在有大量陆军的战争省里看飞机是否已在右侧列；
2. 取 `nUPY` 的 `air=`/`ax=` 数据做实证；
3. 「重合/叠两层」：哑火探针统一"搬家"后重查；
4. 空袭结算闪退（r6d160 `safeUpd`）复测；
5. 防空 AD-2、钢四科技系统移植（挂账，未开工）。
