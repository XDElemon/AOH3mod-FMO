## 1) 版本号 + 一句话定位

**r6d162**（v119 / 1.035-DEMO.1）。本版**不改任何游戏机制**，只修 r6d161 引入的**致命字节码错误**——
让游戏能正常开局（r6d161 装机后一进游戏就闪退）。

## 2) 设计目标

- **玩家可见的问题**：r6d161 装机后，进入游戏（新局初始化）立刻闪退，游戏完全不可玩。
- **上层意图**：把 r6d161 想要的"陆军一列、飞机一列"**以正确、可验证的字节码**交付出来。

---

## 3) 修 bug 三件事（核心）

### ① 错误的规则（r6d161 实际做出来的）
在省份排版循环里，对"当前处理的部队"做身份判定（是不是空军）时，
**这段判定代码被放在了 `check-cast v2, ArmyDivision` 之前**——
那一刻 `v2` 还只是"从列表里取出来的 Object"，按 `ArmyDivision.key` 去访问字段。

### ② 正确的规则（r6d162）
判定代码必须在 **`check-cast` 之后**执行：先把 `v2` 明确转成 `ArmyDivision`，再去读它的 `key`。
其余规则与 r6d161 完全一致（空军独立纵向计数 + 横向 +56px；陆军原样不动）。

### ③ 为什么之前会错（症状 → 原因）
| 症状 | 原因 |
|---|---|
| 装机无异常，开机进游戏即 **闪退**（GLThread FATAL） | ART 校验器在**首次加载 Province 类**时拒绝整个类：`VerifyError: cannot access instance field ArmyDivision.key from object of type Reference: java.lang.Object`（`[0x25]`） |
| 崩在 `InitGame.initGame → LoadManager.loadProvincePoints` | 新局初始化会碰省份数据 ⇒ 这是"第一次用到 Province 类"的时刻 ⇒ 校验失败在这里爆 |
| 为什么校验期没发现 | 我的补丁把判定块作为"锚点前缀"拼接 ⇒ 锚点选的是 `check-cast … ; 后续公式`，**块被拼在了锚点之前** = 拼到了 check-cast 前面。静态检查（参数越界/寄存器类型）与文本门禁都**不检查"类型是否已 cast"**，所以三条防线全部放行；设备侧 ART 校验本机不可用（内存不足被杀）。 |

### 症状与本次修复的对应关系
- "开局闪退" ⇒ 本版把判定块**移到 check-cast 之后**（字节码顺序正确）⇒ 类可被校验 ⇒ 开局不崩。
- "以后不能再犯同类错" ⇒ 新增 **`check_castorder.py`**（类型流静态检查：**未 check-cast 就访问字段**即报错），
  并接入预装流水线；实测它能**精确复现本次血案**（坏版 1 处、修好后 0 处）。

## 10) 变更清单摘要

- **代码**：`Province.smali` 的 `updateArmyPosY()`：判定块从 `check-cast` **之前** 移到 **之后**（唯一改动）。
- **工具链**（本版新增，防止再犯）：
  1. `check_castorder.py` —— 类型流检查（未 cast 就访问字段）；
  2. `regtype_gate.py` + `regtype_baseline.tsv` —— 把 regtype 检查改成**增量门禁**（大文件里游戏自身的既有噪声不再阻塞流水线）；
  3. `check_params.py` 修正 —— **实例方法要计入 `this`**（原来会把整份 Province.smali 报成 288 处假阳性）；
  4. 门禁 `check_r6d162.py` —— 复用 r6d161 的 4 断言 + 位置断言 + 类型流断言 + 负样本 N6（把块挪回去必须变红）。

## 11) 风险与待办

- **已知限制**：设备侧 ART 校验在本机不可用（关掉游戏后系统仍只剩 ~160MB，`app_process` 被 OOM 杀）；
  `cmd package compile -m verify -f <包名>` 经**已知坏版校准为无效**（对 r6d161 也返回 Success，不报 VerifyError）⇒ 不能当作前置闸门。
- **待办**：① 用户实测开局是否正常；② `ProbeVerifier` 生成器自身有个 VerifyError（见下）——修好后探针类的真机校验才能用；
  ③ 「重合/叠两层」；④ 空袭闪退复测；⑤ 防空 AD-2 / 钢四科技（挂账）。
- **本版顺带发现（待修）**：`gen_verifier.py` 生成的 `ProbeVerifier.main(String[])` 有参数个数错误
  （logcat：`expected 2 argument registers, method signature has 1`）⇒ 真机校验虽能起 ART，但驱动自身被拒。
