# 设计逻辑 · r6d163「横向对称分列 / 单边居中」

> 本版是对**用户两条明确要求**的实现（此前 r6d162 都没做）：
> ① 陆军师离开该省后，空军师**回到中心**（陆军同理）；
> ② 同省空军+陆军并存时，**不只空军右移，陆军也要左移**。

---

## 0) 先回答"做了没有"

| 用户要求 | r6d162 是否做到 | r6d163 是否做到 |
|---|---|---|
| ① 陆军走了 ⇒ 空军回中心；空军走了 ⇒ 陆军回中心 | **没做**（空军永远 +56，陆军永远不动） | **做了**（只有一类时偏移 = 0 ⇒ 居中） |
| ② 两类都在 ⇒ 陆军也左移（对称分列） | **没做**（只有空军右移） | **做了**（陆军 −28、空军 +28） |

---

## 1) 版本号 + 一句话定位

**r6d163**（v119 / 1.035-DEMO.1）。本版只改一个系统：**省份内"部队图标横向怎么分列"**——
把 r6d162 的"空军单方面右移"升级为**按本省构成决定的对称分列**。

## 2) 设计目标

- 玩家可见问题①：空军单独在一个省时，仍然偏右 56px，看着"没对齐省份中心"。
- 玩家可见问题②：同省有陆军时，只有飞机挪了、陆军没挪，"两列"看起来像是飞机被挤出去，而不是"分列"。
- 上层意图：**分列是为了"两类都在时互不遮挡"**；既然是为了避让，就应该是**对称的一对列**；
  没有需要避让的对象时，就**回到中心**。

## 3) 设计规则与判定顺序（人话版）

对任何一支部队求"横向偏移"时：

1. **若** 它的 key 为空 ⇒ 不加任何偏移（保持居中）。（安全兜底）
2. **否则** 取它所在的省份（由 `ArmyDivision.provinceID`），统计该省部队：
   - 若 key 以 `airhq_` 开头 ⇒ 记 1 个"空军"，否则记 1 个"陆军"。
3. **若** 无此省 / 该省为空 / **只有一类** ⇒ 偏移 = **0**（**居中**）。
4. **若** 两类都有 ⇒
   - 该部队是**空军** ⇒ 偏移 = **+28**（右）
   - 该部队是**陆军** ⇒ 偏移 = **−28**（左）

优先级/先后：先判"key 是否为空"，再判"本省构成"，最后按"是不是空军"决定方向。
**纵向**规则完全沿用前两版（空军用自己的槽位计数 `jAir`、陆军用 `j`），本版不动。

**为什么写在"默认偏移函数"里**：游戏有多个地方会把"默认横向偏移"重新写进部队
（部队宽度刷新 `updateArmyWidth_Just`、移动初始化 `MoveUnits`）——写在默认函数里 ⇒ **所有写入者自动带上同一结果**，
不会出现"某一帧被重置回居中"的闪烁。

## 4) 参数与阈值表

| 名称 | 当前值 | 单位 | 含义 | 调大/调小 |
|---|---|---|---|---|
| 分列半间距 | **28**（`0x1c`） | 屏幕像素（不随缩放） | 陆军 −28 / 空军 +28 ⇒ 两列中心相距 **56px** | 调大：两列更分开（可能压邻省）；调小：可能互相遮挡 |
| 纵向槽距 | 34（=图标高32+2） | 屏幕像素 | 同类部队纵向间距（沿用） | 未改 |
| 判据 | key 前缀 `airhq_` | 字符串 | 识别空军 | 改错 ⇒ 方向判反 |
| 单边偏移 | **0** | — | 只有一类时居中 | 这是本版核心行为 |

## 5) 状态与生命周期

- 偏移**不存状态**：每次需要时按"当前省份构成"现算 ⇒ **陆军离开/加入的下一帧就自动生效**（无需额外事件）。
- 谁负责：`ArmyDivision.defaultShiftX()` 取"默认横向偏移"；`Province.columnShiftFor(省id, 是否空军)` 负责算分列量。
- 旧存档/老单位同样适用（没有新字段，`provinceID` 是既有字段）。

## 6) 边界与不变量

- **对齐**：纵向规则、移动排版（`upySk`）、缩放偏移字段语义——一律不动。
- **明确不修改**：陆军纵向堆叠；飞行中单位的位置由移动排版接管（横向也按同一分列规则，避免起飞/落地跳变）。
- **不变量**：
  - 只有一类部队时，偏移必须为 0（否则"回中"就不成立）；
  - 分列必须是**对称**的（+28 / −28）；
  - key 为空 ⇒ 一律 0。

## 7) 玩家可感知的表现

| 情况 | 表现 |
|---|---|
| 战争省：多个陆军 + 1 空军 | 陆军列整体**左移 28**；飞机贴在**右侧 28**，两列并排、互不遮挡 |
| 只有空军 | 飞机**在省份中心**（不再偏右） |
| 只有陆军 | 陆军**在省份中心**（和以前一样） |
| 陆军全部离开 | 同一支空军**下一帧回到中心**（X 由 −28→0、Y 回到 −16） |
| 异常（判反） | 陆军跑到右边、空军跑到左边（一眼可见） |

## 8) 失败与回退

- 无省/无部队/key 空 ⇒ 偏移 0（安全兜底，不会崩）。
- 地图缩到极小时 ±28 是常量（与陆军堆叠同性质，可调）。
- 回退：装 `dbg_signed77_v119_r6d162.apk`（上一版）。

## 9) 验收标准（可证伪）

- **A**（要求②）：战争省里，**陆军方框整体比省中心偏左**，飞机在其右侧；两者各成一列。
- **B**（要求①）：把该省陆军调走（或换到一个只有空军的省）⇒ **飞机回到省中心**。
- **C**（要求①对称面）：空军的省里调来陆军 ⇒ 陆军在中心（若只有陆军）；调来空军 ⇒ 变成对称两列。
- **D**（不回归）：只有陆军的省，堆叠观感与 r6d162 一致；纵向不被挤走（飞机仍在自己那一列）。
- 数值侧（日志 `nUPY`）：`ax=` 在"两类都在"的省里，空军应为 +28 档、陆军为 −28 档；单边时都回到 0 档。

## 10) 变更清单摘要

- **规则**：横向偏移由"空军恒 +56"改为"按省构成：两类都在 ⇒ ±28；否则 0"。
- **新增方法**：`Province.columnShiftFor(II)I`（省 id、是否空军 → 偏移量），扫该省部队计数两类。
- **改动方法**：`ArmyDivision.defaultShiftX()`（改为 `居中量 + columnShiftFor(provinceID, 是否空军)`）。
- **参数**：半间距 28（等价于两列相距 56，与上一版目视间距一致）。
- **门禁/模拟器**：`check_r6d163.py`（11 条规则断言 + 调用点断言 + 类型流 + 3 负样本）；`armypos_sim_v3.py`（5 断言 + 反转敏感性自检）。

## 11) 风险与待办

- **性能**：`defaultShiftX()` 会扫一遍本省部队（O(n)，n=本省部队数，通常 ≤20）⇒ 可忽略；
  若将来大编制省份出现卡顿，可把结果缓存到 `Province` 的一个"本省构成版本号"上（待办）。
- **常量缩放**：±28 不随地图缩放（与陆军堆叠同样的性质）；如需可改为按 `mapScale` 缩放。
- 待办：用户实测 A/B/C/D 四条；「重合/叠两层」；空袭闪退（r6d160 `safeUpd`）复测；防空 AD-2；钢四科技移植。
