# 设计逻辑 · r6d164「横向分列真正生效（+ 取证）」—— 修 bug 版

> 用户提问：「非战争省份的堆叠，你没有做是吗？我现在和平时期把陆军师和空军师叠起来，怎么没反应」

## 0) 先回答"做了没有 / 为什么没反应"

**结论：分列规则本身没有"战争/和平"之分（和平省份同样逐支绘制），但 r6d163 的横向偏移写错了地方 —— 写在了一个"不常被调用"的函数里，和平时期刚叠起来的那一刻它还没被执行，所以 `iShiftX` 仍是 0 ⇒ 看不到分列。**

| 检查项 | 结果 |
|---|---|
| 和平时期是不是"每省只画一个图标"？ | **不是**。和平省份逐支绘制：`ProvinceDrawArmy$1.drawArmy` 的 `if-nez inBattle` 表示"**非战斗**才继续画" ⇒ 和平时期走的就是这条路（实测 `nAIF` 59,316 行、`nTO` 2,628 行都在逐支绘制链上） |
| 那为什么没反应？ | r6d163 的横向偏移只写在 `ArmyDivision.defaultShiftX()`；它只在"部队宽度刷新 / 移动初始化"时被调用 ⇒ 叠放那一刻**还没被写过** ⇒ `iShiftX = 0`。日志侧证据：`nUPY` 里 `ax=`（读的就是空军的 `iShiftX`）**一直是 0** |
| 上一轮我为什么没抓到数据 | 我把位置探针 `posD` 插在了 `drawProvinceArmyWithFlag` 里，而**战斗中的师由 `Battle/BattleLine` 另画**，和平时期看不到区别；另外它还走 `dKey`（被 `debug:0` 闸掉）⇒ 既没数据也不该用来判断 |

## 1) 版本号 + 一句话定位

**r6d164**（v119 / 1.035-DEMO.1）。本版只改一件事：**把"横向分列"的写入时机搬到"每次省份排版都会执行"的地方**，
让它和纵向堆叠**同一时刻生效**——不再依赖 `defaultShiftX()` 的调用时机。

## 2) 设计目标

玩家可见问题：和平时期把陆军师与空军师叠在同一省，**看不到"陆军左、飞机右"**。
上层意图：**"分列"必须与"堆叠"同时生效**（堆叠是排版算出来的，那么分列也该由排版写入），
并且**必须能取证**（下次同类问题能一眼看出是"没算"还是"没画"）。

## 3) 设计规则与判定顺序（人话版）

排版（`Province.updateArmyPosY`）逐支处理本省"不移动"的师：

1. 先判它是不是空军（key 前缀 `airhq_`）。
2. 按前几版规则算**纵向**（空军用自己的槽位计数 `jAir`、陆军用 `j`），写 `iShiftY`。
3. **本版新增**：紧接着算**横向**：
   - `居中量 = -(宽度/2)`
   - `偏移 = Province.columnShiftFor(本省ID, 是否空军)`：两类都在 ⇒ 空军 +28 / 陆军 −28；只有一类 ⇒ 0
   - 写 `iShiftX = 居中量 + 偏移`（**与 Y 同一次排版写入**）
   - 记一条取证 `nUPX p=<省> air=<0/1> off=<±28/0> x=<最终值>`
4. 移动中的师仍交给移动排版（`upySk` / `MoveUnits`），不变。

`defaultShiftX()` 里的同一套规则**保留**（它被宽度刷新/移动初始化调用时也返回同一结果），
两条路径互相一致，谁最后写都一致。

## 4) 参数与阈值表

| 名称 | 当前值 | 说明 |
|---|---|---|
| 分列半间距 | **28**（`0x1c`） | 两类都在 ⇒ 空军 +28 / 陆军 −28（两列相距 56px） |
| 单边偏移 | **0** | 只有一类（或空省/无省）⇒ 居中 |
| 纵向槽距 | 34 | 沿用（H=32 + 2） |
| 判据 | key 前缀 `airhq_` | 判反 ⇒ 左右互换（一眼可见） |
| 取证行 | `nUPX p= air= off= x=` | 新增；用于判断"有没有算 / 算了多少" |

## 5) 状态与生命周期

- 偏移**不存状态**：每次排版按"当前本省构成"现算 ⇒ 增删部队的**下一次排版**就生效（陆军走/来 ⇒ 自动回中或分列）。
- 写入者：`Province.updateArmyPosY`（本版起，权威）+ `ArmyDivision.defaultShiftX`（一致的第二写入者）。
- 取证：每次写入打一条 `nUPX`（走免节流的 `aircfg_diag`，且写入器已加锁防交错）。

## 6) 边界与不变量

- **不改**纵向规则、移动排版、缩放偏移语义、战斗中的绘制（那条由 `Battle` 负责）。
- **不变量**：① 两类都在 ⇒ 必须 ±28；② 只有一类 ⇒ 必须 0；③ `iShiftX` 必须由排版写入（不再只依赖默认函数）。
- 探针只读（`upx` 只写日志）。

## 7) 玩家可感知的表现

| 情况 | 表现 |
|---|---|
| 和平省：1 陆军 + 1 空军 | **陆军偏左、飞机在右**（两列并排） |
| 把陆军调走 | 飞机**回到省中心** |
| 只有陆军 | 居中（与旧版一致） |
| 战争省 | 与 r6d163 相同（纵向不被挤走 + 横向分列） |
| 异常 | 若仍无反应 ⇒ 看新日志 `nUPX`：有 `off=28` 却看不到 ⇒ 属"画的问题"；没有 `nUPX` ⇒ 排版没跑 |

## 8) 失败与回退

- 无省/空省/key 为空 ⇒ 偏移 0（安全）。
- 回退：装 `dbg_signed77_v119_r6d163.apk`（上一版）；源码树 `/tmp/revx/{Province,AirPosProbe}.smali.pre_r6d164`。

## 9) 验收标准（可证伪）

- **A**：和平省里叠 1 陆军 + 1 空军 ⇒ 陆军偏左、飞机在右（本次要修的那条）。
- **B**：把陆军调走 ⇒ 飞机回中心。
- **C**：日志 `nUPX` 在"两类都在"的省里出现 `air=1 off=28 x=…` 与 `air=0 off=-28 x=…`；单边省 `off=0`。
- **D**：开局不闪退；纵向规则不回归。

## 11) 风险与待办

- 排版里多了一次 `columnShiftFor`（O(本省部队数)，≤20）⇒ 可忽略；若大编制卡顿再加缓存。
- ±28 是常量（不随缩放）。
- 待办：① 用户复测 A/B（这次要么有分列、要么至少有 `nUPX` 证据）；② 若 `nUPX` 显示 `off=28` 但仍看不到 ⇒ 说明问题在绘制侧（下一步查 `getArmyPosX` 的坐标合成）；
  ③ 「重合/叠两层」；④ 空袭闪退复测；⑤ 防空 AD-2 / 钢四科技。
