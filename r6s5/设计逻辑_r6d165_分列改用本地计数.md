# 设计逻辑 · r6d165「横向分列改由排版自己的计数驱动」—— 修 bug 版

> 起因：用户复测 r6d164 后报「没反应」。抓样结论：`nUPX` 1256 行里 **`off=` 永远是 0**（连 `air=1` 的 167 条也是 0）
> ⇒ `Province.columnShiftFor(provinceID, isAir)` 里"按 id 再取一次省份 + 数两类"这条链**始终判不出"两类都在"**。

---

## 1) 版本号 + 一句话定位
**r6d165**（v119 / 1.035-DEMO.1）。本版只改一件事：**横向分列不再"按省 id 反查省份"，改用排版自己数出来的计数**。

## 2) 设计目标
玩家侧：和平省把陆军与空军叠在一起**看不到分列**。上层意图：**分列判定必须建立在"已经证明可用"的数据上**——
排版循环本来就逐支读过本省部队、并且数出了"空军几支 / 陆军几支"，那就**用这份计数**决定分列，不再另开一条查省的路。

## 3) 规则与判定顺序（人话版）
`updateArmyPosY()` 现在分两遍：

1. **第一遍（纵向）**：逐支处理"不移动"的师——空军用 `jAir`、陆军用 `j` 算 `iShiftY`（沿用 r6d161/162 规则）；
   循环结束时得到两个总数：**v5 = 空军支数**、**v1 = 陆军支数**。
2. **第二遍（横向，本版新增）**：再逐个遍历本省部队（跳过移动中的）：
   - 若 `v5>0 且 v1>0`（两类都在）⇒ 空军 `+28` / 陆军 `−28`；否则 ⇒ `0`（居中）
   - `iShiftX = -(宽度/2) + 上面这个偏移`
   - 记一条 `nUPX p= air= off= x=`
   整段包在自带的 try/catch 里（万一异常只记栈，不影响主流程与纵向）。

`ArmyDivision.defaultShiftX()` 里那套规则**保留**（第二条路径），但**不再承担主责**。

## 4) 参数与阈值表
| 名称 | 值 | 说明 |
|---|---|---|
| 分列半间距 | **28**（`0x1c`） | 两类都在 ⇒ 空军 +28 / 陆军 −28（两列相距 56px） |
| 单边偏移 | **0** | 只有一类 ⇒ 居中 |
| 纵向槽距 | 34 | 沿用 |
| 判定依据 | **排版自己的计数**（v5 空军数、v1 陆军数） | 本版核心改动 |
| 取证 | `nUPX`（真值） + `nCSF`（旧反查链诊断） | `nCSF` 用来看"反查"到底错在哪，事后可删 |

## 5) 状态与生命周期
不存状态：每次排版按"当前本省构成"现算 ⇒ 部队增删的**下一次排版**即生效；两遍遍历都是 O(n)（n≤20）。

## 6) 边界与不变量
- 不改纵向规则、移动排版（移动中的师由 `upySk`/`MoveUnits` 负责，第二遍跳过它们）、缩放语义、战斗绘制。
- **不变量**：两类都在 ⇒ ±28；只有一类 ⇒ 0；`iShiftX` 必须由**排版**写入（不再依赖任何"按 id 查省"的旁路）。
- 探针只读。

## 7) 玩家可感知的表现
| 情况 | 表现 |
|---|---|
| 和平省 1 陆军 + 1 空军 | 陆军偏左、飞机在右（本次要修的） |
| 把陆军调走 | 飞机回省中心 |
| 只有一类 | 居中 |
| 异常 | 若仍不可见：看 `nUPX` 的 `off=`——有 28/-28 而看不见 ⇒ 问题在**绘制坐标合成**；若 `nUPX` 的 `off=` 仍是 0 ⇒ 说明连"两类都在"都没数出来（下一步查 `nCSF`） |

## 8) 失败与回退
- 第二遍整体 try/catch；无省/空省/key 空 ⇒ 偏移 0。
- 回退：装 `dbg_signed77_v119_r6d164.apk`（上一版）；源码树 `/tmp/revx/*.pre_r6d165`。
