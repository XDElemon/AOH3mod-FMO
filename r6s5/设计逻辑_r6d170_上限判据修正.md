## 0) 修 bug 三件事（世界书强制）

### ① 错误的规则是什么
`AirDefDiag.aline` 里"是否到达 `nADA` 行数上限"的判据**整体走反**：

```
if-ge v0, v1, :cond_ok      // 意图：cap≥40 ⇒ 截断
…截断块（sput skip；return）…  // 但它被写成了 fall-through
:cond_ok …写行（sput cap）…      // 意图是"截断"，实际却在写
```
⇒ 真实行为变成：**`cap>=40` 才写行，`cap<40` 一律截断** ⇒ 全世界的阵地明细**永远写不出来**。

### ② 正确的规则是什么
```
if-lt v0, v1, :cond_write    // cap<40 ⇒ 跳到"写行"
…截断块（sput skip；return）…   // cap>=40 落空到这里 ⇒ 截断
:cond_write …写行（sput cap）…
```
即：**先写满 40 行，再截断**；被截断的行数由 `nADTRUNC` 报出。

### ③ 为什么之前会错（症状 → 原因），以及症状与修复的对应
| 项 | 内容 |
|---|---|
| 症状 | `nADA` **0 行**；`nADTRUNC` **93/93 回合、恒为 `n=2`**（而全场只有 2 个有阵地的省 `pAAA=2`） |
| 原因 | "截断分支"与"写分支"的路径整体互换 ⇒ 每回合两个阵地省都被当"超限"处理 |
| 为什么门禁没拦住 | 当时的 P5 是**纯文本断言**（只检查 `if-ge … :cond_ok` 是否存在）——**门禁里写的判据和我犯的是同一个错**，所以全绿放过 |
| 修复对应 | ① 改判据 + 改标签名（`if-lt … :cond_write`）；② 门禁 P5 升级为**语义断言**（要求"截断块位于跳转标签之前"，并禁止 `if-ge + :cond_write` 血案形态）；③ 新增**行为级模拟器**（解释执行真实 smali，见 §9） |

## 1) 版本号 + 一句话定位

## 2) 设计目标
上一批虽证伪了"建筑没识别"与"没有目标"两条假设，但因为明细全被截断，**P2（射程）与 P3（没机场⇒不 tick）仍无数据**。本批把明细打通，好让 AD-R1 有据可依。

## 3) 设计规则与判定顺序（修正后）
```
每回合：① 自证 nABOOT（仅首次） ② 计数器归零
③ mline：写 nADM（all/alive/dep/noDep）
④ pline：逐省统计 AAA/雷达/中层雷达 → 累加全局
     若该省 AAA>0 → aline()
⑤ gline：写 nADG   ⑥ trunc：若 skip>0 → 写 nADTRUNC

aline(prov, civ, aaa, turn):
   若 cap >= 40 → skip++；返回            ← 本批修正点（原来是反的）
   cap++
   A   = getAirportsForCiv(civ).size()
   inR = 同省或 ≤300px 的、敌方的、已部署且有活飞机的任务数
   写 nADA t=… c=… p=… aaa=… A=… inR=…
```
