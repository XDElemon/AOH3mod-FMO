- 本批动两个系统：**①雷达盘着色（仅"逐行盘"）**、**②防空射程规则（雷达加成）**，并**修掉一个从 r6d182 就带着的极性 bug**。

## 1) 版本号 + 一句话定位

**r6d185** —— 把"玩家看到的雷达圆盘"里**逐行自绘那一套**改成**饱和蓝**（只改它，贴图套不动）；同时把防空的"雷达加成"从**加法 +150** 改成**乘法 ×1.3**（300 → 390），并顺手修正三处同源分支的**极性反写**。

## 2) 设计目标（玩家可见的问题 + 上层意图）

- 可见问题 A：雷达圆盘颜色反复调不出想要的蓝（历史上还出现过"要蓝的变成绿的"）。
- 可见问题 B：防空射程的"雷达加成"规则与设计不符，且实际生效条件与直觉相反（无雷达反而加成）。
- 上层意图：①把"颜色到底是哪套渲染器在管"钉死，并且让调色变成**改一个参数文件**的事；②把射程规则写成"**同省同时有雷达建筑与反导阵地 ⇒ 原射程 ×1.3**"，其余情况保持 300px。

## 3) 设计规则与判定顺序（若…则…）

**A. 雷达盘的"两套渲染器"（大前提，来自 v119 原生）**

1. 画"**逐行自绘盘**"（`RadarBitmap`）：逐行 `Pixmap.fillRectangle` 填出椭圆 → 整张贴图绘制；**只画"不属于玩家"的省**（`isEnemyProvince`＝`prov.civ != Game.player.iCivID`）。颜色/透明度由代码常量决定。
2. 画"**贴图盘**"（`ProvinceDrawArmy.drawAirForceRadarIcons` 三段）：遍历 `AirForceManager.radarProvinces`（`syncRadar` 扫全地图，凡有 短波雷达 / 长波雷达 / AAA 的省都进集合，**不分国别、无迷雾门**），半径取 `RadarDataManager.getRange("MIDCOURSE_ABM"|"RADAR"|"ABM_SITE")` × 纬度系数；颜色＝`radarFill.png` 本色 × `setColor` tint。
3. 判定顺序（同一帧内）：`RadarBitmap.draw` 先画（他国逐行盘）→ 贴图三段后画（可叠加）。
4. 本批**只改 1 的颜色**，2 的 tint 与贴图 PNG **一律不动**。

**B. 防空射程（本批改的核心）**

1. 入口：`AirForceManager` → `AirDefense.tickTurn()`（每回合一次）→ `tickAll()` 遍历全省。
2. 逐省：有反导阵地（`airDefenseAt(i)>0`）才继续；否则跳过（**不涉及"无雷达不许开火"——本批明确不做这道门**）。
3. 射程 `R`：**若该省有短波雷达 ⇒ R=390**；**否则若有长波雷达 ⇒ R=390**；**两条都没有 ⇒ R=300**（=只有阵地时保持 300）。
4. 命中判定：`AirLat.hit(dx, dy, R, y)`（椭圆，吃纬度，`y`＝开火省中心 Y）——与渲染同口径，**本批不改**。
5. 选靶/发数：走 `eligible → inRange`（唯一射程入口）、`countTargets`、`pickTarget` 轮转、每阵地 1 发——**本批不改**。
6. 红圈（D4）：半径**与判定同源**，必须一起改成同一公式（否则"看得见的圈"与"打得到的范围"脱钩）。

## 4) 参数与阈值表

| 名称 | 当前值 | 单位 | 含义 | 调大/调小 |

## 5) 状态与生命周期

- **逐行盘**：`AirForceManager.syncRadar()`（装填 `radarProvinces`）→ `RadarBitmap.markDirty()` → `draw()` 里 `rebuild()/refresh()`（逐行填 Pixmap → `new Texture(bmp)`）→ `draw()` 贴整张（乘 α）→ 脏则下帧重建。
- **射程判定**：`tickTurn` → `tickAll` → `fireProvince` → `countTargets` → `eligible` → **`inRange`（唯一射程入口）** → `pickTarget` → `applyMdDamage` → `logAD` 写探针 `nAD`。
- **红圈**：`drawAirForceRadarIcons`（D4 段）每帧按"同省是否有阵地/雷达"重算半径后画一次。

## 6) 边界与不变量（对齐 / 不改 / 必须成立）

**对齐**：`inRange` 是射程唯一判定入口（`eligible` 调它）；`AirLat.hit/f` 是唯一纬度口径；`RadarDataManager.getRange` 是贴图盘半径来源。

**明确不改**：
- 贴图盘（本国/图标盘）、飞机雷达圈、**红圈的"配色规则"**（仍为贴图 × (1,0.25,0.25,1)）、机场雷达盘（`drawAirForceRadar` 保持禁用——你确认过是有意为之）。
- 发数规则（每阵地 1 发）、命中率/伤害、AI 与玩家一视同仁、`RadarConfig.json`（**死数据**：`ColorR/G/B/A`、`ShowLayer` 全树无人读取）。

**必须成立的约束**：
- 三处射程公式（判定 / 诊断镜像 / 红圈半径）**数值与极性完全一致**；
- 逐行盘三处分支（长波/短波/AAA）的 tint 保持 1/1/1（若改色只改 `RadarBitmap`，避免"两套一起变"）。

## 7) 玩家可感知的表现

- **正常**：进入游戏后，地图上**逐行自绘的那套雷达盘**呈**饱和蓝**（比之前的浅灰蓝更蓝、更沉）。
- **正常**：某省"有阵地 + 有雷达"时，能打到的距离 =300×1.3=390px；探针 `nADA` 的 `inR` 计数与之一致；同省红圈半径与判定同源。
- **正常**：只有阵地没有雷达 ⇒ 仍然 300px（红圈更小）。
- **正常**：`nAD` 行数在"阵地+雷达"省不减少（本批**不做**雷达许可门）。
- **异常（=bug）**：圆盘颜色没变成饱和蓝 ⇒ 你看到的可能是**贴图盘**（本批未改）；红圈大小与"打得到的范围"不一致 ⇒ D4 段没跟上；探针 `inR` 与判定不一致 ⇒ 诊断镜像没跟上。

## 【本批是"修 bug" ⇒ 三件必须写清的事】

1. **错误的规则是什么**：三处（判定 `inRange` / 诊断 `inR` / 红圈 D4）的雷达加成分支写成了 `if-nez hasRadar → :add` 与 `if-eqz hasLW → :done`，实际语义是"**无短波雷达 ⇒ 加成；有短波但无长波 ⇒ 不加成**"。
2. **正确的规则是什么**：`if-eqz hasRadar → :add`（有短波直接加成）与 `if-nez hasLW → :done`（无长波保持基线，有长波落进加成）⇒ 语义"**有短波或长波 ⇒ 加成；都没有 ⇒ 基线**"。数值同时由 +150 改为 ×1.3（300→390）。
3. **为什么之前会错**：①数值与条件在文档里写的是"有雷达 ⇒ +150"，代码里两条分支的助记符**整对写反**，肉眼读常量（300/450）看起来"对"，属"文本断言与实现同错"型事故；②诊断镜像与红圈是**复刻**同一段逻辑，于是三处一起反、互相印证，更难察觉；③装机版 r6d183 反汇编后跑同一模拟器确认：`(雷达=0,长波=0) → 450`、`(1,1) → 300` —— **反的状态已经在线上跑了**。
4. **症状 ↔ 本次修复的对应关系**：以往"雷达圈与探测距离对不上"的直觉、以及"有雷达的省打不远/没雷达的省反而打得远"这类体感，都可由此解释；本批把三处一起改成正确形态并用**行为级模拟器**（含反转敏感性自检）锁死。
