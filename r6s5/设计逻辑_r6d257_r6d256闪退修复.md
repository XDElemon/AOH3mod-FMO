## 0) 三件事（本批核心）

- **错误的规则（r6d256）**："在 `adFxStep` 里用 **v11/v12** 当 wide 临时对记当前时间，再写 `adFxStepMs`。"
- **正确的规则（r6d257）**："在 `adFxStep` 里用 **v9/v10**（真正的本地寄存器）当 wide 临时对。"
- **为什么之前会错（症状 → 原因）**：
  - 症状：r6d256 装机后**开局闪退**。logcat：`VerifyError: Verifier rejected class aoc...ProvinceDrawArmy`，
    `adFxStep [0x21] instance field access on object that has non-reference type Long (Low Half)`；崩溃在
    `Renderer → InitGame`（类首次被使用时）。
  - 原因：`adFxStep` 声明 `.registers 16` 且带 **5 个参数** ⇒ **v11..v15 就是 p0..p4**（p0 = 目标任务
    `AirMission` 对象！）。`move-result-wide v11` 把 **p0 覆盖成"毫秒低 32 位"（Long Low Half）**，
    随后 `iput-wide v11, p0, ...adFxStepMs:J` 又把这个"数值寄存器"**当对象用** ⇒ ART Verifier
    精准报错并**拒绝整个类** ⇒ 进初始化画面即 FATAL。
- **症状与修复的对应**：日志里的 `[0x21] … Long (Low Half)` 正是那两行插入代码；改成 v9/v10 后
  写法与 A2A 侧 `msFxStep` 的 `msFxStepMs` **完全相同**（它一直工作正常）——同款姿势、同域本地寄存器。

## 1) 版本定位
r6d257 = 修 r6d256 的"开局闪退"；**功能与 r6d256 设计完全一致**（迷雾兜底 + 出入迷雾衔接 + adSpd 钩子），
只是实现层换了个寄存器。坏版 r6d256 归档已按铁律**删除**。

让"迷雾兜底"真正能跑起来：r6d256 因寄存器 bug 连游戏都进不去；本版扫清障碍，其余同 r6d256。

## 5) 状态与生命周期

## 6) 边界与不变量（本版新增工具化边界）
- **寄存器分配不变量（新）**：方法内"可用本地寄存器"上界 = `.registers − 参数槽数（long/double 占 2 槽）− 1`；
  **wide 写（`move-result-wide` / `const-wide*` / `iget-wide` / `sget-wide`）必须让 vN 与 vN+1 都落在本地范围内**。
- 与 r6d256 一致：防双结算 / 可见优先 / 发射侧冻结 / 存档白名单等全部不变。
