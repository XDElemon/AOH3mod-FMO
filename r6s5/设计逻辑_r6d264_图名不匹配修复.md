# 设计逻辑 · r6d264（图↔名不匹配修复）——11 项

> 2026-10-11｜《终序千禧》AI 空军 MOD｜类型：微修复（1 方法；Δ=0）

## 0) 修 bug 三件事（必写）
- **错误的规则**：`genOf` 把表内低 8 位**直接当"代"返回**——但低 8 位实际存的是**图号**（70..133）。
- **正确的规则**：`代 = ((图号-70) >> 4) + 3`（图号→0..63→>>4→0..3→+3→3..6）。
- **为什么会错**：r6d262 打包表时（本人）把图号填进了低 8 位，而读取端按"代"解码（编码/解码不对称）；当时的门禁只测了 `bestIdx`（用桩值测 `genOf`），没有"解码链"的行为模拟——r6d263 修好钳位后，第一个"动代"的图链才把它暴露。
- **症状与修复对应**：'图全锁定最高级（6 代）+ 与名不匹配' ↔ 图号 70..133 被当作代→全部 ≥6→钳位压到 6；修复后图与名同源自同一记录。

## 2) 设计目标
玩家可见问题：图会换但全部最高级、与名不符。目标=图的代与名的记录一致。

## 3) 设计规则与判定顺序
`airImgForTypeP(imgType)`：bestIdx →（记录 idx）→ genOf(idx)=((图号-70)>>4)+3 → pickAirImage(gen, 组, 型) → 图。名字端：bestIdx → keyOf → 翻译。两端 idx 相同 ⇒ 同代同型。
