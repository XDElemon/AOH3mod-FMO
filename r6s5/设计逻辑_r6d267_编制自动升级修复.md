# 设计逻辑 · r6d267（修"J11 编制自动变 J20"）——11 项

> 2026-10-12｜《终序千禧》AI 空军 MOD｜类型：微修复（2 文件，纯 dex）

## 1) 版本号 + 一句话定位
r6d267：把"未盖章"哨兵从 0 改为 -1，修复"合法记录号 0（歼11）被反复重盖章、编制被自动升级"的问题。

## 2) 设计目标（玩家可见的问题）
- 用户实测：造 J11 → 研究 J20 → **J11 编制直接变 J20 编制**（不该变）；
- 目标语义：编制**不随研究自动升级**；只有新造的飞机才带新机型。

## 3) 设计规则与判定顺序（人话）
- 盖章判定：`若 modelAid ≥0 → 已盖章（0 也是合法！）跳过；若 <0 → 未盖章 → 有"当前最佳"则盖之`；
- 建制兜底：桶值仍为 -1（无研究且未盖章）时，编制 aID 写 0（旧观感）；
- 其余（分桶/建更删/贴图链）全部不变。

## 4) 参数与阈值表
| 参数 | 当前值 | 含义 |
|---|---|---|
| 未盖章哨兵 | -1 | 构造器默认；仅此值会被补章 |
| 合法记录号 | 0..N | 0=各型列表第 1 条（如 CN 歼11） |
| 兜底钳位 | aID<0 → 0 | 防 -1 进 UI |

## 5) 状态与生命周期
- 新飞机：ctor 给 -1 → 建造盖章给 best（≥0）→ 之后**永不**被同步改写；
- 旧档：原值保留（被误升的不可追溯，修复后不再发生）。

## 6) 边界与不变量
- 不改存档结构/战斗/科技/贴图链；只动"盖章判定 + 两处钳位"；
- 不变量：任何 ≥0 的章在同步中只读不写。

## 7) 玩家可感知的表现
- 正常：J11 编制（名/等级/图）研究 J20 后**不变**；新造 J20 = 新编制新图；
- 异常（应视为 bug）：编制再出现自发换代。

## 8) 失败与回退
- 无最佳且未盖章 → 留 -1，编制钳 0（旧观感）——正常节流，不算 bug。

## 9) 验收标准（可证伪）
① 造 J11 → 研究 J20：J11 编制不变；② 新造 J20：出现 J20 编制；③ 无崩溃。

## 10) 变更清单摘要
构造器默认 -1；补章守卫 `if-gtz→if-gez`；更新/创建两处 aID 钳位。

## 11) 风险与待办
- 旧档中已被误升的编制无法回溯（需自然换代）；
- 本批流程改动：**装机后不做自动冒烟**（用户指示），由用户手动启动验证——后续批次沿用；
- 三次极性笔误均被门禁拦下（S1–S3/N1–N3 为证）——继续坚持"判定点必须行为模拟"。
