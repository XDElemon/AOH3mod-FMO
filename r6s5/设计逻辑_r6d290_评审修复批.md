# 设计逻辑 · r6d290（2026-10-13）
> 类型：**修 bug + 取证加固批**（依据外部评审 E1–E6）。目标：让"配额烧光/死参/缺数据"不再碍事，为**点击修复**与**布局改造**铺平。

## 1) 版本号 + 一句话定位
- **r6d290**（dex `51ad4bab…`；apk `0cc8efc0…`；装机 i=5，12:26:27）
- 定位：动"探针配额与几何取证"系统；达成 = 每次打开面板都从零开始给证据（评审 E2/E4），0x44 死参接线（E3），补齐 E1 定案所需的 nTTP/nTTD-w/h。

## 2) 设计目标
- 玩家问题：r6d289 修复后的 topVisible 仍待实测；"点不到"待定位。
- 上层意图：**排除取证系统自身缺陷**（配额被主菜单动作烧光、日志只记一次），让下一轮抓样一定拿到"页签点击现场"。

## 3) 设计规则与判定顺序
- 打开面板 → 构造 `addTopTabs` → **首先把全部探针计数清零**：tree{dbgTVB,dbgVIS,dbgMD,dbgMA,dbgMB,dbgMM,dbgAE,dbgTP} + tab{dbgTBG,dbgDRW}。
- 此后每一帧 pin：`nTTP`（前8次/每次打开）记录 pin 入参 (tx,ty)；绘制 `nTTD` 前3次记录（现含 w/h）。
- 点击：actionDown→actionUp→（nMMU/nMMD 前48/32次）→ 派发（nMMA/nMMB）→ 页签（nTTCLICK）。
- 由于清零发生在**每枚菜单构造时**，进入面板后的所有动作都在配额内。

## 4) 参数与阈值表
| 名称 | 值 | 说明 |
|---|---|---|
| nMMU 上限 | **0x30（48）** | 由24提额 |
| nMMD/nMMA/nMMB | 32 | 不变 |
| nTTVB / nTTCNT / nTTIX 相关 | 32/1/3次 | 不变 |
| nTTP | 8次/每次打开 | 新增 |
| nTTD | 3次（现含 w/h） | 扩容 |
| 清零时机 | 每次 addTopTabs | 新增 |

## 5) 状态与生命周期
- 计数字段=static（进程级），但**每次打开面板被主动清零** ⇒ 语义从"进程级一次"改为"每面板一次"。
- `dbgPIN` 仍为实例字段（每实例一次 dump+过滤）。

## 6) 边界与不变量
- 不改任何游戏判定（仅探针 + 构造器 setHeight 接线 + 清零）。
- `TechTopTab.<init>` 新增 `setHeight(p7)`：p7=0x44=68，与 pin 每帧的重算并存（pin 仍以 BUTTON_HEIGHT 覆写，此为“补接线、不改变观感”）。

## 7) 玩家可感知的表现
- 正常：无可见变化（本批不影响画面/交互）。
- 异常：若点击仍未派发，日志将首次完整呈现"按下→选中→抬起→派发"全链（此前配额常在进面板前烧光）。

## 8) 失败与回退
- 回退点：`.pre_r6d290`（TREE/TAB/MN）；归档 r6d289 为回退包。
- 已知：dbgTVB 每开面板重记（评审 E4 的"第二次不再出现"问题已消除）。

## 9) 验收标准（可证伪）
- 打开面板 1 次：出现 `nTTAF land`、`nTTCNT`、`nTTP tx/ty`（1–8行）、`nTTV off/vis`。
- 连开两次：第二次仍出现 `nTTVB/nTTVS` 与 `nTTP`（若不再出现 ⇒ 清零未生效=不通过）。
- 点页签：出现 `nMMD x/y`、`nMMU x/y/id(±px/py/w/h)`，以及是否出现 `nMMA/nMMB/nTTCLICK`。

## 10) 变更清单（规则级）
- **E2/E4 修复**：探针计数在每次开面板时清零；nMMU 上限 24→48。
- **E3 修复**：`newTopTab` 的 0x44 参数接线到 `setHeight(68)`。
- **E1 取证**：`nTTP`（pin 入参 tx/ty）、`nTTD` 增加 `w/h`。
- 门禁新增 **S20**（nTTP/清零/nTTD-w/E3 断言）。

## 11) 风险与待办
- E1 的 pin 公式（`−menuPos+posX` 与 v8 偏移不对称）**本版不改代码，先收 nTTP/nTTD-w/h 数据**再定案（避免拍脑袋改布局公式）。
- 点击尚未修复——等本轮数据（配额已保证不烧光）定位"被谁吃掉/为何不派发"。
- 布局改造（标题上顶/内容到底/中间三按钮）排在点击修复后，是 E1 定案后的下一批。
