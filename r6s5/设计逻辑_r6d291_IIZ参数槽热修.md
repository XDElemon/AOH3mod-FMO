# 设计逻辑 · r6d291（2026-10-13）· 热修：MenuManager 探针"参数槽"崩溃
> 类型：纯热修（1 处寄存器边界）。产物：dex `8b468b52…`；apk `1ebbce158f…`；装机 i=22（12:54:00）。

## 1) 定位
修 r6d290 引入的启动崩溃；其余功能与 r6d290 完全一致。

## 2) 症状 → 原因 → 修复（修 bug 三件事）
- **症状**：r6d291 前版本一进游戏（initGame）即闪退；栈：`VerifyError: MenuManager.actionElement(int,int,boolean) [0x35] tried to get class from non-reference register v1 (type=Integer)`。
- **错误规则**：IIZ 探针里把 `v1` 当局部计数器/临时寄存器写。
- **正确规则**：该方法 `.registers 5`、参数 4 槽（this+3）⇒ **局部上界 = v0（只有 1 个！）**；`v1` 实际就是 `p0=this`。写 v1 = 把 this 覆盖成 Integer。
- **为何之前会错**：写探针时按“v0/v1 都是临时”套模板，没有逐方法做“寄存器分区核对”。
- **修复**：`.registers 5 → 6`（局部扩到 v0..v1），探针无需改；反汇编复核确认 `const/16 v1,0x20` 已落在真局部。
