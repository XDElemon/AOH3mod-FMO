# 设计逻辑 · r6d300（2026-10-13）· 全屏布局：标题贴顶 / 按钮带 / 科技区到底（全分辨率自适应）
> 类型：**功能批**（布局改造）｜依据 `调研_全屏布局_v1.md` + `调研_r6d300_r2/r3`。

## 1) 版本号 + 定位
r6d300：把科技树从"居中悬浮窗"改成"**全屏栏**"——标题贴屏顶、科技画布直落屏底、三个切换按钮安置在两者之间的空带；所有几何改为**运行时量**推导，任意分辨率成立。

## 2) 设计目标
- 玩家可见问题：树窗上下都在"浪费屏幕"（上被资源条顶开 132px、下空 132px、按钮还叠在树顶上）。
- 上层意图：科技树是全屏工作台，可视科技区最大化；按钮不再遮挡内容；换机不改数值。

## 3) 设计规则与判定顺序（人话）
- 若打开科技树 → 菜单 y = **标题图高**（标题栏画在菜单原点上方，于是标题上沿=0）。
- 菜单高 = **屏幕高 − 标题图高** ⇒ 菜单/画布底边 = 屏幕底。
- 切换按钮带：每帧钉在 `菜单y + 2×PADDING` 起、高 BUTTON_HEIGHT（相对定位，自动跟着走）。
- 科技节点与连线：整体下移 `2×PADDING + BUTTON_HEIGHT + 5`（= 按钮下留 20px 的净增量；节点原带 15 的留白，故 +5）。
- 底板高 = **max(内容底, 可视高)**：正常情况下=可视高（底到屏底）；小屏内容更高时允许纵向拖动。
- 顺序：构造函数定几何 → 每帧 pin（首帧含一次 relayout/重建连线）→ 其余逻辑零改动。

## 5) 状态与生命周期
无新实体。树：new → ctor 定几何（新规则）→ 每帧 pin 按钮 → 点击/切栏走 applyTopFilter → 关闭销毁。重走 ctor 的"重建路径"自动获得新几何。

## 6) 边界与不变量
- 对齐/不动：pinTopTabs 相对公式、relayout*/isInView 保底、连线重建、重建入口、语言包、滚动 X 逻辑——**全部不碰**。
- 必须成立：`maxY ≥ iHeight`（防拖动范围反转）；页签 rel y 仍 = 2×PADDING。
- 明确修改的东西：仅 `InGame_TechnologyTree.smali` 的 5 处几何。

## 7) 玩家可感知
- 视觉：标题栏贴顶；按钮横带居中；树画布/边框直落屏底。
- 正常：任何分辨率下形态一致；切栏即显、点科技留栏（不回退）。
- 异常（本版应看不到）：标题不贴顶 / 按钮叠内容 / 底部留缝 / 切栏空白。

## 8) 失败与回退
- 锚点计数≠1 → 拒绝写盘（本次一次通过）。
- 汇编期抓到一次格式红线：`add-int/2addr v19,…` 非法（12x 格式寄存器域 4 位，v19 超界）→ 改 `add-int v19, v19, v0`（23x，8 位域）后通过。
- 真机异常 → 归档回退 r6d299。

## 9) 验收标准（可证伪）
1. 肉眼：标题上沿=屏顶；三按钮在标题下方空带；科技区底=屏底。
2. 探针：`nTTG2 o=(0,60)`、`t0.y≈72`、`nTTG h=1020`（屏幕 1080 时）。
3. 功能回归：切栏/点科技/页签点击与 r6d299 行为一致。
4. 门禁：check_r6d300 全绿 + sim_layout_r6d300 多机型全绿（已跑）。
看到以上=通过；出现任一异常项=不通过。

## 10) 变更清单摘要
E1 菜单 y→titleH；E2 高度→屏高−titleH；E3 底板高=max(内容,可视)；E4 节点+Δ；E5 cyOf+Δ。另：新增门禁/模拟器（toolchain 已并行归档）。

## 11) 风险与待办
- 风险：标题覆盖顶部资源条（**预期**，z 序由科技树置顶保证）；小屏需纵向拖动时内容可能在屏外（可拖，正常）；屏幕极矮时按钮带以下内容更少（设计使然）。
- 待办：用户实测（本条挂在世界书）；GitHub 仍暂缓（按用户指示）。
