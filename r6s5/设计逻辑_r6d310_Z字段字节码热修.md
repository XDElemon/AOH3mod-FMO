# 设计逻辑 · r6d310（2026-10-14）· 修 bug：r6d309 开局闪退（Z 字段字节码规格）
> 类型：**修 bug（热修）**｜依据崩溃栈与审计报告。

## 1) 版本号 + 定位
r6d310：修掉 r6d309 的"进游戏即闪退"——布尔字段 `scxOn:Z` 用了 int 版 `sget/sput` 访问指令。

## 2) 设计目标
- 玩家可见问题：安装 r6d309 后 GLThread 在 AA_Game.initGame 抛 `VerifyError: expected field …scxOn to be of type 'Integer' but found type 'Boolean'`（以及 actionDown 的 put 类型不符）⇒ 拒类 MenuManager ⇒ 启动即崩。
- 上层意图：保留 r6d309 的"科技树自有增量滚动"，只修正访问指令规格。

## 3) 设计规则与判定顺序（人话）
- 错误规则：以为 `sget/sput` 对布尔字段（Z）也能用（字节码层面会被当成 Integer 存取）。
- 正确规则：**Z 字段必须用 `sget-boolean` / `sput-boolean`**（实例字段同理用 `iget-boolean`/`iput-boolean`）；否则 verifier 直接拒类。
- 修法：`scxOn:Z` 的 1 次读、2 次写全部改为 `-boolean` 形式。

## 4) 参数与阈值表
本版无参数变化（仅指令规格）。

## 5) 状态与生命周期
无变化；scxOn 语义同 r6d309。

## 6) 边界与不变量
- 仅改 3 处指令助记符（sget→sget-boolean ×1；sput→sput-boolean ×2）；
- r6d309 的主体（:cond_6b 自有滚动、actionDown 复位、scuLog/scaLog）逐字保留；
- 审计器新增 **E 类检查**：我们改动的行里出现"普通 get/put + Z 字段"⇒报红。

## 7) 玩家可感知
- 修复前：启动闪退；修复后：正常进游戏（原生路径 100% 与 r6d309 设计一致）。

## 8) 失败与回退
- 门禁 check_r6d310（S1–S5+N1–N2）全绿；模拟器全绿；三件套/八件套过；审计增扫 E=0。
- 回退：r6d308（上一安全版）。
