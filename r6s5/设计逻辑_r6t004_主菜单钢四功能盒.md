## 1) 版本号 + 一句话定位

**r6t004**：动的是"主菜单功能入口"——新增 `HoiBox`（盒子绘制）+ `HoiButton`（条目按钮），把 继续/新游戏/载入/设置 四个入口以居中纵向列表呈现；动作全部沿用原版实现。

## 2) 设计目标

- 问题：r6t002 清掉原面板后，主菜单只剩 TNO 三按钮（新游戏/编辑器/退出），没有读档、设置、快速继续入口。
- 意图：按用户指定的"钢四式居中框"补齐功能；外观扁平深色；动作零新增逻辑（全部抄原版）。

## 3) 设计规则与判定顺序

1. **进入主菜单**：`MenuManager` 重建 `MainMenu` → 构造器依次调用：
   - `TnoBlock.populate(list)`（清空旧元素 + 加入 TNO 三按钮）；
   - `HoiBox.populate(list)`（追加 0–4 个条目）：
     - 若 `MainMenu.canContinue` 为真 → 加「继续游戏」（mode 0，文案 lang("Continue")）；
     - 加「开始新游戏」（mode 1，lang("NewGame")）；
     - 加「载入游戏」（mode 2，lang("LoadGame")）；
     - 加「设置」（mode 3，lang("Settings")）。
2. **每帧绘制**（`MainMenu.draw`）：TnoBlock.draw → **HoiBox.draw**（画盒子：边框底 + 深色底 + 按钮间分隔线）→ `super.draw`（元素层，所有按钮绘制在盒子之上）。
3. **条目按钮视觉**（HoiButton.drawButtonBG）：若 active → (0.26,0.27,0.32,0.95)；否则若 hover → (0.20,0.21,0.25,0.92)；否则 → (0.13,0.14,0.17,0.88)。填充用 `Images.pix` 纯色矩形；文字用游戏默认按钮文字色（`Button.getColor`）。
4. **点击动作（逐字抄原版）**：
   - 继续：`View.IN_GAME` + `setViewIDWithoutAnimation` + `setOrderOfMenu_InGame` + 地图模式复位 + `ProvinceDraw.updateDrawExtraDetails()`（＝原 $2）；
   - 新游戏：`View.SCENARIOS` + `setOrderOfMenu_Scenarios()`（＝原 $5）；
   - 载入：`View.LOAD_GAMES_LIST`（＝原 $9）；
   - 设置：`Settings_Menu.goBackToMenu = View.MAINMENU` + `View.SETTINGS`（＝原 $11）。
5. **自证**：populate 每次执行写一行 `nTNO4 v=r6t004 box=1` 到 `aircfg_diag.txt`（dWrite）。

## 5) 状态与生命周期

- `HoiButton`（元素）：随主菜单实例创建/重建；无静态状态。
- `HoiBox`：全静态工具；`canContinue` 在 populate 与 draw 各读一次（有无存档即时反映）。
- 交互：点击由菜单元素系统分发到 `HoiButton.actionElement`。

## 6) 边界与不变量

- 不动：TNO 块/三按钮、背景体系、原版任何既有类（只新增两文件 + MainMenu 两行）。
- 无新素材：纯色块用 `Images.pix` 绘制；文字复用游戏字体与默认按钮文字色。
- 不变量：四个入口动作必须与原版一字不差；"继续游戏"仅当 `canContinue` 为真出现。

## 7) 玩家可感知的表现

- 正常：主菜单上中部出现深色盒子，纵向 3–4 条；悬停条目高亮；点击分别：直接继续存档 / 进选局 / 进读档列表 / 进设置。
