# 调研 · B3 R2b：乙方案"开局起始科技"机制全链（第一遍 · 实证）

> 2026-10-10｜只读勘察｜**结论：乙＝纯数据可实现（无需改代码）**；全链已实证（smali 行号见下）。

## 1) 机制链（证据）
1. **数据源**：各剧本 `Data.json` 的文明条目可带 `TechnologyID`（现况：WW2 有 48 条、USA_States 51 条；qianxi 等为 0 条）；缺失/负值 → 回落剧本级 `Details.CivDefault_Technology`；哨兵 `DEFAULT_VALUE=-2`。（Civilization@1963 区域）
2. **发放**：`buildTechTree_UnlockTechnologies(ID)` ＝ 标记 ID 已研究 ＋ **递归把 RequiredTech / RequiredTech2 全祖先链一并标记**（TechQueue1/2 @2050/2136，Civilization@6035）。
3. **生效**：初始化随后**遍历所有"已研究"节点**逐个 `addTechnology(id, loadScenario=true)`（@1993-1995）；该方法把 `lTechUnlocksUnits[id]` 的单位加入 `unlockedUnits`（@2101-2103），末尾 `updateBestUnits()` 重算（@1999）。
4. **使用**：招募/升级/可研究判定本就按 `getTechResearched(...)` ⇒ **开局即全部生效**。

## 2) "3代包"设计（每国一个起始节点）
- 每国 4 个 3 代机型节点（CN：J-11/J-8/Q-5/H-6 …）通过 req(req2) 链互相挂接，链顶（或增设"XX3代空军"入口节点）作为该国 `TechnologyID` 目标 ⇒ 一次发放＝整包点亮。
- **连带解锁（说明）**：素材中横跨多代的机型，其全部档位会随包一起解锁（"同型号只研究一次"的自然结果）：

| 国 | 附带解锁的档位 |
|---|---|
| CN | 4攻（J-11） |
| US | 无 |
| EU | 4战 / 4截 / 4攻 / 4轰 / 5轰（台风 / 鹰狮 / 狂风） |
| RU | 4截 / 4轰（MIG-31 / TU-160） |

（分离这些档位＝把同型号拆成两次研究，与既有裁定冲突，不做。）

## 3) 工作量（乙的代价盘点）
- 六剧本国家条目 ≈ **955 条**（qianxi 236 / ModernWorld 236 / WW2 182 / USA_States 51 / brazil 27 / SouthAmerica 223）→ 每条写入"3代包"ID；组别沿用 `artGroupOf` 前缀表（中/欧/俄/美，默认俄）。
- 覆盖率校验＝上线门槛：每国必有合法值，**漏网=0**。
