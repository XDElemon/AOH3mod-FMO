## 1. 施工目标（口径 B 最终形态）

在 **`executeAIAssignment(I)` 的机场级门**上补一条"玩家机场 + 自动打击开 ⇒ 放行"，**其余一切照旧**：

```
若 mode == Mode.AI                    ⇒ 派发（不变）
否则若 无玩家（playerCivID < 0）       ⇒ 派发（不变，观战场景）
否则若 机场.civID != 玩家 civID        ⇒ 跳过（不变）
否则若 机场.autoStrikeOff != 0         ⇒ 跳过（不变：玩家机场默认就是跳过的）
否则（＝玩家自己的机场 且 开关为"开"） ⇒ 派发  ★新增
```

## 3. 施工文本（整块替换，B → B'）

**B（旧，逐字）**
```smali
    if-ltz v4, :cond_65

    iget v3, v2, Laoc/kingdoms/lukasz/map/battles/Airport;->civID:I

    if-ne v3, v4, :cond_62

    goto :goto_65
```

**B'（新，逐字）**
```smali
    if-gez v4, :cond_62

    iget v3, v2, Laoc/kingdoms/lukasz/map/battles/Airport;->civID:I

    if-ne v3, v4, :cond_65

    iget-boolean v3, v2, Laoc/kingdoms/lukasz/map/battles/Airport;->autoStrikeOff:Z

```

代码单位增减：`if-ltz`→`if-gez`（同宽 2 units）｜`if-ne`→`if-ne`（同宽，仅目标变）｜删 `goto`（1 unit）加 `iget-boolean`（2 units）+`if-nez`（2 units）⇒ **净 +3 code units**（6 字节）⇒ 本方法内所有分支偏移仍远小于 127（最近跳转 ≤10 units）⇒ **无跳转拓宽（无需 goto/16）**。

## 4. 真值表与极性（逐条；写反会怎样）

| # | 判据 | 正确写法 | 目标标签 | 写反的表现 |
|---|---|---|---|---|
| ① | 模式门 | `if-eq v3, v4, :cond_62`（**不动**） | 派发 | 改成 if-ne ⇒ AI 机场全部不派发（AI 侧崩） |
| ② | 无玩家 | `if-gez v4, :cond_62` | **派发** | 写成 `if-ltz` ⇒ 观战/无玩家场景从"派发"变"跳过"（行为回退） |
| ③ | 文明比较 | `if-ne v3, v4, :cond_65` | **跳过** | 写成 `if-eq …:cond_65` ⇒ 玩家机场永跳过（＝本 bug 原样）；写成 `if-ne …:cond_62` ⇒ AI 非 AI 机场误入老路（nA2L 空转回归） |
| ④ | 开关 | `if-nez v3, :cond_65` | **跳过**（`!=0`＝关） | 写成 `if-eqz` ⇒ 语义变成"开关打开＝跳过"，开关**反向**（这正是本项目反复踩的"归零/非零侧"坑） |

**极性自证（引擎既有用法）**：`a1Scan:874`／`a1bScan:2436` 处 `iget-boolean …, LAirport;->autoStrikeOff:Z` 紧跟 `if-nez …, :跳过` ⇒ **非 0＝跳过＝关闭**，与本文第 4 行一致（不靠记忆，靠同文件同字段的既有用法）。

## 10. 【设计逻辑】（交付时可直接复用，11 项）

1. **版本 + 定位**：r5c046n（暂定）——只动"玩家机场能否进入自动指派"这一个门；达成"自动打击开关真正生效"。
2. **设计目标**：玩家可见问题是"按了自动打击开关没反应"；上层意图＝让 `autoStrikeOff` 成为真实开关（与作者在 `a1Scan` 的用法、UI 默认值、按钮翻转三者语义一致）。
3. **判定顺序（人话）**：见 §1 五条"若…则…"；先后次序固定为 **模式 → 无玩家 → 文明归属 → 开关**，前一条命中即不再判后面。
4. **参数与阈值表**：10% 概率门（`0.1f`，不变）｜派发机型 `BOMBER`（不变）｜每回合每机场 1 次尝试（`update(civ)` 频率决定）｜`autoStrikeOff`：`0=开`、`!=0=关`（默认 1）。
5. **状态与生命周期**：机场 `mode`（UI/`toggleAirportPatrol` 设置、存档持久化）→ 门判定 → `executeAIAssignmentForAirport` → 任务入 `activeMissions` → 结算链照旧；本版**不新增任何字段/状态**。
6. **边界与不变量**：AI 侧零变化｜无玩家场景保持派发｜不新增字段、不改存档｜不提高 `.registers`｜玩家/AI 不重复派发｜内层 `nA2L` 原样保留。
7. **玩家可感知**：打开开关后，交战时自己的机场会**自动出动轰炸机**（10%/回合/机场）；关闭开关或旧档（默认关）行为与今天完全一致；信息条暂无开关状态反馈（登记待办）。
8. **失败与回退**：正常"不出兵"＝骰未中／未交战／无可见目标／无闲置轰炸师（都由下游静默返工，非本版 bug）；异常＝`nA2L` 归零（AI 侧被误伤）⇒ 立即回滚 `.pre_r5c046n`。
9. **验收（可证伪）**：见 §7 六条；核心三条＝①该省出现 `nA4*` 序列 ②`nA2L` 保持旧量级 ③未按开关的机场行为不变。
10. **变更清单**：E1/E2/E3（§9）。
11. **风险与待办**：已知"开关无 UI 反馈"、"与手动出击可并存"（同 base 时代）；下一批候选＝开关状态显示、`nA*` 探针清理、以及"是否把 `autoStrikeOff` 也纳入 AI 侧（不需要：AI 由新线负责）"。
