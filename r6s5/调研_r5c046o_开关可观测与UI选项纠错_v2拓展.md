## 4. 历史成因（为什么会有这个坑）

1. `iActiveID` 初值 -1 + 五处静默钳位是**原版设计**（面板未选中时退化为"作用于第 0 个机场"）。
2. 我们 v83 给按钮加了**动态文本**（`getTextToDraw` 显示「自动巡逻：开/关」「自动打击：开/关」）——但文本用的是**同一套钳位**，于是"显示的状态"与"实际对象"都指向第 0 个机场，用户以为自己看的是当前机场 ⇒ 观感"全关了还在出动"。
3. 实测佐证：r5c046n 场次中 `k=0`（成功派发）全部集中在后半段、且**最后一次之后 12% 的切片完全安静** ⇒ 开关本身有效，问题在"看不出作用于谁"。

## 5. 边界与不变量

1. **A 纯日志**：不改变任何控制流；不新增字段；不动 `.registers`（`p0Air` 保持 10）。
2. **B 只在"越界/未选中"时改变行为**：`iActiveID` 合法时行为与 r5c046n **逐字相同**。
3. 不新增静态字段、不改存档、不改任务创建与开关语义。
4. 不提高任何方法的 `.registers`（`actionElement` 11 / `getTextToDraw` 8 / `p0Air` 10 全部保持不变）。
5. 新增标签不得落在方法尾部（其后必须有指令）。
6. 探针命名约定：沿用 `e5i`（进 key 日志、不限流）；**不用 `logOnce`**（500 ms 全局限流，历史教训 ㊿）。

## 6. 失败模式与回退

| 风险 | 表现 | 处置 |
|---|---|---|
| 标签写错 / 语法错 | `RunSmali` 汇编失败（必须校验输出含 `result=true`） | 拒绝出包；回滚＝重装 r5c046n |
| `v` 区越界 | 汇编期报 `Invalid register` | 同上（本批不新增寄存器使用，风险极低） |
| Toast 空指针 | 面板未初始化时 `menuManager` 为 null | 用 `if-eqz … :skip` 守卫（照抄既有模板） |
| 按钮"未选中时不动作"被玩家当成坏了 | 按了没反应 | **同帧弹 Toast「请先选择机场」** + 探针 `afp:noSel` ⇒ 有提示、可诊断 |
| 日志体量增长 | `nA2m/nA3b` 每行 +10% | 已知、可接受；如需可后续只在 `nA2m` dump 加（`nA3b` 复用同一方法，无法单独裁剪） |
| 显示文本变更影响判读 | 旧判读键不受影响（新文本只在未选中时出现） | — |
