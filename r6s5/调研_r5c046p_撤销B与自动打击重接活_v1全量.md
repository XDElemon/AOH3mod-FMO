## 1. 直接结论（先说结论）

**是我的 r5c046o-B 改动把按钮弄哑的，不是"开关没接活"。**
本场（o 装机后）日志证据：

| 探针 | 值 | 含义 |
|---|---|---|
| `afp:noSel` | **9** | 你按了 9 次任务按钮，全部落到我新加的"未选中"分支 |
| `afp:press ap=` | **0** | **一次都没有真正执行**（原逻辑完全没跑到） |
| ` strike=` | 9822 条**全 =1（关）** | 九个机场的开关一直没被改成"开" |
| `nA4e k= a=0` | 60 | 这 60 次派发**不是**开关打开的机场——是 `mode==AI` 的那些机场走了门①（`mode==AI ⇒ 派发`，本就无视开关） |

⇒ 你按「自动打击」想把它打开，但**按钮被我的分支拦下**，所以既没有 Toast 之外的效果、` strike=` 也永远是 1。

## 2. 引擎原本的设计（为什么会有"静默落到第 0 个机场"）

| 位置 | 行为 |
|---|---|
| `InGame_AirForceOptions.<clinit>` [26] | `iActiveID` 初值 **-1** |
| `MenuManager.setVisibleInGame_AirForce` [38655-38661] | **关闭空军界面时**把 `iActiveID` 复位成 **-1** |
| 同上 [38663-38712]（`:cond_35`） | 打开界面时若 `iActiveID<0` ⇒ **显示"机场列表"屏**（`IN_GAME_AIRFORCE`）并**隐藏司令部屏**（`IN_GAME_AIRFORCE_OPTIONS`） |
| `InGame_AirForce$BtnAirport.actionElement` [44-54] | 点列表项 ⇒ `sput iActiveID = airportIndex` ⇒ `setVisibleInGame_AirForce(true)` ⇒ 切到司令部屏 |
| `BtnMission` 的 4 处读点（含我改的 2 处） | 原版一律 `iActiveID<0 ⇒ 0；≥size ⇒ 0`（**静默作用到列表第 0 个机场**） |

⇒ **引擎自己的兜底**是"没选中就用第 0 个机场"，而且它把"选没选中"用**显示哪个屏**来区分。
⇒ 于是：**在"列表屏"上按钮依然可点**（按钮属于司令部屏但屏幕上可见/可点），此时 `iActiveID=-1` ⇒ 原版会作用到第 0 个机场（＝你之前遇到的"关了它还在动"）；而我改成"不动作" ⇒ **直接哑掉**（＝这次的现象）。两种都不对。

## 3. "该以什么为准"——正确的默认目标（可用现成 API）

| 候选来源 | 字段/方法 | 说明 |
|---|---|---|
| ① 面板选择 | `InGame_AirForceOptions.iActiveID`（+`getAirportsForCiv(player)`） | 点了列表就用它（**首选**） |
| ② 当前打开的机场省 | **`AirForceManager.selectedAirportProvinceID`**（`GameActiveProvince:1562` 写、`Game:15581` 写、`ProvinceDraw:908` 读） | 权威"我打开的机场是哪个省" |
| ③ 反查 API | **`AirForceManager.getAirportByProvinceID(I)Airport`（AFM:8283）** | 省 → 机场对象（现成，无需自造） |
| ④ 再兜底 | `Game.iActiveProvince`（`Game:15585` 写） | 当前激活省 → 再走③ |
| ⑤ 最后兜底 | 原版行为 `list[0]` | **绝不让按钮变哑**（保底可操作） |

⇒ 正确形态应为：`iActiveID 合法 ⇒ 用它；否则 selectedAirportProvinceID → getAirportByProvinceID；再否则 iActiveProvince；全失败 ⇒ list[0]`。
这样既"永远能按"，又"作用在你打开的那个机场"——正好满足用户"默认就该选中那个机场"的预期。
