## 2. 性能与副作用（必须写清）

- `getTextToDraw` **每帧都会被调用**：现版它自己已经在每帧调 `AirForceManager.getInstance()` + `getAirportsForCiv()` + `size()`；
  新增的 `pickAirport` 在此基础上最多多 1 次 `getAirportByProvinceID`（`allAirports` 的 Map 查询，O(1)）。
  ⇒ **量级不变**；仍不建议更重的操作（如遍历全部省）。
- 纯读：不写任何游戏状态；只多两条日志探针（按键时 `afp:press ap=`、走兜底时 `afp:tgt fb=`），**无每帧日志**。

## 4. 历史成因（为什么会有这个坑，必须入档）

1. 原版：`iActiveID` 初值 -1；**关屏复位 -1**；开屏时 `iActiveID<0` ⇒ 引擎改显示"机场列表"屏；任务按钮在"列表屏"下**依然可点**，此时原版**静默落到 `list[0]`**。
2. `r5c046o` 的 B 把这条静默兜底**换成"提示+不动作"** ⇒ 在"列表屏"下按键全部变哑（本场实测 `afp:noSel`×9、`afp:press`×0）⇒ 用户报"按钮没接活"。
3. 正确形态＝**保留"永远能按"**，但把落点从"第 0 个"升级为"**你打开的那个机场**"（①→④ 兜底）。

## 5. 边界与不变量

1. **按钮永远不会哑**：`pickAirport` 在"有玩家且该玩家有≥1 个机场"时**必返回非 null**（最差 `list[0]`）。
2. 不恢复任何"未选中机场 / 请先选择机场 / 不动作"文本与分支（用户明确要求取消）。
3. 不提高既有方法的 `.registers`（`actionElement` 11 / `getTextToDraw` 8 保持不变）；新方法 `pickAirport` 自定 `.registers`（≤16，实测需要 6）。
4. 不新增静态字段/不改存档/不改派发与开关语义。
5. 新标签不得落在方法尾部。
6. 探针只走 `e5i`（key 日志、不限流），**不用 `logOnce`**。

## 6. 失败模式与回退

| 风险 | 处置 |
|---|---|
| `pickAirport` 返回 null（无玩家/无机场） | `actionElement` 直接 `return-void`；`getTextToDraw` 落到原有 `:cond_3d`（返回 super 文本） |
| 兜底 ②③ 都查不到机场（省没有机场） | 顺序继续 → ④ `list[0]`（不会卡死） |
| 新方法寄存器/标签写错 | 汇编失败即拒绝出包；回滚＝重装 r5c046o |
| 每帧多一次 Map 查询 | 已评估：O(1)，量级不变（见 §2） |
| 用户"点了列表但 `iActiveID` 仍 -1"的老现象 | 现在会走 ②/③ 兜底 ⇒ 仍**打到"你打开的那个机场"**（这正是本次修复的目的） |
