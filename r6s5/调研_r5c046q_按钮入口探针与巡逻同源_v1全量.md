## 0. 本批要解决的三个问题
1. 按钮按下无反应（`afp:press` 两次会话均为 **0**）；
2. 文本显示与实际机场不符（解析 95% 落到 `list[0]`）；
3. 由此导致"自动打击开关翻不到开" ⇒ **攻击机线/轰炸线对玩家全被门挡**（用户报"不派攻击机"）。

## 1. 两条智能线的真实结构（本轮更正上一轮的错误结论）

| 线 | 入口 | 逐机场门（玩家机场） | 门后动作 |
|---|---|---|---|
| 轰炸线 `a1Scan` | `update(I)`(9942) → `strikeTick_A1(I)`(10123) → `a1Scan(p0)`(6730) | AFM **866-874**：`player.iCivID == airport.civID` ⇒ 读 `autoStrikeOff`；**必须 `==0`（开关开）** 才继续 | 设 `a1PkTier/a1PkPid/a1PkScore` → 轰炸派发 |
| **攻击机线 `a1bScan`** | 同上 → `a1bScan(p0)`(**6732**) | AFM **2415-2455**：同款玩家门（`autoStrikeOff==0` 才继续），AI 机场直接过；**线级 K 门**：`a1CivInflight(civ, ATTACK_ARMY) >= 3 ⇒ nP2cap 退出` | `a1bPick(ap,p0)` → **`a1bDispatch`(1488)** → `AirMission.createAttackArmy`(**1532**) |

⇒ **攻击机自动打击确实存在**（计划书 §1743/2030/2190：`nA1b ap=` k=0 实测 48 次成功建任务＝"攻击机真的起飞"）。上一轮我"老路从不造攻击机"的说法只对**旧路**（`executeAIAssignmentForAirport`）成立，**不适用于本线**。

## 2. 攻击机/轰炸机不派的直接原因（本次会话日志硬证）

| 证据 | 值 | 含义 |
|---|---|---|
| ` strike= a=1` | **3948 条全是 1** | 九个机场「自动打击」**全是关**（1=关/0=开） |
| `nA2m mode=` | 全 `1`(=OFFENSIVE) | 不是 PATROL |
| ⇒ 结论 | `a1bScan`/`a1Scan` 的玩家门每次都把玩家机场跳过 | **两条线都不派 ⇒ "不派攻击机"＝开关没打开** |

⇒ **"不派攻击机"与"按钮没反应"是同一个根因**：按钮没响应 ⇒ 开关翻不过来。
⇒ **D（在老路补攻击机派发）不需要做**：智能线本就派攻击机，只要开关能开。

## 3. 按钮链（用于定位"按下无反应"）

```
手指 → MenuManager.actionElement(menuIdx, elId, isHold)  [MenuManager:5653(PPM)/5669]
     → Menu.actionElement(I)  [Menu.smali:752]  ── try/catch Exception ⇒ CFG.exceptionStack
     → MenuElement.actionElement()（基类＝空实现，MenuElement:111）
     → BtnMission.actionElement()（本类覆写，唯一入口）
```
- `getTextToDraw()` **只被 `draw()` 调用**（`Button.drawText`）⇒ 每帧调用 ⇒ 它是"代码是否在跑"的探针（`afp:tgt` 1115 次 ✓）；
- `autoStrikeOff` / `stopAirportPatrols` 全树 **UI 侧只有 `$BtnMission` 会写** ⇒ 你按的键一定是这个类；
- `Menu.actionElement(I)` 与 `MenuManager` 都**没有**点击总探针可借（历史未埋）；
- logcat 里**没有任何** `Menu`/`BtnMission`/`Airport` 的异常；735 次异常全部是引擎自带的 `ProvinceNamesManager:431`（每帧 `get(0)` on 空表，**该类 smali 无我们的探针**，非本批）。

## 4. 关键未知项（本批必须用探针切开）
`afp:press` 为 0 的两种可能，**互斥**：
1. 点击没派发到本类（元素 id 对不上／被上层菜单吃掉）；
2. 点击到了，但 `pickAirport()` 返回 null ⇒ 走了 `if-nez v0, :pn_end` 提前返回
   （**但这会同时让按钮文本变成父类默认文本**，与用户看到的「…：关」矛盾 ⇒ 可能性低）。

⇒ 本批埋 **入口探针 `afp:ent`（方法第一行）** ＋ **空值判别探针 `afp:null`**，一次点击即可判定，不再靠推理。
