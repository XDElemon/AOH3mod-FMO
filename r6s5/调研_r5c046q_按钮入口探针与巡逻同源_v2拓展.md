# 调研 · r5c046q — v2 拓展调研

## 1. 上下游与生命周期
- 上游：`MenuElement.actionElement()`（虚调用）；`actionElement` 内部被 `try/catch Exception` 包住（异常只进 `CFG.exceptionStack`，界面表现为"按了没反应"）。
- 下游（本类）：`pickAirport()` → 设置 `Airport.mode` / 翻转 `autoStrikeOff` / `stopAirportPatrols(provinceID)` / `rebuildInGameAirForce()`；巡逻键与打击键共用同一段顶层解析（`v0` = 机场）。
- 被消费者：`a1Scan`(866-874) / `a1bScan`(2415-2455) 读 `autoStrikeOff`；`Airport.mode` 供巡逻链消费。

## 2. 边界与不变量（本批硬约束）
1. **只改一个文件**：`aoc/kingdoms/lukasz/menusInGame/AirForce/InGame_AirForceOptions$BtnMission.smali`。不动 AFM / Menu / MenuManager / 其它按钮类 / quick 栏 / 存档。
2. `actionElement` **不得新增"提前 return"**：除"列表为空"（引擎原版同义）外，任何失败都必须落到 `list[0]`；
3. 现存方法 `.registers` **不得上调**（`actionElement` 11 / `getTextToDraw` 8 / `pickAirport` 7）；
4. `afp:press ap=`、` strike=`（AirDbgLog.p0Air）保留；
5. 探针**不得放在会被异常跳过的位置**：入口探针放 `actionElement` 第一条指令（`const/4 v0,0x1` 之前）；
6. 巡逻分支文本端改用同一解析器（否则两个键"显示/实际"脱钩，正是用户看到的"像默认开启"）。
