# 调研 · r6d019（对外干净版：关闭探针）

> 目标：出**正式对外版**——所有调试探针默认静默（不再往 `airdbg_key.txt` 写任何字节），功能与 r6d018 完全一致。

## 第一轮：全量调研（探针是怎么落盘的）
- 探针唯一漏斗：`aoc/kingdoms/lukasz/map/battles/AirDbgLog.dKey(String,String)I`
  - 结构（`.registers 10`，locals v0..v7，params p0/p1）：
    ```
    [空判]  if-eqz p0, :cond_63
            if-eqz p1, :cond_63
    :try_start_4  Log.d → StringBuilder 累积 → 距上次 flush ≥ 500ms 才写文件
                  → FileWriter(append) 写 /storage/emulated/0/Android/data/<pkg>/files/airdbg_key.txt
    :cond_63  const/4 v0,0 → return v0
    :catch_65 → return 0
    ```
  - **所有**探针（`afp:*`/`nA*`/`p1b*`/`aiBldS`/`dcfg*`/`e5*`/`p0*` 等）最终都走 `dKey`（或走它包裹的 `d*`/`logOnce`）。
- **r6d011 的临时改动**：把 `dbgOn` 总闸**摘掉**（诊断期探针恒开）⇒ 本次要**恢复**。
- 写盘开销全在 `dKey` 内部（`FileWriter`+`flush`），闸一旦恢复，写盘即完全不发生。

## 第二轮：拓展调研（上下游 / 不变量 / 血案）
- `dbgOn` 写入点：由配置驱动设置（`demoLoadCfg` 里依据 `dgDebug` 写入 `dbgOn`）；`dgDebug` 的默认值在 AFM `<clinit>` 里＝**0**（r6d012 引入）。
- ⇒ **两道保险**：①设备配置文件 `debug: 0` ②代码默认值 0（配置文件缺失/读不到也静默）。
- 血案对齐：
  - 「标签不得放方法尾部」⇒ 本次**只往方法开头插 3 行**，跳到既有 `:cond_63`（该标签已在用、位置合法）。
  - 「寄存器不得越界」⇒ 只用 `v0`（locals=8 内）✔。
  - 「move-result 紧邻 invoke」⇒ 本次不新增 invoke，不涉及。
  - 「不要整段替换」⇒ 本次只**插入**（并删掉 r6d011 那行注释）。
  - 「插入点必须在 try 之前」⇒ 是（`try_start_4` 之前），且跳转目标 `:cond_63` 在 try 之后但在方法体内 ✔。
- 不碰：任何业务逻辑、判定方向、配置项语义、水印、启动弹窗。

### ⑤ 验收标准（可证伪）
