# 调研 · r6d031 第一轮（全量调研）："师推进"链从入口到出口

> 批次 **r6d031** ｜ 目标现象：大规模空战时**部分飞机停在一省不动**（r6d030 抓样实锤：70 条停滞候选，最长连续 23 个采样点 ≈ ≥20s，全部为 AI 文明 c73/c226/c88）

## 1. 谁在推进"师所在省"（`airDivisionAtProvinceID`）

| 层级 | 位置 | 作用 |
|---|---|---|
| 驱动器 A（每帧，渲染线程） | `Renderer/RendererGame$3:367-371` → `RealTimeSim.getInstance().updateFrame()` | **主力** |
| 驱动器 B（每帧，渲染线程） | `AFM.updateMissions()`（渲染栈）→ 对每条任务 `AirMission.update()` | 内部 8021 行也会调 `moveDivisionAlongFlight()` |
| 推进本体 | `AirMission.moveDivisionAlongFlight()`（7200） | 真正改 `airDivisionAtProvinceID`（另见 5702/5804/5941/5988/7545 等写点：`placeAirDivision`/`returnAirDivisionHome`/`setupReturnLeg`） |

## 2. `RealTimeSim.updateFrame()` 的真实结构（关键）

```
try_start  for (AirMission m : AFM.activeMissions) {
       if (m.state != EN_ROUTE && m.state != RETURNING) continue;
       ...
       AFM.dedupAirhqDivision(m);
       m.moveDivisionAlongFlight();          ← 推进
   }
   PlayerFogOfWar.detectEnemyMissions();
   lastFrameTime = now;
   return-void;
catch_5e  CFG.exceptionStack(t);             ← 只 printStackTrace + 可能写 logs.txt
   lastFrameTime = now;
   return-void;                             ← ★ 异常后本帧剩余任务全部不再处理
```

**⇒ 结构性问题：`try/catch` 把"整条遍历"包住**。任何一条任务在 `dedupAirhqDivision` 或 `moveDivisionAlongFlight` 里抛异常：
- 本帧**后面的任务全部不推进**；
- 若该异常每帧复现 ⇒ **排在它后面的任务永久停住**。
这与抓样规律（**卡住的多是较新的任务** = 列表靠后的任务）**方向一致**。

## 3. 遍历里的两个可疑抛点

1. **`AFM.dedupAirhqDivision(m)`**（我们自己加的）：1000 ms 全局节流后，遍历 `Game.lProvinces` → 每个省的 army 列表，`Province.removeArmy(int/String)`、`addArmy_Load()`、`updateArmyPosY()` ⇒ **在一个省的 army 列表上边遍历边删除**，并把师搬到 `sourceProvinceID` 的省。
2. **`moveDivisionAlongFlight()`**：`.registers 16`，直接读写 `airDivSegAnimMs`、`flightProgress`、`airhqDivision`、`Game.mapScale`、(多条)省级数据；早退条件 `airhqDivision == null`。

## 4. 本轮结论（可用作第二轮输入）

- 有**两个**每帧驱动器同时改同一个 `airDivisionAtProvinceID`（`RealTimeSim` 与 `AFM.updateMissions`），且**两者都不做"异常隔离"**（前者吞异常但中断循环；后者无 catch ⇒ 会直接崩）。
- "停住"的下游特征（`at` 不变、`s=1`）**不与"到点等待结算"相关**，而与**"推进被中途掐断"**高度吻合。
- 下一步（第二轮）：确认 `dedupAirhqDivision`/`moveDivisionAlongFlight` 的**具体抛点证据**（logcat 里 `printStackTrace` 的痕迹）、两个驱动器的先后顺序与重复推进风险、以及历史改动（`dedupAirhqDivision` 是我们哪一批加的、为什么加）。
