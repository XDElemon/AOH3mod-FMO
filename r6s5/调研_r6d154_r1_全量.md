## 2. airhq key 的一生（身份全靠字符串 key）

| 环节 | 代码 | 依据 |
|---|---|---|
| key 形态 | `airhq_<civID>_<provinceID>_<ord>_<n>` | `getKeyCiv`=split("_")[1]、`getKeyOrd`=split("_")[3] |
| 任务侧 key | `AirMission.getAirDivKey()` @4135：`airhqKey` 字段非空则用它；否则拼 `"airhq_"+civID+"_"+sourceProvinceID`（**只有 3 段！**） | 与 5 段真 key 不匹配的风险点 |
| 认领 | `AirMission.airhqDivision` 字段（35），写入点 @5685/6151 | — |
| 布置到省 | `AirMission.placeAirDivision(I)V` @5736：先用 `getAirDivKey()` 对**旧省** `removeArmy(key)`；再对目标省 `getArmyKeyID(key)>=0 ⇒ removeArmy` 去重；再 `addArmy(div)`；写 `airDivisionAtProvinceID=p1` | **删除/去重全按 key 字符串匹配** |
| 摘 key | `AirDbgLog.airDrawAsPlane(key,div)` @224：key 不以 `airhq_` 开头 ⇒ 不算飞机；**编制为 null/空 或 编制里无航空兵种 ⇒ `stripFakeKey(div)` @2998 ⇒ `div.key ← CFG.extraRandomTag()`** | r6d059 批次（用户验收过） |
| 写回 key | `AirMission.tickInvars()Z` @7914 头部：`airhqDivision != null` 且 `div.key != null` ⇒ **无条件** `div.key = mission.airhqKey` | 每 tick 都执行 |
| 删除实现 | `Province.removeArmy(String key)` @15787：遍历 `lArmies`，`division.key.equals(key)` 才 `removeArmy(i)` | **key 不匹配 ⇒ 删不掉** |
| 去重实现 | `Province.getArmyKeyID(String)` @11323 / `addArmy` @1316：`getArmyKeyID(div.key)>=0` ⇒ 判重（`logDupAdd`） | key 变了 ⇒ 判重失效 |
| 查任务 | `AirForceManager.getAirMissionByKey(String)`：只查 `activeMissions` 且跳过 COMPLETED/ABORTED | key 变了 ⇒ 查不到 ⇒ 走驻场样式 |

**⇒ 结构性结论**：只要 `div.key` 与 `mission.airhqKey` 出现**任何时刻的不一致**（摘 key 的随机串 / 3 段兜底 key / 其他系统改写），就会出现
① 旧省删不掉 + 新省又加一份 ⇒ **同一师两省并存** ⇒ 两省各画一次 ⇒ **同一架飞机画两次**（叠两层）；
② `getAirMissionByKey` 查不到的那一次 ⇒ 该份按"驻场样式 + 省份主人涂装"画 ⇒ 与飞行样式那一份**不同涂装叠加**。
