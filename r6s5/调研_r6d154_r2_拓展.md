## 2. 与既有机制的对齐（哪些不能碰）

1. **r6d059 的"编制判据 + 假 key"是用户验收过的东西**：不能把 `airDrawAsPlane` 改回"只看 key 前缀"，否则"假身份画成飞机"的老 bug 回归。
2. **`dgAirGroup` 还有别的消费者**：`drawAirForce`/`drawAirportIcons`（@1383/1390/1397/1404）与 UI 的 `airImgForTypeP`。⇒ 本批**不删 5941 行的写入**（删了会让机场图标永远用"组0"），只在 `drawAirDivisionAsPlane` 内部换成"按飞机自己的国家取图"。
3. **UI 侧 `armyCardImgFor(civ)` 口径是对的**，不动。
4. **`airImgForCiv(II)` 是现成函数但零调用**：本批首次启用，语义 = `(civ, type)`（内部 `artGroupOf(civ)` + `pickAirImage(3, group, type)`）。
5. **编号/机型序数来自 key 第 3 段**（`getKeyOrd`），本批不改。

## 3. 相邻系统的风险面（为什么"删不掉"会真的发生）

| 风险源 | 说明 | 现有证据 |
|---|---|---|
| `div.key` 被随机化 | `stripFakeKey` → `CFG.extraRandomTag()` | r6d059 文档 + 代码 @3009 |
| `div.key` 被无条件写回 | `tickInvars` @7937-7938：`div.key = airhqKey`（每 tick） | 代码（**"摘/写"两段同时存在 ⇒ 存在振荡窗口**） |
| `getAirDivKey()` 的 3 段兜底 | `airhqKey==null` 时 `airhq_<civ>_<prov>` | 代码 @4145-4167 |
| 游戏自身的部队移动/占领 | 空军师本质是普通 `ArmyDivision`，可能被游戏/AI 移动（`GameThread.updateMoveUnits`、占领推进）⇒ 任务侧 `at` 过期 ⇒ 删除打到错的省 | 结构性（未证） |
| `save/load` | 存档只存 `airhqKey`，不存"师当前在哪个省"的一致性；读档后 `at` 可能与实际省不符 | 结构性（未证） |

**⇒ 结论**：不要在没有数据的情况下改去重/删除逻辑（会砸存档与任务流）。**先探针取数，再一次修**。

## 5. 边界与不变量（本批必须成立）

- 不改：任务状态机、`placeAirDivision` 的删除/去重语义、存档格式、AI 派发、UI 取图、`dgAirGroup` 的写点。
- 探针只读、绝不在业务方法里 `iput/sput` 业务字段；探针方法独立成方法，主方法只留 1 行 `invoke`。
- 所有新增点位的锚点必须**带上下文**且命中数 == 1（门禁断言）。
- 寄存器：`drawAirDivisionAsPlane` 的 `.registers 16` ⇒ **p0..p3 = v12..v15**，新增调用不得占用；`airImgForKey` 新增方法自带局部寄存器。
- 走 `dWrite`（免 debug 闸、免节流）；采样用**计数器取模**，不用时间戳。
