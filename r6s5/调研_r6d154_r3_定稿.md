## 五、探针输出格式（全部走 `dWrite` → `aircfg_diag.txt`，免 debug 闸、免 500ms 节流）

|---|---|---|---|---|

| `adp`（重复报告支） | 同上，命中"同 id 但绘制省不同" | **无条件**（同 id 只报一次，`ldup` 去重） | `nADPD id=… p1=… p0=… k=…` | **H3：同一师被两个省各画一次 = 叠两层** |

| `fkr` | `AirDbgLog.airDrawAsPlane` 摘 key 分支 | 每次 | `nFKR id=… rg=… k=…` | **H4：摘 key 是否打到我方真空军师（`rg=0` 或全陆军）** |

判读字典：`id` = `System.identityHashCode(division)`（同一对象恒定）；`dp`/`at` = 师/任务自认所在省；`p` = 正在绘制的省。

## 六、门禁（`toolchain/act/check_r6d154.py`，≥4 断言 + 3 负样本）

**断言**
1. `ProvinceDrawArmy` 中 `airImgForType` 只剩 **4** 处且寄存器均为 `v0`（那 4 处属于机场图标路径）；`airImgForKey` 调用恰 **4** 处且形如 `{v3, p3}`。
2. `airImgForKey` 方法体：调用 `getKeyCiv` **1** 次、`airImgForCiv` **1** 次、含 `if-ltz` 守卫 **1** 次、`return v0` **1** 次；方法定义恰 **1** 个。
3. 4 个探针调用各恰 **1** 处（`adp`/`pap`/`fkr`/`tkr`），且各自都在预期方法内（按方法名切片验证）。
4. `AirPosProbe` 中 4 个探针方法定义各恰 **1** 个，且每个方法体内**不出现** `iput`（只读保证）；10 个新字段齐备。
5. 越界纪律：全部新方法的 `pN` ≤ 参数个数-1、`vN` < `.registers`（由 `check_params.py` 复核）。

**负样本（必须变红）**
- N1：把某一处 `invoke-static {v3, p3}, …airImgForKey` 改回 `{v3}` 形式 ⇒ 断言 1 失败。
- N2：删掉 `E5` 的 `pap` 调用 ⇒ 断言 3 失败。
- N3：在 `fkr` 方法体内插入一行 `iput-object p0, p0, …->key:Ljava/lang/String;` ⇒ 断言 4 失败。

## 七、验收标准（可证伪）

1. **修①**：让一架我方飞机执行任务飞进**敌国省**，在地图上它应**保持我方涂装**（与停在自家机场时同款）；旧版会变成敌国涂装。
2. **不回归**：自家机场驻场贴图不变；AI 国家的飞机仍显示各自国家涂装（我方在自家省显示我方）。
3. **探针自证**：启动后 `aircfg_diag.txt` 有 `BOOT2 dbg=…`；执行一次出击/返航应出现 `nPAP`/`nFKR`（可选）/`nADP` 行。
4. **叠两层定位**：若复现"叠两层"，日志里应出现 `nADPD`（同一 `id` 出现在两个不同省）⇒ 根因锁定；若**没有** `nADPD` 但有两次同 `id` 同省绘制 ⇒ 属"同省重复条目"，另案。
5. **不通过**（立即回退 r6d153）：开局闪退 / 飞机贴图整体消失 / 任务流程异常（卡在 PLANNING、飞机不返航）。

## 九、设计逻辑（11 项）

1. **定位**：本版动的是"地图飞机贴图的国别取图口径"（+ 只读诊断），让"飞机是哪国的就画哪国的"成立，并为"叠两层"取证。
2. **设计目标**：玩家可见问题 = 飞机飞进敌国省后涂装变成敌国的（且可能看到两层）；上层意图 = 地图贴图必须与"编制卡片图/金环"口径一致（都按飞机自己的国家）。
3. **规则与判定顺序**：绘制一架飞机的贴图时：①先判 `key` 是否 `airhq_` 开头（不是 ⇒ 不归本路径）；②有任务且状态∈{在航/执行/返航}且航段有效 ⇒ 用航段插值位置；③否则（无任务/规划中/无航段）⇒ 用"飞行样式"在本省位置绘制（r6d153）；④**取图时**：机型序数取 `key` 第 4 段；**美术组取 `key` 第 2 段（飞机自己的国家）**，解析失败则退 RU 组。
4. **参数与阈值表**：美术组 0=CN / 1=EU / 2=RU（兜底）/ 3=US；机型 type 0..3（与 `pickAirImage` 夹取）；`getKeyCiv` 取 `split("_")[1]`；采样闸：例行行每 64 次。调大/调小只影响日志量，不影响画面。
5. **状态与生命周期**：空军师 = `ArmyDivision`（key=`airhq_…`）→ 任务 `airhqDivision` 认领 → `placeAirDivision` 在省间搬迁（按 key 删除/去重）→ tick 中 key 可能被"摘/写"→ 绘制时按 key 找任务、按 key 取国别 → 任务结束 `returnAirDivisionHome` 归位。
6. **边界与不变量**：只改"取图依据"与新增只读探针；不动 `dgAirGroup` 写入、`stripFakeKey`、删除/去重语义、状态机、存档、UI；不变量 = 每个师每帧仍只画一次（单调用点未变）。
7. **玩家可感知**：正常 = 敌国省上空的飞机保持本国涂装；异常 = 涂装仍跟省份或飞机贴图消失。
8. **失败与回退**：`key` 解析失败 ⇒ 退 RU 组（不崩）；如果出现开局闪退/贴图消失 ⇒ 装回 r6d153。
9. **验收标准**：见第七节（可证伪）。
10. **变更清单**：见第八节。
11. **风险与待办**：①`airImgForKey` 用 key 而非 `mission.civID`；二者理论一致（key 由任务创建时写入），若发现不一致（`nPAP` 的 `eq=0`）则下一批改为优先用 `mission.civID`；②若 `nADPD` 出现 ⇒ 下一批修"按对象身份的删除/去重兜底"；③若 `nTKR` 频繁 ⇒ 说明"摘/写振荡"真实存在，改 `stripFakeKey` 不再动真实 key；④r6d153 的位置问题（Y 轴拉伸）仍挂账。
