# 调研 · r6d161「陆军一列 / 飞机一列」（三轮）

日期：2026-10-02 ｜ 状态：定稿，可施工
用户实测结论（本批起点）：**"拉伸"实为误判**——战争省份里陆军师很多时，空军师被排到图标列很深处
（`j=12 ⇒ sy=392px`），飞机贴图看起来"跑到别的省去"。用户给的修法：**陆军排一列、飞机另排一列**。

---

## 第一轮（全量）：这个"位置"是谁算的、按什么规则

### 1.1 唯一排版入口 `Province.updateArmyPosY()V`（Province.smali:21625）
```
.registers 6            # locals v0..v4, this=p0=v5
AirPosProbe.up(provinceID)                    # ← r6d149 的只读汇总探针
i=0 (v0) ; j=0 (v1)
:loop  if (i >= iArmiesSize) -> :end
  div = lArmies.get(i)
  if (div.inMovement) { Province.upySk(this,div,i); goto :continue }   # 移动中的师：走 upySk，不占槽
  H = ProvinceDrawArmy.getArmyHeight()
  div.iShiftY = H*j + 2*j - H/2                 # ← 唯一的"堆叠"公式
  Province.upyPr(this,div,i,j,thatY)            # ← 只读探针
  j++                                           # ← 只有"不移动"的师占槽位
:continue i++ ; goto :loop
```
**结论**：`iShiftY` 是"非移动师"的第 j 个槽位 × (H+2) 再减半高。**陆军与空军共用同一个 j** ⇒
战争省里陆军多 ⇒ 空军被排到第 j 个槽（log 实证 `j=12 / sy=392`）。

### 1.2 屏幕坐标（消费端，世界书已核）
`getArmyPosX/Y(prov, armyID)`：
```
((iCenterShiftX/Y + mapCoords.getPosX/Y() + iShiftX/Y_Scaled) * mapScale) + iShiftX/Y
                                    └─ 乘 scale（缩放）      └─ 不乘 scale（屏幕像素常量）
```
⇒ **`iShiftY` 是屏幕像素偏移**，与缩放无关；改它的语义安全。
⇒ `iShiftX` 同样是不乘缩放的屏幕像素偏移 ⇒ **可以用它做"横向错开"**。

### 1.3 空军师怎么认
key 以 `airhq_` 开头（全工程统一口径；探针 `AirPosProbe.up` 里也是这么判的）。
`AirMission.getAirDivKey()` 在 `airhqKey==` 时输出 3 段兜底 key（`airhq_73_6337`）。

## 第二轮（拓展）：`iShiftX/Y` 的**所有写入者**，谁压谁

| 写入者 | 写什么 | 何时 |
|---|---|---|
| `Province.updateArmyPosY()` | `iShiftY`（堆叠公式） | 省份编制变化时（Civilization/Battle/AirMission/AirForceManager/Province.addArmy…共 20 处调用） |
| `ArmyDivision.updateArmyWidth_Just(Z)` | `Z!=0` 时：`iShiftX=defaultShiftX()`、`iShiftY=defaultShiftY()`、`iShiftX_Scaled=0`；`Z==0` 时**什么都不写** | `Renderer$SimpleTaskArmyText.update()`（传 `updateShift` 标志）、NewGame |
| `MoveUnits.<init>` 附近 | `iShiftX=defaultShiftX()` | 部队移动初始化 |
| `GameThread.updateMoveUnits` / `Civilization.cancelMove` | `iShiftX/Y_Scaled` | 移动中每帧 |

**关键推论**：`defaultShiftX()` = `-(getArmyWidth(iArmyWidth)/2)`（水平居中量）、`defaultShiftY()` = `-(H/2)` = -16。
⇒ 若把"横向列偏移"写进 `defaultShiftX()`，则**所有写入者都会自动带上**（不会被覆盖）✓
⇒ 而 `iShiftY` 的堆叠值只由 `updateArmyPosY` 产生（`updateArmyWidth_Just(true)` 只会把它抹回 -16＝居中，对飞机的目标位置无害）。

**其他不变量（不可破坏）**：
- `iShiftX/Y_Scaled` 的语义（移动插值）不动；
- 陆军师的堆叠公式与槽位计数 **一个字节都不改**（否则步兵堆叠、点击判定全变）；
- 探针类只读，不许写业务字段（本批把"写字段"的部分放进了 Province / ArmyDivision 本体）。

## 第三轮（定稿）：施工点、寄存器、真值表、失败模式

### 3.1 编辑点
| 文件 | 方法 | 改动 |
|---|---|---|
| `Province.smali` | `updateArmyPosY()V` | `.registers 6→7`；新增 `jAir`(v5)；遇到 `airhq_` 师用 **jAir** 算 `iShiftY` 并 `jAir++`，陆军路径原样 |
| `ArmyDivision.smali` | `defaultShiftX()I` | `.registers 2→4`；`airhq_` 师返回值 **+0x38(+56px)** |
| `AirPosProbe.smali` | `up(I)V` | 加 `ax=`（空军师 `iShiftX`）取证 |

### 3.2 寄存器分配
- `updateArmyPosY`：原 locals v0(i)/v1(j)/v2(div)/v3,v4(临时) ⇒ 新增 **v5=jAir**，`.registers 7`（p0 变 v6，代码全用符号名 p0 不受影响）。
- `defaultShiftX`：原 locals v0(返回值) ⇒ 新增 v1(key 临时)、v2("airhq_")，`.registers 4`。
- `AirPosProbe.up`：`.registers 14`，v13 空闲 ⇒ 用 v13（入口置零）。

### 3.3 真值表（本批血案的续集——**零比较极性**）
| 助记符 | 跳转条件 |
|---|---|
| `if-eqz vA, :L` | **vA == 0** 才跳 |
| `if-nez vA, :L` | vA != 0 才跳 |
| `if-ltz vA, :L` | vA **< 0** 才跳（曾被我当"≥0"用反） |
| `if-gez vA, :L` | vA **≥ 0** 才跳 |

本批用法：
- `if-eqz v3, :r6d161_ground`（key == null ⇒ 陆军路径）✓
- `startsWith` 结果 `move-result v3`；`if-eqz v3, :r6d161_ground`（**false ⇒ 陆军路径**）✓
- `if-eqz v1, :r6d161_done`（key == null ⇒ 不加偏移）✓
写反的后果：① 空军判成陆军（=现在的 bug 不变）；② 陆军被判成空军（**堆叠全乱**，立刻可见）。

### 3.4 参数
| 名称 | 值 | 单位 | 含义 | 调大/调小 |
|---|---|---|---|---|
| 空军列偏移 | `0x38` = **+56** | 屏幕像素（不乘缩放） | 飞机相对省份中心的横移 | 调大更靠右（可能压到邻省图形）；调小可能压住陆军方框 |
| 空军纵向槽位 | `H*jAir + 2*jAir - H/2`，H=32 ⇒ 步长 34 | 屏幕像素 | 飞机自己一列，互不重叠 | 与陆军同规则 |

### 3.5 失败模式与回退
| 失败 | 症状 | 回退 |
|---|---|---|
| 极性写反 | 陆军被右移/堆叠异常 | 装回 r6d160 |
| `.registers` 不足 | ART `VerifyError`（整类拒绝） | 已静态核对；装机后若崩→回退 |
| 空军 key 恰为 null | 走陆军路径（=旧行为，安全） | — |
| 偏移过大 | 飞机压到邻省 | 改 `0x38` 一行即可 |

### 3.6 验收（可证伪）
- 日志 `nUPY`：战争省里 `air=` 应**不再等于深槽位**（如 392），而应是空军自己的小值（0、34、68…）；
- 新增 `ax=`：空军师 `iShiftX` 应为 **+(空军宽度/2 的负值) +56**，即比同省陆军大一档（56 的可辨差）；
- 肉眼：战争省份里飞机贴图**贴在陆军方框右侧、不再被挤到省外**；
- 负样本：若 `air=` 仍随陆军数量增长 ⇒ 补丁没生效（说明 `updateArmyPosY` 里走的是 ground 分支）。
