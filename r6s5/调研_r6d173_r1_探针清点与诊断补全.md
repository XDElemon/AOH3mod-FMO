## 2. 为什么以前不崩

- 它们大多插在**很少走到的分支**（`posD` 战斗分支、`fkr` 机场路径、`tkr` 任务不变量检查等），一直"哑火"；
- **新行为（防空开火）会把游戏推进新路径**（击落 ⇒ 任务收尾/返航/编队变动），这些探针就会被调到 ⇒ 一旦参数为 null 就崩。
- ⇒ 与其"崩一个修一个"，不如**一次性给所有探针加统一判空**（本批做法）。

## 3. 诊断补全盘点（Part A 的目标）

上一轮（r6d172 抓样）出现 **`inR=0` 全场 175 个样本、`nAD` 零行**，但**无法判断"周围根本没敌机"还是"敌机只是超出 300px"** —— 因为现有日志只记"射程内数量"，没有"最近距离"。

⇒ 本批给 `nADA` 增两个字段：
- **`d=`**：到最近一个**合格敌方任务**的距离（px；无条件圆整；没有则 0）；
- **`w=`**：**900px 内**的合格敌方任务数（宽域窗口，便于判断"差多远"）。

（射程仍为 300px、开火规则完全不变 —— 用户已确认"300 就够了"。）

## 4. 数据来源与不变式

- 目标口径与 `AirDefense.eligible` / `AirDefDiag.inR` **逐条一致**：`live(任务)`（编队非空）+ `airDivisionAtProvinceID >= 0`（已部署）+ `任务.civID != 省主人`（敌方）+ 同省或 ≤ 阈值半径；
- 省中心取 `Province.getCenterX_Real()/getCenterY_Real()`（与射程同源）；
- **只读**：不写任何游戏字段；不改开火与伤害。
