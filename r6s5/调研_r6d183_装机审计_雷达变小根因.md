# 调研：手机当前装机版本审计（r6d183）+「雷达圈变小」根因

日期：2026-10-04｜包名 `age.of.history3.qiamxi.zhiri`

## 0. 结论摘要
1. **手机装的不是 r6d180，而是 r6d183**（`nABOOT v=r6d183`；安装时间 2026-10-04 21:45:40）。
2. **与 r6d180 相比，整个 APK 只有 `classes.dex` 变了**（资源/data 逐条 CRC 全同）。
3. **dex 里只有 4 个类变了**：`AirDefense`、`AirDefDiag`、`ProvinceDrawArmy`、**`RadarBitmap`**。
4. 前三类＝PC 端回传的 r6d181（AD-2：D1 雷达许可 / D2 +150px / D3 纬度口径 / D4 红圈 / D5 每阵地1发），与回传文档一致。
5. **`RadarBitmap` 不在回传清单里 ⇒ 是 r6d182/r6d183 新改的**，而且改的正是**雷达盘绘制**：
   - `draw()` 的 alpha `0.2f → 0.15f`
   - `refresh()` 填充色 `(0.431,0.725,1.0,1.0)`（浅蓝）→ **`(0,0,0.16,1.0)`**（ICBM 的短波雷达色）
   - `drawRadarEllipse()` 剖面常数 **`1.0f → 0.16f`**
6. **第 3 条就是"雷达小了一圈"的根因**：该常数 K 决定半轴（`x = sqrt(K − t²)·R`，t = y/halfH）。
   - K=1.0 ⇒ halfW = R，halfH = R·f
   - K=0.16 ⇒ halfW = **0.4R**，halfH = **0.4·R·f**（因为 `√0.16 = 0.4`）
   ⇒ **雷达盘两个半轴同时缩到 40%（=2.5 倍变小）**。颜色变暗、alpha 变小让"变小"的观感更明显。

### 1.5 几何后果（读 `drawRadarEllipse` 逐行推出）
```
for (int y = -halfH; y <= halfH; y++) {
    float t = (float)y / (float)halfH;      // t∈[-1,1]
    float v = K - t*t;                       // K=1.0（旧）/ 0.16（新）
    if (v <= 0) continue;                    // 该行不画
    int dx = (int)(Math.sqrt(v) * halfW);
    bmp.fillRectangle(cx - dx, cy + y, dx*2, 1);
}
```
- K=1.0 ⇒ `dx_max = halfW`（在 y=0），有效 y 范围 `±halfH` ⇒ **椭圆 (halfW, halfH)**
- K=0.16 ⇒ `dx_max = 0.4·halfW`，有效 y 范围 `±0.4·halfH` ⇒ **椭圆 (0.4·halfW, 0.4·halfH)**
⇒ 半径整体 ×0.4（不是"少一圈"，是**缩到 40%**）。

### 1.6 影响范围
`RadarBitmap.refresh()` 里逐省过滤 `isEnemyProvince()`；该方法语义（逐行）：
```
v0 = true; if (Game.player != null && player.iCivID == prov.getCivID()) v0 = false; return v0;
```
⇒ `RadarBitmap` 只画**非本国**（敌/第三方）的雷达盘覆盖（一张 Pixmap 贴图，`ProvinceDrawArmy:2729` 处 `RadarBitmap.draw(sb)` 绘制）。
⇒ 本国雷达盘由 `ProvinceDrawArmy.drawAirForceRadarIcons` 逐省 sprite 绘制，**本版没改**（尺寸不变）。
所以：**变小的圈＝"非本国雷达盘"**；若玩家看的是自己家的圈，理论上尺寸不变 —— 这一点需要你确认（见 §3）。

## 2. 「雷达变小」的责任归属
- **不是** AD-2 的 D1–D5 引起（那些类里没有任何绘制半径改动）。
- **是** 后续 r6d182/r6d183 对 `RadarBitmap` 的三处常量改动引起（非回传清单内容 ⇒ 未走我们的门禁/模拟器流程）。
- 旁证：`(0,0,0.16,1.0)` 与 `0.15` 恰好等于 ICBM `Units/Radars.txt` 里短波雷达的 `RadarColor 0.0 0.0 0.16 0.15` ⇒ 这次改动像是"照 ICBM 配色"，但**把颜色分量 0.16 误当成尺寸系数**（于是 `√0.16=0.4`）。（此推论是动机猜测，非事实；事实是常数被改。）

## 3. 待确认（决定下一步）
**Q1**：你看到的"变小"，是（A）敌/他国的雷达覆盖盘（RadarBitmap 画的），还是（B）你自己雷达建筑的盘（drawAirForceRadarIcons 画的）？
- A ⇒ 与本次审计完全吻合；
- B ⇒ 说明还有别处（但 dex 级比对显示只有这 4 类变过，需要重新审视"变小的那一个到底是什么对象"）。

## 4. 回退/修复口径（等指示，不擅自改）
- 最小回退（恢复 r6d180 观感）：`RadarBitmap.drawRadarEllipse` 的 `0.16f` 改回 `1.0f`；`draw()` alpha 回 `0.2f`；`refresh()` 色回 `(0.431,0.725,1.0)`。
  —— 但我们**不建议**简单回滚：你已明确"旧版绘制方式你不满意"，正解应按 ICBM 口径重做（见《调研_ICBM雷达圈绘制_全量_v1.md》）。
- 因这 4 个类的源码目前只在 PC 端（手机侧无 r6d182/r6d183 的 smali 树），任何修复都必须**先从装机 dex 反汇编出对应类**（已具备能力：`DumpClass.java` / `DexDiff.java` 已落在 `toolchain/act/`）。
