## 0. 范围与结论（先行）

### 0.1 全工程导弹系统清点（关键词扫描：missile / ICBM / nuke / rocket + 字段族追踪）

| 系统 | 归属 | 打什么目标 | 现行机制 | 本次处理 |
|---|---|---|---|---|
| **AD 地对空导弹** | 我们（mod） | 飞机（移动单位） | 纯追踪 + 接触结算（r6d252~254 已验收 ✅） | 不动 |
| **A2A 空空导弹** | 原版（我们仅加过探针） | 飞机（移动单位） | **时间驱动三件套**（见 §2） | **唯一统一对象** |
| 对地“打击” strike / A1 系列 | 原版字段 + 我们部分扩展 | 陆军师（移动）/建筑 | 时刻表进度，无弹迹（机炮 fx 走 drawAirGunFx） | **不在范围**（它不是导弹） |
| ICBM / 核 | — | — | 未发现独立弹道系统（仅事件/贴图名出现相关字样） | 不涉及（用户也明确排除） |

**结论：统一工程 = 只改 A2A 一条线。** 把“时间插值动画 + 到点结算”改为“纯追踪动画 + 接触结算”；**发射条件 / 弹药 / 冷却 / 目标选择全部保持原样**。

### 0.2 现在的问题（用户视角——为什么要统一）

1. 原版 A2A 导弹**逼近到目标 8px 以内就从屏幕上消失**（`msFxInit=2` 后不再绘制），而伤害要到“时刻表”时间才落地 ⇒ 视觉上“最后一段看不到、结算和画面对不上”。
2. 动画首帧是**按时间比例插值定位**的——第一帧画出来时导弹可能已经“在半路”，起步突兀。
3. 伤害与视觉**完全解耦**：没碰到也会在到点时结算（保证命中）；碰到了也可能还没结算（等时钟）。
4. 速度由“剩余距离 ÷ 剩余时间”一次性算出（首帧后不再重算）——目标移动时观感不匀速。

统一后（对齐 AD 已验收的效果）：**从载机起点出发 → 恒速纯追踪 → 方块碰到目标即结算即消失**。

## 2. 原版 A2A 全链路（现状，逐段）

### 2.1 发射（`missileTick` 前半，行 4948~5677）

判定链（按代码顺序）：

1. **若 `strikeKind==1`（已有弹在飞）** → 不发射，走“在飞”分支（§2.3）。
2. **若** 任务类型 ≠ `INTERCEPT` **或** 状态 ∉ {`EN_ROUTE`,`EXECUTING`} **或** `airDivisionAtProvinceID ≤ 0` → 不发射。
3. **若** `missilePerPlane≤0` → 惰性初始化：`missilePerPlane = missileCountForGen(unitGenOf(首机))`；`missilesLeft = perPlane × 存活机数`。
   （`unitGenOf` 现值恒 3 ⇒ `missileCountForGen(3)=2` ⇒ **每机 2 发**）
4. **若** `missilesLeft≤0` 且 `strikeKind≠2` → `strikeKind=2`（打空，记录 `nMS dry` 后直接 return）。
5. **冷冷却**：`now - lastMissileHours < 4h` → 跳过（发射间隔 ≥4 游戏小时）。
6. **目标搜索**（遍历 `activeMissions`）：敌我不同 / 状态∈{EN_ROUTE,EXECUTING} / 飞机在省 / **邻接判定**（相邻省 或 两省中心距² ≤ `missileRangeForGen(3)²=100²`）。
   - **拦截机偏好**：若本方首机是 INTERCEPTOR，优先挑“非 STRATEGIC_BOMBING / ATTACK_ARMY”的目标；找不到再放宽重试一轮。
7. **发射落章**：
   - `missilesLeft -= min(missilesLeft, 存活机数)`
   - `lastMissileHours = TURN_ID*24+HOUR`（单调时钟）；`lastMissileMs = currentTimeMillis()`
   - `strikeKind=1`；`strikeTargetMissionID=目标ID`；`strikeProgress=0`
   - **`msFlyHours = 2 × clamp(d/20 + 2, ≤8)`**（d=两省中心距）⇒ 4~16 游戏小时
   - `msFxTgtAt = 目标当时所在省`；`msFxInit=0`；`msFxTN=0`；`msFxTH=0xf`（清尾迹）
   - 记录 `nMS fire ... d= / ft= / r=` 日志

### 2.2 在飞（双轨：tick 业务 + 帧动画）

- **业务轨（每 tick）**：见 §2.3。
- **动画轨（每帧，仅当绘制闸放行）**：`drawAirMissileFx`：
  1. **入口守卫**：`strikeKind==1` ∧ `strikeTargetMissionID≠0` ∧ 能在 activeMissions 里找到目标。
  2. **坐标**：源 = `getAirSpriteX/Y(射手)` → 退化 `getAirDrawPosX/Y(射手省)`；目标 = `getAirSpriteX/Y(目标)` → 退化 `getAirDrawPosX/Y(目标省|msFxTgtAt)`；四端 **+0x14（20px）**。
  3. **换算到地图坐标**（screen/scale − mapPos）
  4. `msFxStep(mission, srcX, srcY, tgtX, tgtY)`
  5. `msFxInit==1` 时：画尾迹（白 3×3 点阵，环索引 `(TH-i)&0xf`）+ 画弹头（14×14 `pix`，己方 `(0.35,0.6,1,1)` / 敌方 `(1,0.3,0.3,1)`）+ 恢复白色。

### 2.3 结算（时间驱动）

- **到点**：`now ≥ lastMissileHours + msFlyHours` 时：
  - 目标任务仍存在且有存活机 → `dmg = Σ(射手存活机 airAttack) × 2.0 × defenseMul(目标)` → `applyAirDamage(目标, dmg)`（池倾泻模型，与 AD 的 applyMdDamage 同口径）→ 日志 `nMS hit`。
  - 目标不存在 → 日志 `nMS miss`（**无伤害**）。
  - 随后清场：`strikeKind=0`；`strikeProgress=0`；`strikeTargetMissionID=0`；return。
- **未到点**：return（什么都做不了，等时钟）。

### 2.4 动画推进（`msFxStep` @9774）

- 前置闸：游戏未运行/菜单打开 → return。
- `msFxFrameDt()` → 真实帧间隔 `dt`。
- **首帧（init==0）**：
  - 算总时长 `T = (msFlyHours/2) × base`（base=playSpeedTIME，缺省 300）
  - 进度 `f = (now − lastMissileMs) / T`，clamp ≤0.9
  - **位置 = 源 + (目标−源) × f**（⇒ 可能“半路出现”）
  - 基础速度 `msFxSpd = 剩余距离 / 剩余毫秒`（≥32ms 兜底）
  - `init=1`；清尾迹；落点
- **飞行帧（init==1）**：
  - 若与目标距离² < 64（**< 8px**）→ `init=2`；return（**从此不再绘制**）
  - 否则：朝目标方向移动 `msFxSpd × dt`（**速度不再重算**）；落点。
- **停帧（init==2）**：直接 return（msFxStep 不做事；drawAirMissileFx 也不会再画它）。

## 3. 对照：AD 现行机制（基准，已验收）

| 维度 | 原版 A2A（现状） | AD（r6d254，已验收） |
|---|---|---|
| **推进** | 首帧插值 + 固定速度归航 | 首帧置源点 + **恒速纯追踪**（`V0 ÷ (spd÷HPT) × dt`） |

| **与倍率联动** | playSpeedTIME 参与首帧总时长 | ✅ 每帧实时读 `playSpeedTIME÷HPT` |

## 4. 统一改造设计（草案 · 5 个手术点）

> 原则：**只动“推进与结算”，不动“发射与弹药”**；视觉语言（红蓝弹头、白尾迹、14×14、+0x14）全部沿用。

### S1 `msFxStep` 引擎替换：时间插值 + 冻结 → 纯追踪 + 接触

- `init==0`：把位置置于**源点**（p1,p2），`init=1`，清尾迹 → 随后走本帧推进。（不再有“半路出现”。）
- `init==1`：朝 (p3,p4) 方向移动 `step = V0_ms × dt ÷ (spd÷HPT)`（`V0_ms` 为新常量旋钮，实时读倍率）。
- **接触判断**：`dist ≤ step` → **调 S2 结算 helper** →（helper 内清场）。
- `init==2`（防御位）：return。
- 坐标空间：`msFx` 系列在**地图坐标**（非屏幕 px）；建议 `step` 使用时除以 `scale`，使**屏幕上观感速度与 AD 一致**（缩放不影响观感）。【定稿轮确认】

### S2 接触结算 helper（`AirMission` 新增 public static，拟名 `msFxContact`）

- 伤害：`Σ(射手存活机 airAttack) × 2.0 × defenseMul(目标)` → `applyAirDamage`（与原口径一字不差）。
- 日志：`nMS hit`（**改走 dWrite 免节流通道**，避免 500ms 吞行）。
- 清场（与现 :goto_cc 同款）：`strikeKind=0`；`strikeProgress=0`；`strikeTargetMissionID=0`；`msFxInit=2`（防重复步进）。
- 目标定位：与现绘制同法（按 `strikeTargetMissionID` 在 `activeMissions` 里找）。

### S3 `missileTick` 改造：删“到点伤害”，加“丢失/兜底”清场

- **删除**：`now ≥ due` 的伤害/失的块（伤害不再到这里）。
- **替换为**（`strikeKind==1` 分支内）：
  1. 目标失效（不在了/无存活机）→ `nMS lost` → 清场（保持“接触才伤害”语义）。
  2. `now ≥ due + 宽限`：
     - 若该导弹的**动画近期在步进**（新增字段记录最后步进时刻）→ 继续追（设硬上限）。
     - 若**从未步进**（离屏 AI 战场）→ 按原版口径兜底结算（存在即命中）→ `nMS fb` → 清场。
  3. 其余 → return。
- 发射/冷却/弹药/目标选择逻辑**一行不动**。

### S4 `drawAirMissileFx`：基本不动

- 守卫、坐标、+0x14、颜色、尺寸、尾迹全保留。
- 与时间结算耦合的代码本就在 `msFxStep` 内部，随 S1 一并替换。

### S5 探针与门禁（施工纪律）

- 新日志：`nMS hit`（接触点）/ `nMS lost` / `nMS fb`，均建议 dWrite。
- 行为级模拟器：解析新 `msFxStep` 分支（init0→置源；追不上→位移；够得着→走 helper 路径），配反转敏感性自检。
- VerifyError 防线：`msFxStep` / `drawAirMissileFx` / `missileTick` 三方法 `.registers` 均已满（16/16/15）⇒ 插入代码必须**独立成方法**或复用死寄存器；落盘后跑 `check_params.py` + `regtype_gate.py` + `check_castorder.py`。

## 5. 判定顺序（改造后 · 人话版）

1. 发射环节判定链 **保持 §2.1 原样**（冷却 4h、邻接、拦截机偏好、弹药扣减…）。
2. 弹在飞时：**每帧**（可见/自己/侦测的战斗）纯追踪一步；**碰到即结算即消失**。
3. 若目标先死/先落地 → 下一 tick 清场，**无伤害**（nMS lost）。
4. 若离屏（纯 AI 战场，动画不步进）→ 到点 + 宽限后按原版兜底（nMS fb），避免“永远卡在在飞态”。
5. 一切清场后回到空闲，按 4h 冷却进行下一轮齐射。

## 8. 边界与不变量（必须成立）

- **不变量1**：伤害口径与原版一字不差（Σ攻击×2×defMul）。
- **不变量2**：发射条件/冷却/弹药/目标选择不改（本次只换“推进与结算”）。
- **不变量3**：同一任务任意时刻至多一发在飞（strikeKind 状态机不变）。
- **不变量4**：可见战斗的伤害只可能在“接触帧”发生；不可见战场才走兜底。
- **不变量5**：AD 系统一行不动（已验收）。
- **不变量6**：`strikeKind/strikeProgress` 语义不变（0/1/2），外部（returnToBase 等）不受影响。

## 10. 验收标准（可证伪）

**通过标志：**
1. 空空导弹从**载机位置**起飞（不再半路出现），**恒速追着目标飞机**跑。
2. **碰到即结算即消失**（不再是“冻结 8px 消失 + 时钟结算”）。
3. 伤害数字/击杀发生的**瞬间与视觉接触同刻**。
4. 探针：`nMS hit` 落点时间与接触一致；无闪烁、无残留、无卡死（在飞态能自然清场）。
5. 回归项：发射频率（每 4h 一发）、弹药数（2 发/机）、目标选择偏好、AI 空战平衡大体不变。

**不通过标志：**
- 导弹再次出现“先停住再等时钟”、半路起步、或接触后不消失。

##13. AD（地对空）乙实装核查（回答用户提问：有没有实装？）

**结论：没有实装。AD 目前是"纯接触制"，乙待补（已列入 r6d256）。**

- 伤害唯一出口 = `adFxStep` 接触帧 `applyMdDamage` + 全清场（r6d252 起）；`tickHits()` 自 r6d252 起为 `return-void` 桩——正好留着一个现成的"空位"。
- AD 由 `tickTurn → tickAll`（遍历**全部省份**）开火 ⇒ 玩家看不见的 AI 互殴战场真实存在，离屏问题在 AD 上是实打实的。
- 离屏后果（现状）：
  1. 动画不步进 → 永不接触 → **伤害只累积（adHitDmg）不落地**；
  2. 在途标记（adFlyHours>0）持续占用：后续命中只累加、不再开新弹迹；
  3. 目标先消失 → 在途伤害随任务消亡而丢失；若之后才被看见 → 补飞、补结算。
- 修复计划（**r6d256**）：`adFxStep` 记录"最后步进时刻"（新增运行字段）→ `tickHits` 桩复活为兜底闸：`now ≥ adHitAt + GRACE` 且从未步进 → 按原版口径 `applyMdDamage(adHitDmg)` 兜底 + 清场；近期在步进 → 继续等（硬上限）。
