## §0 本批目标与范围

**目标（一句话）**：把 r6d255 给空空导弹（A2A）装的「乙：双模式离屏兜底」同样补给地对空（AD）；并把
两端速度常量接入 `adSpd()` 科技钩子。**触发语义修正（用户 2026-10-08 补充）**：
- 兜底触发条件不是「在屏幕外」，而是「**目标在迷雾内**」——即弹迹不步进（不绘制=不推进）的一切时刻；
- 屏幕外但已侦测（可见）的弹迹，照常推进、照常接触结算，**不适用**兜底；
- 必须做好「入迷雾（有动画→无动画）」与「出迷雾（无动画→有动画）」的衔接。

**范围（做什么）**：
1. `AirDefense.tickHits()` 复活：空桩 → 「迷雾兜底闸」（到期 + 宽限 + 近 10 秒步进判定 + 硬上限）。
2. `ProvinceDrawArmy.adFxStep` 记录「最后步进时刻」到新字段 `AirMission.adFxStepMs:J`。
3. `adFxStep` 的速度常量 `0x42870000` 改调 `AirDefense.adSpd()`（TECH-HOOK 单点）。
4. 配套：门禁（语义断言 + 负样本）、行为级模拟器（解释真实 smali + 反转敏感性）、nABOOT 升版。

**范围（不做什么）**：
- 发射链（`fireProvince` 的命中判定/弹药/冷却/目标选择）——一行不动；
- 接触结算（`adFxStep` 内的 `applyMdDamage` 块）——一行不动；
- 渲染/尾迹/弹头视觉——不动；
- 存档格式——不动（弹迹字段不在白名单，本来就不存，见 §7）。

## §2 现状全链路（含「兜底缺口」）

### 2.1 发射（不动）
- `fireProvince`：命中判定 `roll<=chance`（r6d210 极性修正后）；命中则 `v3++`、`adFxSrc=p1`、`scheduleHit(v5, dmg)`。
- `scheduleHit`：`adStartGh=now`；**若 `adFlyHours<=0`（无在途）**才排定 `adHitAt`；`adFlyHours` 只在此时设；
  `adHitDmg` **每次命中都累加**（同一目标多次命中合并为一次结算，"保留最早到达时刻"）。

### 2.2 绘制/步进（不动）
- 每帧：`drawAirForceMissions` 遍历任务 → `myOrDetectedMission==true` 才调 `drawAdMissileFx`。
- `drawAdMissileFx` 守卫：`adFxSrc>=0`、`adFlyHours>0`、`mapScale!=null`；取源（阵地省中心直投影）、目标（sprite 优先，±8px/帧平滑到 `adFxTgtX/Y`）。
- `adFxStep`：纯追踪（首帧置源点 + 清尾迹；每帧 `步长=67.5÷(playSpeedTIME÷HOURS_PER_TURN)×dt`；`v7=min(步长,距离)`；`v7==距离`→接触）。
- 接触帧：`applyMdDamage(p0, adHitDmg)` → 清场八连（`adFxInit=0`、`adFlyHours=0`、`adFxTN=0`、`adFxX/Y=-100000`、`adHitDmg=0`、`adFxSrc=-1`；**不清 `adHitAt`**——残留无害，见 §4）。

### 2.3 兜底缺口（本批修复点）
- `tickHits()` 自 r6d252 起是 `return-void` 空桩（旧逻辑死后仍留在文件里，共 112 行，含完整清场+结算+`nADK` 日志——**本批复用其清场/日志骨架**）。
- **后果**：目标处于迷雾内 → 弹迹不步进 → 永不接触 → `adHitDmg` 悬浮不落地；`adFlyHours>0` 持续占用"在途标记"；目标任务先消亡则伤害随任务丢失。
- **修复**：把空桩替换为「迷雾兜底闸」——到期后按「宽限 + 近 10 秒步进 + 硬上限」三条件裁决：能接触的让它继续接触；接触不了的按原版口径兜底结算。

## §3 「迷雾=不步进」的精确判定（本批的核心语义）

`myOrDetectedMission(m)` @10015（三段任一为真＝可见）：
1. `isMyMission(m)`（自己的任务）；
2. `PlayerFogOfWar.airDetSeen` 集合包含 `m.missionID`（**曾侦测过**——持久集合）；
3. `m.targetProvinceID>=0` 且该省 `getCivID()==player.iCivID`（正在打我方省）。

三个皆伪 ⇒ **迷雾内** ⇒ `drawAdMissileFx`/`adFxStep` 不被调用 ⇒ `adFxStepMs` 不刷新。

**与"屏幕外"的关系（用户裁定）**：绘制不做视口裁剪——屏幕外但已侦测的弹迹照常每帧步进。
所以「是否步进」完全由迷雾闸（`myOrDetectedMission`）决定，与摄像机视口无关。**兜底只针对"迷雾内"**。

**其它不步进场景（顺带说明）**：
- 游戏暂停 / Esc 菜单（`adFxStep` 开头守卫 `gameThread.play` + `!getVisibleInGame_Escape`）；
- 这类场景回合线程同样停摆，`tickHits` 不跑，无竞争窗口（见 §5.3）。

## §4 字段与状态机（现状）

| 字段 | 写者 | 语义 |
|---|---|---|
| `adHitAt:I` | `scheduleHit`@1094（无在途时排定）；（死代码清 0） | 到期时刻（游戏小时 = TURN_ID*24+HOUR） |
| `adHitDmg:F` | `scheduleHit`@1113（+=）；接触清 0；兜底清 0 | 在途伤害池（合并结算） |
| `adFlyHours:I` | `scheduleHit`@1100（=max(2,2*dist)）；接触清 0 | **在途标记**（>0=有弹迹/在飞） |
| `adFxSrc:I` | `fireProvince`@724（=省）；接触清 -1；（死代码清 -1） | 弹迹源省；**<0=弹迹结束** |
| `adFxInit:I` | `adFxStep`（0→1 首帧）；接触清 0 | 0=待首帧（置源点）；1=在追 |
| `adFxTN/TH/TX/TY` | `adFxTrailAdd` | 尾迹环（16 点） |
| `adFxX/Y:F` | `adFxStep`；清场置 -100000 | 弹迹当前位置（**地图坐标**） |
| `adFxTgtX/Y:F` | `drawAdMissileFx`（±8px/帧平滑） | 目标点平滑缓存（地图坐标） |
| `adStartGh:I` | `scheduleHit`@1070 | 发射时刻（诊断用） |
| **`adFxStepMs:J`（本批新增）** | `adFxStep`（每步进帧写 `currentTimeMillis`） | **最后步进墙钟**；0=从未步进 |

**状态机（每发弹）**：`无弹迹 → （命中）在途(adFlyHours>0) → 可见:步进中/迷雾:冻结 → 接触结算 或 兜底结算 → 无弹迹`。
两个出口的清场等价（接触路径不清 `adHitAt`，但下次命中由 `scheduleHit` 重设覆盖；**无副作用**）。

**防双结算第一闸**：两出口都清 `adHitDmg=0`；`tickHits` 只处理 `adHitDmg>0` 者 ⇒ 接触后不可能再被兜底。

## §5 接口面 / 频率 / 竞争窗口

### 5.1 调用频率
- `tickHits`：**每回合 1 次**（`tickTurn` 内 TURN_ID 变化检测；`updateAll` 由 `GameThread_Turns` 调）。
- `adFxStep`：**渲染帧**（可见时 ~60fps；不可见=0 次）。
- 两者的"时间粒度"差：兜底判定用「游戏小时」比较到期，用「墙钟毫秒」判定近 10 秒是否在步进。

### 5.2 `applyMdDamage` 语义（复用）
- 池空/伤害耗完：自然返回 0；**不抛异常、不做池空特判**（目标无活机时 k=0，安全）。
- 结尾 `recalcPool()` 维护派生数据。

### 5.3 竞争窗口（结论：无并发问题，均为同线程）
- 游戏逻辑与渲染都跑在 libGDX 主线程；`tickHits`（回合线程侧）与 `adFxStep`（渲染侧）不并发。
- 暂停/菜单时：双方都停，无窗口。
