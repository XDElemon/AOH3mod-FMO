# 调研 · r6d264 R1：图↔名不匹配的根因（全量）

> 2026-10-11｜起因：用户反馈——图会换了，但**全是最高级（6 代）图**，且与左侧名称对不上。

## 1) 取证（以真机同源数据）
- `AirModelTables` 低 8 位实存值（逐条核）：
 | 记录 | 低8位 | 含义 |
 |---|---|---|
 | A_CN_J11_F | 70 | 图号 |
 | A_CN_J20_F | 86 | 图号 |
 | A_CN_J36_F | 118 | 图号 |
 | A_US_F14_F | 82 | 图号 |
- `genOf` 当前实现：`and-int/lit16 v0, v0, 0xff` 直接返回 → **把图号(70..133)当"代"**；
- 链路：`airImgForTypeP → genOf(=86) → pickAirImage(86,…)` → 上限钳位把它压到 6 ⇒ **一律 6 代图**；
- 名字链路不经过 `genOf`（`keyOf` 正确）⇒ 名字对、图全错位、且全锁定最高级。**症状 100% 对应。**

## 2) 结论
- **编码/解码不对称**：生成器把"图号"打进低 8 位；读取端按"代"解码。
- 正确解码公式（表内不变）：`代 = ((图号-70) >> 4) + 3`（图号 70..133 → 0..63 → >>4 → 0..3 → +3 → 3..6，逐条可验）。
