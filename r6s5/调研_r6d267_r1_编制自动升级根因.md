# 调研 · r6d267 R1：J11 编制"自动变 J20"的根因（全量）

> 2026-10-12｜起因：用户实测——"为什么是 J11 编制直接变 J20 编制？"（编制不应随研究自动升级）

## 1) 根因：哨兵值 0 撞车
- 机型记录号（armyID）**从 0 开始**——歼11 恰好是战斗机列表的**第 0 条**（A_CN_J11_F, ImageID 70）；
- r6d265 的盖章设计里把"**modelAid≤0 = 未盖章**"当哨兵：
 - 同步补章守卫写的是 `if-gtz v5, :astamped`（>0 才跳过）；
 - ⇒ **歼11 飞机（0）每次同步都被当成"没盖章"，重新盖成"当前最佳"**；
- 用户流程：造 J11（盖 0）→ 研究 J20 → 下一次同步把 0 重盖成 J20（best=1）→ 编组分桶到 J20 → **编制（名字/等级/图）直接变 J20**。
- 这正是用户看到的现象，与 r6d266 的贴图修复无关（贴图两条链都读的是这个被污染的章）。

## 2) 正确语义（用户裁定）
- 编制**不随研究自动升级**：J11 编制就一直是 J11，直到飞机被换掉/消耗；
- 0 是**合法**记录号；"未盖章"必须用**独立哨兵（-1）**。

## 3) 修复三件套
1. `AirUnit.<init>` 默认 `modelAid = -1`（未盖章哨兵）；
2. 同步补章守卫：`>0` → **`≥0` 跳过**（`if-ltz`）；`<0` 才补章；
3. 兜底钳位：桶值为 -1（无研究且未盖章）时，编制 aID 钳到 0（避免 -1 进 UI）。
