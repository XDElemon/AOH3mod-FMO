# 调研 · r6d269 R1：为什么"起飞后的飞行贴图"没被前一批修到（全量）

> 2026-10-12｜起因：用户实测——待命贴图已对，**起飞后的飞行贴图仍不对**。

## 1) 全量盘点：地图上"飞机贴图"只有两条活链
- **机场计数图标**（drawAirForce 内）→ `airImgForAirportOrd`（r6d268 已修）；
- **编队精灵**（`drawProvinceArmyWithFlag` → `drawAirDivisionAsPlane`，**全树唯一调用点**）→ `airImgForKey`；
- 其余均为死代码/非飞机图：`drawAirMissionFlyingPlane`（**零调用**）、`drawAirDivisions`（stub）、`drawAirportIcons`（通用 `airUnit` 基地图标）、missions 段只画**航迹线(pix)与特效**。

## 2) 关键事实
- `AirDbgLog.airDrawAsPlane(key, div)`：`key 以 "airhq_" 开头 且 军团含空气型(uID∈7..10)` ⇒ 该编队按"飞机精灵"绘制（待命与飞行**同一条链**）。
- 因此"待命对、飞行错"必然发生在 **`airImgForKey` 的三段解析在飞行态失效**：
 1) 任务链：`getAirMissionByKey(编队key)` → 飞行/动画态可能拿不到或飞机列表不可用；
 2) DivKey 链：`key→省→getArmyKeyID(key)` → 编队处于任务/动画态时，原 key 可能查不到；
 3) 旧回退：`airImgForCiv(国最佳)` ⇒ **研究出 J20 后显示 J20**（用户所见）。
- 反向佐证：待命态 1/2 至少一条能中，所以已修好。

## 3) 结论
不要再依赖 key 解析——**在绘制入口（调用 `drawAirDivisionAsPlane` 之前）就能拿到"这个编队自己的军团记录"**（v8=ArmyDivision），把它写进静态变量，取图时优先用。
