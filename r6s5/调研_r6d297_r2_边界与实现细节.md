# 调研 · r6d297 R2：边界与实现细节
> 承接 R1｜改动面：relayoutNodes（rank 构建）+ cxOf（线端点）

## 一、改动点与影响面
1. `relayoutNodes` 两遍扫描（maxCol / mark 列）都加条件：`isTechAllowedForCiv(i, civID)`。
   - 新增 civID 取值（Game.player.iCivID）一次，寄存器 **v13**（数值组，之前只作 const100 用，前段空置）。
2. `cxOf`（连线端点）加同一判定：不允许 → `:cx_park`（-1800 中心）。
   - 新增 v5=civID、v6=allowed 结果（该法上界 v6，恰好用完，不越界）。
3. 元素 loop / 底板宽 / relayoutLines / 探针：**不动**（元素天然只含允许项；底板宽自动跟着新 nCols 变）。
4. `'all'` 分支：仍恒等（不受影响）。

## 二、边界
- B1 数据封闭性（R1 已验证）：悬挂前置 0 处 ⇒ cxOf 的"不允许→park"分支实际不会在日常中触发，作兜底保留。
- B2 运行期换国（读档/新局）：每次开面板/切栏都重算 rank（civID 当场取）⇒ 换国后打开即自适应。
- B3 寄存器纪律：v13（relayoutNodes）与 v5/v6（cxOf）均属**数值组**，不破坏角色表。
- B4 顺序：allowed 判定必须在 `aget aColRank[col]` **之前**（否则非允许列可能越界——模拟器 M5 会实证）。
- B5 gate/sim 同步升级：新断言 S9/S10、负样本 N6；模拟器扩展为 4 组×3 栏全量对账 + M5 极性。
