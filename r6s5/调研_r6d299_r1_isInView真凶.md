# 调研 · r6d299 R1：真凶——isInView 视野标记的"只在移动时重算"
> 2026-10-13｜承接 r6d298 未竟的瑕疵1

## 症状（用户实测）
- 选研究科技后 → 树消失，拖一下才出现；
- 切栏有时不消失，但只限 1–2 个栏；重新选研究科技状态又变。

## 机制链（全部实锤）
1. `Menu.drawMenuElements()` 绘制条件 = `getVisible() && getIsInView()`（第407行起）。
2. `isInView` 由 `Menu.updateMenuElements_IsInView()`（4438，公开方法）统一重算：逐元素 `IsInView_Y && IsInView_X`。
3. 它平时只在 **菜单位置发生变化的那个 update 帧**被调用（Line 249–263：`iNewMenuPositionX != iMenuPosX → 置标志 → 调它`）。
4. 我们 r6d296–298 换栏/重建时**移动了节点坐标**，但多数情况 menuPos 不变（r6d298 的钳制只在越界时改位置）⇒ **没有任何一次"位置变化帧"** ⇒ isInView 保持旧值（对应旧坐标）⇒ 新位置的节点被判"不在视野" ⇒ **不绘制 = 空白**。
5. 用户拖动 → 位置变化帧出现 → 全量重算 → 内容出现。**症状 100% 吻合**（包括"有些栏不消失"＝那些栏钳制恰好改了位置、触发了重算）。

## 修复
`relayoutDone` 在钳制块之后**显式调用 `updateMenuElements_IsInView()`**（公开方法，同帧生效；位置未变时它就是唯一的重算来源，位置变了时最多多算一次，无害）。
