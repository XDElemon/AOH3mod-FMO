# 调研 R2 · 全屏布局改造（r6d300）——边界与实现细节

## A. 关键链（实测）
1. `InGame_TechnologyTree.<init>`：
   - `titleHeight v14 = image(titleTechTree).height`（=60，H/XH/XXH 三档一致；跨设备仍以运行时取值为准）。
   - `menuY v17 = topStatsH + 2*PADDING + title928H`（=132）= 旧菜单 y 的来历（为避开顶部资源条）。
   - `tMenuHeight v10 = min(内容底 v0, GAME_HEIGHT−v17−2*PADDING)`（=816）。
   - 底板 `Empty(0,0,tMaxX+100, v0)`：高度取 **v0=内容底**（不是 v10）。
   - `initMenu(title, x=0, y=居中公式, w=GAME_WIDTH, h=tMenuHeight, …)`。
   - 标题画在**菜单原点上方**：`[posY−titleH, posY]`（MenuTitle.draw: sub-int p3,height）。
   - 页签 pin：rel y = 2*PADDING（12）− menuPosY + posY ⇒ 旧屏 144；改造后自动落 titleH+12。
2. 纵向拖动范围 = `[posY + iHeight − maxY, posY]`；`maxY` 来自 `updateScrollable()`（全部元素包围盒，含底板）。
   - 旧版：iHeight==maxY（都是816）⇒ 纵向锁死。
   - 全屏后必须保持 **maxY ≥ iHeight**（底板高度 = max(内容,可视)），否则范围反转会出怪。
3. 绘制顺序：`draw()` 先 `pinTopTabs` → `super.draw()` ⇒ 首帧 pin 内的一次性 `applyTopFilter`（重建连线用 cyOf）**先于**元素绘制 ⇒ ctor 里初始连线不落痕，无需改。
4. z 层：开树时 `MenuManager.setOrderOfMenu_TechnologyTree()` 把树与其 EMPTY 伴生菜单提到绘制序最上层 ⇒ 标题贴 0 会盖住顶部资源条（符合需求；验收观察即可）。

## B. 自适应口径（回答"别的机型怎么办"）
- **标题与按钮带：不可压缩、纯运行时量**：posY=titleH（贴顶）；按钮带= titleH+2*PADDING 起、高 BUTTON_HEIGHT。
- **科技区：吃掉全部剩余高度**：菜单/底板高 = GAME_HEIGHT−titleH；内容顶 = titleH+2*PADDING+BUTTON_HEIGHT+20；底=GAME_HEIGHT。
- 数值全部来自 `GAME_HEIGHT / titleHeight / PADDING / BUTTON_HEIGHT` 四类运行时量；只保留两个固定数：网格 0xf(15) 与 用户指定 0x14(20)。⇒ 不同分辨率自动重排。
- 小屏（如 720P）：科技区自动变矮；若内容高于可视区，纵向拖动自然生效（maxY>iHeight）。

## C. 编辑点（定稿版见 r3）
- E1 `initMenu` y：居中公式 → `move v3, v14`（titleH）。
- E2 `tMenuHeight`：min 结果后覆写 `v10 = GAME_HEIGHT − v14`。
- E3 底板：`v3 = max(v0, v10)` 作为 Empty 高度（防范围反转）。
- E4 节点 y：`v19 += 2*PADDING + BUTTON_HEIGHT + 0x5`（0x5=20−15）。
- E5 `cyOf`：同 E4 偏移（连线端点与节点同心）。
