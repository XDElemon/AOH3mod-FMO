# 调研 · B5c 布局压缩 R2（边界与实现细节）
> 2026-10-13｜承接 R1（调研_布局压缩_v1.md）｜全部结论来自现行 smali 逐行核实。

## 一、R1 之后新挖出的五个关键事实

### F1（最重要）滚动范围的真源头＝游戏自建的"全宽透明底板"
- 构造器里在按钮建完后，会扫描所有元素取 `tMaxX = max(posX+width)`，然后创建一枚 **`Empty(0,0, tMaxX+100, tMenuHeight)`**（透明、不可点击）加入元素列表。
- 实测：元素 `id46` 的几何 = **(0,0, 31100, 816)**；31100 = (400+100)×62+100，恰为"最右列(61)节点右缘+100"。
- ⇒ **只挪节点不缩这块底板，updateScrollable 的 maxX 依旧是 31100，滚动范围不变**。方案A必须把底板同步缩到"压缩后内容宽+100"。
- 识别方法：运行时 `instance-of Empty`（该菜单里 Empty 仅此一枚）。

### F2 滚动上限是"缓存字段"，由 updateScrollable() 从**全部元素**（含隐藏、含底板）重算
- `Menu.iMaxSliderPositionX/Y` private；`updateScrollable()` 遍历 `iMenuElementsSize` 个元素取 `pos+尺寸` 最大值（不检查 visible）。
- 该字段 private ⇒ 子类不能直接 iget；**需在 Menu 加一个 getter**（本批加 `getMaxSliderX()`，仅用于探针读数）。
- 调用时机：MenuManager 在若干处调用；我们在重排后**显式补一次**，保证当场生效。

### F3 连线的两端＝节点中心（复刻要点）
- 原构建器对每个科技 i：先建 `(RequiredTech → i)` 线，再建 `(RequiredTech2 → i)` 线；
- 四个坐标 = `(W/2+100)+(W+100)*col`、`(H/2+15)+(H+15)*row`（即**节点中心**）；
- `researched` 参数 = `Game.getCiv(player.iCivID).getTechResearched(i)`（目标科技是否已研究）。
- 构造器内部把点列算好；**重建 = 用新坐标 new 一个新的 TechLine**（researched 当场重查，还能顺手刷新已研究线样式）。

### F4 跨栏前置 18/82 条（真实存在）
- 例：EarlyFighter(空)⇐ModernTechFoundation(民)；WarTactics(陆)⇐EarlyFighter(空)；FutureTechnology(民)⇐MainBattleTank(陆)…
- 线集过滤沿用既有规则：**只看目标科技所属栏**（rebuildLines 现状）。因此当另一端点被隐藏时：
  - 端点节点"停靠"到 x=-2000（节点左缘）⇒ 线中心 = -2000+W/2 = **-1800**；
  - 线的起点落在屏幕左侧外，视觉上"从左边进来"——符合"前置在当前栏之外"的语义，不删除该线（保信息量）。

### F5 首开时机无问题
- 首开的 applyTopFilter 发生在 **draw→pinTopTabs→(dbgPIN 首帧)→dumpPinGeom→applyTopFilter**，此时 `initMenu` 早已执行、`iMenuElementsSize>0`（getMenuElementsSize 会返回真实数量）。
- ⇒ 首开即压缩，无需额外补挂点；每次"开面板"也走同一路径（dbgPIN 每次 addTopTabs 清零）。

## 二、既有约束清单（不许碰）
1. B3b 国别过滤：建按钮与建线都要求 `isTechAllowedForCiv(i, civID)` ⇒ 重建线循环照抄。
2. 线的顺序：i 递增；每个 i 先 req 再 req2 ⇒ 重建时保持同序（绘制层次/样式一致）。
3. 页签 pin 公式、探针配额重置、topVisible 过滤：本批零改动。
4. `applyTopFilter` 现调用序：syncTabSelection → applyNodeVisibility → rebuildLines；本批在其中插两步（节点/线重排）+一步（滚动+打点），**rebuildLines 保持在最后**。

## 三、边界与失败模式
- E1 空栏（理论）：sel 无匹配 → maxCol=0、nCols=0 → 底板宽 100；所有节点停靠；不崩。
- E2 停靠值 -2000：仅参与"max"比较不会成为最大值；不会被点中（在可视区外/不可见）；不可见节点 draw 跳过。
- E3 'all'（无入口，仅防回归）：节点恒等映射（原列）、底板不缩、不做停靠。
- E4 重建线时若 req 非法（>=size）？数据保证 req∈[-1..74]，照抄原逻辑仅判 `>=0`。
- E5 性能：每次切栏重建 ≈82 条线的折线（内存操作），量级可忽略。
- E6 副作用：中心定位（centerToTechID，构造期算的旧坐标）首开后可能偏——无入口触达，挂账。
