# 调研 · B5c 布局压缩（消除水平"旷量"）v1
> 2026-10-13｜只读调研（全部数据来自现行 r6d270 JSON + 现行 smali）｜目的：切换 陆军/空军/民用 后，**不再有大段"没科技的空列"**。

## 一、现状机制（实锤）
1) **坐标数据**：每个科技 `TreeColumn/TreeRow`（JSON 字段）。现行75条的列占用：
   - 陆军21：列27–40，实用12列（仅2个内部空列）
   - 空军47：列27–61，实用23列（**内部空列12个，最大连空7列**）
   - 民用7 ：列26–41，实用7列（**内部空列9个，最大连空4列**）
2) **列→像素公式**（InGame_TechnologyTree 构造器）：
   - `x = (iTechnologyWidth + 100) * col + 100`；`iTechnologyWidth=400`（techBlue.png 400×120）⇒ **单元格 500px**，即 `x = 500*col + 100`
   - `y = (iTechnologyHeight + 15) * row + 15` ⇒ 单元格135px
3) **滚动上限**：`Menu.iMaxSliderPositionX/Y` 由 `updateScrollable()` 遍历**全部元素** `posX+width / posY+height` 取最大值（**不检查 visible**）。⇒ 只移动"可见节点"不够，**隐藏节点必须停靠到 0**，滚动范围才会真正缩短。
4) **连线**：`TechLine{ iTechID, lPointsX/lPointsY(绝对坐标点列), researched }`，由构造器 `(outer, iTechID, x1,y1,x2,y2, researched)` 一次性生成折线。列映射变化后，需要**用新坐标重建 TechLine**（researched 可复用，保留已研究样式）。
5) 可挂点：我们的 `applyTopFilter(栏)`（切换/首开都会走）。

## 二、目标
切换栏后：科技**连续排布、没有空列**；横向可滚范围=内容实际宽度；`全部`时恢复原貌（当前无"全部"态，仅默认陆军）。

## 三、效果预估（单元格500px）

|---|---|---|---|---|---|
| 陆军 | 14列≈7100px | 3.1屏 | **12列≈5600px** | 2.4屏 | −21%，内部空列清零 |

## 四、方案清单
### 方案A（推荐）：类别列压缩（保形）
- 规则：对当前栏，把"用到的列"按出现顺序重编号 → `x' = 500*rank + 100`；隐藏节点统一停靠 `x=0`（不影响观感，但不再撑大滚动）；**连线按新坐标重建**；随后调用 `updateScrollable()`；`全部`时用原列号（天然还原）。
- 优点：**保留科技树形态**、行列语义不变、边缘（前置关系）自然，工作量中。
- 缺点：节点间距本身500px不可再压（那是按钮尺寸+间距），空军仍有约4.8屏——但**空列洞全部消失**。
- 风险：折线重算需复用同一公式（有先例：连线构造器）；切换时需重建~90条线（开销可忽略）。

### 方案B：网格重排（彻底"一屏化"）
- 规则：忽略原列，对该栏科技按"每列最多N行"重排成紧凑网格（默认 N=6 或 10），同步重建连线。
- 效果：空军47 → 8列(≈1.8屏) 或 5列(≈1.1屏)；陆军/民用≈1屏。
- 优点：**最紧凑，近乎无旷量**。
- 缺点：不再是"树形"（前置连线会绕行），跨度感/仪式感变弱；实现与调优都最重，且与未来科技扩展的审美需再定。

### 方案C：仅滚动钳制+自动定位（最省事，不符合你的要求）
- 仅把可滚范围夹到该栏包围盒、切换时滚到最左；**内部空列依旧存在**。
- 明确不满足"没有多余旷量"，仅列为对照。

### 方案D：A + 行压缩/间距微调（可选加强）
- 行方向目前0–5行基本用满，收益小；间距100px若缩到40px，可再省~10–15%（观感略挤）。
- 可作为A落地后的参数微调项（一个常数）。
