### 4. 升格"追过去"所需字段（已确认存在且类型正确）
```
 .field public type: MissionType          # 可写（引用型）
 .field public targetMissionID:J          # 追谁（被 trackTarget 读）
 .field public targetProvinceID:I         # 追到哪个省（被 trackTarget 读）
 .field public missionID:J                # 自己 id（供 hasActiveChaser 比对）
 .field public civID:I                    # 敌我判定
 .field public huntUsed:I                 # 防重复追猎
```
`AirMission.update()V`（`.registers 9`）的既有序列：
```
 … state.ordinal() → trackTarget() → airCombatTick() → missileTick() …
```
⇒ **升格钩子插在 `trackTarget()` 调用之前**即可（后续三道门全部自然放行）。

### 5. 玩家与 AI 都能拿到的原因
升格逻辑放在 **`AirMission.update()`（任务侧）** ⇒ 与"这条任务属于谁"无关；AI 的巡逻任务（创建于 AFM:6504 / 8525 / 11250）同样会走这条链 ⇒ **③b 自动满足**。

## 二、第三轮定稿（可直接施工）

### 2.1 设计规则（人话，按判定次序）
1. **若** 本任务 `type != PATROL` ⇒ 不做任何事；
2. **若** `aliveAircraft` 为空 ⇒ 不做；
3. **若** 本回合已经升格/交战过（沿用 `gunLastHours` 与 `HOURS_PER_TURN` 的既有节奏）⇒ 不做；
4. **若** `huntUsed != 0` ⇒ 不做（本任务已用过追猎）；
5. 扫描 `AirForceManager.getInstance().activeMissions`，取**第一个**满足全部条件的敌方任务 `m`：
 - `m.civID != this.civID`；
 - `DiplomacyManager.isAtWar(this.civID, m.civID)`（**仅交战状态**）；
 - `AirForceManager.aiRadarVision(m, this.civID) == true`（**视野内**，①a）；
 - `AirForceManager.hasActiveChaser(m.missionID, this.civID) == false`（无他人已在追）；
6. **若** 找到 ⇒ **升格**：`type = INTERCEPT`；`targetMissionID = m.missionID`；`targetProvinceID = m.airDivisionAtProvinceID`；
7. 之后一切交给既有链路：`trackTarget`（追）、`airCombatTick`（打，含机炮/导弹节奏与伤害）、`tryHunt`（返航时补一刀）。
8. **边界**：不追出视野（每回合重新判）、不打中立/非交战、不改变原有 INTERCEPT/轰炸/对地逻辑。

### 2.2 目标白名单必须一起放宽（否则"追到了也打不着"）
`airCombatTick` 内候选筛选（AirMission:800–812）当前只接受 `STRATEGIC_BOMBING` / `ATTACK_ARMY`。
用户②b＝**视野内所有敌机** ⇒ 定稿采用 **"取消类型过滤"**：
把该段三行
```

 sget-object v5, ->MissionType;->ATTACK_ARMY …      if-eq …:cond_9b
 goto :goto_9d
```
替换为 **"直接选中该候选"**（即 `move-object v2, v0` 后走 `:goto_a0`），保留 `:cond_9b` / `:goto_9d` / `:goto_a0` 标签体系不变、**不新增寄存器**。

### 2.5 失败模式与回滚
| 情况 | 表现 | 处置 |
|---|---|---|
| 视野判定始终为假 | 一架都不升格 | 查 `aiRadarVision` 参数方向（第一参数是"被看任务"） |
| 升格后不飞向目标 | 原地打转 | 查 `targetProvinceID` 是否需写 `m.airDivisionAtProvinceID` |
| 一群飞机追一个 | 目标被秒 | `hasActiveChaser` 判据方向错 ⇒ 反转 |
| 自家领空乱开火 | 误击中立 | 检查 `isAtWar` 参数顺序（`civA,civB`） |
| 编译/校验失败 | 汇编 E>0 | **从 `.pre_<批次>` 整份复原重做**（不得行级清洗） |
回滚点：`AirMission.smali.pre_<批次>`（施工脚本自动落）、`AirDbgLog.smali.pre_<批次>`；装机回退包 `r6d077`。

### 2.6 验收标准（可证伪）+ 门禁计划
- **门禁（独立脚本、真解释器）**：≥4 断言 + 3 负样本
 1. `patrolEngage` 定义存在、`.registers` ≥ 需求、且 `update()` 内挂点 1 处；
 2. `type != PATROL` ⇒ 不升格（负样本：INTERCEPT 任务传入不产生写入）；
 3. `!isAtWar` ⇒ 不升格（负样本）；
 4. `aiRadarVision == false` ⇒ 不升格（负样本）；
 5. 命中全部条件 ⇒ `type/targetMissionID/targetProvinceID` 三写齐备；
 6. 白名单段已无类型过滤（断言 3 行已消失、`:goto_9d` 仍被引用）。
- **抓样（dWrite 免节流）**：`contact= id= civ= mtype= vis= war= chaser= up=0/1`；
 看到 `up=1` 即"巡逻机升格开打"；看到 `contact` 有但 `up=0` ⇒ 判据写反。
- **肉眼**：巡逻中的战斗机遇到视野内敌机时会**转向并追**，随后出现交战（飞机掉血/掉机）。
