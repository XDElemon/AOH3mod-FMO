## 一、R2 新增的关键事实（改写了 R1 的结论）

### 1) 游戏既有的唯一口径（**已存在，不要另造**）

```
// PlayerFogOfWar.smali:28
calcCosK(I y)I  ⇒  int
    f = clamp( cos( (y-4300.0)/4300.0 * π/2 ), 0.25, 1.0 )      // π/2 = 0x3fc90fdb
    return (int)( f*f * 1000.0f )                                // 即 f² 的千分比

// PlayerFogOfWar.smali:80
calcInEllipse(I dx, I dy, I R, I cosK)Z      // 逐字语义：
    f2 = cosK / 1000.0f
    return ( dx*dx*f2 + dy*dy ) <= R*R
    ⇒ 命中 ⇔ |dx| <= R/f（东西向半轴×1/f）且 |dy| <= R（南北向半轴=R）
```
**这是等距圆柱投影下物理正确的"地面等距圈"**：1px 纵向=固定 km；1px 横向=km×cos(φ)。
⇒ 高纬处"圈"应当**横向变宽（×1/f）、纵向不变**。

## 二、口径 A 的施行方式（定稿）

**统一目标式（唯一真值）**：
```
判定：calcInEllipse(dx, dy, R, calcCosK(centerY))     // 已存在
渲染：半轴 (Rx, Ry) = ( R·scale / f , R·scale )        // 即 ×(1/f) 与 ×1
```

### 逐点改法（渲染：1 行算术 + 4 行 draw 参数互换）

以 R1（2601-2713 区）为例，**现状**：
```
2665  int-to-float v7, v7
2667  mul-float v7, v7, v3          # v7 = R·scale（屏幕 R）
2669  mul-float v6, v6, v7          # v6 = f·屏幕R   ← 要改
2671  float-to-int v6, v6           # v6 = Y 半轴
2673  float-to-int v7, v7           # v7 = X 半轴
2699  sub-int v10, v4, v7           # x = cx - X半轴
2701  sub-int v11, v5, v6           # y = cy - Y半轴
2703  shl-int/lit8 v12, v7, 0x1     # w = 2*X半轴
2705  shl-int/lit8 v13, v6, 0x1     # h = 2*Y半轴
```
**改为**（X 半轴=R/f、Y 半轴=R；靠"互换 y/x 角色"实现，不动寄存器个数）：
```
2669  div-float v6, v7, v6          # v6 = 屏幕R / f  ⇒ 新 X 半轴
2671  float-to-int v6, v6
2673  float-to-int v7, v7           # v7 = 屏幕R      ⇒ 新 Y 半轴
2699  sub-int v10, v4, v6           # x = cx - v6
2701  sub-int v11, v5, v7           # y = cy - v7
2703  shl-int/lit8 v12, v6, 0x1
2705  shl-int/lit8 v13, v7, 0x1
```
R2 同法（其 Y 半轴叫 v2，X 半轴叫 v7：`div-float v2, v7, v6` + 三处 draw 互换）。
R3（`RadarBitmap`）：`drawRadarEllipse(bmp, cx, cy, p3, p4)` 的 `p4` 由 `v0·f` 改为 `v0`，另需给 `p3` 传 `v0/f`（要一个额外寄存器，R3 时按实取）。
R4（飞机雷达圈）：待读到 draw 调用后再定（同法或改用 `calcInEllipse` 同源的半径函数）。

### 唯一入口（"以后全走这个"）
- **判定侧**：直接用游戏既有的 `calcCosK` + `calcInEllipse`（不改名、不包装，天然就是唯一入口）。
- **渲染侧**：把内联 cos 块替换/改写为同一算式；建议新增我方 `AirLat.smali` 提供
  `xMul(I y)F = 1/f`、`yMul(I y)F = 1f`（f 取 clamp 后），让 4 处渲染**调用同一函数**，
  并让 `calcRadarRy` 与新函数同源（`calcRadarRy` 语义需同步为"返回 R/f"或标记废弃）。
  ⚠️ `calcRadarRy` 有 1 个既有调用点（4093），改动前必须先读该处 draw 的轴映射（R4 待办）。
- 参数文件化：`toolchain/act/airlat.expected`（`MIN_F=0.25 / MAX_F=1.0 / MID_Y=4300 / MODE=A`），门禁读它校验各算式一致。

## 三、验收标准（可证伪）

1. **静态**：`AirLatSim`（行为级模拟器，解释真实 smali）断言
   - `calcInEllipse`：dy=0 时 |dx|≤R/f 为真、R/f+1 为假；dx=0 时 |dy|≤R 为真、R+1 为假；
   - 渲染侧 4 处：给定 (R,scale,f) 产出 (X,Y)=(R·scale/f, R·scale)；
   - 反转敏感性自检：把 `div` 改回 `mul` 必须变红。
2. **端到端（探针）**：新增 `nLAT` 诊断行（走 `dWrite`，免 500ms 节流），每回合打印
   `nLAT c=73 y=… f=… R=… Rx=… Ry=…` 一段，覆盖 f=1.0 与 f=0.25 两个极端省份。
3. **肉眼**：高纬雷达圈**横向变宽（约 1/f 倍）、纵向不变**；且"站在圈外探测不到"重新成立。
4. 反向门禁：不得出现 `mul-float` 后紧跟"Y 半轴"的旧形态（旧形态计数必须=0）。
