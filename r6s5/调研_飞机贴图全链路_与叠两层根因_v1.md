## 二、取图口径（**你问的那件事：是的，按"所在省的主人"**）

`ProvinceDrawArmy.smali:5937-5942`（就在调用绘制的前一行）：
```
v9 = v7.getCivID()                       // v7 = 省 ⇒ 「省份主人」的国家
v9 = AirForceManager.artGroupOf(v9)      // civ → 美术组
AirForceManager.dgAirGroup = v9          // ← 全局静态；跨省绘制时被反复覆盖
ProvinceDrawArmy.drawAirDivisionAsPlane(...)   // 内部 airImgForType() 读 dgAirGroup
```
- `artGroupOf(civ)`：按 `Civilization.getCivTag()` 前缀映射（chi/chn→0；usa→3；默认2=RU…）。
- `dumpAirGroup` 的**唯一写点就是这里** ⇒ 飞机涂装实际由**它当前所在省份的主人**决定；飞机飞进敌国省 ⇒ 变成敌国涂装。
- **工程里本来就有正确函数**：`AirForceManager.airImgForCiv(Laoc…Airport 的 civ, type)`（内部 `artGroupOf(civ)` + `pickAirImage(3, group, type)`）—— **全工程 0 个调用者（死代码）**。
- UI 侧用的是 `armyCardImgFor(civ)`（按国家）✓ ⇒ 所以"卡片图对、地图贴图错"。

## 三、"叠两层"根因（主嫌：假 key 的"摘/写"振荡）

`AirDbgLog.airDrawAsPlane(key, div)`（r6d059 批次定稿、当时用户验收通过）：
```
1 key==null → 否 2 key 不以 "airhq_" 开头 → 否 3 编制列表为空/null → **stripFakeKey(div)** → 否 4 编制含任一 isAirUnitID(uID)（File 以 "Air" 开头）→ 是 5 编制全是陆军 → **stripFakeKey(div)** → 否```
`stripFakeKey(div)` ＝ **`div.key ← CFG.extraRandomTag()`（把 key 永久改成随机串！）**；另有反向修复在 `AirMission.tickInvars`：key 非 `airhq_` ⇒ **写回** `mission.airhqKey`。

⇒ **同一个师的 key 会在"随机串 ↔ airhq_真key"之间来回振荡**，而全系统**所有身份操作都是按 key 匹配**：
- `AirMission.placeAirDivision`：`Province.removeArmy(getAirDivKey())` 从旧省删除、`getArmyKeyID(key)>=0` 去重；
- `AirForceManager.getAirMissionByKey(key)`（绘制时找任务、判定飞行态）；`getKeyCiv/getKeyOrd(key)`（涂装组/机型序数）。

**推断的事故链**（与"飞到敌国省"吻合）：
1. 飞机起飞 ⇒ airhq 师的编制里没有"驻留在师里的航空单位"（都出任务了）⇒ 判定链走到 3/5 ⇒ **key 被改成随机串**；
2. 任务 tick ⇒ `placeAirDivision(新省)` 的 `removeArmy(真key)` **匹配不到** ⇒ 旧省那份**删不掉**，新省**又加了一份** ⇒ **同一个师同时存在于两个省**；
3. `tickInvars` 把 key 写回 ⇒ 两省都按 `airhq_` 真 key 被绘制 ⇒ **同一架飞机被画两次**；
4. 两省的**主人不同**（我方省 vs 敌国省）⇒ 两次绘制可能取到**两套国别涂装**（见第二节的全局 `dgAirGroup`），所以看起来是"两层贴图"。

**次嫌**（暂列）：敌国省本来就有敌国的 airhq 师，两台各自按所在省取图；或同一省内因去重失败出现两条记录（画在相邻槽位）。

**与 r6d153 的关系**：r6d153（起飞空窗改飞行样式）**没有制造重复**，但让"无有效航段"时也会绘制 ⇒ 原来"看不见的重复"现在**变得可见**。这是暴露、不是新引入。
