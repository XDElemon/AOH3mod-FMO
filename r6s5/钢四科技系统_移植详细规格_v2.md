# 0. 最关键的技术前提：**新字段怎么加才生效**

本作资源 JSON 走 **libGDX `Json` 反射绑定**（`TechnologyTree.load()` 里 `setElementType(...,"Technology",TechnologyTree$Technology.class)` 后 `fromJson`）。

⇒ **加一个字段 = 三步**（全部可控、可回滚）：
1. 在 `TechnologyTree$Technology.smali` 里加 `.field public StartYear:I`
2. 在 `assets/game/technologies/Technologies.json` 的节点里加 `StartYear: 2030,`
3. 在业务代码里 `iget` 读它

**旧存档不受影响**（缺键 → 字段保持默认值 0），**未知键被忽略**（不会崩）。

# 2. 逐件详细规格（可勾选）

## ★ M1 年份门槛 `start_year`（钢四的灵魂机制）

| 项 | 内容 |
|---|---|
| 钢四原机制 | 每科技 `start_year`（如 fighter1=1936、jet=1945+ 且需特殊项目）；早于年份研究要付惩罚 |
| AoH3 现状 | **无年份概念** |
| 落点 | ① 加字段 `TechnologyTree$Technology.StartYear:I`（smali 加 `.field`，JSON 加键）② 注入 **`Civilization.getAvailableToResearch(I)Z` @8257 的末尾**（`return true` 之前，`cond_5a` 分支） |
| 注入伪码 | ```
:cond_5a
iget v0, v0, ...Technology;->StartYear:I      # 取该节点年份
if-lez v0, :ok                                # <=0 = 不设门槛
invoke-static {}, Game_Calendar;->getYear()I  # 或等价取当前年
if-ge v1, v0, :deny                           # 当前年 < 门槛 ⇒ 不可研究
:ok   const/4 v0, 0x1 / return v0
:deny const/4 v0, 0x0 / return v0
```
| 自动覆盖范围 | **5 个调用方一并生效**：`AI_SelectTechnology`（AI 选科技）、`GameThread`（自动兜底选科技）、`PlayerTechQueue` ×2（玩家排队）、`InGame_TechnologyChoose`（UI 置灰） |
| 真值表 | `StartYear<=0` → 可研究（不拦）｜`当前年 < StartYear` → **不可研究**｜`当前年 >= StartYear` → 可研究（前置另判） |
| 风险 | **AI 空转**：`GameThread` 的兜底逻辑是"扫描第一个可研究对象"，若某年代全部被年份拦住，AI 会一直扫（性能）且不产出研究 → **必须同时给 AI 兜底策略**（见 M2 或把 AI 改为"只扫未超前的"） |
| 工作量 | 1 批（含 1 次真机验证） |
| 验收（可证伪） | 把某节点 `StartYear` 设为 2030 → 开局该节点置灰不可研究；把系统年份推到 2030 → 可研究；AI 在开局仍能正常研究（不空转） |

## ★ M2 AI 兜底与权重（M1 的必要配套）

| 项 | 内容 |
|---|---|
| 落点 | `AI_SelectTechnology.selectTechnology(I)V` + 节点 `AI:I` 字段 + `GameThread` 兜底扫描 |
| 做法 | ① 给新节点 `AI: 8~10`（现全树多为 5）② 兜底扫描改为"只扫 `StartYear<=当前年` 的节点"，避免空转 ③（可选）加"同带优先"策略 |
| 工作量 | 与 M1 同批 |
| 验收 | 开局 AI 会研究、且**不会**研究被年份锁住的节点 |

## ★ M3 提前研究惩罚（ahead-of-time penalty）

| 项 | 内容 |
|---|---|
| 钢四原机制 | `BASE_YEAR_AHEAD_PENALTY_FACTOR = 2`（早于年份，成本翻倍级上升） |
| 落点 | **`TechnologyTree.getResearchCost(II)F` @915**（静态、集中，被 Civilization×2、UI×1 调用） |
| 注入伪码 | `cost = base`；`if (StartYear>0 && year<StartYear) cost *= (1 + (StartYear-year) * P)`，建议 `P=0.5`（每提前 1 年 +50%） |
| 真值表 | 准时研究 → 原价｜提前 1 年 → ×1.5｜提前 2 年 → ×2.0｜提前 4 年 → ×3.0 |
| 风险 | 需保证 UI 与实际消耗走**同一入口**（已确认 UI 走 `getResearchCost(II)F`，天然一致） |
| 工作量 | 与 M1 同批 |
| 验收 | 提前研究时 UI 显示成本与实扣一致；准时研究时无变化 |

## M4 研究槽（2 槽 → N 槽）

| 项 | 内容 |
|---|---|
| 钢四原机制 | `BASE_RESEARCH_SLOTS = 2`，可由国策/科技增加 |
| AoH3 现状 | **已有 2 条**（主槽 + 备选槽），容器是 List |
| 落点 | ① 新字段 `Civilization.iResearchSlots:I`（默认 2）② 改 `GameThread` tick（5520/5604 一带）为"循环 K 槽" ③ 槽数来源可挂：建筑（`ResearchFromBuildings`）或科技节点加成 |
| 风险 | 中高：要动 tick 主循环 + 存档兼容 + UI 是否显示多槽 |
| 工作量 | 2 批 |
| 验收 | 默认 2 槽；通过某建筑/科技把槽提到 3 后，能同时推进 3 项研究 |

| 项 | 内容 |

| AoH3 现状 | **无类别概念** |
| 落点 | ① 加字段 `Category:I` ② 维护一张"类别 → 加成"表（可从政体/法律/事件写入） ③ 在 `getResearchCost(II)F` 或 `addResearchProgress(IF)V` 里应用乘区 |
