## 四、AD-1 代码本身的问题（重启要改的地方）

| # | 问题 | 说明 |
|---|---|---|
| P1 | **只打"在任务里、且已部署"的飞机**（`AirMission.airDivisionAtProvinceID >= 0`） | 若游戏里大多数飞行单位此刻并不满足该条件，就会像观测到的那样"永远没目标" |
| P2 | **射程 300px（省中心距）** | 中国/欧洲省份密集时够用，但 **大省（如俄罗斯、蒙古）省中心距可能 >300px**，即在省内开火也可能判"不在射程"（同省是单独一条 `a == prov.getProvinceID()`，这条在，理论不中招） |
| P3 | **每国每回合并发触发**：`AirForceManager.updateAll()` 只遍历**有空军基地**的国家 | ⇒ **没有机场的国家，其防空永远不会 tick**（用户若拿"只有反导阵地、没机场"的国家测，必然看不到任何动静） |
| P4 | **开火条件过窄**：要求目标国"还有活飞机"且"任务未收尾" | 观测到 `nAD` 零行，与 P1/P3 组合最可能 |
| P5 | **下一回合才可能再判**：`update(I)` 是每回合一次 | 用户若只看一两回合就断言"没反应"，属正常节流 |

→ **重启时第一件事不是恢复开火，而是先用"只读探针版"把 P1–P4 逐条证伪/证实**。

## 五、重启路线（建议分 3 步走，先诊断后开火）

### 步 1 · AD-R0「只读诊断版」（**零行为改动**，1 批，风险≈0）
把 `AirDefense` 以"**只读**"形式放回：**不算伤害、不记账、不写任何游戏字段**，只回答四个问题并写 `dWrite`：

| 探针 | 回答什么 |
|---|---|
| `nADT c=<civ>` | 本回合 tick 有没有跑（沿用） |
| `nADC c=<civ> p=<pid> aaa=<n> rad=<n> mid=<n>` | 每省**是否有反导阵地/雷达/中层雷达**、各几个（回答"建筑到底有没有被识别"） |
| `nADM t=<total> own=<civ's> enemy=<敌> noDep=<未部署> empty=<空编队> air=<有飞机>` | **任务盘点**：全世界任务里各状态各多少（回答 P1：到底有没有"在任务里且已部署"的敌机） |
| `nADR p=<pid> near=<n> d=<最近省中心距px>` | 每省到最近敌机的距离分布（回答 P2：300px 到底卡掉了多少） |
| `nADK c=<civ> ap=<机场数> aaaOnly=<有阵地无机场的省数>` | 回答 P3：有没有国家因"没机场"而永不 tick |

**判定**：装上后玩 2–3 回合，把日志发我 ⇒ 能直接判出"没目标 / 建筑没识别 / 射程不够 / 国家不 tick"是哪一条。**这一步不改变任何游戏行为，因此"空军被改坏"若再出现，也一定与防空无关**（可作对照实验）。

## 八、回档后必须守的纪律（防空重启版）

- 装机前 `df -h /data`（空间不足会装失败）；`pm install` 前先 `cp` 到 `/data/local/tmp/`（SELinux）。
- 打包模板 = **上一个归档包**（当前 = `dbg_signed77_v119_r6d168.apk`）。
- 探针一律走 **`dWrite`**（免 debug 闸、免 500ms 节流）；`dKey` 只作业务通道。
- 新类放回树之前，先跑 `check_regtype.py` / `check_castorder.py` / `check_params.py`；**插入块必须在 `check-cast` 之后**。
- 每批交付都要写「设计逻辑 11 项」+ 实测记录；实验版若无行为改动，要显式标注"零行为改动（对照用）"。
