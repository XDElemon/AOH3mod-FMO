# 地图范围盘：叠放与裁剪

> 来源：2026-10-25~26，v77→v88 十几个版本，其中 v78–v87 基本是弯路。
> 详细交接：`/sdcard/GLG/DSHA/FMO_雷达盘裁剪_交接_20261026.md`

## 1. 用户确认过的口径（别再自己发明）

1. **红圈默认压在蓝圈之上**
2. **半径小的盘压在上面**（大的先画）
3. 防空阵地这种「蓝圈比红圈小」的：**小蓝圈可以压在该红圈之上**
4. 但这个小蓝圈若被**更大的蓝盘**覆盖：**被覆盖部分退到红之下（露出红）**，没覆盖的仍在红之上
5. **不要**描边环、**不要**半透明混色

用户认可的目标图：`/sdcard/GLG/DSHA/v85_mock_compare.png` 第 ① 张。

## 2. 代码结构

| 文件 | 角色 |
|---|---|
| `src/java/.../province/AirDiscQueue.java` | 每帧收集四类盘 → 排序 → 需要让位的蓝盘求差 → 逐行落笔 |
| `src/smali/.../province/AirRect.smali` | 1×1 白纹理 + 纯色矩形 `fill(Object,int x,int y,int w,int h,int rgb)` |
| `src/java/.../province/AirRadarBld/AirRadarAD/AirRadarPlane` | 三类盘的收集端（`addBlue` / `addColor`） |
| `ProvinceDrawArmy.drawAircraftRadar` | 任务蓝盘改入库；`RadarOverlay.end` 之前 `flush` |

盘半径口径：蓝 = 空军基地 200 / 雷达 600 / 反导阵地 300 / 中层反导 2400（世界像素×scale）；
红 = 100 或 130 × `iMapScale(=4)` ⇒ 400/520。
**红比蓝小/大的情况都会出现**，所以排序必须按实际半径，不能按颜色分组。

## 3. 排序

稳定插入排序，**按 rx 降序**；等半径保持收集顺序。
红盘不参与"被裁"，永远整盘画；蓝盘才可能需要让位。

## 4. 裁剪（CPU 扫描行差集）

```
for 每个蓝盘 d（按排序）:
    need = 与任一前序蓝盘相交 且 与任一红盘相交
    if !need: 整盘画
    else: for y in [-ry, ry) step 2:
            iv = 圆盘在该行的横区间
            blocked = (前序蓝盘并集) ∩ (红盘并集)     # 只为"红色覆盖"让位
            画 iv - blocked 的剩余段（AirRect 2px 高）
```

要点：
- **只裁「更大蓝盘 ∩ 红盘」**。无条件裁蓝会在蓝蓝重叠处裁出洞（那个位置没有红可露）。
- 区间求差收尾：`if (be >= end) { start = end; break; }`，否则收尾又把遮挡段画回去。
- 行宽 < 2px 跳过，避免椭圆边缘残条。

## 5. 五条死路（都真机验证过，别再试）

| 方案 | 结果 |
|---|---|
| 红盘改**描边环** | 用户明确否掉 |
| 半透明混色 | 用户否掉（颜色会混） |
| **stencil 裁剪**（FBO 带模板） | 真机**整帧画空**：带 stencil 的 `FrameBuffer` 在本机建不完整 |
| **每帧重烘纹理 + `Texture.draw(pixmap,0,0)` 上传** | 上传不生效：只有角度绕回 0 时视觉跳一下 |
| **旋转贴图表现椭圆扇面** | 压扁椭圆旋转后不再重合，会转出盘外 |

推论：**这个项目里凡是"GL 状态/动态上传"的裁剪方案都要先做最小验证**，别直接铺开。

## 6. 未解问题（v88，真机）

- 大蓝盘在**左** → 小蓝盘**整块消失**
- 大蓝盘在**右**且**未包住小蓝盘圆心** → 绘制错乱
- **离线模拟器复现不出** ⇒ 失败点在真机取数/绘制路径，不在几何模型

优先怀疑（按顺序）：`rowInterval` 把区间打包成 `(left<<16)+right`，**left 为负**（盘有一部分在屏幕外左侧）时的解码；
`AirRect` 在屏幕坐标下的落点；单帧矩形数是否超 SpriteBatch 单批容量。

## 7. 离线模拟器（动裁剪前必须先跑）

Python + PIL 复刻同一算法，改参数出图，见
`/sdcard/GLG/DSHA/FMO_雷达盘裁剪_交接_20261026.md` §3.2 与 `v88_cases.png` / `v88_case1_sweep.png`。
**纪律：任何裁剪改动先在模拟器里看形状，再出包装机。** 装机一轮的成本远高于渲染一张图。

## 8. 下一步（推荐）

**方案 B：整盘阈值判断**——小蓝盘被「更大蓝盘 ∩ 红盘」覆盖的面积占比 > 阈值（如 60%）就整盘不画，
否则整盘画。不会出现残条/错位/消失，几行代码，阈值可调。
保底：退回 v83（纯半径排序，不裁）。

## 9. 验收清单

- [ ] 蓝蓝重叠无洞
- [ ] 红环/红面在蓝之上（红比蓝小时）
- [ ] 小蓝盘被大蓝包住时"该消失就消失"，半包时只剩外面那一块
- [ ] 被裁边缘没有残条（行宽<2 跳过）
- [ ] 缩放/拖动地图时不抖、不错位
